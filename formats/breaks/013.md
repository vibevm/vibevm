# Break 013 — install/update/reinstall reports: the `hooks` member is removed

**Date:** 2026-11-22 · **Format:** `cli-install-report`, `cli-update-report`, `cli-reinstall-report` · **Epoch:** 1 (unchanged)

## What changed on the wire

The root `hooks` member is gone from all three reports. It reported the package
`[hooks]` table, which is no longer read (PROP-020 `#LEGACY-HOOKS-REMOVED`), so
since that removal it was always empty.

- `vibe update` and `vibe reinstall` no longer emit `"hooks": []`. Before:

  ```json
  { "ok": true, "command": "reinstall", "forced": false, "hooks": [] }
  ```

  After:

  ```json
  { "ok": true, "command": "reinstall", "forced": false }
  ```

- `vibe install` omitted the member when empty, so its documents are
  byte-identical to before.
- The `install_hook_report`, `update_hook_report` and `reinstall_hook_report`
  definitions are removed from the schemas, together with the generated types.

An install script's outcome travels as its row in `contributions`, exactly as it
did before this change.

## Why it is a break rather than an addition

The update and reinstall schemas declared `hooks` as always present
(`x-empty: emit`). A key the old schema promised disappears, so a consumer that
indexed it unconditionally now finds nothing.

Readers are permissive: an old document that still carries `"hooks": []` parses
under the new generated types, which drop the key.

## Why no epoch

The system is in the pre-publication regime (`public = false`, break window
open), with one world that is rebuilt rather than migrated. The member carried
no information — it was empty in every document written since the `[hooks]`
removal — so there is nothing to keep side by side.

## Who fixes it

Scripts and tools that key on `.hooks` in the JSON output of `vibe install`,
`vibe update` or `vibe reinstall`. Nobody else has an action.

## Sunset

None. The old shape is not published in parallel.

## User recipe

Read script outcomes from `.contributions[]`. A consumer that must accept both
old and new documents treats an absent `hooks` as empty.
