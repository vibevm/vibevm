# Full application configuration portability (Unreleased)

This change implements selected-installer export/import and continuation. Cargo remains 1.0.11; this note does not assign a release number. It supersedes the portable-configuration refusal recorded at the earlier runtime stage in [005](005.md). It does not activate configured package solving for other package kinds. There are no new `vibe.toml` keys in this increment, and the ordinary `vibe install -g` source grammar stays unchanged.

## Public files and commands

| Surface | Producer/reader behavior |
| --- | --- |
| `vibe-apps/1` | The existing legacy document remains readable with its prior reader tolerances. Legacy-only automatic export remains version 1, including its intentionally weaker effective-only feature/parameter history. The legacy-only library projection still refuses data it cannot represent. |
| `vibe-apps/2` | New strict JSON and TOML document, owned by `schemas/application/e2/apps.jtd.json`. Full original configuration history, exact selected roots and recorded dependency closure travel together. |
| `vibe-app-import-input/1` | New strict JSON target decisions, `schemas/application/e1/import_input.jtd.json`; supplied through `app import --target-input FILE`. |
| `vibe-app-import-secrets/1` | New strict JSON ephemeral answers keyed by exact application and parameter; supplied through `--secret-input FILE`. Answers are not serialized into application/cohort state. |
| `vibe-app-import/1` response | Additive optional `pending = { target, input }`, where input contains the exact application key and required parameter IDs. Waiting exits 2 and retains completed prefix outcomes; it is not Installed, Skipped or terminal Refused. With no pending object the old response shape is preserved. |

`app export --configuration` explicitly chooses full version 2. Without that flag, selected common configuration or value-free secret-origin information that version 1 cannot carry selects version 2 automatically. Detection includes required closure and, under `--all`, every carried row. Legacy feature/parameter/held fields alone do not change automatic version-1 behavior. `--json` chooses JSON; the default remains TOML. Serialization/admission finishes before an output file is truncated.

Version 2 requires `protocol`, `exported`, `home`, `platform`, `arch`, `roots` and `application`. Optional arrangement fields remain `collection`, `pin` and `launcher`. `home = "project"` is descriptive export data, not a new project import route; import still targets the user home.

Each application row requires `key`, `installer`, `platform`, `arch`, `mark`, `held`, `hidden`, `licenseAccepted`, `configuration` and `requires`. An edge contains the requested package spelling, exact key, build/runtime scope and optional step. `roots` contains unique present Manual keys, separately from carried rows and their ownership marks. Selected roots retain their order. Required closure can include hidden/nonroot Manual records and Auto records. Source license acceptance is historical information; target consent still belongs to the existing license owner.

`configuration.kind` is closed:

- `legacy-effective`: `features`, `parameters`, `secretOrigins`. These are effective values and known provision metadata; missing historical intent is not reconstructed.
- `configured`: `history`, containing `definition`, `fingerprint`, `input`, `reliance` and typed public/secret parameter history. It contains no fabricated resolved plan or interactive controls. Public rows retain type, origin, lexical source and optional historical realization. Secret rows retain only value-free origin/provided metadata.

Export and decode share semantic admission, including exact edges/roots, history references and public-value/known-secret overlap rejection. Full export uses one home lock and refuses relevant unfinished work or a relevant unindexed replacement. Complete operations with an optional failed step remain valid completed installations. Relevant retained child plans count even before the child's work begins. Reading/export does not migrate the index or work records.

## Presence, paths and scoped decisions

Portable omission is `None`. On the new fields explicitly annotated `x-null-alias = "absent"`, JSON null also decodes to None, and canonical serialization omits None. Empty lists/maps, false, zero and empty strings remain actual values. A present selection object with omitted members remains present and is different from an absent group entry; explicit empty members remain empty. Exact/additive intent and dormant answers are retained. Required fields/containers stay required.

This does not change the canonical `vibe-configuration-input/1` required-nullable members or old reader grammar. A target replacement uses that existing canonical input vocabulary and requires its actual `expectedDefinition`. Missing canonical required members still refuse. Signed i64 values/bounds keep canonical decimal strings; unsigned formats are unchanged.

A source-host path realization is diagnostic history, never a target-host path default. Each consumed public Path needs an explicit absolute native B binding, validated against B's current declaration. Its original profile/default/explicit origin and lexical source are retained, while subsequent B maintenance reuses B's validated realization. A's path need not exist. Declared secret defaults are public definition data; runtime secret answers are redacted regardless of whether the answer overrides such a default.

Target JSON has required `protocol` and `applications`. Each exact-key target value requires `pathBindings` and may contain `installer`, `reviewDefinition` and `configuration`. A changed target definition requiring automatic-policy review is not approved merely by loading the portable file. A deliberate replacement is separately guarded against the actual current definition. Public-to-secret reclassification refuses before public persistence; configured history cannot be flattened into a legacy target installer.

Secret JSON has required `protocol` and `applications`, whose values are parameter-ID-to-string maps. A known Explicit source secret requires fresh resupply. A B answer offered for a later row also leaves a value-free obligation when an earlier row parks; losing that answer does not renew its default. Same-ID parent/child answers are never broadcast. A completed child proved to belong to the same cohort is reused without consuming its answer again or claiming answer equality. A fresh answer for an unrelated installed opaque secret requires explicit reconciliation.

FILE `-` reads standard input once. Competing standard-input consumers refuse. Secret file read/parse errors discard filenames, raw values and underlying error chains. Terminal cleanup does not reopen an unused secret file. New flags on a legacy portable import refuse instead of being ignored.

Pure validation examines the entire source document. Fresh target resolution/preparation uses only roots plus recorded required closure. Unused orphan Auto rows remain operator-file data: they are not queried, prompted or installed. Explicit target/secret submissions for inactive rows refuse with an unused-input explanation. No-roots input creates no application jobs; arrangement remains a separate existing operation. Retained cohorts are not pruned or rewritten on read.

## Migration examples

Use the producer to obtain complete configured definitions/history rather than reconstructing an old effective record:

```sh
vibe app export --configuration --output apps.toml
vibe app export --configuration --json --output apps.json
vibe app import apps.toml --target-input target.json --secret-input -
vibe app import --resume OPERATION_ID --secret-input -
```

For an exported application declaring a public Path parameter `data`, a target input can be:

```json
{
  "protocol": "vibe-app-import-input/1",
  "applications": {
    "org.example/editor@1.0.0": {
      "pathBindings": { "data": "/srv/editor-data" }
    }
  }
}
```

The matching secret document is separate, for example a runtime `token` answer under `applications["org.example/editor@1.0.0"]["token"]`. It never belongs in the exported history. If the target installer/platform changes, provide the actual offered installer explicitly; review/replacement fingerprints must come from the actual current definition, not the source file's old basis.

A complete minimal version-2 TOML file can still describe legacy effective data:

```toml
protocol = "vibe-apps/2"
exported = "2026-11-05T00:00:00Z"
home = "user"
platform = "linux"
arch = "x86_64"
roots = ["org.example/editor@1.0.0"]

[[application]]
key = "org.example/editor@1.0.0"
installer = "main"
platform = "linux"
arch = "x86_64"
mark = "manual"
held = false
hidden = false
licenseAccepted = false
configuration = { kind = "legacy-effective", features = [], parameters = {}, secretOrigins = {} }
requires = []
```

Old version-1 files remain effective-only; reading them cannot restore an original profile, dormant input, default consent or missing secret receipt. Existing legacy import behavior remains separate from full import. Old binaries do not support the new file/input/private protocol tags and must not be used to continue new full cohorts. No read-time migration claims compatibility with those old writers.

## Finite continuation and compatibility

The existing import-work directory is still the only cohort owner: `<home>/cache/app-work/imports/<operation>/import.json`. New full cohorts use `vibe-app-import-work/2`, schema `application/e2/import_work`. The old strict work/1 reader remains byte-preserving. There is no index/steps version increment in this change, no sidecar and no second operation database.

Full work retains typed roots/bindings, cursor, required-nullable current child, ordered outcomes, policy/arrangement progress, required-nullable waiting input, `secretRequirements` and `completedBindings`. Required maps/lists are present even when empty. Each binding stores immutable source row plus admitted target source/installer/declaration identity, per-step agent modes and public target input. Waiting must belong to the active root/required closure; descendant waiting requires a real current root attempt. Cursor advancement requires exactly one ordered outcome for every settled root.

`app-import-bindings/1:sha256:…` frames canonical cohort target, immutable roots order and typed bindings. Source value-free secret history belongs to that meaning; cursor/results/availability/current resupply obligations and answers do not. Imported operations use `app-execution-context/2:<scope>:sha256:<context-hash>`, including that scope inside the hashed typed execution context too. A no-import operation keeps its exact prior execution-context/1 computation and bytes. These are drift checks, not authentication of editable storage, recipe reproducibility or secret equality.

Imported exact edges bind before installed-newest selection, including a legacy intermediary. Compatible source ranges can share one exact child. Compatible existing Manual ownership/visibility/held policy is preserved. Target-only dependencies use ordinary requirements; their questions are not mislabeled as imported root answers. A verified exact direct child resume can resupply its own ordinary target-only input without broadcasting it or admitting unknown whole-cohort secret-file recipients. A retained ordinary target-only resolver query checks the saved route immediately before invoking that resolver; installed/completed reuse and cleanup do not require an unused lookup. Caller-owned resolver closures remain the caller's responsibility.

A terminal Refused root is recorded before its slot is released. Successful imported descendants can transfer to direct cohort ownership through `completedBindings`, keyed by exact application key. Each receipt requires `target`, `publicationRecord`, `scope`, `originRoot`, `originRow`, `previousParent`, `previousParentOwner` and `state` (`captured`, `reparented`, `detached`). Capture precedes reparenting; reparenting precedes unlinking the old edge. Known cuts are recoverable through the same owners. The Refused ancestor is never a successful receipt; its exact target remains historical outcome evidence for a same-cohort retry.

Receipt reuse requires exact retained generation, ownership, scope and live publication identity, with no pending/unindexed replacement. Retained ownership blocks new same-key execution and removal, including opaque-answer changes that would leave public metadata equal. Target-only children do not acquire invented source-binding receipts. Completion or explicit cohort abandonment retires these reservations through ordinary work cleanup. Completed cleanup is repeatable after sources/unused executors/answer files disappear; it neither repeats setup nor consumes new answers.

## Generator and Rust API changes

The opt-in `x-null-alias = "absent"` is legal only on optional nullable fields with omission/None default. Invalid placement/type/conflicting policy refuses before collection early-return handling. Grammar-aware traversal distinguishes schema keywords from arbitrary definition/variant/member names. The optional-shape stitch key includes required versus optional presence; identical OptionValue decisions can share a representation, while indistinguishable conflicting transformations refuse. No nullable bit is guessed from generated Rust, and unopted legacy collection behavior is not globally tightened. Real compiled JSON/TOML witnesses cover direct/ref collections and required/optional collisions.

New portable and target/secret input formats are operator-owned and `recoverable = false`; the historical apps/1 classification is unchanged. New private work remains closed. Public pending references use explicit consumer-site permissive projections without weakening their strict canonical private targets.

Library additions include versioned `PortableDocument`, `export_portable`, pure `selected_import_keys`, `prepare_full_import`, `preview_full_import`, `import_full`, `resume_full_import`, inspection and scoped input parsers. `EvaluationRequest.previous` now accepts the narrow `ConfigurationHistory` view and explicitly distinguishes local realization reuse from transfer. `InstallRequest` / `PlanInput` gain transfer data, and `OperationContext` carries an optional host-created import scope. Public struct-literal callers must supply the new fields (ordinary callers use None); no request/state serializes an ephemeral scope or secret owner. Local configuration evaluation, normal maintenance and full transfer share the existing evaluator and runner.
