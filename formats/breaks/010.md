# Authored changes and pure migration proposals (Unreleased)

M13C1's pure manifest migration planner is accepted. The M02B1/B2 authored-change and work-graph readers are accepted at their original pure parser/read/structural-identity boundaries. These additions do not change `vibe.toml`, `vibe.lock` or `vibe install -g` syntax and do not add a public migration/scaffold command.

The core manifest API can propose the recognized legacy `materialization = "snapshot"` to `"copy"` rename over an explicitly selected finite grammar. It preserves bytes outside the selected token, including comments, ordering and unrelated values. Missing choices return typed input requirements; unknown profiles and unsupported shapes refuse. Current absent-epoch and epoch1 profiles produce explicit unchanged proposals. Successful package tests are synthetic, not proof of migration over a historical real-project corpus. Proposals do not apply themselves.

The new Rust-owned `change-manifest` and `change-work` formats are separately registered at epoch1, with strict unknown-field rejection. They are authored state, not disposable caches (`recoverable = false`). A change lives under a caller-configured specification root at `changes/<immutable-id>/change.toml`; editable title and slug do not change its identity or addresses. A trusted caller supplies the selected node and specification root; this library parameter is not a new project setting or CLI flag.

The initial change reader admits identity, exact origin pin/capture declarations, ordinary intent/refinement/acceptance/work/closure roles and opaque user metadata. Closure is excluded from normative inputs. Origin hash declarations do not authenticate source bytes. Ordinary parsing admits schema1; only an explicitly selected pure proposal handles the bounded pilot0→1 transition. Unknown epochs and later unsupported prototype fields refuse. Final-prototype bound-origin and release-impact vocabulary requires its separate implementation; this initial reader does not claim it.

Work documents contain structural IDs, predecessors, artifact needs and touches hints. They reject cycles, duplicate declarations and scheduler-state fields such as `done`, `owner` and `current`. Distinct versioned identities cover normative intent, the whole work graph and a selected predecessor closure. Cosmetic metadata and closure/log output do not change normative intent; changing unrelated work does not change a selected contribution. These identities are observations of declared inputs, not completion verdicts or scheduling/write authority.

Saved readers preserve ordinary shared hardlinks and refuse unsafe source paths through the existing no-follow reader. They retain observed bytes for later analysis without reopening files. This is a per-file observation guarantee, not an atomic snapshot of the whole change. There is no new writer, work migration, automatic epoch upgrade, editor overlay or closure publication in this boundary. Older libraries lack these new APIs/formats; no existing supported format is silently reinterpreted.
