# Package admission before project mutation (Unreleased)

No new `vibe.toml` keys, lockfile/wire epoch or direct `install -g` grammar. Valid common package definitions and authored requires input are still unsupported by the generic package runtime; this change makes the refusal consistent across actual install/update/reinstall consumers instead of silently dropping that meaning.

Scoped update checks every workspace consumer, selected candidate and consumed unchanged provider before project effects. Selected app-installer configuration and a workspace package's own interface declaration are distinct and are not globally prohibited. Legacy update controls remain supported.

`--git` changes the prepared raw and finalized manifests in memory before resolution; the command publishes the admitted raw delta afterwards. Legacy lock-root migration similarly seeds in memory before resolution. A failed plan now leaves the source file unchanged; successful Fresh migration retains locked versions without a new solve. This deliberately changes the previous eager publication on planning failure. Existing owned-file publication protects changed selected semantics.

Protected in-place consumers use the new Rust `InstallSource::prepare_in_place` capability and opaque `PreparedInPlace`. `Fetched.in_place` becomes an optional preparation instead of a boolean. The preparation binds actual manifest, immutable Git object/commit/ref and destination; application does not choose a source or mutable ref again. Old raw materialization remains a source API, but it is no longer the protected consumer path. Custom sources must implement preparation to support that path; an unverifiable source refuses explicitly.

Existing-slot preparation uses the repository's actual Git transport context. Object database and `FETCH_HEAD` acquisition may occur before admission; HEAD, index, configuration, named refs, hooks and worktree must remain unchanged. Source/cache acquisition is not described as zero I/O. Relative/tilde origin behavior is delegated to Git; a fresh spelling Git itself cannot clone remains unsupported. Canonical registry URI and actual serving origin remain distinct.

Unverifiable transformations of authoritative `vibe.toml`—custom filter, working-tree encoding, ident expansion or checkout-local attribute overrides—refuse before checkout. Ordinary EOL and unrelated payload behavior retain their boundary. Acquisition failures may use the existing mirror route; manifest/identity/attribute failures after acquisition are terminal, preserving typed causes rather than becoming another source's success.

`InstallManifestMutation` callbacks are now explicitly in-memory only. `plan_prepared_without_publication` composes the same planner with the operation's one owned publication; it is not a second solver or journal. No configured package effects, new optional-dependency grammar or universal source authentication is delivered by this safety increment.
