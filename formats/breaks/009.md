# Compiler embed provenance (Unreleased)

Accepted implementation at the F17/F19 boundaries. This is not a public release; platform and opaque-transform limits are stated below.

Compiler IR moves from epoch1 to epoch2 (`ir_schema = 2`) to retain typed nested embed occurrences and their association with the actual body through compiler transformations and emission. The active registry points to `schemas/compiler_ir/e2/ir.jtd.json`; the epoch1 schema, corpus and generated representation remain historical inputs, registered separately as compiler-ir-v1 with the same strict reader policy. A historical unannotated snapshot is not evidence of provenance-preserving execution. Old transform replies cannot silently erase occurrence data; the owning pipeline must rebuild from actual inputs or return a typed incompatibility.

Generated XML must carry actual embed provenance through the existing c1 comment codec without changing semantic paragraph text. The bounded tree reader may observe those actual generated comments at their mapped XML positions; it must not reinterpret escaped prose or CDATA as controls. Existing legacy raw-comment framing/fence behavior remains. Tree JSON v1 keeps its existing address/start_line/end_line surface; the annotated writer/reader path is verified by the real install/repeat/reinstall and declared-transform controls. This does not authenticate editable history or certify arbitrary post-emission rewrite semantics.

This change does not alter authored `vibe.toml`, `vibe install -g` declaration syntax or the application installation record. It changes compiler snapshot/transform compatibility and generated boot framing. Recompilation may be required for old derived artifacts; no read-time fabrication of missing provenance is allowed. Actual source/lock history is not discarded as a regeneration shortcut.

Required acceptance includes real install/repeat/reinstall for paragraph-adjacent and standalone embed layouts, nested/repeated/empty/suppressed occurrence controls, literal examples, text roundtrip, old/new strict wire readers and stale-transform refusal. Passing the older synthetic tree wrapper tests alone is insufficient.

## Native compiler exchange (accepted boundary)

The actual native compiler request/reply schemas advance to native/e2 with compiler exchange envelope2 and IR2 payloads. Epoch1 request/reply schemas remain separately registered as native-compile-request-v1 and native-compile-reply-v1, preserving their foreign-request/permissive and host-reply/strict roles. A manifest declaring only ir_schema1 refuses before invocation. The low-level FFI ABI, phase/slot lifecycle exchange and separate bounded-byte native-backend-reply epoch1 are not bumped mechanically; each retains its own contract. Active/historical reader, manifest and backend compatibility gates passed at the documented Linux boundary.

## Existing compiled-unit cache upgrade (accepted boundary)

Generated unit INDEX files gain the comment `# vibe:compiler-recipe compiler-artifact/2`, after the graph fingerprint or its immediately adjacent native-pending comment. The existing graph hash and TOML entry grammar are unchanged. Missing, malformed or different recipe stamps prevent reuse and require normal regeneration; a failed rebuild must preserve old artifacts. Node INDEX files without a unit fingerprint are unchanged by this stamp. This adds no authored vibe.toml/install-g field or sidecar. The old unstamped cache→rebuild→subsequent reuse control passed.

## Existing post-emission ownership

Typed provenance gates cover Closure/Link/Lane and backend output. The already supported opaque post-backend byte-transform position remains able to rewrite output, recording its pass identity and final byte digest; this change does not impose a new universal semantic-preservation gate there. Tree describes committed framing. Useful transforms that explicitly promise preservation, such as the XML minifier, must retain that promise with the new canonical embed controls.

## Meaning and identity qualifications

Embed source/directive positions identify the effective normalized pre-Embed view after source merge and directive removal; they are not raw authored-file edit coordinates. The builtin XML minifier behavior identity advances to epoch2 because its accepted framing behavior changed; this does not bump the FFI ABI or unrelated lifecycle/backend-byte protocols.
