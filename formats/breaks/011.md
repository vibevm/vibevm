# Strict text-only migration planning (Unreleased)

M13C2 is accepted at its strict neutral planning boundary. It exposes the accepted neutral migration planner through `vibe refactor plan-migration` and MCP `plan_manifest_migration`. Planning consumes supplied text and produces a proposal; it does not discover project paths, change files, create recovery state or invoke external providers.

Three new transient machine formats are registered at epoch1: `migration-plan-request`, `migration-plan-report` and `migration-plan-error`. Unknown fields and wrong types refuse. Request `schema` must be exactly1; `source_text` is required. Optional `source_profile`, `target_profile` and `recipe` must be strings when present; explicit null is invalid, not an omitted choice. The generated optional Rust representation alone cannot retain that distinction, so JSON consumers must use the presence-aware domain decoder.

The CLI accepts a literal `--request-json` argument or JSON from stdin and emits one JSON response before ordinary settings/tracing/context initialization. For example:

```sh
vibe refactor plan-migration <<'JSON'
{
  "schema": 1,
  "source_text": "[package]\nname='demo'\ngroup='org.example'\nkind='flow'\nversion='1.0.0'\nmaterialization='snapshot'\n",
  "source_profile": "materialization-legacy-absent-r1",
  "target_profile": "materialization-current-absent-r1",
  "recipe": "snapshot-to-copy-r1"
}
JSON
```

Omitting compatible choices returns `needs_input` with named alternatives, even if only one alternative remains. No choice is guessed. Planner outcomes are `planned`, `no_op`, `needs_input` or `refused`, with stage `planner`; malformed requests use the separate `preflight` error root. Successful/no-op CLI outcomes exit0, questions and request-usage errors exit2, and planner refusals/input-read failures exit1. Existing commands retain their routes.

Plans expose exact before/after text and identities, selected profile/epoch/recipe, ordered edits and diff identity. Byte offsets use canonical unsigned decimal strings rather than lossy JSON numbers. Absent authored epoch is distinct from explicit epoch1. Report validation compares with the actual core recipe and original request; a byte-consistent forged edit set is insufficient. This is consistency checking, not authentication or a write grant.

MCP advertises the same admitted fields. A new typed `ToolError::StructuredPreflight` preserves its registered error in `structuredContent` with `isError=true`; it remains an error before planner execution. Ordinary unrelated tool errors stay text-only. Planner refusal uses the executed-result channel, and a question report is inspectable without pretending an effect occurred. Rust consumers with exhaustive ToolError/FormatId matches must handle the added variants.

No authored `vibe.toml`, `vibe.lock` or `vibe install -g` syntax changes here. Source-descriptor decisions, feature/Redbook migration recipes, actual application, journals and recovery are separate capabilities. Their future fields are not silently registered or defaulted in this neutral interface. Older binaries do not expose these new commands/types; no existing format is reinterpreted.
