# Unreleased: common selected-installer configuration and safe proxy publication

Cargo remains 1.0.11; no release number is assigned here. This cumulative note records the earlier contract foundation and the subsequently integrated runtime described below.

## Earlier accepted contract foundation

The initial L2 atom made the following contracts/readers available before enabling their runtime writers.

- Four new public protocol1 documents: `vibe-configuration-input/1`, `vibe-configuration-description/1`, `vibe-configuration-evaluation/1`, and `vibe-app-configuration-plan/1`. Submitted input is closed, including nested original intent. Public output fields explicitly project from strict canonical vocabulary; output projection does not weaken submitted input or private state readers.
- Member lists, defaults/fallback, control selections and other declared nullable values preserve required presence: `null` records the field's absent/unavailable meaning, `[]` records explicit empty members, and omission of a required field refuses. Signed integer values and bounds are represented as strings with a domain contract of canonical i64 decimal spelling. The generated serde reader admits the string shape; rejecting positive signs, leading zeros, negative zero and overflow belongs to the later domain validator, which this atom does not activate. Existing unsigned grammar and authored TOML omission semantics are unchanged.
- The available application index contract is schema `application/e3/index.jtd.json`, protocol `vibe-user-applications/4`. It can retain original common configuration/evaluation, historical definition/default basis, value-free secret origins and an application pending target. The exact old index schema e2/protocol3 remains registered as `application-index-v3` with its original `recoverable=false` classification and strict reader/corpus.
- The available package work contract is `application/e2/steps.jtd.json`, protocol `vibe-app-steps/2`. Its operation includes required `retirements` (`[]` is legal), with `{key, expectedRecord, state}` and queued/removing/removed states; `retiring` is a phase. `parent` and `publicationRecord` are required-nullable. Their typed identities carry no supplied secret values or answer digests. The exact old steps schema e1/protocol1 remains registered as `application-steps-v1`; its original `recoverable=true` classification and strict reader/corpus are preserved.
- The independent cohort contract is `application/e1/import_work.jtd.json`, protocol `vibe-app-import-work/1`. It describes a finite import's target/context/rows/cursor/outcomes/current child and arrangement state, separate from package steps or installed records. This schema availability does not create that runtime work owner.
- The standalone PATH proxy now admits protocol3 or4 through their complete strict generated index readers, then derives an in-memory routing view. Default/session selection, location rules, operand forwarding and the proxy's own `vibe-app-proxy/2` contract are unchanged. Unknown versions and malformed fields refuse; reads do not migrate or rewrite stored data.

Registry recovery metadata distinguishes authoritative request/history from derived output: `configuration-input`, current `application-steps` e2 and `application-import-work` are `recoverable=false`; submitted intent and exact continuation/cohort outcomes cannot be reconstructed by deleting and reprojecting them. Configuration description/evaluation/app-plan remain `recoverable=true`. Archived steps1 remains `true`; both index owners remain `false`.

At the earlier foundation boundary, current registry IDs advertised available contracts while runtime readers/writers and public application_work remained on their incumbent versions. Runtime operations, flags, work output and API changes became available only in the subsequent activation described below. No new vibe.toml key or full rich portable import/export support is claimed by either stage.

The seven new corpora are synthetic retained examples captured from the frozen future-runtime candidate and read through the generated contract types. They prove typed shapes and compatibility boundaries when the relevant checks run; they do not prove that current main already writes those records or recreate their historical paths. Old index3/steps1 worlds remain independently readable. No existing stored schema or bytes are migrated on read. The real common-writer-to-copied-PATH-proxy journey remains a required gate at runtime activation.

## Selected-installer runtime activation (Unreleased)

The preceding section records the independently accepted canonical-contract foundation. The following producer and command integration adds runtime behavior on those contracts; it does not activate all-kind configured package solving or complete portable configuration. There are no additional vibe.toml keys and Cargo remains1.0.11.

- New generated public contracts: `vibe-configuration-input/1`, `vibe-configuration-description/1`, `vibe-configuration-evaluation/1`, and `vibe-app-configuration-plan/1`. The input is strict, including nested intent. Output-only views use explicit permissive projections of the same canonical vocabulary. `featureResult` can explain resolved feature closure while the outer `resolved` and executable plan are absent. That component never authorizes execution.
- New member-list fields `members`, group `defaults` / `fallback`, and control `selection` are required-nullable: `null` represents omitted/unavailable input as defined by that field; `[]` is an explicit empty set. Missing required wire fields refuse. Authored TOML omission semantics and existing optional-preserve readers are unchanged. Signed integer wire values are canonical i64 decimal strings; existing unsigned fields retain their grammar.
- The current application index schema moves to `application/e3`, protocol `vibe-user-applications/4`. The strict old3 reader remains available. Writing old3 is allowed only when every retained record datum is representable. Rich records preserve original input, normalized evaluation, historical typed definition/default basis, public parameter realizations and value-free secret origins. `pending` is an application target reference only. Supplied secret answers and answer digests are never durable configuration data. Authored default literals remain public definition data.
- Package work adds `application/e2/steps`, protocol `vibe-app-steps/2`: exact home/key/generation, original public request, source route, executor policy, dependency attempts and narrow phases. `publicationRecord` is required-nullable and binds the exact expected public installation before index publication. `parent` is a required-nullable canonical continuation union. Its application arm names an application target; its import arm names an import target and zero-based row index. Old1 remains readable with weaker effective-only provenance; reading never migrates it.
- A finite import has its own sole record at `<home>/cache/app-work/imports/<operation>/import.json`, protocol `vibe-app-import-work/1`. It is not an installation or an index row. Its closed generated document contains `protocol`, `target`, `phase`, `context`, and `cohort`. The cohort retains preclassified public rows/source policy, cursor, outcomes, current child and arrangement progress. Result `target` and `rowIndex` are required-nullable; non-row notes have no row/attempt. Terminal refusal is durable before releasing that attempt, permitting a later dependency to retry the same package. Cleanup never follows an old attempt into a newer generation.
- Public `vibe-app-work/1` retains ordinary legacy row shapes. New work can add `entries[].operation`, `entries[].retainedFor.owner`, and top-level `imports`. The latter contains honest cohort targets and progress, not invented package coordinates. Existing allow-unknown e1 readers accept the additions. Completed retained children explain their owner; cleanup protects unfinished relations too. Explicit cohort cleanup preflights its whole selection and clears only matching selected `index.pending` references, preserving installation and step/failure evidence.
- CLI: `app describe/plan --configuration`; complete `--configuration-input FILE` (`-` reads stdin once) on supported selected-app operations; exact `app resume KEY --operation ID`; `app import FILE` or mutually exclusive `app import --resume ID`; and `app work --import ID` for cohort inspection/cleanup. Import remains user-home only and does not accept unscoped `--set`. Secret resupply names an exact child application operation. Existing explicit manual install/update `--resume` retains its current-work selection meaning; a fresh replacement or reopening kept work creates a new generation.
- Explicit scoped secret provision may strengthen Default/Absent to Explicit during continuation. Before suffix effects, steps2 records only the current resupply obligation; original/prefix metadata remains distinct. A later park cannot fall back to a default after that provision. Old3/old1 missing provenance remains unknown historical provision, not reconstructed absence/default.
- Legacy selected options and successful e1 descriptions remain supported. A legacy view that cannot represent common configuration refuses rather than emitting empty feature arrays. Rich export to `vibe-apps/1`, and legacy-file import into a selected common installer, refuse before output truncation or row effects. A typed rich portable epoch/import remains required campaign work. Package configuration is retained separately from selected installer execution; this change does not implement configured package solving or arbitrary runtime configuration-file writes.

New concrete corpora were captured from actual CLI views and index/steps/import writers, then read through generated types. Their historical example source/home paths are data; loading them does not recreate those paths. Old index3 and steps1 corpora remain registered and tested. Older executables cannot execute the new continuation protocols or flags; output-reader compatibility is not a claim that old work-cleaning commands understand the new ownership relations.

Follow-through before publication: steps2 now requires `retirements` (including `[]`), each row `{key, expectedRecord, state}` with `state` one of `queued`, `removing`, `removed`; `retiring` is an operation phase. Update binds this list once, including automatic older-kept cleanup. Removal begins only after replacement setup succeeds. A parked or required-failed replacement keeps previous versions: this intentionally changes the former failure-path timing. Once removal may have executed, resume refuses automatic replay or success, and ordinary Fresh/from-step cannot erase that uncertainty. Explicit scoped work cleanup remains deliberate abandonment. Completed cleanup/finalization uses exact installed record identities, not recipe source or a now-unused agent; `ResumeInfo.cleanup_only` exposes that distinction to the CLI.

Rust-facing APIs change with their actual owner types: `Index::to_wire/from_wire` use generated application/e3 types (even when losslessly emitting protocol3); `describe` is fallible; rich `Plan::to_wire` refuses lossy legacy projection, while `to_configuration_wire` returns the new plan. `resume`, `resume_info`, `import_cohort`, `import_resume_info`, `resume_import`, `work_import`, and `clean_import` expose exact owner-specific operations. `OperationContext` accepts retained source-admission/resolver scope; no raw argv is serialized. These source-API changes are distinct from preserved successful legacy e1 wire shapes.

Explicit same-home `app work --clean --all` remains deliberate abandonment of the complete selected work cohort, including unreadable package work, after every readable relation and installed pending reference is preflighted. Only matching validated local-slot pending references are cleared; installations/payloads and other homes remain. An unreadable single-package selection cannot prove a surviving owner and refuses with whole-cohort cleanup guidance. No corrupt relation is reconstructed or followed to a foreign path.

### Existing copied proxy upgrade and checked publication APIs

At an actual stored3-to-next4 transition, the mutation owner refreshes already-existing declared global and per-installation session copies, including hidden retained installations. It admits one captured image by querying both `vibe-user-applications/3` and `/4`; the exact same bytes are copied. Under the original executable name, `vibe-app-proxy --supports-index PROTOCOL` returns0 and exactly `PROTOCOL` plus newline for those two supported values. Unsupported protocols and old images return nonzero. Existing `--probe` remains `vibe-app-proxy/2`; `--version` is unchanged. A private temporary executable snapshot is deleted after admission; no persistent proxy registry, capability marker or routing index is added.

The compatibility barrier precedes index replacement and does not create absent session exposures or remove old commands. A later catalog revision failure still reports failure, while already-existing valid global/session commands remain readable. A rejected image or unsafe destination leaves the old index intact; a partially upgraded reader still understands3. Stored index protocol admission is separate from lossless downgrade eligibility: an actually tagged4 document with only legacy-shaped records still requires a4 reader until new bytes are published. This guarantee covers managed stored copies under cooperating current mutation locks, not already-loaded old processes or old clients ignoring that lock.

`Index::save(settings,event)` now takes the home mutation lock itself. Atomic read-modify-write callers already holding it use public `Index::save_locked(settings,event,&MutationLock)`; both raw writers refuse a first4 publication that needs an image for existing managed commands. The ordinary application operation API supplies the admitted image at its publication owner. `sync_proxies` also takes the lock and validates the image against the persisted index; public `sync_proxies_locked` is its already-locked counterpart. Session exposure takes the same lock, while dependency exposure uses its caller's existing lock. A token belongs to the actual canonical home, allowing aliases of that home but refusing another home. Tokens/images are ephemeral implementation values, never serialized request or state fields.

Compatibility/ownership failures use `proxy_upgrade_failed` (failure class), while ordinary filesystem failures retain `state_io`, with path/reason and an upgrade/retry recipe; capability-query child output is not embedded in the error. Source images need not be probed for unrelated3/data-only operations without managed readers. Proxy replacement uses an exclusively allocated temporary sibling and atomic persist instead of a predictable PID-named writable temporary file. The exact-byte capability query has a bounded deadline; only transient OS ExecutableFileBusy is retried on the same snapshot.

Already-tagged4 metadata publication does not rescan or refresh cached sessions and needs no image when no actual global command will be written. Current global sync and session exposure still admit compatible captured images under the home lock. This avoids unrelated image reads on each metadata write; it is not a repair mechanism for arbitrary preexisting corrupted4 homes.
