# Unreleased: canonical configuration contracts and a forward proxy reader

Cargo remains 1.0.11. This atom makes the following contracts and readers available; it does not activate their application runtime writers or assign a release number.

- Four new public protocol1 documents: `vibe-configuration-input/1`, `vibe-configuration-description/1`, `vibe-configuration-evaluation/1`, and `vibe-app-configuration-plan/1`. Submitted input is closed, including nested original intent. Public output fields explicitly project from strict canonical vocabulary; output projection does not weaken submitted input or private state readers.
- Member lists, defaults/fallback, control selections and other declared nullable values preserve required presence: `null` records the field's absent/unavailable meaning, `[]` records explicit empty members, and omission of a required field refuses. Signed integer values and bounds are represented as strings with a domain contract of canonical i64 decimal spelling. The generated serde reader admits the string shape; rejecting positive signs, leading zeros, negative zero and overflow belongs to the later domain validator, which this atom does not activate. Existing unsigned grammar and authored TOML omission semantics are unchanged.
- The available application index contract is schema `application/e3/index.jtd.json`, protocol `vibe-user-applications/4`. It can retain original common configuration/evaluation, historical definition/default basis, value-free secret origins and an application pending target. The exact old index schema e2/protocol3 remains registered as `application-index-v3` with its original `recoverable=false` classification and strict reader/corpus.
- The available package work contract is `application/e2/steps.jtd.json`, protocol `vibe-app-steps/2`. Its operation includes required `retirements` (`[]` is legal), with `{key, expectedRecord, state}` and queued/removing/removed states; `retiring` is a phase. `parent` and `publicationRecord` are required-nullable. Their typed identities carry no supplied secret values or answer digests. The exact old steps schema e1/protocol1 remains registered as `application-steps-v1`; its original `recoverable=true` classification and strict reader/corpus are preserved.
- The independent cohort contract is `application/e1/import_work.jtd.json`, protocol `vibe-app-import-work/1`. It describes a finite import's target/context/rows/cursor/outcomes/current child and arrangement state, separate from package steps or installed records. This schema availability does not create that runtime work owner.
- The standalone PATH proxy now admits protocol3 or4 through their complete strict generated index readers, then derives an in-memory routing view. Default/session selection, location rules, operand forwarding and the proxy's own `vibe-app-proxy/2` contract are unchanged. Unknown versions and malformed fields refuse; reads do not migrate or rewrite stored data.

Registry recovery metadata distinguishes authoritative request/history from derived output: `configuration-input`, current `application-steps` e2 and `application-import-work` are `recoverable=false`; submitted intent and exact continuation/cohort outcomes cannot be reconstructed by deleting and reprojecting them. Configuration description/evaluation/app-plan remain `recoverable=true`. Archived steps1 remains `true`; both index owners remain `false`.

Registry current IDs describe the new available contracts. Existing application domain readers and writers continue their incumbent explicit versions until the corresponding producer integration. No new install/modify/resume/import operation, common-installer execution, CLI flag, cleanup behavior, `Index`/`Plan` domain API migration, or vibe.toml syntax is delivered by this atom. Public `application_work` schema/generated types and existing producers remain unchanged. Full rich portable import/export support is not claimed.

The seven new corpora are synthetic retained examples captured from the frozen future-runtime candidate and read through the generated contract types. They prove typed shapes and compatibility boundaries when the relevant checks run; they do not prove that current main already writes those records or recreate their historical paths. Old index3/steps1 worlds remain independently readable. No existing stored schema or bytes are migrated on read. The real common-writer-to-copied-PATH-proxy journey remains a required gate at runtime activation.
