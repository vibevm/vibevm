# Explicit package dependency configuration (Unreleased)

The explicit workspace/local-copy installation and replay boundary is accepted in F16. Selection, shared consumers, original input, reconfiguration and cold replay have actual CLI evidence. This is not completion of the broader common configuration capability.

## Authored input

An existing `requires.packages` inline declaration gains `optional = true`. Omission and explicit `optional = false` keep the dependency mandatory; explicit false survives serialization. Mentioning a mandatory dependency in an unselected feature does not make it optional. There is no implicit feature alias or second dependency table.

A package can declare:

```toml
[requires.packages]
"org.example/backend" = { version = "^1", optional = true }

[[configuration.features]]
id = "backend"
name = "Backend support"
effects = [{ kind = "dependency", target = "org.example/backend" }]
```

Its actual workspace consumer supplies the already existing configuration input:

```toml
[requires.packages."org.example/driver"]
version = "^1"
configuration = { policy = "require-selection", default_features = false, features = ["backend"] }
```

The declaration reader retains optional metadata across registry, git, path and version.var spellings; that parser coverage is not runtime support for every source. The first runtime admits ordinary local-registry copy sources with explicit, non-automatic inputs. Owner-self optional roots, unsupported source/solver combinations, profiles/default reliance, package parameters, forwarding, subskill and config-value consumers retain explicit refusals while their actual integrations are unfinished. Existing selected-installer configuration is a separate accepted capability. No new `vibe install -g` command grammar is introduced by this increment, and the example is ordinary project installation.

## Retained state and readers

`vibe.lock` schema8 adds a typed `configurations` map associated with its existing package rows. It retains original consumer inputs separately from selected features, active declarations and their causes. Package version, content and source identity stay in the existing package rows. Changing only exact/additive intent must update retained input even when the selected package graph is unchanged.

The new reader accepts legacy schema7 without inventing original requests and does not rewrite files on read. Legacy-only writes retain7; rich records require8. Older schema7-only binaries reject8. Use a reader that supports the retained format; deleting a rich lock is not a safe automatic migration because historical decisions may be lost. Missing configuration records in an existing rich world must refuse before re-resolution rather than silently recreate history from current authored input.

Only explicitly classified no-rich schemas1–6 retain the existing install regeneration exception and historical empty remap requirement layer. Malformed data, rich records under old epochs and unknown future epochs must not become an empty world. Remap admission must precede consent changes. Targeted compatibility and maintenance gates pass.

## Consumer API and rollout boundary

Rust consumers receive configuration records through the existing Lockfile, Fetched and ResolvedDep owners. InstallSource gains configured-solving and selected-record hooks; a custom source that does not implement the configured route must refuse it instead of dropping original input. Ordinary legacy source methods retain their route. Lockfile::parse_str shares read admission over captured bytes. RegistryError::Configuration carries a truthful unsupported-operation cause rather than a fabricated transport/metadata failure. These are changes to the Rust consumer surface; custom implementations retain explicit unsupported behavior until they implement the configured route.

Acceptance covered: ordinary OFF/ON effects and original/cold state; original-only input changes; missing/corrupt/future records; exact pinned reinstall and missing-slot repair; old7/known-legacy controls; remap precedence and consent; source/candidate drift refusal before effects; incumbent behavior and required static/traceability gates. Transitive consumer-conditioned solving, strong/weak forwarding, automatic default receipts and wider user surfaces remain subsequent capability work. No sunset or forced read-time migration is scheduled by this change.

The current configured runtime refuses incremental in-place paths before preparation, including mixed graphs, while preserving the old unconfigured path. Affected configured uninstall refuses before mutation; unrelated legacy removal remains supported. Within remap matching, loaded-source order now participates before source-local row index, so accepted package priority is effective without rewriting provenance.
