# lang:org.vibevm.ai-native/lean-ai-native-lang {#root}

<status stage="spec" state="done" audience="user"/>

@fact:SCOPE Version 0.1.0 defines the first AI-Native Lean model-proof lane: a checked theorem sidecar, a scanner and a targeted runner using Lean 4.34.1. The language-neutral discipline comes from `flow:org.vibevm.ai-native/core-ai-native@^1.1.0`. @status:spec/done

## Commands {#commands}

@fact:COMMANDS The binary is `lean-ai-native`, declared at `crates/lean-ai-native-cli`. Its command surface is `scan`, `check --subject`, and `verify-witness --subject`. Installation materializes package source; building the binary and running a checker are separate operations. @status:spec/done

@fact:ACTUAL-CHECK A successful proof witness requires an actual successful checker run for the selected named theorem, with its statement, source/dependency identity, subject, toolchain and permitted assumptions bound to the result. Scanning or loading a witness cannot supply that result. @status:spec/done

@fact:FRESH-VERIFY `verify-witness` checks the exact requested subject and current source/toolchain identity and performs a fresh proof check. Changed inputs, wrong subject, malformed carrier, missing theorem, failed checker or unpermitted axiom must not become a current success. @status:spec/done

Run `lean-ai-native --path PROJECT [--toolchain-dir INSTALL_ROOT]` followed by `scan --carrier lean-proof.toml`, `check --carrier lean-proof.toml --subject URI`, or `verify-witness --carrier lean-proof.toml --subject URI --witness proof.json`. Global options precede the command.

Commands return JSON `Reply{ok,result?,error?}`. A successful `check` has the witness directly in `result`; extract it only after confirming `ok == true`. `verify-witness` consumes that object and returns `{status:"matched",witness:...}` in `result`. `scan` returns declared inventory and no proof verdict.

Malformed CLI operation arguments produce an `invalid_request` JSON reply and
exit 2. `--help` and `--version` retain their ordinary display. A refused
executed operation exits 1; a successful operation exits 0.

The [guide](vibevm/vibespecs/lean/GUIDE-AI-NATIVE-LEAN.xml),
[runner contract](vibevm/vibespecs/mechanisms/LEAN-PROOF-RUNNER.xml), and
[carrier contract](vibevm/vibespecs/mechanisms/LEAN-THEOREM-CARRIER.xml)
state the interface and evidence boundary.

## Toolchain and proof scope {#proof-scope}

@fact:PINNED-LEAN Supply an externally installed, reproducible Lean 4.34.1 distribution through `--toolchain-dir` or `LEAN_AI_NATIVE_TOOLCHAIN_DIR`; the carrier pins `leanprover/lean4:v4.34.1` and the runner binds the distribution identity. The package does not contain a developer-specific toolchain path or fetch a toolchain during a proof. List local sources in explicit dependency-first order. Initial imports are those modules plus the pinned distribution. Arbitrary Lake dependency scripts are unsupported. Project Lean source is trusted code; elaboration is not a sandbox. @status:spec/done

@fact:G1 A G1 witness means the selected model theorem was checked under its recorded assumptions. It does not certify the meaning of the model, a Rust or TypeScript implementation, an external adapter, or a running product. G3 implementation refinement is unsupported by this release. @status:spec/done

@fact:POLICY Subject selection and axiom permission belong to the consumer's explicit carrier. Version 0.1.0 selectors support ASCII dotted module/theorem names; quoted or Unicode selectors are unsupported. This does not replace ordinary Lean source syntax. Allowed logical axioms are limited to `propext`, `Quot.sound`, and `Classical.choice`; custom, sorry and native proof axioms are refused. A full `spec://group/package/document#anchor` address is an identity link; it grants no execution or acceptance authority. @status:spec/done

Every check captures local sources and specs once, compiles in a private
temporary directory, verifies theorem kind and originating module, inspects the
transitive axiom closure, and replays each local module with `leanchecker`.
The witness records the exact checker-source and inspector digests as well as
the actual compiled local `.olean` objects (including generated definitions)
and the pinned distribution's complete `bin`/`lib` fingerprint. Toolchain and input
bytes are checked again before the result is returned. The configured local
toolchain is a trust input: the runner records its bytes and checks its version
and release commit; release authenticity comes from the verified installation,
not a signature generated by this runner.

The process timeout defaults to 30 seconds per subprocess (1–120 admitted).
Output is bounded to 1 MiB per stream; source compilation has a 1 GiB Lean
allocation limit and reflection a 4 GiB limit. These are typed failure bounds,
not sandboxing or a guarantee that every theorem fits them.

### Reproduce the toolchain

Use the exact [Lean 4.34.1 release](https://github.com/leanprover/lean4/releases/tag/v4.34.1),
commit `5045d0056413266e57c625dcd7c365b10e377c52`. With an existing Elan installation:

```sh
elan toolchain install leanprover/lean4:v4.34.1
elan run leanprover/lean4:v4.34.1 lean --print-prefix
```

Pass the printed directory to `--toolchain-dir`. No global default change is
needed. Direct archive installations are also supported: the official Linux
x86-64 asset is `lean-4.34.1-linux.tar.zst`, SHA-256
`47bf4bbd78f70c2e9670598ab7124d92b6efb7330ff33e5fbb4030f6fd72e4e4`.
Verify the appropriate release asset before extraction; a toolchain's recorded
content fingerprint is identity evidence, not an authenticity signature.
The family version remains `0.1.0`, independently of the Lean release and
carrier/witness schema epochs.

## Focused maintainer checks

```sh
export LEAN_AI_NATIVE_TEST_TOOLCHAIN=/absolute/lean-4.34.1-distribution
cargo test --locked -p lean-ai-native-check -p lean-ai-native-cli
cargo fmt --check -p lean-ai-native-check -p lean-ai-native-cli
python3 tooling/sync-core.py --check
```

The real-check integration cases require that environment variable and fail
explicitly when it is absent. They cover reproducibility, fresh saved-witness
verification, forged/wrong-subject/stale claims, changed theorem/spec/dependency,
missing theorem/dependency/toolchain, mismatched toolchain, failed proof,
unexpected and incomplete-proof axioms, malformed carrier and G3 refusal.
The vendored neutral parser/specmark sources are byte-identical to
`flow:org.vibevm.ai-native/core-ai-native@1.1.0`; the sync script is a maintainer
operation against the source catalog, not a runtime dependency.
