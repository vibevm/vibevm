# M-16-C.1 fixture admission review

Reviewed local 1.1.0 subjects: `5c4547f0b` establishes the initial pre-effect reservation law; `7ad768de4` adds the leased durable pointer index; `48f3f79fc` strengthens the law to cover the separate reservation/journal crash window; `714c6e5b8` assigns real-domain linkage and adapters to C.2/C.4; `a63f23ab3` adds the fixture journal fence. The task remains a bounded infrastructure atom. Its new index at `.vibe/machine-submissions.json` retains admission keys, request/plan SHA-256 identities, a domain run pointer and journal-ready bit; it does not retain domain result or execution status.

The owner issues a scoped namespace with a monotone durable epoch, random token and bounded TTL under the existing lifecycle lease. The index uses that lease's pinned safe file operations and a size-bounded atomic publication; a possibly published error refuses effect dispatch. Same-key/same-payload replay resolves to the retained run, a changed payload refuses, and expiry/retirement leaves a tombstone. Observed host clock rollback refuses; an unobserved OS clock jump cannot be proved away. The portable guarantee is for cooperating writers using the lease, not content CAS against a process that ignores it.

The orchestrator fixture service reserves an owner-proposed run ID, reads the existing lifecycle state, initializes that exact ID when absent before journal-ready, rereads it, durably marks the admission ready and only then invokes the fixture effect. A newly created reservation colliding with a prepared journal refuses. A retry with a pending reservation may initialize the same missing journal but never invoke on behalf of an earlier submitter. Once ready, a missing, different or uncertain journal refuses; a complete matching fixture outcome is replayed without another effect. Eight contending fixture submissions produced one counted effect. The fixture result is retained in the lifecycle journal's execution row and checked against the exact run ID.

**Accepted boundary:** the C.1 fixture admission mechanism, durable pointer/journal handshake and negative crash-window behavior. Current default lifecycle is not routed through it: `prepare_default_lifecycle` creates scratch before this reservation, and prerequisite install can precede lifecycle state journaling. C.2 must bind actual lifecycle/build/deploy/publication owners, retained outcomes and crash recovery; C.4 must route CLI/MCP/local API submissions through that owner. This review does not claim duplicate-effect prevention for existing user-facing commands or cross-platform native execution.
