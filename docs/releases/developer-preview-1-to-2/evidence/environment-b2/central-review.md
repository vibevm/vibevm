An old package row keeps kind/group/name/version/content hash and its recorded source URL, optional Git ref/commit, registry/source kind, dependencies, features and materialization exactly as written. A `sha256:` recipe-zero identity remains recipe zero; an empty old dependency list is unknown closure, not proof of an empty closure. An exact-environment proposal names missing source capture, configuration bytes, selected target, dependency role, recursive closure, payload prefix and physical target instead of inventing them. An old artifact's `verified`, `unverified` or `failed` status remains a historical production verdict. Reading its record does not rehash the output file or certify a current generation.

The pure mirror decision requires a full 64-lowercase-hex hash under the same named recipe plus a separately supplied source-owner proof; it retains both canonical and alternate locators in its result. Changed content/recipe, missing proof and malformed locator refuse or request input. The actual Multi fetch already tries mirrors against an expected hash, but its returned/durable package row still retains only the canonical URL; the actual serving mirror remains in trace/clone state. M-15-B.2 owns transport and durable origin-provenance integration, so this decision makes no claim that current install persists `served_by`. Prefix-bound changes refuse and relocatable claims require matching producer evidence. No GitHub endpoint is required by the pure contract.
