# M-16-B.1 retained extension operation schema — read-only design/perimeter audit

**Observed boundary.** `ExtensionDecl`/`ExtensionDeclWire` have no operation-schema field; `pass.formats` is compiler-pass output, `config` is arbitrary handler TOML, and native `crate_dir`/`prebuilt` point to executable artifacts. None identifies a registered request/result/error schema. The extension-world adapter retains each parsed `Manifest` and clones `manifest.extensions` into `DependencyExtensionSource`; the pure registry retains each declaration and provider metadata. Its `ExtensionRegistryRow::declaration()`/`provider()` accessors are a zero-load projection seam. `vibe-native-loader::NativeLoader` opens a library and reads its ABI manifest, so it cannot supply discovery metadata. Current machine `FormatId::ALL` exposes registered IDs and epochs; `machine-operation-descriptor`/`machine-operation-envelope` are epoch 1, many-parser, deny-unknown formats. The bounded prior audit found no admitted extension schema producer. Root reports 29 `ExtensionDecl { … }` source files; their bodies were not read here.

**Recommended source-law amendment before code.** Add a versioned *authored declaration* under each `[[extension]]`, for example `[extension.machine_operation_schema]`, parsed by a strict named wire struct into `Option<ExtensionOperationSchemaDecl>` (not `ExtensionConfig`). Its finite fields are `operation_id` (namespaced), optional `model_id`, `input_format_id`, `result_format_id`, `error_format_id`, `event_format_id`, and `schema_epoch = 1`. No authored `domain_owner`, provider path, source hash, availability, authorization or implementation status: those come from the selected provider, retained manifest/capture and later admission. Each present format ID must resolve through the **existing** generated `FormatId::ALL` and declared `.epoch()`; unknown IDs, unsupported epoch, duplicate operation IDs or IDs that collide across providers refuse before discovery. A registered outer `machine-operation-envelope` reference alone proves only outer shape: a JSON string payload remains unavailable until its specific generated domain reader and semantic owner are registered. No loader manifest, arbitrary schema URL/path, install/build/fetch or implicit `config` key may upgrade it.

The projection should join `(provider typed group/name/version, provider content identity when established, declaration id/ordinal, authored operation id, registered format IDs/epochs)` from one parsed selected-world snapshot. Dependency rows have typed `DependencyProviderId` and content hash; host content hash is optional. Absence or mismatch of a measured source/content binding yields a descriptor with `availability = unavailable` or a gap reason, never a validated/authorized operation. The provider root/path is provenance data, not physical read or execution authority. A pure projection over `ExtensionRegistry::rows()` can emit retained descriptor candidates without loading ABI 1, but a *separate owning source-authentication step* must establish actual manifest/schema bytes before marking the schema validated. The current `MachineOperationService` does not perform that join. Native handler admission and effect authorization remain later independent checks.

**Public-struct cost and alternative.** Adding `pub machine_operation_schema: Option<…>` to `ExtensionDecl` makes the existing manifest → world → registry carriage automatic, but all 29 reported Rust struct-literal sites need exact mechanical `None`/fixture updates; this cannot be assumed a two-file edit. A narrower *literal-churn* representation is a strict sibling `[[extension_operation_schema]]` table in the same manifest, keyed by `extension_id`, then joined to the declared extension. It avoids the `ExtensionDecl` field but requires a new retained `Manifest` collection, a second cross-table join through host/dependency world carriers, and more chance of an orphan or split-epoch row. It is not a `config` shortcut. I recommend the direct optional field only after Root binds the exact 29-site list and proves the mechanical edit scope; otherwise the sibling table needs its own explicit source/carriage law, not a silent workaround.

**Small proof packet to bind next.** A temporary authored package manifest declares one inert extension and `[extension.machine_operation_schema]` naming a real registered host-owned format/epoch; parse it through the strict manifest owner, collect from an injected already-parsed world, and discover its descriptor with a trap native opener that must remain untouched. The positive proves retained schema identity without native load, *not* callable domain payload semantics. Negative clones: unknown format ID, path-like/foreign schema reference, and provider/content/source provenance mismatch; all refuse or stay explicitly unavailable before descriptor publication. A second duplicate-ID clone covers conflicting provider ownership. Do not synthesize an admitted/available descriptor merely from a successful parse.

**Exact perimeter needed before editing.** First authorize source writes to `vibevm/vibespecs/common/PROP-080-machine-operations-and-observability.xml` and `PROP-054-lifecycle-and-extensions.xml` for authored grammar, retention and zero-load status law. Bind exact reads/writes for `crates/vibe-core/src/manifest/extension.rs`, `extension/wire.rs`, its named `extension/tests.rs`, and the manifest module/export owner if a new public type is exposed. Root must supply or authorize a filenames-only inventory and then bind all 29 `ExtensionDecl` literal owners before a public field edit; those files were not inspected here. Bind the exact `vibe-extension-registry` projection owner (`model.rs` and its direct collector/view file if needed), the `vibe-workspace/src/extension_world.rs` source-binding owner, and the exact orchestrator/MCP discovery adapter/test owners before projecting it externally. The existing `formats/REGISTRY.toml` and generated `format_id/properties.rs` can be read as the registry oracle; no new format or generated edit is justified solely by this declaration. If domain-specific formats are newly needed, their `schemas/`, `formats/REGISTRY.toml`, corpora and generated owners require a separate explicit registration/codegen packet. Do not edit `vibe-native-loader` for discovery.
