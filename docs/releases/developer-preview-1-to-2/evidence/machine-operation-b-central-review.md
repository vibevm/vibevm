# M-16-B work-package review

This review covers accepted child atoms B.1 (retained operation/model registry and one pure planner), B.2 (entity/snapshot/page/location values) and B.3 (on-demand framed session). Their permanent source law is PROP-080; registered machine and migration formats remain epoch one within mutable package version 1.1.0. The previous child decisions are retained in [B.1](machine-operation-b1-central-review.md), [B.2](entity-view-b2-central-review.md) and [B.3](machine-session-b3/central-review.md).

The three children fit without a second domain engine. B.1's descriptors carry an owner, source and explicit implementation/availability/authorization states. A descriptor cannot itself grant the single admitted pure planner route. B.2 adds typed identity, snapshot, paging and location values over caller-supplied retained captures; it neither authenticates source bytes nor creates a global atomic observation. B.3 adds a byte-framed per-connection transport whose request passes through the same neutral orchestrator planner exchange as the MCP adapter. The existing line-delimited MCP protocol and fixed initialize version remain independent. Shape-valid values still pass owner semantic validation, and an invalid domain result stays diagnostic rather than becoming a normal published report.

Compatibility and effect checks: registered readers deny unknown structure; the B.2 page cursor is process-local and one-use; B.3 refuses unknown/foreign/duplicate IDs, unsupported epochs, malformed frames and fabricated context roots. HOME/container are unavailable in the current frame handshake. The only B.3 runtime route is pure planning, with `no_effects` outcomes and streaming/replay/control advertised false. No new daemon, IDE adapter or effectful execution route was introduced. B.1/B.2 focused receipts and B.3's 25 selected passing cases cover these changed contracts. Existing format registration and the 35-model authority map have targeted checker evidence; neither is a whole-product capability verdict.

M-16-B's bounded contracts are accepted. Remaining M-16 work owns responsive service adapters, journal/recovery/control and broader client coverage. Before M-16 milestone acceptance, reconcile the complete workstream's permanent release-impact records and finite source/capability/documentation deltas. This parent decision is not that reconciliation, native Linux/macOS/Windows proof, or public release authorization.
