# M-06-A.1 explicit source interpretation — bounded central review

M-06-A.1 introduces a strict `[[package.sources]]` declaration and a pure selector that chooses an exact file before the longest directory default. An absent declaration remains unclassified; incompatible equally specific rows return path-specific `NeedsInput`. The declaration names media, interpretation, role and loading but grants no trust. Host-observed source bytes and their SHA-256 stay separate. Generated boot outputs cannot become authored sources. The permanent contract is [PROP-072](../../../../vibevm/vibespecs/common/PROP-072-boot-observability.xml#SOURCE-DESCRIPTOR-GRAMMAR), including precedence, observation and migration clauses.

The selected reader (`b35bbb47b`) and captured-inventory walk (`451ed4c91`) dispatch only after descriptor selection. Foreign or undeclared Vibe-shaped XML does not mint facts in that path; invalid, unavailable and ambiguous sources are distinguishable from an empty successful read. A directory default cannot claim a complete fact set without a separate host census. The first existing consumer, `vibe facts adopt` (`417610c11`), uses this path only for Mixed installed slots with explicit file descriptors. It pins the slot, compares source bytes to validated slot-record hashes and refuses incomplete/converted/directory cases before a registry write. Packages without descriptors retain the pre-existing adoption route, including the 1.0.x compatibility test; retiring suffix-only routing across the rest of the product belongs to M-06-A.4.

The finite migration extension uses the incumbent M-13 planner and application journal. `2466ce0ff` added lossless ordered zero-length edit replay; `ba1fdc7c6` registered path-specific request decisions and questions; `01489818b` added an explicit old `flow`/`format="normal"`/single `[boot_snippet].source` profile. It asks for media at the exact path rather than inferring from `.xml` or `.md`, then appends one TOML-safe descriptor row while retaining every old byte. `7321157a2` proves application through the existing one-file grant/journal, same-operation `NoOp` replay and changed-source refusal. The profile intentionally refuses fragments, simple packages and unrecognized old forms; no second executor or automatic file migration was added.

Root checked focused cases on the reviewed sources: core source-selector 8/8; declared reader 6/6; captured walk 6/6; CLI declared adoption 3/3 and existing 1.0.x adoption 1/1; core migration 21/21; workspace planning 13/13; migration application 2/2. `cargo xtask check-codegen` was clean after the migration wire commit. Formatting and staged diffs were checked for the related commits. These are selected Linux-host checks, not macOS/Windows native execution or a whole-product gate; no mutation run was warranted for this bounded grammar/reader work.

**Accepted A.1 boundary:** the declared source identity, selected reader, one production adoption route and executable finite migration are present together. M-06-A.2 owns structural ordinary CommonMark, A.3 owns XML data and opaque resource treatment, and A.4 owns remaining suffix-only consumers and completeness/provenance routing. This review does not claim those later tasks, a complete directory census, converted-slot original-byte recovery or final documentation/release gate completion.
