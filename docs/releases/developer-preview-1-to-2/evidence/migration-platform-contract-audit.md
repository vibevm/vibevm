# D1 bounded platform contract audit

## Verdict and evidence limit

The named code contains Linux/macOS/Windows execution branches, but this review cannot establish macOS/Windows usability merely from their presence. No native execution, build, test or filesystem change ran. The concrete macOS concern is a directory-sync capability/classification path with no reduced-tier bootstrap allowance; actual APFS directory behavior remains unmeasured. No blanket claim that every macOS directory F_FULLFSYNC returns EINVAL is justified by the reviewed primary evidence.

Root separately observed rustc 1.98.0, commit 88d9e12ae178fab0fb5cc050a94da85685d449ea (2026-08-18), host/only installed target x86_64-unknown-linux-gnu; its command exited 0. I verified the [exact official Rust commit Unix source](https://raw.githubusercontent.com/rust-lang/rust/88d9e12ae178fab0fb5cc050a94da85685d449ea/library/std/src/sys/fs/unix.rs), lines 1325–1335: Apple fsync uses fcntl(F_FULLFSYNC), without a plain fsync fallback. This pins the implementation pattern to the observed compiler source, not a built or executed macOS target. Earlier current/1.90 inspections are corroboration only.

## Exact branches and consequences

crates/vibe-safefs/src/transaction/operations.rs:235–288 reopens the same held Unix directory readably, checks directory/handle identities, calls readable.sync_all(), then rechecks identity. Thus Apple directory checkpoints use the full-flush API, not directly POSIX fsync. [Apple XNU's dispatcher](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/kern/kern_descrip.c) routes F_FULLFSYNC to the filesystem VNOP_IOCTL and provides no general full-sync fallback. [Apple's fsync manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/fsync.2.html) distinguishes fsync from the drive-cache flush and documents unsupported file-type EINVAL; its socket example does not establish APFS directory behavior. Actual filesystem/kernel outcomes must remain unknown here.

The source-level blocking branch is precise: Unsupported/PermissionDenied maps to DirectoryDurability::Unsupported, but any InvalidInput maps to Failed. runtime.rs:95–137 accepts Unsupported/JournalRecoverable with a reduced durability warning, while Failed produces synchronization_failed and Unconfirmed. If a valid directory full-flush is rejected as InvalidInput, ordinary publication can stop despite available weaker namespace recovery. This conditional is proven by source; whether a particular APFS directory takes it is not.

Moreover external.rs:181–204 require_durable_bootstrap accepts only Synced, except Windows JournalRecoverable. New macOS external-store parents with Unsupported or Failed checkpoints are refused. Existing stores skip that creation chain, but remain subject to later directory checkpoints. operations.rs:296–310 promotes the reduced checkpoint class only on Windows. Therefore runtime's general Unsupported acceptance does not itself establish a usable macOS bootstrap path.

For Windows, external_sync.rs:44–65 deliberately opens the retained regular image read/write without create/truncate, then requires sync_all. [Official Rust Windows source](https://raw.githubusercontent.com/rust-lang/rust/88d9e12ae178fab0fb5cc050a94da85685d449ea/library/std/src/sys/fs/windows.rs) calls FlushFileBuffers; [Microsoft's contract](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers) requires GENERIC_WRITE, matching that open. Reduced Windows namespace tier handling is explicit. No concrete Windows blocker was found in these named branches. Native handle-sharing, rename, filesystem and restart behavior outside this read perimeter remain unverified; this is not a whole Windows implementation proof.

## Minimal correction if the directory limit is confirmed

Keep retained-image/file-data sync mandatory. Keep the held-directory identity checks and exact before-image/journal recovery. Bind a Darwin-specific directory checkpoint implementation: attempt the appropriate held-directory metadata sync, classify a demonstrated unsupported directory operation narrowly, and preserve genuine IO/identity failures. A directory-only plain fsync fallback may be reasonable if its successful guarantee is defined honestly; it must not silently replace regular-file full-flush requirements or promise power-failure persistence. Reduced bootstrap allowance needs the same pre-journal liveness-only reasoning already explicit for Windows. Do not globally turn InvalidInput, PermissionDenied or all macOS failures into success. Native fixtures must decide the supported filesystem path before claiming it works.

## Acceptance interpretation

M-13-D.1 requires working implementation paths on all three platforms and usable recovery, preservation and reports. The owner ruling explicitly separates tested Linux evidence from macOS/Windows implementation and later native proof; it does not demand all native measurements before foundation acceptance. It permits measured-native debt later, not a knowingly unusable path. It also expressly permits precise refusal for genuinely unsupported filesystems or failed durability operations. Root decides whether the present conditional branch requires correction now or an exact native binding first; the central review and guide's implementation-path wording cannot substitute for that judgment. No guarantees, mutable 1.1.0 rule or public-publication hold are waived.


Final disposition: no reviewed primary source establishes that the current branches necessarily defeat a common supported APFS/Windows filesystem path. The absence of a macOS fallback and reduced bootstrap tier is an exact conditional limitation, not a proven universal failure. Source-level portable foundation acceptance with explicit later native proof debt is permitted by the ruling; no new native-platform gate should be invented. Working-path obligations remain binding: a later demonstrated ordinary-directory unsupported result would require the narrowly scoped correction above, and any genuine I/O failure must remain a failure. Root retains acceptance.
