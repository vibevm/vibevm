# M-14-C target-binding parent review

The three accepted children form one internal opt-in host-admitted path. [C.1](environment-c1/central-review.md) provides the strict optional wire binding, separate bound state key and refusal of an unadmitted effect while preserving legacy None bytes. [C.2](environment-c2/central-review.md) adds the physical settings lock, pinned source/settings/home/bin/store observations, alias and stale-generation refusals, and binding-aware sidecars. [C.3](environment-c3/central-review.md) connects the first local UserProfile builtin to the incumbent transaction and proves real output and bound receipts in two disposable homes, with retained intent and uncertain truth after a possible publication.

The binding is passed as a separate host-issued operation argument rather than copied into the ordinary legacy `DeployTargetRequest` or `DeployPlan` structs. The bound request is the pair of that argument and the body after preflight; the prepared bound plan is tied to the same binding by `bound_plan_hash` and is rechecked under the physical lock before effect. This preserves the old provider ABI and None record bytes while ensuring an unpaired plan cannot be applied by the admitted route. Intent, lock sidecar, checkpoint, inverse and receipt carry the binding explicitly. The provider's effect-capable store can only be constructed from a live `LockedLocalDeployBinding` in production code. `receipts_bound` walks held state directories for cross-target ownership rather than reopening an ambient path.

The source contract's portability limit remains explicit: Linux/macOS file locks coordinate cooperating writers; no platform receives hostile-writer content CAS by file identity or rename alone. The local Linux tests prove alias contention and independent roots. Native macOS/Windows execution is still an integration obligation, not a waiver. The first bound path refuses prior intent/receipt/update/remove/recovery and non-builtin providers. A foreign pending intent containing only an immutable CAS payload may coexist with another binding; once a launcher/pointer exists, the no-prior occupancy check refuses the second writer. Domain recovery and the production host generation source are M-16-C work before public adapter exposure. The public shape-only `execute_bound_deploy_targets` still refuses.

**Accepted parent boundary:** explicit target binding, physical alias fencing and cross-target refusal are executable through the internal local-host builtin seam without changing the historical unbound route. M-14 workstream integration, release-impact/documentation reconciliation and native platform proof remain open; no public 1.1.0 Git update is authorised or performed.
