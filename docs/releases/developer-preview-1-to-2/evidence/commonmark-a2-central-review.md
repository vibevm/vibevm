# M-06-A.2 ordinary CommonMark — bounded central review

M-06-A.2 adds a separate ordinary CommonMark structural reader (`d00908242`) using pinned `pulldown-cmark 0.13.4` offset events. It builds snapshot-local heading sections, code blocks, links, text and inline-code nodes with byte spans. Equal sibling headings are ambiguous; no first-match or ordinal fallback exists. `@requires`, `#use` and quoted `@fact` remain text rather than Vibe facts or directives. The existing Vibe Markdown/SpecDoc adapter is unchanged.

[PROP-072](../../../../vibevm/vibespecs/common/PROP-072-boot-observability.xml#SOURCE-EXPORT-SELECTOR) now defines conservative `[[package.source_exports]]` rows: package-unique ASCII name, exact file and nonempty root-to-section heading path (`e9abbbba8`). The manifest owner validates and round-trips these rows; the pure reader resolves them against one captured CommonMark snapshot, returning `sha256:<hex>`, section span and a node ID that is explicitly local to that snapshot (`e8f1bfe79`). The descriptor-selected host join (`d88c6dfe1`) checks the authored export, selected `commonmark`/`text/markdown` descriptor, resource identity, captured byte witness and resolved SHA before returning a durable package/export name. Ordinary structure mints zero Vibe facts. Missing, malformed and ambiguous selectors refuse; directory defaults remain incomplete without a host census.

The pre-existing fact-anchor scanner incorrectly treated repeated `@fact:X` inside inline code as definitions. `8a4c096f3` removed that raw-line recount, kept real anchors, pinned paragraph and table-cell quotations, and removed the one now-stale `UNPARSABLE_PROJECTIONS` entry. No broad parser replacement was made.

Root checked the affected cases on these sources: CommonMark structure/export 5/5, manifest export grammar 2/2, descriptor-selected observations/exports 16/16, anchor cases 7/7, the selected 54-page documentation-corpus check 1/1, and the prior Vibe Markdown adapter family 14/14. Formatting and staged diffs were checked. No mutation or workspace-wide gate was run for this bounded pure reader/manifest change.

**Accepted A.2 boundary:** structural view and raw content share the same captured bytes; exported names are stable manifest identities while node IDs and byte spans belong to one snapshot; no CommonMark node gains normative Vibe authority. M-06-A.3 still owns XML data/opaque resources, and A.4 owns further consumers, directory census and transformed-source provenance. Final documentation and native campaign gates remain separate.
