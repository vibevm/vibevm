# Root review of authored extension-schema source law

Accepted as desired source law only, before extension-schema implementation. Current PROP-054 and PROP-080 bytes are bound in the accompanying retention manifest. PROP-054 names the optional typed `[extension.machine_operation_schema]` table, schema_epoch=1, explicit operation/model identity and at least one registered format reference. The core manifest owner checks shape/local duplicates without depending on vibe-wire; the selected-world/format owner checks registered IDs/epochs/provider joins. Existing declarations without the table keep their old grammar. A typed descriptor remains data, never a native-handler call or authorization.

Initial source authoring put a section inside `<facts>`; both the native scanner and closed SpecDoc loader refused, with raw failures retained. Moving the section outside `<facts>` passed both readers. Later exact field/owner separation and the fingerprint ruling each passed the same two readers. An independent review then found that "excluded from the fingerprint" was too absolute: provider content hash is already a fingerprint member and may change indirectly with an authored manifest. Root corrected the law to say the schema adds no separate executable frame, while the existing provider pin and manifest/source witness still identify their own changes. The final source unit/SpecDoc reader checks exited zero after that correction. The native P080 source unit/SpecDoc checks also exited zero; its body did not change in the later P054 corrections.

This acceptance does not claim the strict TOML parser, FormatId/world source join, authenticated retained schema, native zero-load discovery, complete capability catalogue or M-16-B.1 task has passed. Unknown/unverified source remains unavailable; the actual package byte/physical authority limit must be disclosed in implementation evidence. No native library, provider, public publication or user installation was invoked.
