# Domain authority and observability

Domain views and operations preserve resolver, compiler, registry, settings, lifecycle, journal and receipt authority. Shared application services delegate existing library values. The authority map is review/design data, not an operational wire or runtime ABI. A new universal graph, parser, requirements scheduler, plugin, IDE product or MVP is outside this architecture. Governing contracts are [domain authority](../../vibevm/vibespecs/common/PROP-080-machine-operations-and-observability.xml#DOMAIN-AUTHORITY), [observability closure](../../vibevm/vibespecs/common/PROP-080-machine-operations-and-observability.xml#OBSERVABILITY-CLOSURE) and [finite map consistency](../../vibevm/vibespecs/common/PROP-080-machine-operations-and-observability.xml#AUTHORITY-MAP-CONSISTENCY).

## Table grammar and interpretation

The three table headers above are exact. Every binding has one stable inventory identity, literal inventory owner, exact source-ID set joined by semicolon plus space, and one unique conformance identity. Machine cells contain no links or inline code. Pipes in data are Markdown-escaped. Status is exactly PROPOSED UNRUN. A canonical Markdown AST reader may compare these finite joins against the generated Coverage reader; it proves reference consistency only. Domain owner in the conformance table is an independently proposed existing seam, requiring independent semantic review; it is not inferred authority from the copied owner prose.

## Universal external access and observability policy

Universal external access requires an externally accessible, owned semantic or diagnostic path for every capability and meaningful internal analysis/debug structure; architecture of shared feature services precedes client work. External IDE clients are consumers of those contracts. Plugin implementation, an IDE product and an MVP remain excluded. The full finite model and planned-family set is represented above; declared presence does not close an implemented interface gap.

Extreme Total Observability applies generally: every meaningful state, decision, transformation, action and refusal needs machine-readable inspection or explanation with provenance and explicit incompleteness. State maps retain authoritative observations; decisions retain selection/admission/rejection reasons; transformations retain captured before/after and stage basis; actions retain actual/partial/uncertain effects and recovery identity; refusals retain reason and scope. Inspection and explanation are independently owned projections. Provenance identifies source/world/target/record/operation; incomplete, uncaptured, evicted, unread, redacted and truncated portions stay visible. The proposed obligations exercise these distinctions without pretending they have run.

Discovery/capture/query/prepare/admit/submit/observe/recover are delegated boundary names, not new lifecycle phases or an automatic workflow. Discovery executes no provider; capture/query declare read effects; prepare binds before-state; admission is scoped domain authority; submission/observation/recovery retain existing run, journal, lease or receipt identity. External orchestration stays external under the [transport owner seams](../../vibevm/vibespecs/common/PROP-080-machine-operations-and-observability.xml#TRANSPORT-OWNER-SEAMS) law. Independent semantic review, governing source contracts and executed domain conformance are required before closure. Finite reference consistency establishes assignment only; every proposed obligation remains unrun.
