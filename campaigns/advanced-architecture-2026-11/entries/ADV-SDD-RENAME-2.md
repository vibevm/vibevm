# ADV-SDD-RENAME-2

Planned at commit `9d8428d07`. Line numbers below are hints from that commit; find each place by the quoted text or the item name.

**Outcome.** `vibe refactor rename-package` also rewrites `spec://org.old/foo` URI references (followed by `/`, `#`, `@` or any non-name character) in authored .md/.xml files under each workspace node's vibevm/vibespecs. Generated files that mention it are listed as untouched with reason `generated` and get no other record.

**Write.** `crates/vibe-cli/src/commands/refactor/rename_package.rs`, `crates/vibe-cli/src/commands/refactor/rename_package/census.rs`, `crates/vibe-cli/src/commands/refactor/rename_package/spec_uris.rs`, `crates/vibe-cli/tests/cli_refactor_rename_package.rs`

**Check.** `cargo test -p vibe-cli --test cli_refactor_rename_package 2>&1 | grep -F "test result: ok. 4 passed"`

**Test.** Add `spec_uris_are_rewritten_and_generated_files_reported` to crates/vibe-cli/tests/cli_refactor_rename_package.rs. The file has 3 tests before this entry, so the check's "4 passed" fails until it lands. Call write_fixture(root, false), then write these two files:

**Steps.**
1. In census.rs add the variant `Spec` to EditKind, so it serializes as "spec". Change `contains_coordinate` to `pub(super)`. In `plan`, before the final sort, call `super::spec_uris::scan(workspace, old, new)?` and extend `edits` and `untouched` with its results. In rename_package.rs add `mod spec_uris;` and print the edit kind in the human line as `kind=spec` for Spec (match on EditKind).
2. Create rename_package/spec_uris.rs with `pub(super) fn scan(workspace: &vibe_workspace::Workspace, old: &super::Coordinate, new: &super::Coordinate) -> anyhow::Result<(Vec<super::census::FileEdit>, Vec<super::census::Untouched>)>`. For each `(rel, _)` in `workspace.iter_nodes()`, let dir = `workspace.node_abs_path(rel).join(vibe_core::layout::current_specs_root())`. If it is a directory, walk it recursively, reading entries sorted by path. Skip directories whose name equals `vibe_core::layout::VIBEDEPS_DIR`, equals "target", or starts with '.'. Consider regular files with extension "md" or "xml". Collect the absolute paths into a BTreeSet first so a file reached from two nodes is scanned once. The path string is `vibe_core::machine_json_path(abs.strip_prefix(&workspace.root)?)`. A file that is not valid UTF-8 fails the plan with context `reading `{path}``.
3. Add `fn rewrite_spec_uris(text: &str, old: &Coordinate, new: &Coordinate) -> (String, usize)`. It replaces each occurrence of `spec://{old.group}/{old.name}` whose following byte (if any) is not in [a-z0-9_-] with `spec://{new.group}/{new.name}`, and returns the new text and the number of replacements. Classify each file first. Generated file: any of its first 3 lines, lowercased, contains "generated by vibe" (the same rule as has_generated_marker in convert_source.rs). A generated file gets at most ONE record: push Untouched { path, reason: "generated" } when the rewrite would replace at least one occurrence, never push a FileEdit for it, and never run the contains_coordinate check on it (its text still holds OLD, so that check would add a wrong `unrewritten-spec-text` record). For an authored file only (never a generated one): when the count > 0, push FileEdit { kind: EditKind::Spec, original, rewritten, occurrences }; then, when `contains_coordinate(<rewritten text, or the original when count == 0>, &old.to_string())` is true, push Untouched { path, reason: "unrewritten-spec-text" }. Write this as an if/else on the generated flag so the two branches cannot both run.
4. Add the test from the test field. The apply step in rename_package.rs already writes every FileEdit generically, so do not change it. Run `cargo fmt --all` and `cargo clippy -p vibe-cli --all-targets -- -D warnings`. Run `wc -l` on census.rs and rename_package.rs, and if either would pass 600 lines, put the new code in spec_uris.rs instead.

**Decisions already made.**
- Scanned: only `<node>/vibevm/vibespecs/**` (current_specs_root) .md and .xml files of workspace nodes. Not scanned: Rust `#[spec]` strings, package `rules/` pages outside the spec root, CLAUDE.md/AGENTS.md.
- URI match is exact `spec://<old-group>/<old-name>` with a non-name following byte, so `spec://org.old/foobar` is never touched and anchors and paths after the coordinate are kept.
- Generated files are detected by "generated by vibe" in the first 3 lines; they are only reported with reason `generated`, never edited, and never also reported as `unrewritten-spec-text`.
- Untouched reasons added: `generated`, `unrewritten-spec-text`.
- Entries 1, 2 and 3 share rename_package.rs, census.rs and the test file, so they run one after another in that order.

**Not in this entry.** Not in this entry: rewriting spec URIs in Rust source or outside vibevm/vibespecs, rewriting `installed:<group>/<name>` boot conditions, renaming anchor ids or files, running install, and moving the shared walker out of convert_source.rs.
