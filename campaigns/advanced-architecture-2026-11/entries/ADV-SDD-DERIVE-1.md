**Decisions already made.**
- Planner's choice, not an owner decision (owner decisions 1 to 6 in PLAN.md do not cover this; the research note proposed a `[[derived]]` array in vibe.toml and registry-cache base bytes): the record lives in a separate committed project-root file `vibe-derive.toml` so vibe-core's manifest schema and toml_preserve editing stay untouched; it stores per-file base hashes; nothing reads the registry cache. This is put to the owner as an open question; if the owner picks the vibe.toml form, this entry and entry 3 are re-planned before entry 1 opens.
- Record shape is exactly: top-level `schema = 1`, array of tables `[[copy]]` with keys name, package (`group/name`), version (exact semver), path (in the package, no trailing slash), to (project-relative directory), and `[[copy.file]]` rows with path (relative to `to`) and sha256 (64 lowercase hex).
- `to` is always a directory. A file source `templates/a.txt` lands at `<to>/a.txt`; a directory source `templates` lands each `templates/x/y` at `<to>/x/y`.
- Default name `<package name>-<last path component>` sanitized to [A-Za-z0-9_-] with `-2`, `-3` suffixes; default `--to` is `derived/<name>`.
- Every refusal (bad source, not installed, in-place, empty selection, bad or taken name, invalid or overlapping `to`, existing `to`) happens before any file or record is written.
- Files are read from the verified slot and re-hashed against the slot record before copying; `.vibe/cache` is never read.
- This entry is the only one that writes the four registration files (mod.rs, command.rs, main.rs, command_progress.rs). Adding a top-level command requires the TOP_LEVEL_COMMANDS line, or the unit test top_level_policy_inventory_matches_clap fails in the workspace gate.
- derive.rs is also written by entries 2, 3, 4 and 5; they run one after another in id order after this one (their depends_on form the chain 1 -> 2 -> 3 -> 4 -> 5).
- New source files start with `specmark::scope!("spec://org.vibevm.core/vibevm/VIBEVM-SPEC#cli-surface");`; only `pub fn run` carries `#[spec(implements = ...#cli-surface)]`. No spec file changes; do not run `cargo xtask specmap`.
- Items in derive/record.rs are pub(crate) because entry 6 reads DeriveRecords from the tree command; everything else is private or pub(super).
