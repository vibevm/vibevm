# ADV-SDD-RENAME-1

Planned at commit `9d8428d07`. Line numbers below are hints from that commit; find each place by the quoted text or the item name.

**Outcome.** `vibe refactor rename-package org.old/foo org.new/bar` in a two-member workspace rewrites the target's [package] group/name and the `"flow:org.old/foo"` dependency key in the other member byte-for-byte, keeping comments. `--dry-run`/`--json` print the same per-file plan and write nothing. An existing NEW coordinate is refused with a named error, and a second run changes nothing.

**Steps.**
1. Create crates/vibe-cli/src/commands/refactor/rename_package.rs. Declare `mod census;`. Define `#[derive(Debug, Args)] pub(crate) struct RenamePackageArgs` with: `#[arg(value_name = "OLD")] pub(crate) old: String` (doc: Current coordinate, `<group>/<name>`); `#[arg(value_name = "NEW")] pub(crate) new: String`; `#[arg(long, default_value = ".")] pub(crate) path: PathBuf` (doc: Directory to discover the workspace from); `#[arg(long)] pub(crate) dry_run: bool` (doc: Print the plan without writing anything). Define the private `struct Coordinate { group: String, name: String }` with `fn parse(text: &str) -> Result<Coordinate>`. It calls `vibe_core::PackageRef::parse(text)` (signature `pub fn parse(input: &str) -> Result<Self>`; fields `kind: Option<PackageKind>`, `group: Option<Group>`, `name: PackageName`, `version: VersionSpec`). It accepts only kind == None, group == Some and version == VersionSpec::Latest; any other result, including a parse error, fails with `rename-package refused: `{text}` is not a `<group>/<name>` coordinate`. Implement `Display` as `{group}/{name}` and `PartialEq`.
2. In census.rs (pure planning, no writes) define: `#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize)] #[serde(rename_all = "lowercase")] pub(super) enum EditKind { Manifest }`; `pub(super) struct FileEdit { pub(super) path: String, pub(super) kind: EditKind, pub(super) original: String, pub(super) rewritten: String, pub(super) occurrences: usize }`; `#[derive(Debug, serde::Serialize)] pub(super) struct Untouched { pub(super) path: String, pub(super) reason: &'static str }`; `pub(super) struct RenamePlan { pub(super) root: PathBuf, pub(super) edits: Vec<FileEdit>, pub(super) untouched: Vec<Untouched> }`; and `pub(super) fn plan(workspace: &vibe_workspace::Workspace, old: &Coordinate, new: &Coordinate) -> anyhow::Result<RenamePlan>`. For every `(rel, _)` in `workspace.iter_nodes()`, read `workspace.node_abs_path(rel).join("vibe.toml")` to a String. Parse it with `toml::de::DeTable::parse(&text)`, which returns `Spanned<DeTable>`. toml 0.9 is already a vibe-cli dependency, so do not add toml_edit. Key spans and string-value spans include their quotes. The plan path is "vibe.toml" when rel == "." and otherwise `{rel}/vibe.toml`. Look up child keys by iterating the table and comparing `key.get_ref()` with the wanted name.
3. Identity: for each top-level table named "package" or "project", read its "group" and "name" `DeValue::String` values. A table whose group/name equals OLD marks this node as the target. Add a replacement over the group value's span with `"<new.group>"` (with double quotes) when old.group != new.group, counting 1 occurrence. Add a replacement over the name value's span with `"<new.name>"` when the names differ, also counting 1. A table equal to NEW records this rel as the NEW holder. Dependency keys: when a top-level "requires" table has a "packages" table, check each key with `vibe_core::PackageRef::parse(key)`. When the parsed group/name equals OLD, replace the key's span with a double-quoted new key and count 1. The new key is `{kind}:{new}` when the original key has a `kind:` prefix (split_once(':')), else `{new}`. Splice the replacements in descending span-start order to get `rewritten`. Push a FileEdit with kind Manifest only when occurrences > 0.
4. Still in census.rs, add `fn contains_coordinate(text: &str, coordinate: &str) -> bool`. It is true when `coordinate` occurs where the byte before it (if any) is not in [a-z0-9.-] and the byte after it (if any) is not in [a-z0-9_-]. For every node whose rewritten text (or original text when nothing was edited) still contains OLD this way, push Untouched { path, reason: "unrewritten-manifest-field" }. Push { "vibe.lock", "lockfile" } when `workspace.lockfile_path().is_file()`. Push { vibe_core::machine_json_path(&vibe_core::layout::current_vibedeps_root()), "vibedeps" } when `workspace.vibedeps_root().is_dir()`. Refusals: when both a target and a NEW holder exist, bail `rename-package refused: `{new}` is already declared by workspace node `{rel}``. When neither exists, bail `rename-package refused: no workspace node declares `{old}``. When only the NEW holder exists, keep planning, so leftover OLD keys are still rewritten and an empty plan means nothing to do. Sort edits by path and untouched by (path, reason). Set root to `workspace.root.clone()`.
5. In rename_package.rs implement `pub(super) fn run(ctx: &crate::output::Context, args: RenamePackageArgs) -> anyhow::Result<()>`. Parse both coordinates. If they are equal, bail `rename-package refused: `{old}` and `{new}` are the same coordinate`. Then call `vibe_workspace::Workspace::discover(&args.path)` (signature `pub fn discover(start: impl AsRef<Path>) -> Result<Workspace>`) with `.context("discovering the workspace")` and call census::plan. If not dry-run and edits is non-empty: pre-flight re-read every edit's `plan.root.join(&edit.path)` and bail `rename-package refused: `{path}` changed after it was planned; nothing was written` on any difference from `original`. Then `let project = vibe_safefs::Project::open(&plan.root)?;` and call `project.write_atomic(&edit.path, edit.rewritten.as_bytes())` for each edit. On a write error, bail `rename-package: writing `{path}` failed after {n} file(s) were written: {error}`. `applied` = at least one file written. Output: in JSON mode call `ctx.emit_json(&report)` with a private `#[derive(serde::Serialize)]` report { ok: true, command: "refactor rename-package", from: String, to: String, dry_run: bool, applied: bool, edits: Vec<{path, kind, occurrences}>, untouched: &[Untouched] }. Otherwise println one line per item, `edit {path} kind=manifest occurrences={n}` and `untouched {path} reason={reason}`, then `summary files={n} occurrences={m} dry-run={bool} applied={bool}`.
6. In refactor/mod.rs add `mod rename_package;` and `use rename_package::RenamePackageArgs;`. Add the variant `/// Rename a package this workspace owns and the references to it.\n    RenamePackage(RenamePackageArgs),` to RefactorCommand, and the arm `RefactorCommand::RenamePackage(args) => rename_package::run(ctx, args),` to `run`. machine_entry's `_ => None` arm already covers the new variant; do not change it. In crates/vibe-cli/src/command_progress.rs add `| RefactorCommand::RenamePackage(_)` to the existing ConvertSource/ConvertPackageSrc/ConvertSpecSrc arm that maps to FiniteFallback("Command refactor"). command_progress.rs has 578 lines and the limit is 600, so add exactly one line. Write the test file, then run `cargo fmt --all` and `cargo clippy -p vibe-cli --all-targets -- -D warnings`. Every FileEdit field is read in this entry (original by the pre-flight, rewritten by the write), so no dead-code allowance is needed. Do not add `#[allow]`.

**Decisions already made.**
- Rewritten in this entry: only the target node's [package]/[project] `group` and `name` string values, and keys of `[requires.packages]` in every workspace node. Every other textual mention of OLD in a workspace vibe.toml (comments, `exclude` lists, other tables) is reported as untouched with reason `unrewritten-manifest-field`.
- Edits splice byte ranges from `toml::de::DeTable` spans into the original text, so all other bytes stay identical. Replacement tokens always use double quotes.
- Coordinates are `<group>/<name>` only; a kind prefix or `@version` is refused.
- Refusals exit 1 through the normal anyhow path, with the exact messages given in the steps. exit_code.rs is not edited.
- Writes go through `vibe_safefs::Project::open(&workspace.root)` + `write_atomic(relative, bytes)`. There is a pre-flight byte comparison of every file before the first write.
- JSON field names: ok, command, from, to, dry_run, applied, edits[{path, kind, occurrences}], untouched[{path, reason}]. Paths are relative to the workspace root and use forward slashes.
- No specmark markers and no spec edits.
- Entries 1, 2 and 3 share rename_package.rs, census.rs (1 and 2) and the test file, so they run one after another in that order.
