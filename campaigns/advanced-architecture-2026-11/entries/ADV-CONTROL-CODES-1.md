**Steps.**
1. Create crates/vibe-cli/src/exit_code/classify.rs, starting with `specmark::scope!("spec://org.vibevm.core/vibevm/VIBEVM-SPEC#output-format");`. Define `#[allow(dead_code)] pub(crate) struct CliCode { pub(crate) code: &'static str, pub(crate) exit: u8, pub(crate) refusal: bool, pub(crate) meaning: &'static str }`, one `const` per row listed in the decisions (exit fields name super:: constants, see decisions), `#[allow(dead_code)] pub(crate) const CLI_CODES: &[CliCode]` holding all 12, and `#[derive(Debug, Clone, PartialEq)] pub(crate) struct Classified { pub(crate) code: &'static str, pub(crate) exit: u8, pub(crate) refusal: bool, pub(crate) remedy: Option<serde_json::Value> }` with `impl From<&CliCode> for Classified` (remedy None). In exit_code.rs add `mod classify; pub(crate) use classify::{classify, stamp as stamp_classification};` and end classify.rs with `#[cfg(test)] mod tests;`.
2. Move the whole decision body of `as_exit_code` into `pub(crate) fn classify(err: &anyhow::Error) -> Classified`, keeping the same arm order. Each arm returns a Classified: the dl arm gives `{code: dl.code, exit: dl.exit, refusal: dl.exit == 2}`. The InstallError arm gives the USER_DECLINED or AMBIGUOUS_PACKAGE row with `remedy: install_err.remedy()`. The remap ConsentRequired arm gives CONSENT_REQUIRED, the RemapPackageMissing arm REMAP_PACKAGE_MISSING, the RemapUnreachable arm REMAP_UNREACHABLE and the LockedRemapSourceError arm LOCKED_REMAP_SOURCE. The app arm gives `{code: app_err.code(), exit: super::app_exit_code(app_err.class()), refusal: app_err.class() == vibe_app::ErrorClass::Refusal}`. The malformed-redirect arms give MALFORMED_REDIRECT_BLOCK and the kind-mismatch arms give KIND_MISMATCH. Every other error gives UNCLASSIFIED. `as_exit_code` becomes `ExitCode::from(classify(err).exit)`.
3. After the kind-mismatch loop and before the final fallback, add two chain walks. The first returns PROJECT_BUSY when a cause is `vibe_lifecycle::LifecycleLeaseError::Busy{..}` or `vibe_install::Error::Lease(LifecycleLeaseError::Busy{..})`. The second returns OFFLINE_UNAVAILABLE when a cause is any of: `vibe_registry::RegistryError::OfflinePackageUnavailable{..}`, `vibe_resolver::DepProviderError::OfflineUnavailable{..}`, `vibe_resolver::SolveError::Provider(DepProviderError::OfflineUnavailable{..})`, `vibe_install::Error::Solve(SolveError::Provider(DepProviderError::OfflineUnavailable{..}))` or `vibe_install::Error::Registry(RegistryError::OfflinePackageUnavailable{..})`. Each wrapper variant is matched explicitly, because `#[error(transparent)]` hides the inner error from `chain()`.
4. In exit_code.rs add `impl InstallError { /// The machine remedy of this failure; filled per variant by later work. pub fn remedy(&self) -> Option<serde_json::Value> { None } }`. Add `pub(crate) fn stamp(payload: &mut serde_json::Value, err: &anyhow::Error)` in classify.rs. When the payload is an object it inserts `code` only if absent (map.entry("code").or_insert), always inserts `refusal` as a bool, and inserts `remedy` only when it is Some and the key is absent. In output/lines.rs Mode::Json, call `crate::exit_code::stamp_classification(&mut payload, err);` right after `structured::stamp_structured_error(&mut payload, err);`.
5. Write the five unit tests in crates/vibe-cli/src/exit_code/classify/tests.rs and the three CLI tests named in `test`. **Decisions already made.**
- Codes are snake_case, like crates/vibe-app/src/codes.rs. The busy code is `project_busy`, not `project-busy`.
- The 12 CLI_CODES rows (code, exit, refusal, meaning): usage super::USAGE true 'the command line does not parse'; consent_required super::USAGE true 'a remap question needs the user's answer and nobody can be asked'; remap_package_missing super::USAGE true 'a named remap package is not installed in this home'; remap_unreachable super::USAGE true 'a declared artifact has no reachable source under the remap policy'; locked_remap_source super::USAGE true 'the lock names a remap source this run cannot use'; malformed_redirect_block super::PACKAGE_CONFLICT false 'an instruction file's managed <vibevm> block is malformed'; kind_mismatch super::TYPE_MISMATCH true 'a pkgref's kind disagrees with the package's declared kind'; user_declined super::USER_DECLINED true 'the user declined the plan'; ambiguous_package super::AMBIGUOUS_PACKAGE true 'a short name matches packages in two or more groups'; project_busy super::GENERAL true 'another mutating command holds the project's lifecycle lease'; offline_unavailable super::GENERAL true 'an offline run's local sources do not hold the package'; unclassified super::GENERAL false 'vibe has not classified this failure'. Const names are the upper-case codes.
- The `exit` field of every row names an existing u8 constant of exit_code.rs (USAGE=2, PACKAGE_CONFLICT=3, TYPE_MISMATCH=4, USER_DECLINED=5, AMBIGUOUS_PACKAGE=7, GENERAL=1); no exit number is written as a literal.
- classify.rs and classify/tests.rs never glob-import `super::*`. They refer to the u8 exit constants only as `super::NAME` (in tests `super::super::NAME` or `crate::exit_code::NAME`), because the row consts USAGE, USER_DECLINED and AMBIGUOUS_PACKAGE of type CliCode share those names.
- `CliCode` and `CLI_CODES` carry `#[allow(dead_code)]`, the pattern exit_code.rs already uses, because only the unit test reads them; that attribute keeps every row const reachable for the dead-code lint.
- Exit codes are not changed for any error. Busy and offline stay at exit 1.
- `refusal` comes only from classify(): from a CLI_CODES row, from the app ErrorClass, or from dl exit == 2. It is never derived anywhere else.
- The JSON `code` comes only from typed classification and structured.rs stamps. A code that human or quiet output derives from a prose prefix (output/lines.rs refusal_of) is not copied, and stamp never calls refusal_of; such a failure reports `unclassified` under --json.
- A code already stamped by structured.rs (app codes, source_policy_*, source_host_excluded, lock-hash, review codes) wins over the classified code, because stamp inserts code only when it is absent.
- No remedy for offline_unavailable: the offline posture can come from --offline, VIBE_OFFLINE or user config, so no single flag reverses it. The prose recipes stay in `error`.
- Human and quiet output are not changed.

**Not in this entry.** Not in this entry: listing the catalog in `vibe capabilities` (a separate capability), the clap parse-error envelope, and any remedy content. Do not refactor structured.rs's existing stamps or refusal_of into classify.

**Spec edit (apply as a step of this entry).**

VIBEVM-SPEC.md §9.3 {#output-format}: insert after the paragraph "A `--json` flag produces fully machine-readable output. Skills consuming the CLI use `--json`. Humans use the default." this new paragraph:

Under `--json`, a failed command's last stderr line is one JSON error envelope: `ok: false`, `error` (the prose), `code` (a stable snake_case string; a failure vibe has not classified carries `unclassified`) and `refusal` (`true` only when the command stopped before any effect). Fields are only ever added; the exit codes of §9.4 do not change.
