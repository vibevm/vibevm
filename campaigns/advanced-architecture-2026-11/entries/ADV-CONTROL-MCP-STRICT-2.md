**Decisions already made.**
- Reuse `decode_args` from crates/vibe-mcp/src/tools/args.rs (entry 1); no new helper. In tools.rs it is always called as `crate::tools::args::decode_args(args)?` (the parameter `args` does not clash with the module path).
- A missing required member now reports serde's text, e.g. `missing field `name``; the old `` `name` must be a string `` text is retired and the one compat test that pinned it is updated to the new exact text (a changed expectation, not a removed assertion).
- Tools that already decode strictly (configuration_preview, configuration_preview_v2, read_doc, plan_manifest_migration, manifest_migration_operation, lifecycle_tasks, lifecycle_run, requirements_query) are not edited; their value-free refusal messages stay as they are, which is why the sweep only requires the member name for rows marked true.
- Sweep acceptance variants are exactly InvalidArguments, StructuredPreflight and OperationPreflight.
- The sweep runs against an empty temp directory; every row must refuse during argument decoding, before any project read.
- The spec unit TOOL-ARGS-STRICT was inserted by entry 1 with status impl/plan; this entry only flips its status to impl/done.

**Not in this entry.** Not in this entry: changing the value-free error messages of read_doc / configuration_preview / migration tools to name the member, moving more tool cells out of tools.rs, or adding validation in the lib.rs dispatcher.
