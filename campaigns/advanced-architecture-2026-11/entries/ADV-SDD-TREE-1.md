**Decisions already made.**
- The owner module is `vibe_workspace::tree`. Its public surface is `build_tree(root)`, `build_tree_bound(root, SpecFormat)`, `pub mod model` (all existing pub types and `SCHEMA_VERSION`), and `pub use model::PackageTree`. `artifacts`, `diagnostics` and `in_place` stay private modules.
- vibe-workspace gains the `anyhow` and `chrono` workspace dependencies. The moved code keeps `anyhow::Result` and `chrono::Utc::now()` as they are, and no error-type conversion is done.
- build.rs's call `resolve_spec_format(&manifest, None)` is inlined as `manifest.consumer_node().and_then(|node| node.spec_format).unwrap_or_default()`, the same expression vibe_orchestrator::resolve_spec_format evaluates with a None default.
- The tree-read format recheck at old read.rs:378 calls a private helper in tree/in_place/read.rs. The helper reproduces vibe-cli `reinstall::effective_rederive_format` exactly: `/// The format a re-derive would select now: the manifest pin, then the user\n/// default, then the built-in default (mirrors vibe-cli\n/// `reinstall::effective_rederive_format`).\nfn effective_rederive_format(manifest: &Manifest) -> anyhow::Result<SpecFormat> {\n    let user = vibe_core::user_config::UserConfig::load().context("loading the user config")?;\n    Ok(manifest\n        .consumer_node()\n        .and_then(|node| node.spec_format)\n        .or(user.install.spec_format)\n        .unwrap_or_default())\n}`. Manifest reaches read.rs via the `use super::*` glob chain, and SpecFormat is already imported there. vibe-workspace must not depend on vibe-orchestrator, because vibe-orchestrator already depends on vibe-workspace (crates/vibe-orchestrator/Cargo.toml:28), and it must not depend on vibe-cli.
- All `specmark::scope!` and `#[spec(...)]` annotations in the moved files stay byte-identical, including their vibe-cli/PROP-036 and PROP-072 URIs.
- CLI rendering (plain.rs, layers.rs, tui/, picker.rs, host.rs, and the mod.rs command flow) stays in vibe-cli. The CLI reaches the owner through `use vibe_workspace::tree as build;` and `use vibe_workspace::tree::model;` in commands/tree/mod.rs. No other shim files are added.
- The JSON schema file stays at crates/vibe-cli/resources/package-tree.schema.v1.json, and `vibe tree --json` output does not change by a byte (tree_json stays green without edits).
- The plain-render provenance test moves to the plain.rs `mod tests` block because it calls the CLI renderer.
