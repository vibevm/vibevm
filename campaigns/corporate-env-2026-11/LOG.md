Out of scope, not recorded: repository description, topics, visibility and settings; host releases and their assets; issues/PRs; branches other than via a bundle; signatures on tags/commits beyond what a bundle carries; repository creation on the host (needs the host API and a token). **Problems left open.**
- P1 `[self] install_root` (and any `VIBE_SETTINGS` ≠ install root) splits the shim directories: `vibe self apply` puts `<install root>/opt/bin` on PATH and vibe's shims there, but `vibe install -g` writes application PATH proxies to `<settings>/opt/bin` and payloads to `<settings>/opt/apps`. With `install_root = "C:/Work"` (the "executables only under one directory" network) `codkit` is installed outside the permitted directory and is not on the PATH the profile fixed (reproduced on Linux with `[self] install_root`). Not a local fix: the proxy binary finds its application home by walking up from its own location to `applications/index.json`, so moving proxies needs a home pointer or moving the application home; owner decision (PROP-019 `#install-root` × PROP-059 `#proxy`).
- P1 `archive` steps refuse every symbolic link, so the official Node.js (and similar runtime) tarballs cannot be unpacked by an archive step; packages need a recipe with system `tar` (this package does). Option: accept relative links that resolve inside the payload, or a declared `skip_links`.
- P2 `needs = ["network"]` (the convention of `org.vibevm.apps/mingw-w64`) makes `--offline` refuse a step whose every input is already in the drop or cache (`need_unmet`); this package therefore declares no network need. The need could count as met when every input resolves locally.
