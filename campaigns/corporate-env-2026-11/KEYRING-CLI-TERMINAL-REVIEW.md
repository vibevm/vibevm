# Protected-input terminal review — first candidate, not accepted

Two public CLI tests passed in the isolated builder run, and affected Clippy completed. The controlling-terminal test did not pass. Its harness started a new session with a controlling PTY, retained the slave descriptor in the parent, waited for the hidden-input prompt and observed ECHO off before injecting an actual terminal interrupt byte. The parent checked the same slave after child exit. The interrupted invocation left echo disabled. An operator returning to that terminal would no longer see typed commands. This is an observed automated failure, not an owner-attended test waiver.

Evidence: `cli-pty.py`, `cli-pty-r1.log`, `cli-tests-r1.log`, `cli-clippy-r1.log` in the private synthetic keyring run `vibevm-keyring-storage-20261120T0100Z`. The r1 harness aborts at its echo assertion before reaching the final index comparison: the log does **not** independently establish unchanged index bytes on cancellation.

Repair boundary sent to builder: keep one safe hidden-input terminal guard across the entire edit; return normally on terminal Ctrl-C or Escape and restore the prior terminal state before returning. No process-wide handler or installer UI change. Validate whole-string paste without echo, cancellation after partial entry, preservation of prior terminal attributes, unchanged durable index and no exposed value. Preserve bounded input and Unicode editing. Separately, scope parse-error redaction to the actual secrets command: the preliminary implementation treats any argument equal to `secrets` as a command, including an unrelated command's option value. Keep safe diagnostics for malformed keyring calls and ordinary diagnostics for unrelated commands. These are candidate findings; assess corrected exact bytes separately.

## Controlling-terminal repair result (r2)

The reviewer inspected `cli-pty-r2.py` (SHA-256 `3e28c827d76848e700c5756122a0078eb230cc95ce1a844f60d61786ab37fce8`) and its completed result `cli-pty-r2.log` (`bb8ebb45c84f85b97d7752a7d0bcb9da1e91d257d9572eb0d2e452de70529885`). On the exercised binary, Enter committed the exact synthetic value after Unicode backspace. With a partial value already entered, Ctrl-C, Escape and Ctrl-D each exited nonzero, preserved the index byte-for-byte and restored the entire previous termios structure; the complete synthetic sentinel was absent from the captured terminal stream in all four runs. This resolves the observed terminal regression for this run. It is not evidence for directed signals, Windows input, final source-to-binary binding or acceptance of the whole CLI.

## Parser controls and remaining input timing issue

The r3 CLI log reports three passing public tests, including the control where `secrets` is an ordinary global option operand, and the malformed keyring invocation that must not print its rejected argument. The scoped r3 Clippy log completed. These results do not close the hidden-input boundary: this reviewed implementation writes and flushes the prompt before acquiring raw mode. A prompt-driven paste can therefore arrive before echo is disabled. No actual secret disclosure was observed; the r2 fixture deliberately waited for echo to be off before sending its synthetic input. Acquire the guard before exposing the prompt, then test immediate synthetic paste based on the prompt alone. Reject empty Enter without mutation (the reviewed match currently waits for another key). Preserve the earlier r2 evidence for Ctrl-C, Escape and EOF.
