# Opt-in npm installer: pre-effect deferral

This slice applies to an explicitly supported npm installer option, not to standalone Qwen, Pi or Codex. Do not gate standalone manifests on Node. The first implementation atom covers a truthful operator deferral; installing a supplier runtime and rechecking it is a second atom.

**Owners.** `PROP-065#needs` and `crates/vibe-app/src/steps/plan/decision.rs` decide if a required command is present. Keep the ordinary `StepError::UnmetNeed` / `need_unmet` behavior for callers without an explicit decision. Do not parse display text or move prompts into the pure planner. `PROP-059#commands` and `PROP-065#error-codes` govern caller-facing disposition. CLI selection belongs to `cli/pkg.rs::InstallArgs` and `commands/app/global.rs::install_with_selected`, after resolving the application and installer but before install steps/download, work-directory creation, receipt or publication. Do not catch an arbitrary error from a partially executed install and relabel it preflight.

**First atom and format decision.** No manifest schema change or dependency edge is needed to defer a declared command need. For `install -g` add a narrow explicit decision `--on-missing-command=defer`; default stays unchanged. Reject misuse on non-application routes before mutation. Use the single existing `plan_option_with_modes` call in `install_entered`; do not plan twice or repeat selection, retained configuration or license prompts. Supply an optional decision-only callback through `OperationContext` for the explicit top-level global install, not durable `InstallRequest` state. Handle only a command need from that planning call before agent admission or `pending::begin`. Never install another package or re-enter installation from the callback under the mutation lock. Other paths including nested requirements, imports, resume and plan-only retain their prior behavior. Only a typed unsatisfied required command of the selected option can trigger the decision; unknown options, policy denials and network errors are not deferrals. In an attended terminal present the same choice using the existing question surface. JSON/unattended execution must never prompt. An already satisfied need proceeds normally. No saved answer or automatic retry.

Use a distinct stable refusal code `prerequisite_deferred` through the existing application error/exit mapping (`crates/vibe-app/src/{error,codes}.rs`); retain the existing nonzero refusal category and normal machine error envelope. This is a deliberate not-installed outcome, not a success report (`application-command-report/2` requires an installation identity), a parked job, or a new journal. Give a concrete remedy: install the missing runtime oneself and rerun the original command. Match the structured error code in tests, not localized prose. Inspect server-side/JSON error routing before assuming the code is visible; if not visible, fix the existing boundary rather than printing another JSON document.

**Acceptance.** Reuse original missing-command refusal test. Add an opt-in empty-host fixture: selected npm option, explicit self-install decision → deferred code and expected nonzero exit, no target acquisition, work directory, command proxy, receipt, selected default or version file. Protected existing installation unchanged. In fresh subsequent invocation with an available synthetic npm, normal installation proceeds. No test against a real account. Include a negative non-command failure and a standalone-option regression. Exercise attended choice using a PTY and unattended JSON separately; do not call a renderer unit test a PTY pass. Limit writes to owning spec, install CLI/pure result and code mapping, necessary existing argument constructors and focused tests. Use normal generated schema/format procedures only if the existing surface actually requires a change.

**Second atom.** Offer `Install Node via Vibe` only for a verified npm runtime remediation with an admitted canonical Node package/coordinate and explicit operator choice; never infer a supplier or run a shell command from arbitrary package prose. Use existing app-install admission, re-probe actual executable and supported version before the target proceeds. If the dependency fails or is refused, do not record target success. No side-effectful auto-remediation in the pure need evaluator. This separate atom and actual upstream npm package installation are not claims made by the first test.

**Binding for automatic Node remediation.** A bare `command:npm` need authorizes no installation. Only an explicitly selected npm installer option with a typed reference to its existing digest-pinned package input is eligible. Bind package name, version and supported `engines.node` range to `package/package.json` in that verified tarball; read metadata as data without executing scripts. Reject absent, ambiguous or mismatched metadata and unsupported range syntax before changing Node. Use the admitted `org.vibevm.node/node` supplier, not a supplier inferred from arbitrary manifest prose. Show the selected registry and runtime version for consent. Return from the target preflight before installing Node, revalidate actual resolved node/npm and target identity afterwards, and allow at most one target continuation. Preserve unchanged choices but never silently reuse consent for changed inputs. This is a planned second atom; first-atom acceptance does not cover it.
