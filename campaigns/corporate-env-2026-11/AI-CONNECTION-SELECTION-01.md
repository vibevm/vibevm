# Select a default AI connection without activating a provider

After integration of the first connection consumer, qualify metadata-only selection. Use the existing connection index and CLI. A missing default and an unmanaged harness remain distinct; setting a default does not opt any harness into using it. No inference, network, native credential configuration, value resolution, secret printing or SSH. Isolated synthetic settings only.

First inspect the published connection-index reader/writer and test old-client behavior before extending the format. Retain one atomic selection owner, keep the reference roster valid and never let an old writer drop the selection. Document the minimum compatible epoch or an existing suitable separate selection owner before enabling a new writer; do not silently migrate or create a competing index. If a safe compatible path needs a format decision, hand back the exact old-reader behavior and proposed change before activation.

First public route: show current default (including none), select an existing connection with an observed expected revision, and clear the selection explicitly. No raw values or provider request. Unknown connection and stale expected revision refuse with unchanged state; choosing the already selected ID is a no-op. Removing a selected connection must require explicit clearing first, not silently choose a replacement. Changing the default leaves other connections and their keyring references intact. Keep future per-agent bindings separate; no adapter or setup wizard changes in this atom.

Allowed writes: connection metadata owner, narrowly affected generic metadata admission if necessary, existing CLI, focused tests and format ledger/receipt. Gate with two distinct synthetic connections, selection A then B, stale mutation, removal of selected B, explicit clear, a second process reading each outcome and pre-change binary compatibility. Return exact source/binary identities and actual public results. Do not infer that any harness uses a selected connection until an authorized consumer is implemented and tested.

### Format decision and old-client control

Use `vibe ai connections default show`, `set ID --expect-store N`, and `clear --expect-store N --yes`. Only a first real selection publishes AI index schema 2. Do not migrate on show, ordinary schema-1 writes or clearing an already absent selection. Once schema 2 is active, require an explicit selection state, either none or an existing connection ID, even after clear. Missing, inconsistent or unsupported state refuses. Stale revision tokens never count as valid no-ops. Keep the selection with the authoritative rows under the same lock and atomic publication.

On the accepted pre-selection CLI `497621fb…`, a synthetic schema-2 index and a schema-1 index with an unknown `default_connection` field both caused public list, add and unbind to refuse. Both indexes remained byte-identical. Restoring the original AI index made list succeed. This checks old-client refusal, not a successful selection on a newer CLI.
