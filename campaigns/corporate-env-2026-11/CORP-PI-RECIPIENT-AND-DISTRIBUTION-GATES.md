# Separate managed Pi delivery from supplier redistribution

Existing owners: CORP-AI-CONNECTIONS, CORP-AGENT-DISTRIBUTION. Local acceptance can establish invocation-scoped behavior but cannot authorize copying supplier bytes to a corporate destination. The probe in PI-PROXY-RESULT-20261120.md established network routing, not managed-key delivery.

## Local recipient gate

Identify the actual native provider input and trusted launch path for pinned Pi 1.5.2 from retained supplier sources. Use an isolated local test service and an independently generated, nonfunctional sentinel only. No real provider, model invocation against an external service, host credential store or network egress. Preserve native/unmanaged launch unchanged. An alias resolving to a custom wrapper is not the verified package executable; it must not receive managed credentials merely because its preset is Pi. Do not introduce general key export, argv injection, persistent supplier configuration, or a fallback to inherited ambient credentials. Compare the selected connection's actual endpoint, executable and effective invocation before any protected value is obtained. If a trusted input or destination cannot be established, refuse before delivering the sentinel. The receiver's evidence is a boolean match, never the header, credential or its digest. Distinguish positive receipt, wrapper refusal and unapproved destination refusal from simple metadata selection. Record which conditions are supported versus unqualified; no broad native-agent acceptance from one Pi result.

## Distribution gate — not an implementation substitute

CORP-AGENTS-01.md requests delivery through an existing approved channel. It is not a blanket release instruction. Current package dispositions are recorded in AGENT-PACKAGES-MATRIX-20261120.md and PLATFORM-OPTIONS-RESULT-20261120.md. In particular OpenCode 1.19.6 is HOLD and Claude Code 2.1.328 is not approved for corporate redistribution. No current receipt identifies a cleared artifact plus an approved destination for that copy. A successful download, checksum, local staging, synthetic drop or agent setup cannot change this decision.

Before any external transfer, require both (1) the approved inventory for the specific version/platform with the applicable component notices and distribution decision, and (2) the named corporate registry/drop and scope of allowed action. Do not substitute a public repository or publish private information. Until these exist, leave physical distribution unexecuted and distinguish it from local technical tasks, which can proceed. The owner waiver for one Hermes native-install trial is unrelated to redistribution. Do not retry that waived trial. This packet neither reorders consolidation nor waives a final NST gate.
