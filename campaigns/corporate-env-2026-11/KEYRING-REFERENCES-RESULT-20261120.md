2026-11-20 candidate, baseline `4adc51fa08ec0c7472f2b9f528eec71d696e4256`. Existing original CRUD reference-usage criterion, not secret delivery or aggregate acceptance.

`vibe secrets references ID` delegates to `Store::references` in the existing roster owner. It acquires the same inventory guard as remove, confirms current item existence under the store lock, and returns deterministic sorted unique consumer IDs. Existing free ID returns an empty list; missing ID refuses not-found. Legacy/unknown protocol, unknown participant and incomplete inventory refuse instead of reporting no references. No custom filesystem scan or new roster is introduced. A preview is informational only: removal reacquires/revalidates its existing inventory and expected revision rather than accepting a preview token.

It has a separate registered strict schema and golden fixture, leaving `vibe-secrets/1` and storage/index formats unchanged. No value, digest, value path, authentication metadata or grant token is emitted. Existing private coordination locks are reused; a universal no-filesystem-write claim for malformed stores is not made.
