# First explicit local kit producer

Unaccepted BUILD candidate after accepted INIT `ae603a484`, using `CORP-KIT-BUILDER-FIRST-01.md`. No private corporate inputs, network, publication or new installer framework.

`vibe kit build --file RECIPE --out NEW_DIR` consumes only explicit prebuilt local files. Existing held-handle SafeFS copy checks the recipe hash before copying and rechecks the staged file. The existing bootstrap verifier validates the staged bundle's full closed ZIP, component/source hashes, target and version. The existing SiteProfile parser validates the separately pinned staged profile. The installer is an author-trusted input: SHA-256 establishes exact copied bytes, not role/version/target/publisher authentication. The producer never executes supplied binaries. Help and generated installation guidance disclose this boundary.

The output contains the canonical versioned bundle basename, canonical native installer basename, `profile-linux-auto.toml`, `SHA256SUMS.txt` over the staged input bytes and installation guidance. No existing output is replaced. The existing parent of NEW_DIR must be current-user-owned mode0700; recipe cwd has no such requirement. Insecure parent refuses without chmod. Input/output scopes cannot overlap.

The first actual producer gate was RED: four INIT tests passed, producer failed before staging because Windows-only `OwnedDirectory` creation returns Unsupported on Linux. This is retained in `kit-build-public-runtime-r1.log`, not a Cargo/runtime setup error or a passing install. Architect independently reproduced it and authorized the existing Linux checked-move owner instead.

The correction creates an exclusive private stage under that held trusted parent, observes all expected names and full stable file bytes, uses existing `Pinned::retire_directory_noreplace_to` only to publish the producer-owned stage, and rechecks final directory identity, names and bytes. The syscall refuses unsupported filesystems rather than falling back to replacing rename. Publication authority comes from explicit kit build, not retirement/cleanup policy. Source identity is checked before/after, not atomically compared against a hostile same-user replacement. No new unsafe code, generic Windows lease port, cleanup permission, cross-platform claim or crash-recovery guarantee is introduced. Uncertain/failed stages remain preserved for inspection.

The actual fixture builds a valid synthetic distribution containing the exact current CLI, synthetic companion/source data and the actual separately built native installer. Only the produced output is then consumed: native dry-run and actual installation are separate assertions. Missing/corrupt/version-mismatched inputs, output collision, overlap and unsuitable parent controls are included. The synthetic companions are not native agent/provider functionality. The preceding r2 attempt refused the fixture's non-private default temp parent; the fixture was corrected to explicitly request mode0700, without weakening the product guard.
