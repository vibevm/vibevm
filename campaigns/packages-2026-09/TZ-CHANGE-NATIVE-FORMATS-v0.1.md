переезжает в спеки, план удаляется). **Контракт, который этот план строит:**

опубликованы наружу на миллионы людей. Эволюция максимально быстрая — мы ещё

Подход с serde ужасен и не похож на фундаментальное решение для вечноменяющейся
среды. Нужно: а) документ с идеологией; б) конкретное решение по пакетам и

**Кто исполняет.** Рассчитано на агента слабее автора: каждая фаза несёт точные

## 1. Решения (РЕШЕНО здесь; исполнитель не переоткрывает)

Каждое — с отвергнутыми вариантами и условием пересмотра.

**D1. Архитектура — «одноразовые миры» (PROP-044).** Истина = исходники
пакетов + журнал фактов реестра; всё опубликованное производно и
восстановимо; вечен один хэндшейк. *Отвергнуто:* «вечная линия под машинным
надзором» (Protobuf/Buf-модель) — делает совместимость вечным налогом на
дизайн и слепа к смысловым переломам; «неизменяемый гербарий» (Nix-модель) —
решает 10% задачи и выталкивает агрегаты в неуправляемый слой; «формат как
программа» (данные несут ридер) — поверхность атаки и нестатическая
проверяемость. *Пересмотр:* если тест восстановления невозможно удержать
зелёным (см. риск в PROP-044 §9), архитектура деградирует — остановка,
доклад владельцу.

**D2. Объединение `RepomdFileEntry` становится симметрично тегированным
СЕЙЧАС.** Форма A: `#[serde(tag = "kind", rename_all = "lowercase")]`, оба
плеча несут `kind`. Ломающее изменение провода — бесплатно при нуле
потребителей; разблокирует генерацию (B11). *Отвергнуто:* оставить untagged
(вечно блокирует схему; молча глотает добавленные поля — единственный тип
каталога с этим свойством); adjacently-tagged форма D (`content`-обёртка) —
дороже байтами, а рост числа плеч не ожидается. *Пересмотр:* не предусмотрен.

**D3. Read-modify-write умирает: журнал + проекция.** Мутации сервера и CLI
— дозапись события в журнал фактов, затем перепроекция каталога целиком.
Писатель не принимает на вход типы, прочитанные из собственного каталога.
*Отвергнуто:* «терпимость + захват незнакомого» (`flatten extra`) — лечит
симптом и делает возврат RMW комфортным; статус-кво (строгий RMW) — это
источник половины дефектов базовой линии (B3, B5, B6). *Гейт:* фаза 0
меряет объём переделки (M-RMW ниже); если > бюджета — СТОП-ВЛАДЕЛЕЦ с
задокументированным запасным путём (временный захват на трёх RMW-типах,
явно помеченный как компромисс). *Пересмотр:* по результату M-RMW.

**D4. Свой слой генерации `vibe-wire-gen`.** Постпроцессор/замена
jtd-codegen, эмитящий политику: открытые словари `Unknown(String)`,
детерминизм-дружественные типы, политику пропуска пустого, строгость по
роли, snake_case. *Отвергнуто:* голый jtd-codegen (B11 — не умеет политику);
ручной serde (запрещён PROP-044 законом 5); смена языка схем на JSON
Schema/CUE (JTD выбран за бедность — агент не может выразить опасное; вся
выразительность — в нашем генераторе). *Пересмотр:* если PoC генератора
(фаза 0) обнаружит непроходимое — доклад.

**D5. Эпоха в `vibe.toml` — немедленно.** Поле `epoch = 1` в `[package]`
(u32). Отсутствие = состояние «до эпох» (НЕ «эпоха 1»): читается как
сегодняшний формат, помечается в диагностике. Новые манифесты получают поле
через `vibe init`/шаблоны; массовой правки 172 файлов НЕ делается (кодмод —
поздняя волна). *Отвергнуто:* «отсутствие = 1» (стирает различие «старый»
против «чужой/битый» — довод G4-разбора); обязательность на чтении
(уронит все существующие манифесты). *Пересмотр:* не предусмотрен.

**D6. Идентичность рецепта у `content_hash`.** Формат значения:
`sha256-tree/1:<hex>`; рецепт №1 (список исключений, нормализация путей,
порядок обхода) — данные в `formats/hash_recipes/1.toml`; обе копии
алгоритма читают рецепт из данных; golden-тест на образцовом дереве
замораживает пару (рецепт → хэш). Старые значения `sha256:<hex>` читаются
как рецепт 0 (легаси, замороженный). *Отвергнуто:* оставить константу
(смена списка тихо меняет каждый хэш в мире — запрещено законом «не врать»);
отдельное поле `hash_algo` рядом (две графы там, где хватает префикса).
*Пересмотр:* не предусмотрен.

**D7. Слоты must-understand / подписи / yank — в схему записи сейчас,
криптография — НЕТ.** Поля: `must_understand: []` (список строк-возможностей),
`yanked: bool` (+ `tombstone: {reason, superseded_by?}` на уровне имени),
резерв под `signature`. Безопасность запаркована владельцем (B-015) — только
слоты. *Отвергнуто:* отложить слоты «до надобности» — их окно закрывается
первой публикацией (терпимый читатель, молча глотающий будущее поле подписи,
= downgrade-атака). *Пересмотр:* уведомление владельца по B-015.

**D8. Хэндшейк `hello.json`.** Корень индекса; ключи:
`{vibe: <строка-версия формата хэндшейка>, worlds: [{epoch, path, sunset?}],
min_client?, notice?, successor?}`. Вечный файл, читается максимально
терпимо. Первая реализация вырожденная: один мир, без параллельной
публикации. *Отвергнуто:* версия-в-пути без хэндшейка (клиент без
входной точки не узнаёт о переезде — транспорт без редиректов); HTTP-заголовки
(транспорт — сырые файлы). *Пересмотр:* первый настоящий поезд эпох.

**D9. `vibe.lock` — молчаливая перегенерация.** Несовпадение (эпоха, хэш
генератора, id рецептов) → пересобрать без вопросов; `--locked` → громкий
отказ (CI). Флаг называется `--locked`, НЕ `--frozen`: слово «frozen»
принадлежит пакетам (D14; «snapshot» — его антоним, PROP-044 §2b). *Отвергнуто:* сегодняшний отказ по `!=` (лишний
вопрос пользователю про черновик). *Пересмотр:* не предусмотрен.

**D10. Конфиги: `fn load() -> Config` без `Result`.** Незнакомый ключ —
предупреждение; кривое значение — умолчание + предупреждение. *Отвергнуто:*
строгий отказ (блокировать работу из-за устаревшей настройки при 10 релизах
в день). *Пересмотр:* не предусмотрен. (Отдельная фаза не выделяется —
применяется при первом же касании `vibe-settings` любой волной.)

**D11. Наблюдаемость сервера: подписчик трассировки ставится ВСЕГДА**
(уровень по умолчанию warn, `--log-level` для операторов). Причина: карантин
записей (D3/PROP-044 §4.5) обязан быть виден оператору; лог, существующий
только под флагом автопубликации, — случайная связь (вопрос владельца №3,
`BACKLOG.md` B-071). **РЕШЕНО владельцем 2026-08-13: уровень по умолчанию —
warn; СТОП снят.** *Отвергнуто:* статус-кво (события формируются и
выбрасываются). 

**D12. Узкая публичная проекция, сгенерированные клиенты, кодмод-бот,
репетиции заката — НЕ в этом ТЗ.** Это волна 3 PROP-044; отложено поимённо
(закон: отложенное живёт в плане, не в воздухе). *Пересмотр:* после приёмки
этого ТЗ.

**D13. Допубликационный режим (рулинг владельца 2026-08-10; контракт —
PROP-044 `##THE-PUBLIC-SWITCH`).** До объявления владельцем «первое
представление публике состоялось»: **миграции не применяются вовсе** (ни
кодмодов, ни бот-PR — при переломе манифеста наши 44 авторских файла просто
правятся массово на месте); `formats/EPOCHS.toml` несёт `public = false`
(строку меняет только владелец); пока `false` — окно перелома всегда открыто,
`wire-diff` перегенерирует корпуса и ЗАПИСЫВАЕТ изменение, но записки не
требует (Ф5.2 в этом режиме — отчётный, не блокирующий), календари заката и
параллельные миры не существуют, ридер №0 из Б.4 — удобство, а не
обязательство (его можно удалить, поправив файлы). Факт первого показа
**не выводится из технических событий** — этот план не содержит и не смеет
содержать детектора публикации. *Отвергнуто:* «наполнение дефолтного реестра
= публикация де-факто» — прежняя трактовка снята рулингом. *Пересмотр:*
слово владельца, и только оно.

**D14. Замороженность — флаг манифеста, односторонний; поверхности обязаны
её показывать (рулинги владельца 2026-08-10; контракт — PROP-044
`##THE-FREEZE-MODEL`).** `frozen: bool` в `[package]`, отсутствие = `false`
(**snapshot** — сегодняшняя практика разработки становится легальной
навсегда, B-067 растворяется; терминология PROP-044 §2b: snapshot ↔ frozen —
антонимы, «канал» — отдельная ось указателей PROP-005 §2.18). Фриз — правка автора `frozen = true`:
однонаправленная, внутри хэшируемого содержимого; реестры пишут НАБЛЮДЕНИЕ
в журнал (`Frozen`-событие) и проецируют флаг в каталог. Семантика
несовпадения хэша раскалывается: замороженная координата — тревога;
snapshot — «приехало новое», локфайл для snapshot пинит хэш доставленного
содержимого + локатор.
Конфликт «одна координата, разные байты, кто-то заявляет frozen» — громкий
отказ через машинерию кандидатов. **Обязательство поверхностей:** каждая
поверхность, показывающая версию, показывает статус — machine-JSON несёт
поле по схеме (автоматически из Ф4), человеческие поверхности рендерят
всегда; периметр: `vibe list/show/tree/search/outdated`, план и отчёты
install, MCP-инструменты (`query`/`select`/`explain`/`query_package`), TUI,
HTTP-ответы сервера, узкая проекция. Слот `frozen` едет в волну 0 (Ф1.4) —
задним числом не внедряется: старый читатель без поля счёл бы snapshot
замороженным и уверенно кэшировал протухшее. *Отвергнуто:* носитель в
имени версии (Maven-SNAPSHOT-стиль) — склеивает две ортогональные оси и
делает невыразимой замороженную бету; носитель только в журнале —
журнал пер-реестровый, мнения реестров могли бы расходиться, а посетитель
репозитория пакета флага бы не видел. **РЕШЕНО владельцем 2026-08-13 (СТОП снят): умолчание резолвера не
различает frozen/snapshot — берётся STABLE, если есть (даже незамороженный),
иначе LATEST; ось выбора отделена от оси целостности (после выбора пин хэша
в локфайле, несовпадение — по семантике выше). Контракт: PROP-005 §2.18
`##RESOLVER-DEFAULT-IS-STABLE-THEN-LATEST`.** *Пересмотр:* не предусмотрен.

**Карта на пять вопросов владельца:** №1 (формат каталога) — решается этим
ТЗ целиком; №2 (недетерминированная запись) — растворяется фазами 2–3 (B6);
№3 (логи сервера) — D11; №4 (планка доказательства) и №5 (соединение
движков) — НЕ трогаются, остаются владельцу.

**Р1. Форма `yanked` / `frozen` в записи — `bool` плюс именованный предикат.**
Полей типа `bool` во всём `crates/vibe-index/src/types/` НЕТ ни одного: готовой
формы не существует, её заводят осознанно. Домашнее правило дерева — «всякая
опциональность записи есть пара `default` + `skip_serializing_if`» (35 полей,
ни одного `default` без парного skip). Значит `#[serde(default,
skip_serializing_if = "…is_false")] pub yanked: bool` с одной маленькой
свободной функцией `is_false(&bool) -> bool` рядом с типами — домашний стиль
это ИМЕНОВАННЫЙ предикат (`CompatibilityEntry::is_empty`), а не выражение по
месту. *Отвергнуто:* `bool` без атрибутов, сериализуемый всегда — ломает
домашнее правило и платит байтами на каждой записи за подавляющий общий случай.
*Отвергнуто:* `Option<bool>` под готовый `Option::is_none` — форма нашлась бы
даром, ценой третьего состояния у факта, который PROP-044 §2b объявляет **одной
булевой осью без третьего состояния**; отсутствие поля УЖЕ значит `false`.
**Манифестная половина — та же форма, и это исправление плана, а не
асимметрия.** Текст шага Ф1.4 выше называет `frozen: Option<bool>`; проза
решения D14 называет `frozen: bool`, отсутствие = `false`. Дерево разрешает спор
в пользу D14: у `PackageMeta` УЖЕ есть bool-поля (`bridge`), и у файла УЖЕ есть
ровно этот помощник — `fn is_false(b: &bool) -> bool`
(`crates/vibe-core/src/manifest/package.rs:139-142`). Значит манифестная сторона
— `#[serde(default, skip_serializing_if = "is_false")] pub frozen: bool` с
переиспользованием существующего помощника, а `Option<bool>` снимается как
выброс. Довод «Option сохранит различие „автор написал `false`“ против „не
написал ничего“» не держится: манифест правится документом на месте (закон
кодмодов, PROP-044 §5), а не сериализацией из структуры, поэтому serde этого
различия и так не носит. Один идиом на обеих сторонах, третьего состояния нет
нигде. **Бюджет:** `package.rs` — 572 строки при бюджете 600; поле с честным
доком помещается, но запаса ~28 строк. Если правка переваливает 600 — раскол по
шву `package/<тема>.rs` (домашний образец: файл уже держит десять таких
подмодулей), а НЕ ужатие дока под бюджет.

**Р2. `must_understand` — фильтр над разобранными записями, не в парсере.**
`Index::load_from` собирает RAM-копию **из by-name файлов** и `primary.jsonl`
при загрузке не читает вовсе (`index/memory.rs:262-281`); единственный готовый
цикл «по одной записи» живёт в `primary::parse` (`index/primary.rs:88`), то есть
пропуск, встроенный туда, сторожил бы путь, которым никто не грузит — ровно та
болезнь, которую §8 запускаторов называет «фикстура, которая не может упасть».
Второе наблюдение снимает мнимую сложность: `must_understand` — поле, которое
ЭТОТ шаг и заводит, поэтому наш читатель разбирает его штатно, а незнакомой
является **строка-значение внутри известного поля**, а не незнакомое поле; ни
`deny_unknown_fields`, ни терпимый предразбор тут ни при чём. **Решение:**
фильтр стоит в единственной точке, где записи становятся состоянием в памяти —
цикл разворачивания в `Index::load_from` (`memory.rs:266-271`); парсеры
остаются чистыми «байты → типы». Набор понятных читателю возможностей заводится
ПУСТОЙ константой в новом файле с доком «растёт по мере постройки
возможностей»; имя набора — `reader_capabilities`, НЕ `capabilities`: слово
«capabilities» в этом дереве уже занято тем, что пакет ПРЕДОСТАВЛЯЕТ
(`provides.capabilities`, `cli/capabilities.rs`), и второй смысл под тем же
голым словом — ровно та коллизия, которую запрещает дисциплина именования.
*Отвергнуто:* фильтр в `primary::parse`; фильтр внутри `by_name::parse`
(мешает политику в парсер и требует предразбора, который здесь не нужен).

**Р3. Пропуск не молчит, и его форму выбирают, а не копируют.** Замер нашёл,
что «неполадка, которая не ошибка» выражается в этом крейте вообще не
макросом: сканер собирает структурные заметки о пропусках и отдаёт их
вызывающему (`scanner/org_walk.rs:55-60`). Прецедента «warn из пути загрузки,
видимый в CLI» в дереве НЕТ: подписчик трассировки ставится ровно дважды во
всём `crates/`, и в `vibe-index` он привязан к флагу `--auto-commit-push`
(`cli/serve.rs:67-73`), а не к чтению — код прямо это и декларирует. Решение
трёхчастное: *(i)* носитель — тот, что уже назван **Приложением А.7 этого же
плана**: `Index.quarantined: Vec<Quarantined>` в память при загрузке, в файлы
НЕ пишется; Ф6.2 достраивает на нём ОТВЕТ (`unavailable {…, recipe}`), а не
носитель; *(ii)* человеческая поверхность — `tracing::warn!` из пути чтения;
*(iii)* и чтобы *(ii)* не оказалось предупреждением, которого никто не увидит,
подписчик ставится **безусловно** в `crates/vibe-index/src/main.rs` в форме,
уже доказанной в `crates/vibe-cli/src/main.rs:408-417` (EnvFilter `VIBE_LOG`,
дефолт `warn`, writer stderr), а флаго-зависимая установка в `serve.rs`
удаляется вместе с комментарием, который после этого лгал бы. Это досрочная
выдача части решения D11 — оно уже РЕШЕНО («подписчик ставится ВСЕГДА, уровень
warn»), и данный шаг первым порождает предупреждение, чей смысл — быть
увиденным. *Отвергнуто:* отложить подписчика до Ф6.2 (шаг отгрузил бы обещание
вместо поведения: его собственная приёмка «пропускается с предупреждением»

**Ф2.3 — Идемпотентный upsert. СЕЛА 2026-08-14 — ФАЗА 2 ЗАКРЫТА.**

*Поправка по существу, а не по координате: «пустой diff» оказался недостижимой
формулировкой.* После Ф2.1 часы приходят на СОБЫТИЕ мутации, поэтому у
повторного upsert'а они другие, `generated_at` сдвигается и diff всё равно
получается непустым. Пустой diff не нужно получать — нужно **не создавать
работу**: мутация, ничего не изменившая, не доходит ни до писателя, ни до
публикатора. Форма: `Index::upsert` возвращает «изменилось ли», сравнивая
ЗНАЧЕНИЕ записи целиком, а не номер версии (сравнение по номеру молча теряло бы
настоящие обновления); три серверные мутации приведены к одной форме — причём
приведён к ней был upsert, потому что оба пути удаления так вели себя всегда.
HTTP-семантика не сдвинулась: повтор отвечает успехом, различие
created/changed сохранено. Счётчик мутаций тоже ушёл под условие — счётчик
считает мутации, а no-op не мутация. Спека: факт
`##AUTO-PUBLISH-EVERY-MUTATION-COMMITS-EVEN-A-NO-OP` выведен из строя
надгробием (обе описанные им половины устранены), наследник —
`##A-MUTATION-THAT-CHANGES-NOTHING-COMMITS-NOTHING`.

Повторная идентичная мутация → пустой
diff → авто-коммит не создаётся (`AUTO-PUBLISH-AN-EMPTY-DIFF-IS-SUCCESS`
уже есть — теперь он срабатывает и на редундантном upsert'е, не только на
гонке). Приёмка: тест в `auto_publish.rs`: дважды один upsert → один коммит.

этого же ТЗ реплеит журнал ЦЕЛИКОМ, объявляя инкрементальную перепроекцию
поздней оптимизацией. Значит у персистентного курсора сегодня нет читателя, а
курсор, который никто не проверяет, — состояние, дрейфующее незамеченным. Дом
курсора — первая инкрементальная перепроекция, где его правильность вообще можно
испытать; там же ему нужен и тест.

**(iii) Событий в enum одиннадцать, а не девять: добавлены `Initialised` и
`EntrySetReplaced`** — носители рулингов Ж1 и Ж5/Ж6 соответственно. Приложение
А.2 их не называло, потому что писалось до замера.

**(iv) `Published` несёт БОКСИРОВАННУЮ запись, и на проводе это не видно.**
Поймано clippy (`large_enum_variant`) в боссовом хвосте: запись каталога — около
900 байт против единиц у любого другого варианта, а `replay` отдаёт
`Vec<JournalRecord>`, где каждый элемент резервировал бы ширину самого крупного
варианта независимо от того, какой факт он несёт. `serde` рендерит `Box<T>` ровно
как `T`, поэтому форма NDJSON не сдвинулась ни на байт. Причина вписана в тип, а
не оставлена в коммите.

*Операционная заметка, стоящая записи: воркер, строивший этот шаг, был срезан
внешне на шаге 6/8 — до финального прогона, до двух красных доказательств и до
отчёта. Работа при этом оказалась по сути готовой. Статус «killed» не был принят
за вердикт: worktree прочитан первым, красные доказательства и `clippy` добраны
боссом, и именно `clippy` — шаг, которого срез лишил, — нашёл (iv).*

**Ф3.2 — Проектор.** `Index::project(events) -> Index` — чистая функция;
`write_to` вызывается только над результатом проекции. Серверные мутации:
валидация входа → append в журнал → replay хвоста → write_to(at=событие).
`add`/`remove` CLI — те же события. `reindex`/`rescan-org` — источник
событий `published` из сканера (сканер остаётся как есть). Правило G4
механически: типы из `index_client`/чтения каталога не появляются в
сигнатурах писателей (arch-тест: грубый grep-гейт по импортам модулей
`journal|projector`, шаг self-check). Приёмка: `xtask rebuild --check` —
новый xtask: снести каталог, спроецировать из журнала, сравнить байты
(на герметичной фикстуре); шесть RMW-путей из B3 не читают каталог
(грep-доказательство: `load_from` остаётся только в путях чтения/serve-старте
для ОБСЛУЖИВАНИЯ чтения, не как вход мутации).

*Разбиение Ф3.2 на четыре шага (решение босса 2026-08-14 по замеру
[`harvest/f32-projector-surface.md`](harvest/f32-projector-surface.md)).* Текст
выше описывает Ф3.2 как один шаг; замер показал, что он несёт предусловие,
которого план не видел, и зависимость, которой нет ни у одного существующего
проверочного глагола. Каждый подшаг — отдельный коммит, порядок жёсткий:

- **Ф3.2a — `init` кладёт первую запись журнала.** Разрыв измерен: `Initialised`
  документирован как первая запись `init`, а слова `journal` в `cli/init.rs` нет
  вовсе. Без этого `rebuild --check` провалился бы не из-за дефекта, а из-за
  незаполненного шва. **Правда пишется ПЕРВОЙ**: у порядка «журнал → каталог»
  отказ восстановим (правда цела, каталог достраивается повтором), у обратного —
  нет, и это ровно
  [`##LAW-NO-UNRECOVERABLE`](../../spec/common/PROP-044-change-native-formats.md#laws).
  Сквозной транзакции в дереве не существует; консистентность даётся ПОРЯДКОМ,
  как её даёт `write_to`, штампуя манифест последним.
- **Ф3.2b — сам проектор** `project(events) -> Index`, чистая функция.
  Свёртка дубликата `Initialised` — «последняя запись выигрывает»: повторный
  `init --force` над живым журналом законно допишет вторую идентичность (guard
  смотрит только `repomd`, а у append-only журнала сброса нет), и подавлять этот
  факт писателю не положено — сворачивает его читатель. Прецедент формы в дереве
  есть: `progress-core` так сворачивает `Phase`.
- **Ф3.2c — переделка шести мутаций** на `validate → append → project(replay) →
  write_to`.
- **Ф3.2d — `xtask rebuild --check`.** Отдельным шагом, потому что он тянет то,
  чего не требовал ни один из пяти существующих проверочных глаголов:
  `xtask` не зависит НИ ОТ ОДНОГО продуктового крейта, а `vibe-index` отсутствует
  и в `[workspace.dependencies]` — подключение трогает два манифеста. Форма
  сравнения берётся у `sync-engines --check` (сравнивает сам, в процессе), а не у
  `check-codegen` (делегирует `git diff`): каталог данных не git-трекаем — журнал
  по умолчанию живёт под gitignored `state/`.

**Ф3.3 — Строгость читателя падает бесплатно.** Снять
`deny_unknown_fields` с типов каталога (15 мест B1) — теперь это безопасно:
прочитанное никогда не переписывается. Клиентские view (`wire.rs`) не
меняются. Приёмка: тест «каталог с незнакомым полем читается; запись из
журнала его не уносит, потому что запись не из чтения»; панель зелёная.

*Перед нарезкой дерево измерено тремя read-only пакетами (2026-08-14):
[`harvest/f3-index-state-and-projection.md`](harvest/f3-index-state-and-projection.md),
[`harvest/f3-journal-physics.md`](harvest/f3-journal-physics.md),
[`harvest/f3-rmw-break-and-reset.md`](harvest/f3-rmw-break-and-reset.md).
Замеры опровергли две записанные посылки этой секции и открыли четыре развилки.
Решения ниже приняты БОССОМ; исполнитель их НЕ переоткрывает. Одна развилка
остаётся владельцу и помечена СТОП-ВЛАДЕЛЕЦ.*

**Ж1. Идентичность реестра входит в журнал событием инициализации — и это
следствие, а не вкус.** Пять величин (`registry`, `registry_url`, `naming`,
`generator`, `schema_version`) сегодня приходят в мутацию только из
`repomd.json` через `load_from`. Проектор их из событий не соберёт: в
`VersionEntry` есть лишь `registry`, остальных нет нигде. Довод, закрывающий
вопрос, — **приёмка самой Ф3.2**: `xtask rebuild --check` сносит каталог и
проецирует из журнала. Если идентичность живёт только в `repomd.json`, то после
сноса её взять неоткуда — то есть каталог оказывается ЕДИНСТВЕННЫМ носителем
факта, что прямо запрещено
[`##FORBID-SECRET-TRUTH`](../../spec/common/PROP-044-change-native-formats.md#laws)
(«авторитетный факт, живущий только в производном артефакте»). Значит `init`
пишет первую запись журнала — событие инициализации реестра, — а проектор
сворачивает её правилом «последнее событие выигрывает». *Отвергнуто:* аргумент
проекции из флагов/конфига — у CLI-мутаций и у `serve` таких флагов нет, а
заведение второго источника истины рядом с журналом воспроизводит ту же болезнь
на этаж выше; *отвергнуто:* читать `repomd.json` в мутации — это ровно тот
read-modify-write, ради смерти которого фаза существует (D3, PROP-044 §4.4).

**Ж2. Версию схемы каталога проектор штампует СВОЮ — и факт Ф2.2 получает
клаузу, а не исключение.** Ф2.2 запрещает писателю затирать версию, которую он
ПРОЧИТАЛ. Под журналом читать нечего: проекция рождает каталог с нуля из
событий, и её собственная версия — правда о том, кем этот файл написан. Ложью
Ф2.2 было «файл на диске версии N, мы переписали его содержимое и объявили
версию 1»; здесь содержимое построено нашим кодом, и наша метка честна.
Безопасность при этом не исчезает, а переезжает этажом выше: журнал, написанный
более новым бинарём, отсекается эпохой журнала и `must_understand` записи
(PROP-044 §4.5), а не меткой каталога. Спек-дифф Ф3 обязан дописать эту клаузу к
`##THE-WRITER-KEEPS-THE-VERSION-IT-READ`, иначе факт будет читаться как
опровергнутый. *Отвергнуто:* нести версию каталога отдельным событием — это
делает версию ФОРМАТА состоянием ДАННЫХ, то есть путает две оси; *отвергнуто:*
молча оставить противоречие — факт без клаузы читается следующей сессией как
дрейф.

**Ж3. Журнал живёт по пути-входу, умолчание — `<data-dir>/state/journal/`.**
Замер физики закрыл вопрос числами: `commit_and_push` делает `git add -A` из
корня data-dir (`crates/vibe-index/src/publish.rs:78`), а единственное правило
`.gitignore`, которое пишет `init`, — `/state/`
(`crates/vibe-index/src/cli/init.rs:77`). Значит `journal/` рядом с проекцией
уезжает клиентам тем же коммитом — прямое нарушение рулинга 2026-08-13; а под
`state/` закрыты все три клиентские двери (git, карта `repomd::files`, шесть
HTTP-маршрутов), и НИ ОДИН существующий тест от этого не краснеет. Путь при
этом остаётся **входом**, а не константой: рулинг сам предписывает для
публичного деплоя отдельный репозиторий, и захардкоженный каталог был бы ровно
той случайностью, которую директива усилий запрещает. *Отвергнуто:*
`<data-dir>/journal/` (уезжает клиентам); *отвергнуто:* хардкод `state/journal/`
без входа (делает предписанную рулингом публичную форму недостижимой из кода).

**Ж4. Публикация журнала через git-CAS в Ф3 НЕ строится — именованный дефер.**
Цикл «push только fast-forward; проигравший re-fetch → повтор append в хвост →
push» сегодня не реализован ни одной строкой: во всём `vibe-index` нет ни одного
`git fetch`/`git pull`, а отказ push лечится warn-ом и счётчиком без повтора
(`crates/vibe-index/src/server/routes/packages.rs:418-425`). Строить его сейчас
значит строить механизм под потребителя, которого нет: публичного деплоя не
существует, и его наступление — слово владельца (D13), а не техническое
событие. *Триггер постройки:* объявление владельцем первого показа публике ЛИБО
появление второго писателя одного журнала — что наступит раньше.

**Ж5. Сброс есть ЗАПИСЬ-ВОДОРАЗДЕЛ, и он никогда не усекает журнал.** Журнал —
append-only истина (PROP-044 §3); усечение уничтожает её и нарушает
[`##LAW-NO-UNRECOVERABLE`](../../spec/common/PROP-044-change-native-formats.md#laws).
Значит `--full` дозаписывает событие-водораздел, после которого реплей начинает
свёртку с пустого множества записей; события до него остаются в файлах и
остаются читаемыми — просто перестают вносить вклад. Шардирование от этого не
меняется (водораздел — обычная строка), `journal/checkpoint.json` сохраняет
смысл курсора проектора. *Отвергнуто:* физическое усечение/архивация (уничтожает
истину); *отвергнуто:* компенсирующие `Removed` на каждую исчезнувшую запись —
они утверждали бы АКТ удаления, которого никто не совершал, и раздували бы
журнал на O(n) лжи.

**Ж6. Водораздел сбрасывает только то, что скан способен воспроизвести.**
Надгробия, отзывы, заморозки и уведомления — факты реестра, а не продукт скана:
пересканирование их не восстановит, поэтому сброс, уносящий их, делает состояние
невосстановимым — тот же запрет, что в Ж5. Значит водораздел очищает множество
опубликованных ЗАПИСЕЙ и не трогает журнальные факты, которые проектор применяет
поверх из всего журнала. Это же снимает мину Ф1.4 «полный reindex стирает
надгробия» — и снимает её ШИРЕ, чем она была записана: замер показал, что
инкрементальный reindex стирает их точно так же (оба строят свежий `Index::new`
и переносят только `iter_versions()`), то есть дефер был назван у́же дефекта.

**Ж7. Карантин при проекции всегда пуст, и это не потеря.** Карантин возникает
только при ЧТЕНИИ чужого каталога читателем, которому не хватает возможностей;
журнал — наша истина, и отвергнутая запись в него не попадает. Носитель
`Index.quarantined` остаётся в памяти и наполняется только на пути чтения.

**СТОП-ВЛАДЕЛЕЦ (Ж8): что значит `--full` для записи, которую скан больше не
видит.** Сегодня она исчезает молча (`cli/reindex.rs:252-291`) — и это уже
нарушает [`##FORBID-SILENCE`](../../spec/common/PROP-044-change-native-formats.md#laws)
для имени, потерявшего все версии. Две прочтения защитимы, и законы их НЕ
разводят: *(а)* «скан есть полная правда» — исчезнувшее хоронится надгробием с
причиной «источник больше не отдаёт»; *(б)* «скан есть наблюдение» — запись
удерживается и помечается ненаблюдавшейся, потому что причиной пропуска бывает
сеть, лимит или отозванный доступ, а не удаление. Цена ошибки асимметрична и в
разные стороны: (а) хоронит живой пакет по сетевому сбою, (б) вечно держит
удалённый. Рядом стоит второй вопрос того же владельца: `rescan-org` объявлен
как обновление кэша организации, а идёт с `mode = "full"`
(`cli/rescan_org.rs:72`) — то есть глагол «обновить кэш» сегодня сбрасывает
каталог. Босс не выбирает: угадывание здесь и есть тот отказ, который PROP-044
запрещает. **Ф3 режется без этого решения** — водораздел (Ж5/Ж6) строится, а
семантика исчезнувшей записи остаётся сегодняшней до рулинга.

*(Если Ф0.1 сказал «не укладываемся» — вместо Ф3 исполняется задокументированный
запасной путь D3 и ТЗ возвращается владельцу на пересмотр объёма.)*

**Р1. Шаг Ф4.0 заводится ПЕРЕД всеми и садится отдельным коммитом.** Генератор
учится видеть схемы в подкаталогах и раскладывать выход ПО ПУТИ, а не по стему.
*Почему путь, а не плоская укладка:* каталог схемы несёт **эпоху**
(`schemas/index/e1/…`), и это требование
[`##M-EPOCHS`](../../spec/common/PROP-044-change-native-formats.md#machinery) —
тяжёлый перелом чеканит новый мир новым путём. Плоская укладка убила бы
механизм эпох ради удобства одного шага. *Почему не по стему:* `…/e1/entry` и
будущая `…/e2/entry` дают ОДИН стем — коллизия, которая проявилась бы ровно в
день первого настоящего поезда эпох, то есть позже всего. **Красное
доказательство — пункт приёмки:** схема, положенная в подкаталог, обязана быть
показана НЕВИДИМОЙ сегодняшним кодогеном (выход не появился, `check-codegen`
зелёный) и видимой после шага. *Отвергнуто:* класть схемы плоско (убивает
эпохи); чинить это внутри Ф4.1 (тогда шаг несёт две несвязанные причины и его
дифф нечитаем).

**Р2. Политику несёт СХЕМА, и молчание схемы — ошибка генерации.** Аннотации
в JTD `metadata` проверены прогоном: jtd-codegen принимает ключи `x-…` молча
(exit 0) и в Rust не переносит (спайк §4) — то есть канал есть, и читать его
обязан наш слой. Правило одно, а не четыре: **везде, где нужна политика, схема
её называет, и отсутствие аннотации — ошибка генерации** (эту форму А.5 №3 уже
требует для коллекций; здесь она распространяется на всё остальное):
`x-vocabulary: open|closed` на каждом `enum`; `x-empty: omit|emit` на каждой
коллекции; `x-default: <литерал>` на каждом опциональном скаляре;
`x-rust-type: "<путь>"` там, где строка на проводе есть доменный тип в коде.
*Отвергнуто:* выводить политику из формы (закрытость enum'а не отличает
`PackageKind` от `NamingConvention` — измерено); умолчание «открыто, если не
сказано» (умолчание, которого автор схемы не видел, и есть та случайность,
которую запрещает директива усилий).

**Р3. Доменные типы СОХРАНЯЮТСЯ — генератор эмитит их по `x-rust-type`.**
*Почему:* генератор, чей выход строго хуже заменяемого им рукописного кода, —
не фундамент, а понижение, надетое на автоматизацию. Замена `Group` и
`semver::Version` на `String` сняла бы ровно ту типизацию, ради которой эти
newtype'ы заведены. *Отвергнуто:* оставить `String` и конвертировать на
границе — это прослойка совместимости между проводом и доменом, а прослойки
запрещены
[`##MIGRATION-TAXONOMY`](../../spec/common/PROP-044-change-native-formats.md#placement);
*отвергнуто:* двинуть дерево на `String` (регресс качества ради удобства
генератора). *Пересмотр:* если окажется, что доменный тип не выразим ссылкой
(например, требует дженерика) — доклад, а не молчаливый `String`.

**Р4. `Event` журнала становится СГЕНЕРИРОВАННЫМ, и его плечи `match`
переписываются тем же шагом.** *Почему:* иначе `journal.jtd.json` описывает
формат, чьи типы живут отдельно, и G9 («словарь существует ровно в одной
схеме») держится процедурой, а не машиной — а весь смысл фазы в том, чтобы
перестать держать законы процедурой. При Р2+Р3+Р5 сгенерированный `Event`
эквивалентен рукописному по типам и по проводу. *Цена, названная заранее:*
варианты выходят newtype'ами (`Published(EventPublished)`) вместо структурных
(`Published { entry }`) — на проводе то же самое, в Rust меняется КАЖДОЕ плечо
`match` в проекторе; это механическая правка, входящая в периметр шага.
*Отвергнуто:* оставить `Event` рукописным и внести его в белый список Ф4.3 —
это исключение на САМОМ НОВОМ формате дерева, то есть правило, рождающееся уже
с дырой.

**Р5. Преобразований у генератора СЕМЬ, а не четыре** (Приложение А.5
дополняется; порядок сохраняется):
1. закрытый enum → открытый — **по `x-vocabulary`, а не по факту закрытости**;
2. camelCase → snake_case (снимает `#![allow(non_snake_case)]` в обоих
   потребителях: `crates/vibe-wire/src/lib.rs:52` и одноимённый в engine-крейте);
3. политика пустого по `x-empty`;
4. `deny_unknown_fields` по реестру (`foreign_parsers = "none"`);
5. **`Option<Box<скаляр>>` → `скаляр` + `default` + именованный предикат** по
   `x-default` — иначе двухсоставная ось получает третье состояние; заодно
   снимается бессмысленный `Box` у скаляров;
6. **`DateTime<FixedOffset>` → `DateTime<Utc>`**;
7. **боксирование крупного варианта объединения** — измерено прогоном: на
   нагрузке настоящего размера clippy падает `large_enum_variant` и сам
   предлагает `Box`, а сгенерированный файл руками не правят.
   *Отвергнуто:* `#![allow(clippy::large_enum_variant)]` в сгенерированном
   модуле — подавление линта, который в этом дереве уже поймал реальный дефект
   (Ф3.1, вариант ~900 байт), и прецедента подавления в дереве нет.

**Р6. `xtask/src/codegen.rs` раскалывается в каталог-модуль ПЕРВЫМ делом Ф4.2.**
534 из 600 — постпроцессор «в несколько сотен строк» не влезает. Шов уже
готов: блок `format_id` (`:294-534`, ~240 строк). Прецедент формы в xtask есть
(`batch_review/`, `mirror/`). *Отвергнуто:* ужать постпроцессор под остаток в
66 строк (объём не довод — но и обратное верно: бюджет не повод писать хуже).

**Р7. Ф4.3 садится РЕХЕТОМ (К4), а «реестр + маркер» (К2) — именованный дефер.**
Правило белого списка существует и найдено — К2: файл с рукописным derive несёт
в себе тег формата, тег джойнится с `formats/REGISTRY.toml`, и если у записи
есть построенная JTD-схема, файл красный. Но К2 требует разовой волны
аннотирования всех 133 файлов, а Ф4.2 ровно эти файлы и мигрирует — аннотировать
их ДО миграции значит размечать то, что вот-вот изменится. Поэтому Ф4.3 ставит
рехет по крейтам против замороженной базовой линии (форма доказана соседом:
`conform-baseline.json` + шаг 5 панели): красный — любой рост счётчика.
Периметр гейта включает `xtask/` (иначе `xtask/src/sync_engines.rs` — тот самый
70-й файл — выпадает из гейта, который для него и существует).
*Триггер К2:* посадка Ф4.2, после которой мигрированные эмиттеры перестают
нести рукописный derive. *Отвергнуто:* К1 «по путям» — перечисление, надетое на
имена каталогов; К3 «по крейту-владельцу» — опирается на поле `owner`, которого
в реестре НЕТ (запись несёт шесть ключей: `corpus`, `epoch`, `foreign_parsers`,
`recoverable`, `schema`, `sunset`).

**Р8. Словарь живёт в ОДНОМ документе-словнике, и подстановку делает наш слой
ДО вызова jtd-codegen.** Замер 2026-08-15 нашёл, что G9 нарушен уже сегодня:
`package_kind` записан дословно в `schemas/list_report.jtd.json` и
`schemas/registry_sync_report.jtd.json`, то есть `entry.jtd.json` стала бы
ТРЕТЬЕЙ копией, а не первым нарушением. Починить это средствами JTD нельзя:
форма `ref` разрешается только против `definitions` того же документа —
межфайловых ссылок в языке нет (проверено прогоном). Значит разделение
словаря — восьмой механизм нашего слоя, ровно по букве PROP-044 §4.2 («что
язык схем выразить не может, эмитит наш генератор»): схема называет словарь
аннотацией `metadata."x-vocabulary-ref"`, слой подставляет определение из
одного словника. **Две сегодняшние копии уходят в ту же подстановку** — иначе
фаза закрывает G9 на новых форматах и оставляет открытым на старых. И
**валидацию ссылок слой делает САМ**: на висячей ссылке jtd-codegen не
отказывает, а ПАНИКУЕТ (`no entry found for key` + stack trace), то есть у
ошибки формы нет ни сообщения, ни рецепта — прямое противоречие
[`##AGENT-MESSAGES`](../../spec/common/PROP-044-change-native-formats.md#agents).
*Отвергнуто:* сложить все форматы в один JTD-документ ради общих
`definitions` — тогда путь схемы перестаёт нести эпоху (§4.6) и обесценивается
весь Ф4.0.

**Ф4.0 — Генератор видит подкаталоги (Р1). СЕЛА 2026-08-15** — три коммита:
`9c1ce20d` (раскол по шву `format_id`, чистый рефакторинг), `33b9ce59` (спуск
и зеркальный выход), `f1ba88e0` (отказ на сегменте, который не может быть
модулем). `schemas_under` стал рекурсивным и сортирующим; выход раскладывается
по относительному пути схемы; `mod.rs` синтезируется на КАЖДОМ уровне;
маршрут ключится ДОМОМ схемы, а не стемом; `generated_dir_for` удалена.

*Три поправки по факту исполнения — каждая меняет то, что следующий шаг
считает данностью.*

**(i) Маршрут по стему был вторым дефектом того же корня, и план его не
называл.** Схемы обоих домов сваливались в один плоский список, а дом, из
которого схема пришла, отбрасывался: вторая схема в engine-доме с любым
именем, кроме `specmap`, уехала бы в `vibe-wire`. Починено тем же шагом —
пары «дом → каталог выхода» стали явными.

**(ii) Молчание было и в сборе схем.** Прежний `filter_map(|e| e.ok())`
проглатывал ошибку обхода и отдавал пустой результат, который `check-codegen`
встретил бы зелёным, — ровно та болезнь, ради лечения которой шаг существует.
Ошибки теперь распространяются с контекстом.

**(iii) Имя схемы, не являющееся идентификатором Rust, роняло СБОРКУ ЧУЖОГО
КРЕЙТА, а не кодоген.** Найдено боссовой пробой: `by-cap.jtd.json` даёт
`pub mod by-cap;`, кодоген выходит с НУЛЁМ, а отказ приходит парсером в
`vibe-wire` — без имени схемы и без рецепта. По стему дефект существовал и до
фазы; каталоги его расширили, поэтому сторож лёг в шаг, который расширил.
Проверяется форма сегмента И **набор ключевых слов Rust** (`type`, `crate`,
`match` — слова, к которым автор схемы тянется естественно), отказ называет
схему, сегмент и переименование. Шесть будущих имён Ф4.1 (`entry`, `repomd`,
`by_name`, `by_cap`, `by_purl`, `journal`) закреплены тем же тестом как
законная сторона утверждения.

*Приёмка предъявлена обеими половинами.* Красное: тест спуска прогнан против
плоской реализации и показан упавшим (нашёл `a.jtd.json`, не нашёл
`sub/deep/b.jtd.json`). Зелёное: семь существующих целей не сдвинулись ни
байтом (`check-codegen: clean`), а проба `schemas/probe/e9/pathcheck.jtd.json`
легла в `generated/probe/e9/pathcheck/` с `mod.rs` на каждом уровне (проба
откачена). Панель — `self-check: all green`, реальный код выхода 0, 51 шаг.

**Р9. Ф4.1 режется НАДВОЕ, и порядок половин вынужденный.** Схема, ссылающаяся
на общий словарь, не может лечь раньше, чем ссылки заработают: `ref` на имя,
отсутствующее в локальных `definitions`, роняет jtd-codegen паникой. Значит:

- **Ф4.1a — словник и подстановка** (носитель Р8): `formats/vocabularies.json`,
  модуль подстановки в нашем слое, четыре именованных отказа вместо паники, и
  **две сегодняшние дублирующие схемы переводятся на словник тем же шагом**.
  Дом словника — `formats/`, а НЕ `schemas/`: сканер после Ф4.0 берёт
  `*.jtd.json` рекурсивно, и словник под `schemas/` генератор попытался бы
  собрать как отдельный формат.
- **Ф4.1a — СЕЛА 2026-08-15**, коммит `c7faa208`. Словник
  `formats/vocabularies.json`, модуль подстановки
  `xtask/src/codegen/vocabulary.rs`, четыре именованных отказа вместо паники
  бинаря, обе дублирующие схемы переведены. Решающее доказательство пришло
  зелёным: `check-codegen: clean` — схемы перестали дублировать словарь, а
  сгенерированный Rust побайтово тот же. Красное предъявлено на отказе по
  висячей `ref`. *Именованное следствие, а не дефект:* карта потеряла две
  записи (`list_report::package_kind`, `registry_sync_report::package_kind`) —
  специмап метит определения ВНУТРИ JTD-схем, а единственный дом словаря вне
  его периметра. Проба показала, что переименованием это не лечится (карта
  смотрит только в `schemas/`, а `check-codegen` от переименования падает —
  имя словника несущее). Починка требует тронуть движок дисциплины, что §2
  запрещает прямым текстом ⇒ **дефер по имени**.
- **Ф4.1a-2 — подстановка становится ТРАНЗИТИВНОЙ** (решение босса
  2026-08-15, до нарезки Ф4.1b). Разбор инвентаря показал то, чего план не
  видел: `by_name.jtd.json` и `journal.jtd.json` транзитивно содержат
  `VersionEntry` ЦЕЛИКОМ (`NameEntry` → `PackageEntry` → `VersionEntry`;
  `Event::Published { entry }`), а межфайловых ссылок JTD не имеет — значит
  тридцатиполевая структура с четырнадцатью вложенными типами была бы
  записана ТРИЖДЫ. Это болезнь G9 этажом выше: не словарь-строка, а составной
  фрагмент. Значит словник хранит и составные фрагменты, а запись словника
  вправе сама объявить `x-vocabularies` — резолвер замыкает набор транзитивно
  и отказывает на цикле. *Отвергнуто:* каждая схема перечисляет полное
  замыкание руками — это перечисление в другой одежде (тот же довод, которым
  отвергнут кандидат К1 в правиле белого списка): добавление поля, тянущего
  новый вложенный тип, потребовало бы править каждую схему, которая его
  тянет. *Отвергнуто:* оставить дублирование для составных и делить только
  словари-строки — тогда закон закрывается на дешёвом случае и открыт на
  дорогом.
  **Ф4.1a-2 СЕЛА 2026-08-15**, коммит `71e94e8f`. Замыкание транзитивно,
  цикл и самоссылка отказывают с называнием участников, недостающее имя
  называет ЦЕПОЧКУ, вставка отсортирована, `x-vocabularies` снимается с
  внедрённого фрагмента. Красное предъявлено полностью: все восемь новых
  тестов упали против непра́вленого резолвера. *Попутно найден живой дефект
  предыдущего шага:* проверка столкновения имён сравнивала с картой
  определений В ПРОЦЕССЕ заполнения, поэтому имя, названное в аннотации
  дважды, ложно срабатывало как столкновение с собственной вставкой
  подстановки; теперь снимок «своих» определений берётся до вставки.
- **Ф4.1b — шесть схем каталога** поверх работающей транзитивной подстановки.
  **Режется по два шага, и первый несёт метод проверки для всех остальных:**
  - **Ф4.1b-1 — запись версии и оракул.** `version_entry` со всем замыканием
    едет в словник (её транзитивно содержат ещё две схемы), а
    `schemas/index/e1/entry.jtd.json` — схема, чей КОРЕНЬ есть ссылка на
    фрагмент; форма проверена прогоном и даёт `pub type Entry = VersionEntry;`
    плюс саму структуру. **Сторож — дифференциальный оракул через ПРОВОД:**
    полностью заполненная рукописная запись → JSON → сгенерированный тип →
    JSON → равенство `Value`. Он и только он ловит пропущенное поле; сравнение
    идёт по проводу, а не по типам, потому что типы расходятся намеренно
    (`String` вместо `Group`, `Option<Box<bool>>` вместо `bool`) до тех пор,
    пока Ф4.2 не даст преобразования. Красное — удалить одно поле из
    фрагмента, показать падение, вернуть.
  - **Ф4.1b-2 — остальные пять схем** тем же методом. **СЕЛИ 2026-08-15:**
    `by_name`, `by_cap`, `by_purl` — `b000e51f`; `repomd` — `456c4ea9`.
    Семь красных доказательств за две посадки, из них два стоят отдельного
    упоминания: удаление поля из ОБЩЕГО фрагмента роняет оракул `by_name` на
    ТРЕТЬЕМ уровне вложенности (через пакет и версию) — это и есть свойство,
    делающее общий фрагмент безопасным для деления; и удаление целого плеча
    объединения роняет уже `from_value` («unknown variant»), то есть оракул
    сторожит полноту объединения, а не только поля внутри выжившего плеча.
    *Найдено попутно и записано как B-056:* у JTD нет 64-битного целого вовсе
    (генератор отвергает `uint64` и `int64`), а писатель объявляет `size: u64` —
    то есть наш писатель способен породить документ, который наша же схема
    объявляет невалидным. Развилка владельца, три выхода измерены.
  - **Ф4.2a — боксирование варианта объединения, ВПЕРЁД остальных
    преобразований** (решение босса 2026-08-15, по замеру). Схема журнала не
    может лечь раньше: измерено на пробе с настоящим фрагментом записи —
    сгенерированное объединение роняет `large_enum_variant`, clippy сам
    называет починку `Box<…>`, сгенерированный файл руками не правят, а
    подавления этого линта в дереве нет ни одного (его решали осознанным
    `Box`, и именно он поймал реальный дефект в Ф3.1). **Форма: боксируются
    ВСЕ плечи дискриминатора, единообразно.** *Почему не порог:* эвристика по
    размеру непредсказуема и поедет с версией clippy. *Почему не аннотация в
    схеме:* схема описывает ПРОВОД, а боксирование есть деталь представления в
    Rust; вносить её в описание формата значит смешивать два разных предмета —
    и это единственный довод, который здесь решает, потому что все прочие
    аннотации Р2 описывают именно формат. Провод не двигается: `serde`
    рендерит `Box<T>` ровно как `T`. Цена названа честно — одна аллокация на
    построение варианта, ничтожная для типов, которые разбирают и проецируют
    по разу.
  - **Ф4.1b-3 — схема журнала. СЕЛА 2026-08-15**, коммит `e0a2248c`. Все
    одиннадцать вариантов описаны и все одиннадцать упражнены; оракул несёт
    таблицу «плечо → число ключей на проводе», а не общий счёт, поэтому плечо,
    тихо потерявшее поле, падает на своей строке. Красное — четырежды, двумя
    сторонами и двумя механизмами: пропавшее ПОЛЕ терпимый читатель роняет
    молча и ловится сравнением, пропавшее ПЛЕЧО отвергается на `from_value` с
    перечислением уцелевших тегов. **Боксирование Ф4.2a подтвердилось на
    настоящей цели:** `large_enum_variant` не сработал.

    *Второй пол JTD, записанный, а не замазанный.* `Renamed` несёт кортежи
    Rust, а типа кортежа у JTD нет: `elements` описывает однородный массив
    любой длины, то есть схема принимает и пустой массив, и три элемента, и не
    закрепляет, какая позиция — группа. Записано в описании самого поля (что
    схема говорит, чего сказать не может, и что проверку арности несёт только
    Rust), плюс оракул пинит длину пары. Тот же класс, что B-056.

  **⇒ Ф4.1 ЗАКРЫТА: шесть схем из шести, у каждой свой оракул.** Всего по фазе
  предъявлено **тринадцать** красных доказательств. Сгенерированное дерево
  выросло с 8 подмодулей до 18.

  *Аннотации политики (`x-vocabulary`, `x-empty`, `x-default`, `x-rust-type`)
  пишутся уже в Ф4.1b, хотя их потребитель — Ф4.2. Это не машинерия впрок:
  схема есть единственный законный дом политики, и написать схему дважды
  дороже, чем написать её сразу верно. Но факт, что сегодня их никто не
  читает, обязан быть сказан вслух в каждом отчёте — иначе следующий читатель
  примет их за работающий механизм.*

*Главное доказательство Ф4.1a — зелёное, а не красное:* смысл шага в том, что
провод НЕ ДВИГАЕТСЯ. Схемы перестают дублировать словарь, а сгенерированный
Rust остаётся тем же до байта — это проверяется `check-codegen` на боссовой
стороне и модульным тестом «разрешённый `definitions.package_kind` равен тому,
что стоял инлайном» на воркерской. Красное отдельно требуется на отказе по
висячей `ref` — он сторожит поведение, которого сегодня нет.

**Ф4.1b — Схема каталога.** `schemas/index/e1/`: `entry.jtd.json`
(VersionEntry + вложенные), `repomd.jtd.json` (с тегированным объединением),
`by_name.jtd.json`, **`by_cap.jtd.json` и `by_purl.jtd.json`**,
`journal.jtd.json` (из Ф3.1). Словари — ТОЛЬКО здесь
(enum в JTD); это единственный источник (G9).

*Приёмка переписана по замеру: прежняя («схемы валидны; `codegen` строит без
ошибок») прошла бы на фазе, не построившей НИЧЕГО — до Ф4.0 генератор
подкаталогов не видит, а «построил без ошибок» и «построил ноль целей»
неразличимы.* **Приёмка Ф4.1:** каждая из шести схем даёт СВОЙ подмодуль под
`crates/vibe-wire/src/generated/` (перечислить поимённо и показать, что все
шесть появились); каждый `enum` несёт `x-vocabulary`, каждая коллекция —
`x-empty`, каждый опциональный скаляр — `x-default`, каждая строка-доменный-тип
— `x-rust-type` (Р2), и схема без нужной аннотации роняет генерацию —
доказать пробной правкой и откатить; словарь событий журнала описан во всех
**одиннадцати** вариантах (`Initialised`, `Published`, `Frozen`, `Yanked`,
`Removed`, `Renamed`, `Notice`, `ChannelSet`, `ChannelUnset`, `ForceReplaced`,
`EntrySetReplaced`) — схема, описавшая меньше, описывает формат, которого нет.

*Две последние схемы добавлены 2026-08-14 замером Ф0.3, который нашёл разрыв:
`by-cap/<slug>.jsonl` и `by-purl/<slug>.jsonl` — публикуемые поверхности со
своими типами строк (`CapabilityRow` `index/inverted.rs:66`, `PurlRow` `:75`),
у которых **нет ридера файла** — тогда как у соседей он есть
(`primary.rs:75`, `by_name.rs:57`). Это прямое нарушение G11 («у каждого
публикуемого формата есть сгенерированный ридер, прогоняемый в round-trip
тесте»), и прежний перечень Ф4.1 его не закрывал. Ф4.2 обязана дать обоим
сгенерированные ридеры; `BindingSite` при этом становится ОДНИМ определением
(сегодня писатель `inverted.rs:88` — `kebab-case`, клиент
`index_client/wire.rs:94` — `lowercase`, совпадают случайно: значения
однословные, паритет-теста нет — живой дефект B7).*

**Ф4.2 — `vibe-wire-gen`.** По ветке из Ф0.2: постпроцессор выхода
jtd-codegen (или свой эмиттер) в `xtask/src/wiregen/` (developer tooling,

политика пропуска пустого ПО СХЕМЕ (metadata-аннотация
`"x-empty": "omit"|"emit"` в JTD metadata — генератор читает); строгость по
роли из реестра форматов (`foreign_parsers=none` → deny; иначе терпимо).
Выход — в `crates/vibe-wire/src/generated/index_e1/` и замена рукописных
типов `vibe-index/src/types/**` на реэкспорт сгенерированных (методы
(`finalise`, `sort_key`, конструкторы) живут в отдельных impl-файлах РЯДОМ,
не в generated). Приёмка: `cargo xtask check-codegen` расширен на новые
цели; workspace зелёный; паритет-тест словаря: `PackageKind` в
`vibe-core` == сгенерированному (существующий тест переезжает на новый
источник); `BindingSite` становится ОДНИМ определением с двумя реэкспортами —
B7 закрыт структурно.

*Поправки по замеру 2026-08-15 — читать вместе с Р2–Р6 выше.* **(i)** Первым
делом шага — раскол `codegen.rs` в каталог-модуль по шву `format_id` (Р6);

а не текст→текст. **(iii)** Словарей, сводимых в одно определение, **пять**,

существует, вопреки записанному, так что его копия всё это время стояла без

**третьим** — `primary.jsonl.gz` (О5): сегодня он публикуется, а читается
только несжатый сосед. **(v)** Шов постпроцессора назван замером:
`xtask/src/codegen.rs:185-205`, между проверкой статуса (`:191-203`) и
`module_names.push(stem)` (`:204`); реестр уже разбирается в структуру
(`load_format_registry`, `:320`), схема — ещё нет, и `serde_json` для этого уже
в зависимостях (`xtask/Cargo.toml:17`). **(vi)** Пин генератора (0.4.1) не
сведён с артефактами (`v0.2.1` в шапке всех восьми) и ни одним гейтом не
проверяется — свести ДО того, как постпроцессор будет привязан к форме эмиссии,
не после.

**Р10. Слой преобразований ключится ДОМОМ схемы — тем же ключом, которым Ф4.0
маршрутизирует выход.** Хостовый дом `schemas/` получает политику целиком (все
девять целей, включая семь плоских CLI-отчётов); дом движка не получает её
вовсе. *Почему это не бюджетная отговорка:* политика НАШЕГО провода не вправе
связывать публичный Rust-API чужого пакета с собственным поездом релизов —
именно это и запрещает §2, и именно поэтому запрет там сформулирован как
«вовсе». *Отвергнуто:* аннотировать схему движка и переписать его выход
(нарушение §2, плюс рябь в вендоренные зеркала через `sync-engines`);
*отвергнуто:* применять слой сквозь, но не требовать аннотаций у движка — тогда
правило рождается с дырой, а «ошибка генерации» перестаёт быть ошибкой.
*Триггер расширения:* принятие слоя кампанией самого движка.
**Поправка, которую это решение делает обязательной:** запись Р5 №2
(«snake_case снимает `#![allow(non_snake_case)]` в ОБОИХ потребителях, включая
engine-крейт») после Р10 ЛОЖНА — `allow` движка остаётся. Снимается ровно один,
и он не по-файловый, а crate-wide в РУКОПИСНОМ `crates/vibe-wire/src/lib.rs:52`
(в самих сгенерированных файлах его нет ни одного — измерено).

**Р11. Фрагмент `timestamp` переводится на `"type": "timestamp"`, и это правка
СХЕМЫ, а не обход преобразования.** Провод несёт RFC-3339, а схема сегодня
говорит `"type": "string"` — то есть недоописывает формат, который обязана
описывать. После правки генератор выдаёт `DateTime<FixedOffset>`, и его
переписывает то же плечо `x-rust-type`, что и остальные алиасы: №6 перестаёт
быть отдельным правилом и становится входной формой №8. *Почему не оставить
как есть:* тогда у времени в системе две законные записи — `"type": "string"` и
`"type": "timestamp"` — а вторая появится в первой же новой схеме, и разойтись
им ничто не мешает. Одна вещь пишется одним способом. *Цена, названная
заранее:* `crates/vibe-wire` получает зависимость `chrono`, которой у него
сегодня нет вовсе ⇒ `Cargo.lock` входит в периметр шага. *Что доказывает
безопасность:* провод не движется — это меряют шесть оракулов.

**Р12. Девятое преобразование: `HashMap` → `BTreeMap`, безусловное.**
PROP-044 [`##M-SCHEMA-DESCRIBES-FORM`](../../spec/common/PROP-044-change-native-formats.md#machinery)
перечисляет **`canonical ordering`** среди того, что эмитит наш слой, а
[`##M-CANONICAL-BYTES`](../../spec/common/PROP-044-change-native-formats.md#machinery)
требует «одно состояние — одна последовательность байт: sorted keys». Список
преобразований этого просто не выписал. *Почему без аннотации:* у канонического
порядка ровно один законный ответ — это ЗАКОН провода, а не выбор политики; тот
же довод, которым Ф4.2a обосновала безусловное боксирование. *Почему это
успевает стать дефектом:* оракулы к порядку ключей слепы ПО ПОСТРОЕНИЮ (они
сравнивают `serde_json::Value`, чьё равенство порядок-независимо — сказано в их
собственной шапке), поэтому мерцающий `rebuild --check` пришёл бы уже после
реэкспорта, без сторожа между. Ложится ДО реэкспорта.

**Р13. У `x-default` два значения, и отсутствие ключа остаётся ошибкой.**
`x-default: <литерал>` — отсутствие поля ЕСТЬ это значение, поле схлопывается в
скаляр с `default` и именованным предикатом (форма Р1 фазы Ф1.4).
`x-default: null` — отсутствие есть ФАКТ, поле остаётся `Option<T>` и теряет
бессмысленный `Box`. Отсутствие самого ключа на опциональном скаляре — ошибка
генерации, как и требует Р2. *Почему не «требовать литерал всюду»:* это
заставило бы выдумать умолчание для `license` и `resolved_commit`, где
отсутствие — законное третье состояние ФАКТА, а не третье состояние ОСИ (запрет
PROP-044 §2b — про булеву ось, а не про всякую опциональность). *Отвергнуто:*
«требовать аннотацию только там, где иначе появляется третье состояние булевой
оси» — правило по срезу сегодняшних полей, а не свойство системы; ровно тот
дефект, который запрещает `##VOLUME-OF-WORK-IS-NEVER-AN-ARGUMENT`
(`spec/boot/90-user.md`, директива усилий владельца 2026-08-09).

**Р14. Семь вложенных подсекций: `Option<Box<T>>` → `Option<T>`, и это НЕ
развилка — Приложение Б.2 её уже решило.** Б.2 ратифицирует: «пустая проекция
нормализуется в отсутствие ПРОЕКТОРОМ (писатель никогда не пишет
`{"provides":{}}`); читателю оба вида законны». Значит `Option` на стороне
ЧИТАТЕЛЯ верен и обязан остаться — он и есть способ принять `{}` от чужого
писателя; а нормализация пустого — работа проектора, а не skip-предиката типа.
Преобразование здесь только одно: снять бессмысленный `Box`. *Что это стоит и
когда:* при реэкспорте (Ф4.2c) рукописные `compatibility: CompatibilityEntry`
становятся `Option<CompatibilityEntry>`, и это двигает одиннадцать литералов
записи (Р4 фазы Ф1.4) плюс места чтения. Названо здесь, чтобы встретиться с
этим в плане, а не при сборке. *Отвергнуто:* эмитить `is_empty` для
сгенерированных структур и повторить рукописную форму — генератор начал бы
эмитить ПОВЕДЕНИЕ, а не форму, и семантика пустого объекта осталась бы
невыразимой.

**Р15. №4 остаётся правилом, но его сайты сегодня — ноль, и обе мины закрыты
явно.** Пасс осматривает 69 структур и не выдаёт атрибут ни одной (О8) — это
законно: политика реестровая, и запись `[format.config]` получит схему позже.
Две мины закрываются формой правила, а не молчанием: *(i)* когда одна схема
стоит за несколькими форматами с РАЗНЫМИ `foreign_parsers`, политика
неоднозначна — **громкий отказ, называющий схему и обе записи**, никогда не
«первая попавшаяся»; *(ii)* запись реестра, чья `schema` не существует на диске
(`handshake` сегодня), пассом **пропускается по имени с явной строкой в выводе**,
а не роняет сборку и не считается «нет схемы ⇒ политика не нужна». *Отвергнуто:*
отложить №4 до появления первого `none`-формата со схемой — правило, которого
нет в машине, держится процедурой, а вся фаза существует ровно затем, чтобы
перестать держать законы процедурой.

## 11. Смертность этого плана (закон «план временный», применённый к себе)

Стоячий закон проекта: план — временный документ; содержимое по мере
исполнения переезжает в спеки; утверждения цитируют якоря спек и никогда —
строки плана; закрытая строка — могильник. Для ЭТОГО плана исполнимо так:

1. **По мере исполнения.** Посадка каждой фазы включает её спек-дифф (карта —
   Приложение Б.5), и в том же коммите секция фазы в этом файле СВОРАЧИВАЕТСЯ
   в могильник по образцу закрытых строк `BACKLOG.md`: «Closed <дата> by
   <коммиты>. The ruling and its reasoning now live in <якоря спек>». Контент
   не живёт в двух местах даже один день.
2. **При закрытии плана.** Отчёт кампании сверяет предсказания P1–P6; из
   `spec/common/PROP-044` УБИРАЮТСЯ обе ссылки на этот файл (в `##PURPOSE` и
   `##SOURCES`) — заменяются якорями спек, куда легло содержимое; после этого
   на план не ссылается ни одна спека и ни один живой план, и файл целиком —
   могильники + отчёт. Дальше он удаляем.
3. **Названный пробел машинерии (дефер, не работа этого ТЗ):** «спека не
   ссылается на ЗАКРЫТЫЙ план» сегодня держится процедурой (этим разделом и
   законом отчёта кампании), чекера нет. Норма без чекера дрейфует — гейт
   «реестр закрытых планов → grep по spec/** → красный» дёшев и ложится в
   панель, когда появится первый закрытый план этой волны. Ссылки на АКТИВНЫЙ
   план законны (их держат WAL и `CONTINUE.md`) — гейт обязан различать.

**А.5 wiregen** (`xtask/src/wiregen/`) — **СЕМЬ** преобразований выхода
jtd-codegen, в этом порядке. *(Было четыре; №5–№7 добавлены 2026-08-15 по
замеру — решение Р5 §7. Вход конвейера — `(схема + реестр + сгенерированный
Rust)`, а не только Rust: измерено, что политика в сгенерированном коде следа
не оставляет.)*

**Сквозной закон аннотаций (Р2):** везде, где нужна политика, её называет
СХЕМА, и отсутствие аннотации — ошибка генерации. jtd-codegen ключи `x-…`
в `metadata` принимает молча и в Rust не переносит — проверено прогоном.

1. Закрытый enum → открытый: `pub enum PackageKind { Flow, …, Lang, Unknown(String) }`
   + ручные `impl Serialize/Deserialize` в том же генерируемом файле
   (`Unknown` пишет исходную строку как есть; известные — как раньше).
   **По `metadata."x-vocabulary": "open"|"closed"`, а НЕ по факту закрытости:**
   генератор выдаёт `PackageKind` (открыт) и `NamingConvention` (закрыт)
   синтаксически неразличимыми, отличить их по выходу невозможно.
   **Тегированные объединения этим преобразованием НЕ трогаются** — правило
   именованное, с тестом: сегодняшний сканер пропускает их случайно (между
   `#[derive(…)]` и `pub enum` стоит `#[serde(tag = …)]`, и распознаватель
   возвращает `None`), а совпадение — не механизм.
2. camelCase-поля → snake_case (снимает `#![allow(non_snake_case)]` в ОБОИХ
   потребителях: `crates/vibe-wire/src/lib.rs:52` и engine-крейт).
3. По `metadata."x-empty"` схемы: `"omit"` → `Vec<T>` + `skip_serializing_if
   = "Vec::is_empty"`; `"emit"` → `Vec<T>` без skip; отсутствие аннотации на
   коллекции — ОШИБКА генерации (решение обязано быть записано в схеме).
4. По реестру: `foreign_parsers = "none"` → добавить `#[serde(deny_unknown_fields)]`.
5. **`Option<Box<скаляр>>` → `скаляр` + `#[serde(default, skip_serializing_if
   = "<именованный предикат>")]`** по `metadata."x-default"`. Без этого
   `frozen`/`yanked` получают третье состояние на оси, которую PROP-044 §2b
   объявил двухсоставной, — и решение Р1 фазы Ф1.4, отвергшее `Option<bool>`
   ровно по этой причине, было бы отменено генератором. Домашняя форма —
   пара «default + skip» (35 мест в `types/entry/**`, ни одного `default` без
   парного skip).
6. **`DateTime<FixedOffset>` → `DateTime<Utc>`.** JTD `timestamp` даёт
   `FixedOffset`; дерево живёт на `Utc` (26 вхождений в
   `crates/vibe-index/src`).
7. **Боксирование крупного варианта объединения.** На нагрузке настоящего
   размера clippy падает `large_enum_variant` и сам называет починку
   (`Published(Box<EventPublished>)`); панель гоняет `clippy --workspace
   --all-targets -- -D warnings`, а сгенерированный файл руками не правят.

**А.5a Доменные типы (Р3).** По `metadata."x-rust-type": "<путь>"` строка на
проводе эмитится доменным типом (`Group`, `semver::Version`, `PackageKind`,
`NamingConvention`), а не `String`. Без этого «замена рукописных типов
реэкспортом сгенерированных» есть понижение типов по всему индексу.

**А.6 `hello.json`:**

```json
{"vibe":"hello/1","worlds":[{"epoch":1,"path":"."}]}
```

Клиент (`index_client`): `GET hello.json` → 404 ⇒ сегодняшний путь без
изменений; 200 ⇒ выбрать мир своей эпохи; своей нет ⇒ отказ с перечнем
миров и рецептом. Ключи `min_client`, `notice`, `sunset`, `successor` —
опциональны, absent-если-нет.

**А.7 Карантин:**

```rust
pub struct Quarantined { pub group: Group, pub name: String, pub version: Version, pub missing: Vec<String> }
```

`Index` несёт `quarantined: Vec<Quarantined>` (в память при load/project, в
файлы НЕ пишется); любой ответ по имени с карантинными версиями включает
`unavailable {version, missing, recipe}`; recipe — из каталога рецептов, не
литерал по месту.

**А.8 Слои исполнения.** Это ТЗ — план; на каждую фазу босс режет ПАКЕТ по
транспортному закону зоны (`SUBAGENT-LAUNCHERS.md`): контекст компилируется в
пакет (точные файлы из фазы + формы из этого приложения + self-verify
`cargo check`-классом), `wall_secs` щедрый, отчёт WORKER-REPORT обязателен.
Воркеры не запускают git; диффы читает, правит и коммитит босс; после
каждой фазы — полная панель.

## Приложение Б. Пофактные решения (иначе их переизобретёт исполнитель)

**Б.1 Политика по каждому словарю (для Ф4.1/Ф4.2).** Открытость решается по
вопросу «ветвится ли потребитель, и есть ли у незнакомого безопасное
поведение», и решена ЗДЕСЬ:

| словарь | политика | почему |
|---|---|---|
| `PackageKind` | **открытый**: `Unknown(String)`, строка сохраняется | после Ф3 перезапись из чтения невозможна — довод «одно add и правда уничтожена» умер; фильтры обязаны получить ветку `Unknown` (не молча-пусто: `vibe list --kind plugin` с нулём результатов ГОВОРИТ «kind неизвестен этой сборке») |
| `NamingConvention` | **закрытый**: неизвестное = громкий отказ | по нему строятся пути репозиториев; у незнакомого значения нет безопасного поведения — карантин целой записи, не угадывание |
| `DeliveryMode` | **открытый**: `Unknown(String)` + мягкая деградация | подсказка доставки, не идентичность; неизвестный режим = «описание обязано» (консервативная ветка), в лог warn |
| `DirectoryTag` | **умирает** в Ф1.5 | тег объединения делает его ненужным |
| `BindingSite` | **одно определение** (генерируется), клиентская копия — реэкспорт; wire-строки в схеме `kebab-case` (как у писателя сегодня) | двойная запись с разными `rename_all` — живой дефект базовой линии B7; паритет закрывается структурно |
| `Event.kind` (журнал, новый) | **закрытый** для нашего проектора (незнакомое событие = стоп проекции с внятной ошибкой) | журнал — ИСТИНА; молча пропустить событие значит спроецировать ложь; форвард-совместимость журнала решается эпохой журнала, не терпимостью |
| `SourceKind` | **вне периметра этого ТЗ** — политику назначает следующее ТЗ вместе с манифестом и локфайлом | найден замером 2026-08-15 как пятый раздвоенный словарь (`vibe-cli/src/commands/tree/model.rs:243` — только `Serialize`; `vibe-core/src/manifest/lockfile.rs:199` — оба), правила совпадают (`lowercase`), паритет-теста нет. Обе копии принадлежат форматам, которые это ТЗ описывать НЕ берётся (`cli-package-tree` — JSON Schema, не JTD; `lockfile` — дефер Б.6), поэтому Ф4.2 свести их не может: это именованный дефер, а не пропуск |

*Поправка к таблице по замеру 2026-08-15 (находка
[`f4-vocabulary-and-surfaces.md`](harvest/f4-vocabulary-and-surfaces.md)):
раздвоенных словарей в дереве **пять**, а не один. Строка B1/B7 базовой линии
называла `BindingSite` единственным живым дефектом и утверждала, что

**Б.2 Пусто против отсутствия — пофактное правило (для аннотаций
`"x-empty"` в схемах Ф4.1).** Ратифицируется сегодняшний раскол, он же
становится канонической формой:

- `"emit"` (пустое пишется явно) — **4 payload-коллекции**, чьё содержимое и
  есть смысл контейнера: `Repomd.files`, `PackageEntry.versions`,
  `NameEntry.packages`, `RequiresAnyEntry.one_of`.
- `"omit"` (пустое опускается) — **14 метаданных-коллекций** из базовой линии
  B2 (`authors`, `keywords`, `requires_any`, `subskills`,
  `features.features`, `features.exclusive`, `channels`, `i18n.available`,
  `requires_kinds`, `provides.capabilities`, `requires.packages`,
  `requires.capabilities`, `obsoletes.packages`, `conflicts.packages`).
- **7 вложенных структур** (`compatibility`, `provides`, `requires`,
  `obsoletes`, `conflicts`, `features`, `i18n`): в схеме —
  `optionalProperties`; правило канонизации — **пустая проекция
  нормализуется в отсутствие ПРОЕКТОРОМ** (писатель никогда не пишет
  `{"provides":{}}`); читателю оба вида законны.
- Каталог пишет машина: состояние «не записано» в нём не существует законно,
  различимость пусто/нет НЕ моделируется (довод G2-разбора). Для рукописного
  манифеста этот вопрос НЕ решается здесь (его ТЗ — следующее).

**Б.3 Рецепт хэша — два капкана, закрытые в `hash_recipes/1.toml`
(для Ф1.3). ИСПОЛНЕНО 2026-08-14; первая посылка при этом ОПРОВЕРГНУТА
измерением — читать вместе с поправкой ниже.** (1) **Порядок**: нормализация
путей (`\`→`/`) — ДО сортировки; сортировка — побайтовая по нормализованной
UTF-8-строке. (2) **Не-UTF-8 имя файла — жёсткая ошибка**, не
`to_string_lossy` (сегодня два разных не-UTF-8 имени могут дать один хэш — это
«неверный ответ выглядит верным», запрещено законом 1). Рецепт 0 (легаси,
замороженный) сохраняет сегодняшнее поведение дословно — он существует только
чтобы читать старые строки.

*Поправка по факту измерения (замер `F1-3-PROBE` + посадка, 2026-08-14).*
Скобка «сегодняшний код сортирует `PathBuf` до нормализации — подозрение
ревьюера на расхождение Windows/Unix» **неверна**, и следующий читатель не
должен строить по ней. `Ord` у `Path` в std — **покомпонентный**: разделителя
он не видит вовсе, поэтому рецепт 0 платформенно стабилен, и подозрение
ревьюера не подтвердилось. Рецепты различает не разделитель, а порядок «по
компонентам» (рецепт 0) против «по нормализованным байтам» (рецепт 1), и
расходятся они ТОЛЬКО когда сосед продолжает имя каталога байтом **ниже**
`/` (0x2F) — `spec-x.md`, `-`=0x2D. На байте, который называл этот абзац
(между 0x2F и 0x5C, то есть `specX.md`), рецепты **совпадают**, то есть
фикстура такой формы не доказывала бы ничего. Практическое следствие, оплаченное
регрессией: реализация, сортирующая строку вместо `PathBuf`, тихо меняет хэш
всякого дерева с каталогом-префиксом соседа — ни один golden этого не ловит,
поймал потребитель (`vibe check`, счётчик `local_source_freshness`).
