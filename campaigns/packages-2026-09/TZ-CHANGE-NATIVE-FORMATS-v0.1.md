переезжает в спеки, план удаляется). **Контракт, который этот план строит:**

опубликованы наружу на миллионы людей. Эволюция максимально быстрая — мы ещё

Подход с serde ужасен и не похож на фундаментальное решение для вечноменяющейся
среды. Нужно: а) документ с идеологией; б) конкретное решение по пакетам и

**Кто исполняет.** Рассчитано на агента слабее автора: каждая фаза несёт точные

## 1. Решения (РЕШЕНО здесь; исполнитель не переоткрывает)

Каждое — с отвергнутыми вариантами и условием пересмотра.

**D1. Архитектура — «одноразовые миры» (PROP-044).** Истина = исходники
пакетов + журнал фактов реестра; всё опубликованное производно и
восстановимо; вечен один хэндшейк. *Отвергнуто:* «вечная линия под машинным
надзором» (Protobuf/Buf-модель) — делает совместимость вечным налогом на
дизайн и слепа к смысловым переломам; «неизменяемый гербарий» (Nix-модель) —
решает 10% задачи и выталкивает агрегаты в неуправляемый слой; «формат как
программа» (данные несут ридер) — поверхность атаки и нестатическая
проверяемость. *Пересмотр:* если тест восстановления невозможно удержать
зелёным (см. риск в PROP-044 §9), архитектура деградирует — остановка,
доклад владельцу.

**D2. Объединение `RepomdFileEntry` становится симметрично тегированным
СЕЙЧАС.** Форма A: `#[serde(tag = "kind", rename_all = "lowercase")]`, оба
плеча несут `kind`. Ломающее изменение провода — бесплатно при нуле
потребителей; разблокирует генерацию (B11). *Отвергнуто:* оставить untagged
(вечно блокирует схему; молча глотает добавленные поля — единственный тип
каталога с этим свойством); adjacently-tagged форма D (`content`-обёртка) —
дороже байтами, а рост числа плеч не ожидается. *Пересмотр:* не предусмотрен.

**D3. Read-modify-write умирает: журнал + проекция.** Мутации сервера и CLI
— дозапись события в журнал фактов, затем перепроекция каталога целиком.
Писатель не принимает на вход типы, прочитанные из собственного каталога.
*Отвергнуто:* «терпимость + захват незнакомого» (`flatten extra`) — лечит
симптом и делает возврат RMW комфортным; статус-кво (строгий RMW) — это
источник половины дефектов базовой линии (B3, B5, B6). *Гейт:* фаза 0
меряет объём переделки (M-RMW ниже); если > бюджета — СТОП-ВЛАДЕЛЕЦ с
задокументированным запасным путём (временный захват на трёх RMW-типах,
явно помеченный как компромисс). *Пересмотр:* по результату M-RMW.

**D4. Свой слой генерации `vibe-wire-gen`.** Постпроцессор/замена
jtd-codegen, эмитящий политику: открытые словари `Unknown(String)`,
детерминизм-дружественные типы, политику пропуска пустого, строгость по
роли, snake_case. *Отвергнуто:* голый jtd-codegen (B11 — не умеет политику);
ручной serde (запрещён PROP-044 законом 5); смена языка схем на JSON
Schema/CUE (JTD выбран за бедность — агент не может выразить опасное; вся
выразительность — в нашем генераторе). *Пересмотр:* если PoC генератора
(фаза 0) обнаружит непроходимое — доклад.

**D5. Эпоха в `vibe.toml` — немедленно.** Поле `epoch = 1` в `[package]`
(u32). Отсутствие = состояние «до эпох» (НЕ «эпоха 1»): читается как
сегодняшний формат, помечается в диагностике. Новые манифесты получают поле
через `vibe init`/шаблоны; массовой правки 172 файлов НЕ делается (кодмод —
поздняя волна). *Отвергнуто:* «отсутствие = 1» (стирает различие «старый»
против «чужой/битый» — довод G4-разбора); обязательность на чтении
(уронит все существующие манифесты). *Пересмотр:* не предусмотрен.

**D6. Идентичность рецепта у `content_hash`.** Формат значения:
`sha256-tree/1:<hex>`; рецепт №1 (список исключений, нормализация путей,
порядок обхода) — данные в `formats/hash_recipes/1.toml`; обе копии
алгоритма читают рецепт из данных; golden-тест на образцовом дереве
замораживает пару (рецепт → хэш). Старые значения `sha256:<hex>` читаются
как рецепт 0 (легаси, замороженный). *Отвергнуто:* оставить константу
(смена списка тихо меняет каждый хэш в мире — запрещено законом «не врать»);
отдельное поле `hash_algo` рядом (две графы там, где хватает префикса).
*Пересмотр:* не предусмотрен.

**D7. Слоты must-understand / подписи / yank — в схему записи сейчас,
криптография — НЕТ.** Поля: `must_understand: []` (список строк-возможностей),
`yanked: bool` (+ `tombstone: {reason, superseded_by?}` на уровне имени),
резерв под `signature`. Безопасность запаркована владельцем (B-015) — только
слоты. *Отвергнуто:* отложить слоты «до надобности» — их окно закрывается
первой публикацией (терпимый читатель, молча глотающий будущее поле подписи,
= downgrade-атака). *Пересмотр:* уведомление владельца по B-015.

**D8. Хэндшейк `hello.json`.** Корень индекса; ключи:
`{vibe: <строка-версия формата хэндшейка>, worlds: [{epoch, path, sunset?}],
min_client?, notice?, successor?}`. Вечный файл, читается максимально
терпимо. Первая реализация вырожденная: один мир, без параллельной
публикации. *Отвергнуто:* версия-в-пути без хэндшейка (клиент без
входной точки не узнаёт о переезде — транспорт без редиректов); HTTP-заголовки
(транспорт — сырые файлы). *Пересмотр:* первый настоящий поезд эпох.

**D9. `vibe.lock` — молчаливая перегенерация.** Несовпадение (эпоха, хэш
генератора, id рецептов) → пересобрать без вопросов; `--locked` → громкий
отказ (CI). Флаг называется `--locked`, НЕ `--frozen`: слово «frozen»
принадлежит пакетам (D14; «snapshot» — его антоним, PROP-044 §2b). *Отвергнуто:* сегодняшний отказ по `!=` (лишний
вопрос пользователю про черновик). *Пересмотр:* не предусмотрен.

**D10. Конфиги: `fn load() -> Config` без `Result`.** Незнакомый ключ —
предупреждение; кривое значение — умолчание + предупреждение. *Отвергнуто:*
строгий отказ (блокировать работу из-за устаревшей настройки при 10 релизах
в день). *Пересмотр:* не предусмотрен. (Отдельная фаза не выделяется —
применяется при первом же касании `vibe-settings` любой волной.)

**D11. Наблюдаемость сервера: подписчик трассировки ставится ВСЕГДА**
(уровень по умолчанию warn, `--log-level` для операторов). Причина: карантин
записей (D3/PROP-044 §4.5) обязан быть виден оператору; лог, существующий
только под флагом автопубликации, — случайная связь (вопрос владельца №3,
`BACKLOG.md` B-071). **РЕШЕНО владельцем 2026-08-13: уровень по умолчанию —
warn; СТОП снят.** *Отвергнуто:* статус-кво (события формируются и
выбрасываются). 

**D12. Узкая публичная проекция, сгенерированные клиенты, кодмод-бот,
репетиции заката — НЕ в этом ТЗ.** Это волна 3 PROP-044; отложено поимённо
(закон: отложенное живёт в плане, не в воздухе). *Пересмотр:* после приёмки
этого ТЗ.

**D13. Допубликационный режим (рулинг владельца 2026-08-10; контракт —
PROP-044 `##THE-PUBLIC-SWITCH`).** До объявления владельцем «первое
представление публике состоялось»: **миграции не применяются вовсе** (ни
кодмодов, ни бот-PR — при переломе манифеста наши 44 авторских файла просто
правятся массово на месте); `formats/EPOCHS.toml` несёт `public = false`
(строку меняет только владелец); пока `false` — окно перелома всегда открыто,
`wire-diff` перегенерирует корпуса и ЗАПИСЫВАЕТ изменение, но записки не
требует (Ф5.2 в этом режиме — отчётный, не блокирующий), календари заката и
параллельные миры не существуют, ридер №0 из Б.4 — удобство, а не
обязательство (его можно удалить, поправив файлы). Факт первого показа
**не выводится из технических событий** — этот план не содержит и не смеет
содержать детектора публикации. *Отвергнуто:* «наполнение дефолтного реестра
= публикация де-факто» — прежняя трактовка снята рулингом. *Пересмотр:*
слово владельца, и только оно.

**D14. Замороженность — флаг манифеста, односторонний; поверхности обязаны
её показывать (рулинги владельца 2026-08-10; контракт — PROP-044
`##THE-FREEZE-MODEL`).** `frozen: bool` в `[package]`, отсутствие = `false`
(**snapshot** — сегодняшняя практика разработки становится легальной
навсегда, B-067 растворяется; терминология PROP-044 §2b: snapshot ↔ frozen —
антонимы, «канал» — отдельная ось указателей PROP-005 §2.18). Фриз — правка автора `frozen = true`:
однонаправленная, внутри хэшируемого содержимого; реестры пишут НАБЛЮДЕНИЕ
в журнал (`Frozen`-событие) и проецируют флаг в каталог. Семантика
несовпадения хэша раскалывается: замороженная координата — тревога;
snapshot — «приехало новое», локфайл для snapshot пинит хэш доставленного
содержимого + локатор.
Конфликт «одна координата, разные байты, кто-то заявляет frozen» — громкий
отказ через машинерию кандидатов. **Обязательство поверхностей:** каждая
поверхность, показывающая версию, показывает статус — machine-JSON несёт
поле по схеме (автоматически из Ф4), человеческие поверхности рендерят
всегда; периметр: `vibe list/show/tree/search/outdated`, план и отчёты
install, MCP-инструменты (`query`/`select`/`explain`/`query_package`), TUI,
HTTP-ответы сервера, узкая проекция. Слот `frozen` едет в волну 0 (Ф1.4) —
задним числом не внедряется: старый читатель без поля счёл бы snapshot
замороженным и уверенно кэшировал протухшее. *Отвергнуто:* носитель в
имени версии (Maven-SNAPSHOT-стиль) — склеивает две ортогональные оси и
делает невыразимой замороженную бету; носитель только в журнале —
журнал пер-реестровый, мнения реестров могли бы расходиться, а посетитель
репозитория пакета флага бы не видел. **РЕШЕНО владельцем 2026-08-13 (СТОП снят): умолчание резолвера не
различает frozen/snapshot — берётся STABLE, если есть (даже незамороженный),
иначе LATEST; ось выбора отделена от оси целостности (после выбора пин хэша
в локфайле, несовпадение — по семантике выше). Контракт: PROP-005 §2.18
`##RESOLVER-DEFAULT-IS-STABLE-THEN-LATEST`.** *Пересмотр:* не предусмотрен.

**Карта на пять вопросов владельца:** №1 (формат каталога) — решается этим
ТЗ целиком; №2 (недетерминированная запись) — растворяется фазами 2–3 (B6);
№3 (логи сервера) — D11; №4 (планка доказательства) и №5 (соединение
движков) — НЕ трогаются, остаются владельцу.

**Р1. Форма `yanked` / `frozen` в записи — `bool` плюс именованный предикат.**
Полей типа `bool` во всём `crates/vibe-index/src/types/` НЕТ ни одного: готовой
формы не существует, её заводят осознанно. Домашнее правило дерева — «всякая
опциональность записи есть пара `default` + `skip_serializing_if`» (35 полей,
ни одного `default` без парного skip). Значит `#[serde(default,
skip_serializing_if = "…is_false")] pub yanked: bool` с одной маленькой
свободной функцией `is_false(&bool) -> bool` рядом с типами — домашний стиль
это ИМЕНОВАННЫЙ предикат (`CompatibilityEntry::is_empty`), а не выражение по
месту. *Отвергнуто:* `bool` без атрибутов, сериализуемый всегда — ломает
домашнее правило и платит байтами на каждой записи за подавляющий общий случай.
*Отвергнуто:* `Option<bool>` под готовый `Option::is_none` — форма нашлась бы
даром, ценой третьего состояния у факта, который PROP-044 §2b объявляет **одной
булевой осью без третьего состояния**; отсутствие поля УЖЕ значит `false`.
**Манифестная половина — та же форма, и это исправление плана, а не
асимметрия.** Текст шага Ф1.4 выше называет `frozen: Option<bool>`; проза
решения D14 называет `frozen: bool`, отсутствие = `false`. Дерево разрешает спор
в пользу D14: у `PackageMeta` УЖЕ есть bool-поля (`bridge`), и у файла УЖЕ есть
ровно этот помощник — `fn is_false(b: &bool) -> bool`
(`crates/vibe-core/src/manifest/package.rs:139-142`). Значит манифестная сторона
— `#[serde(default, skip_serializing_if = "is_false")] pub frozen: bool` с
переиспользованием существующего помощника, а `Option<bool>` снимается как
выброс. Довод «Option сохранит различие „автор написал `false`“ против „не
написал ничего“» не держится: манифест правится документом на месте (закон
кодмодов, PROP-044 §5), а не сериализацией из структуры, поэтому serde этого
различия и так не носит. Один идиом на обеих сторонах, третьего состояния нет
нигде. **Бюджет:** `package.rs` — 572 строки при бюджете 600; поле с честным
доком помещается, но запаса ~28 строк. Если правка переваливает 600 — раскол по
шву `package/<тема>.rs` (домашний образец: файл уже держит десять таких
подмодулей), а НЕ ужатие дока под бюджет.

**Р2. `must_understand` — фильтр над разобранными записями, не в парсере.**
`Index::load_from` собирает RAM-копию **из by-name файлов** и `primary.jsonl`
при загрузке не читает вовсе (`index/memory.rs:262-281`); единственный готовый
цикл «по одной записи» живёт в `primary::parse` (`index/primary.rs:88`), то есть
пропуск, встроенный туда, сторожил бы путь, которым никто не грузит — ровно та
болезнь, которую §8 запускаторов называет «фикстура, которая не может упасть».
Второе наблюдение снимает мнимую сложность: `must_understand` — поле, которое
ЭТОТ шаг и заводит, поэтому наш читатель разбирает его штатно, а незнакомой
является **строка-значение внутри известного поля**, а не незнакомое поле; ни
`deny_unknown_fields`, ни терпимый предразбор тут ни при чём. **Решение:**
фильтр стоит в единственной точке, где записи становятся состоянием в памяти —
цикл разворачивания в `Index::load_from` (`memory.rs:266-271`); парсеры
остаются чистыми «байты → типы». Набор понятных читателю возможностей заводится
ПУСТОЙ константой в новом файле с доком «растёт по мере постройки
возможностей»; имя набора — `reader_capabilities`, НЕ `capabilities`: слово
«capabilities» в этом дереве уже занято тем, что пакет ПРЕДОСТАВЛЯЕТ
(`provides.capabilities`, `cli/capabilities.rs`), и второй смысл под тем же
голым словом — ровно та коллизия, которую запрещает дисциплина именования.
*Отвергнуто:* фильтр в `primary::parse`; фильтр внутри `by_name::parse`
(мешает политику в парсер и требует предразбора, который здесь не нужен).

**Р3. Пропуск не молчит, и его форму выбирают, а не копируют.** Замер нашёл,
что «неполадка, которая не ошибка» выражается в этом крейте вообще не
макросом: сканер собирает структурные заметки о пропусках и отдаёт их
вызывающему (`scanner/org_walk.rs:55-60`). Прецедента «warn из пути загрузки,
видимый в CLI» в дереве НЕТ: подписчик трассировки ставится ровно дважды во
всём `crates/`, и в `vibe-index` он привязан к флагу `--auto-commit-push`
(`cli/serve.rs:67-73`), а не к чтению — код прямо это и декларирует. Решение
трёхчастное: *(i)* носитель — тот, что уже назван **Приложением А.7 этого же
плана**: `Index.quarantined: Vec<Quarantined>` в память при загрузке, в файлы
НЕ пишется; Ф6.2 достраивает на нём ОТВЕТ (`unavailable {…, recipe}`), а не
носитель; *(ii)* человеческая поверхность — `tracing::warn!` из пути чтения;
*(iii)* и чтобы *(ii)* не оказалось предупреждением, которого никто не увидит,
подписчик ставится **безусловно** в `crates/vibe-index/src/main.rs` в форме,
уже доказанной в `crates/vibe-cli/src/main.rs:408-417` (EnvFilter `VIBE_LOG`,
дефолт `warn`, writer stderr), а флаго-зависимая установка в `serve.rs`
удаляется вместе с комментарием, который после этого лгал бы. Это досрочная
выдача части решения D11 — оно уже РЕШЕНО («подписчик ставится ВСЕГДА, уровень
warn»), и данный шаг первым порождает предупреждение, чей смысл — быть
увиденным. *Отвергнуто:* отложить подписчика до Ф6.2 (шаг отгрузил бы обещание
вместо поведения: его собственная приёмка «пропускается с предупреждением»

**Ф2.3 — Идемпотентный upsert. СЕЛА 2026-08-14 — ФАЗА 2 ЗАКРЫТА.**

*Поправка по существу, а не по координате: «пустой diff» оказался недостижимой
формулировкой.* После Ф2.1 часы приходят на СОБЫТИЕ мутации, поэтому у
повторного upsert'а они другие, `generated_at` сдвигается и diff всё равно
получается непустым. Пустой diff не нужно получать — нужно **не создавать
работу**: мутация, ничего не изменившая, не доходит ни до писателя, ни до
публикатора. Форма: `Index::upsert` возвращает «изменилось ли», сравнивая
ЗНАЧЕНИЕ записи целиком, а не номер версии (сравнение по номеру молча теряло бы
настоящие обновления); три серверные мутации приведены к одной форме — причём
приведён к ней был upsert, потому что оба пути удаления так вели себя всегда.
HTTP-семантика не сдвинулась: повтор отвечает успехом, различие
created/changed сохранено. Счётчик мутаций тоже ушёл под условие — счётчик
считает мутации, а no-op не мутация. Спека: факт
`##AUTO-PUBLISH-EVERY-MUTATION-COMMITS-EVEN-A-NO-OP` выведен из строя
надгробием (обе описанные им половины устранены), наследник —
`##A-MUTATION-THAT-CHANGES-NOTHING-COMMITS-NOTHING`.

Повторная идентичная мутация → пустой
diff → авто-коммит не создаётся (`AUTO-PUBLISH-AN-EMPTY-DIFF-IS-SUCCESS`
уже есть — теперь он срабатывает и на редундантном upsert'е, не только на
гонке). Приёмка: тест в `auto_publish.rs`: дважды один upsert → один коммит.

этого же ТЗ реплеит журнал ЦЕЛИКОМ, объявляя инкрементальную перепроекцию
поздней оптимизацией. Значит у персистентного курсора сегодня нет читателя, а
курсор, который никто не проверяет, — состояние, дрейфующее незамеченным. Дом
курсора — первая инкрементальная перепроекция, где его правильность вообще можно
испытать; там же ему нужен и тест.

**(iii) Событий в enum одиннадцать, а не девять: добавлены `Initialised` и
`EntrySetReplaced`** — носители рулингов Ж1 и Ж5/Ж6 соответственно. Приложение
А.2 их не называло, потому что писалось до замера.

**(iv) `Published` несёт БОКСИРОВАННУЮ запись, и на проводе это не видно.**
Поймано clippy (`large_enum_variant`) в боссовом хвосте: запись каталога — около
900 байт против единиц у любого другого варианта, а `replay` отдаёт
`Vec<JournalRecord>`, где каждый элемент резервировал бы ширину самого крупного
варианта независимо от того, какой факт он несёт. `serde` рендерит `Box<T>` ровно
как `T`, поэтому форма NDJSON не сдвинулась ни на байт. Причина вписана в тип, а
не оставлена в коммите.

*Операционная заметка, стоящая записи: воркер, строивший этот шаг, был срезан
внешне на шаге 6/8 — до финального прогона, до двух красных доказательств и до
отчёта. Работа при этом оказалась по сути готовой. Статус «killed» не был принят
за вердикт: worktree прочитан первым, красные доказательства и `clippy` добраны
боссом, и именно `clippy` — шаг, которого срез лишил, — нашёл (iv).*

**Ф3.2 — Проектор.** `Index::project(events) -> Index` — чистая функция;
`write_to` вызывается только над результатом проекции. Серверные мутации:
валидация входа → append в журнал → replay хвоста → write_to(at=событие).
`add`/`remove` CLI — те же события. `reindex`/`rescan-org` — источник
событий `published` из сканера (сканер остаётся как есть). Правило G4
механически: типы из `index_client`/чтения каталога не появляются в
сигнатурах писателей (arch-тест: грубый grep-гейт по импортам модулей
`journal|projector`, шаг self-check). Приёмка: `xtask rebuild --check` —
новый xtask: снести каталог, спроецировать из журнала, сравнить байты
(на герметичной фикстуре); шесть RMW-путей из B3 не читают каталог
(грep-доказательство: `load_from` остаётся только в путях чтения/serve-старте
для ОБСЛУЖИВАНИЯ чтения, не как вход мутации).

*Разбиение Ф3.2 на четыре шага (решение босса 2026-08-14 по замеру
[`harvest/f32-projector-surface.md`](harvest/f32-projector-surface.md)).* Текст
выше описывает Ф3.2 как один шаг; замер показал, что он несёт предусловие,
которого план не видел, и зависимость, которой нет ни у одного существующего
проверочного глагола. Каждый подшаг — отдельный коммит, порядок жёсткий:

- **Ф3.2a — `init` кладёт первую запись журнала.** Разрыв измерен: `Initialised`
  документирован как первая запись `init`, а слова `journal` в `cli/init.rs` нет
  вовсе. Без этого `rebuild --check` провалился бы не из-за дефекта, а из-за
  незаполненного шва. **Правда пишется ПЕРВОЙ**: у порядка «журнал → каталог»
  отказ восстановим (правда цела, каталог достраивается повтором), у обратного —
  нет, и это ровно
  [`##LAW-NO-UNRECOVERABLE`](../../spec/common/PROP-044-change-native-formats.md#laws).
  Сквозной транзакции в дереве не существует; консистентность даётся ПОРЯДКОМ,
  как её даёт `write_to`, штампуя манифест последним.
- **Ф3.2b — сам проектор** `project(events) -> Index`, чистая функция.
  Свёртка дубликата `Initialised` — «последняя запись выигрывает»: повторный
  `init --force` над живым журналом законно допишет вторую идентичность (guard
  смотрит только `repomd`, а у append-only журнала сброса нет), и подавлять этот
  факт писателю не положено — сворачивает его читатель. Прецедент формы в дереве
  есть: `progress-core` так сворачивает `Phase`.
- **Ф3.2c — переделка шести мутаций** на `validate → append → project(replay) →
  write_to`.
- **Ф3.2d — `xtask rebuild --check`.** Отдельным шагом, потому что он тянет то,
  чего не требовал ни один из пяти существующих проверочных глаголов:
  `xtask` не зависит НИ ОТ ОДНОГО продуктового крейта, а `vibe-index` отсутствует
  и в `[workspace.dependencies]` — подключение трогает два манифеста. Форма
  сравнения берётся у `sync-engines --check` (сравнивает сам, в процессе), а не у
  `check-codegen` (делегирует `git diff`): каталог данных не git-трекаем — журнал
  по умолчанию живёт под gitignored `state/`.

**Ф3.3 — Строгость читателя падает бесплатно.** Снять
`deny_unknown_fields` с типов каталога (15 мест B1) — теперь это безопасно:
прочитанное никогда не переписывается. Клиентские view (`wire.rs`) не
меняются. Приёмка: тест «каталог с незнакомым полем читается; запись из
журнала его не уносит, потому что запись не из чтения»; панель зелёная.

*Перед нарезкой дерево измерено тремя read-only пакетами (2026-08-14):
[`harvest/f3-index-state-and-projection.md`](harvest/f3-index-state-and-projection.md),
[`harvest/f3-journal-physics.md`](harvest/f3-journal-physics.md),
[`harvest/f3-rmw-break-and-reset.md`](harvest/f3-rmw-break-and-reset.md).
Замеры опровергли две записанные посылки этой секции и открыли четыре развилки.
Решения ниже приняты БОССОМ; исполнитель их НЕ переоткрывает. Одна развилка
остаётся владельцу и помечена СТОП-ВЛАДЕЛЕЦ.*

**Ж1. Идентичность реестра входит в журнал событием инициализации — и это
следствие, а не вкус.** Пять величин (`registry`, `registry_url`, `naming`,
`generator`, `schema_version`) сегодня приходят в мутацию только из
`repomd.json` через `load_from`. Проектор их из событий не соберёт: в
`VersionEntry` есть лишь `registry`, остальных нет нигде. Довод, закрывающий
вопрос, — **приёмка самой Ф3.2**: `xtask rebuild --check` сносит каталог и
проецирует из журнала. Если идентичность живёт только в `repomd.json`, то после
сноса её взять неоткуда — то есть каталог оказывается ЕДИНСТВЕННЫМ носителем
факта, что прямо запрещено
[`##FORBID-SECRET-TRUTH`](../../spec/common/PROP-044-change-native-formats.md#laws)
(«авторитетный факт, живущий только в производном артефакте»). Значит `init`
пишет первую запись журнала — событие инициализации реестра, — а проектор
сворачивает её правилом «последнее событие выигрывает». *Отвергнуто:* аргумент
проекции из флагов/конфига — у CLI-мутаций и у `serve` таких флагов нет, а
заведение второго источника истины рядом с журналом воспроизводит ту же болезнь
на этаж выше; *отвергнуто:* читать `repomd.json` в мутации — это ровно тот
read-modify-write, ради смерти которого фаза существует (D3, PROP-044 §4.4).

**Ж2. Версию схемы каталога проектор штампует СВОЮ — и факт Ф2.2 получает
клаузу, а не исключение.** Ф2.2 запрещает писателю затирать версию, которую он
ПРОЧИТАЛ. Под журналом читать нечего: проекция рождает каталог с нуля из
событий, и её собственная версия — правда о том, кем этот файл написан. Ложью
Ф2.2 было «файл на диске версии N, мы переписали его содержимое и объявили
версию 1»; здесь содержимое построено нашим кодом, и наша метка честна.
Безопасность при этом не исчезает, а переезжает этажом выше: журнал, написанный
более новым бинарём, отсекается эпохой журнала и `must_understand` записи
(PROP-044 §4.5), а не меткой каталога. Спек-дифф Ф3 обязан дописать эту клаузу к
`##THE-WRITER-KEEPS-THE-VERSION-IT-READ`, иначе факт будет читаться как
опровергнутый. *Отвергнуто:* нести версию каталога отдельным событием — это
делает версию ФОРМАТА состоянием ДАННЫХ, то есть путает две оси; *отвергнуто:*
молча оставить противоречие — факт без клаузы читается следующей сессией как
дрейф.

**Ж3. Журнал живёт по пути-входу, умолчание — `<data-dir>/state/journal/`.**
Замер физики закрыл вопрос числами: `commit_and_push` делает `git add -A` из
корня data-dir (`crates/vibe-index/src/publish.rs:78`), а единственное правило
`.gitignore`, которое пишет `init`, — `/state/`
(`crates/vibe-index/src/cli/init.rs:77`). Значит `journal/` рядом с проекцией
уезжает клиентам тем же коммитом — прямое нарушение рулинга 2026-08-13; а под
`state/` закрыты все три клиентские двери (git, карта `repomd::files`, шесть
HTTP-маршрутов), и НИ ОДИН существующий тест от этого не краснеет. Путь при
этом остаётся **входом**, а не константой: рулинг сам предписывает для
публичного деплоя отдельный репозиторий, и захардкоженный каталог был бы ровно
той случайностью, которую директива усилий запрещает. *Отвергнуто:*
`<data-dir>/journal/` (уезжает клиентам); *отвергнуто:* хардкод `state/journal/`
без входа (делает предписанную рулингом публичную форму недостижимой из кода).

**Ж4. Публикация журнала через git-CAS в Ф3 НЕ строится — именованный дефер.**
Цикл «push только fast-forward; проигравший re-fetch → повтор append в хвост →
push» сегодня не реализован ни одной строкой: во всём `vibe-index` нет ни одного
`git fetch`/`git pull`, а отказ push лечится warn-ом и счётчиком без повтора
(`crates/vibe-index/src/server/routes/packages.rs:418-425`). Строить его сейчас
значит строить механизм под потребителя, которого нет: публичного деплоя не
существует, и его наступление — слово владельца (D13), а не техническое
событие. *Триггер постройки:* объявление владельцем первого показа публике ЛИБО
появление второго писателя одного журнала — что наступит раньше.

**Ж5. Сброс есть ЗАПИСЬ-ВОДОРАЗДЕЛ, и он никогда не усекает журнал.** Журнал —
append-only истина (PROP-044 §3); усечение уничтожает её и нарушает
[`##LAW-NO-UNRECOVERABLE`](../../spec/common/PROP-044-change-native-formats.md#laws).
Значит `--full` дозаписывает событие-водораздел, после которого реплей начинает
свёртку с пустого множества записей; события до него остаются в файлах и
остаются читаемыми — просто перестают вносить вклад. Шардирование от этого не
меняется (водораздел — обычная строка), `journal/checkpoint.json` сохраняет
смысл курсора проектора. *Отвергнуто:* физическое усечение/архивация (уничтожает
истину); *отвергнуто:* компенсирующие `Removed` на каждую исчезнувшую запись —
они утверждали бы АКТ удаления, которого никто не совершал, и раздували бы
журнал на O(n) лжи.

**Ж6. Водораздел сбрасывает только то, что скан способен воспроизвести.**
Надгробия, отзывы, заморозки и уведомления — факты реестра, а не продукт скана:
пересканирование их не восстановит, поэтому сброс, уносящий их, делает состояние
невосстановимым — тот же запрет, что в Ж5. Значит водораздел очищает множество
опубликованных ЗАПИСЕЙ и не трогает журнальные факты, которые проектор применяет
поверх из всего журнала. Это же снимает мину Ф1.4 «полный reindex стирает
надгробия» — и снимает её ШИРЕ, чем она была записана: замер показал, что
инкрементальный reindex стирает их точно так же (оба строят свежий `Index::new`
и переносят только `iter_versions()`), то есть дефер был назван у́же дефекта.

**Ж7. Карантин при проекции всегда пуст, и это не потеря.** Карантин возникает
только при ЧТЕНИИ чужого каталога читателем, которому не хватает возможностей;
журнал — наша истина, и отвергнутая запись в него не попадает. Носитель
`Index.quarantined` остаётся в памяти и наполняется только на пути чтения.

**СТОП-ВЛАДЕЛЕЦ (Ж8): что значит `--full` для записи, которую скан больше не
видит.** Сегодня она исчезает молча (`cli/reindex.rs:252-291`) — и это уже
нарушает [`##FORBID-SILENCE`](../../spec/common/PROP-044-change-native-formats.md#laws)
для имени, потерявшего все версии. Две прочтения защитимы, и законы их НЕ
разводят: *(а)* «скан есть полная правда» — исчезнувшее хоронится надгробием с
причиной «источник больше не отдаёт»; *(б)* «скан есть наблюдение» — запись
удерживается и помечается ненаблюдавшейся, потому что причиной пропуска бывает
сеть, лимит или отозванный доступ, а не удаление. Цена ошибки асимметрична и в
разные стороны: (а) хоронит живой пакет по сетевому сбою, (б) вечно держит
удалённый. Рядом стоит второй вопрос того же владельца: `rescan-org` объявлен
как обновление кэша организации, а идёт с `mode = "full"`
(`cli/rescan_org.rs:72`) — то есть глагол «обновить кэш» сегодня сбрасывает
каталог. Босс не выбирает: угадывание здесь и есть тот отказ, который PROP-044
запрещает. **Ф3 режется без этого решения** — водораздел (Ж5/Ж6) строится, а
семантика исчезнувшей записи остаётся сегодняшней до рулинга.

*(Если Ф0.1 сказал «не укладываемся» — вместо Ф3 исполняется задокументированный
запасной путь D3 и ТЗ возвращается владельцу на пересмотр объёма.)*

**Р1. Шаг Ф4.0 заводится ПЕРЕД всеми и садится отдельным коммитом.** Генератор
учится видеть схемы в подкаталогах и раскладывать выход ПО ПУТИ, а не по стему.
*Почему путь, а не плоская укладка:* каталог схемы несёт **эпоху**
(`schemas/index/e1/…`), и это требование
[`##M-EPOCHS`](../../spec/common/PROP-044-change-native-formats.md#machinery) —
тяжёлый перелом чеканит новый мир новым путём. Плоская укладка убила бы
механизм эпох ради удобства одного шага. *Почему не по стему:* `…/e1/entry` и
будущая `…/e2/entry` дают ОДИН стем — коллизия, которая проявилась бы ровно в
день первого настоящего поезда эпох, то есть позже всего. **Красное
доказательство — пункт приёмки:** схема, положенная в подкаталог, обязана быть
показана НЕВИДИМОЙ сегодняшним кодогеном (выход не появился, `check-codegen`
зелёный) и видимой после шага. *Отвергнуто:* класть схемы плоско (убивает
эпохи); чинить это внутри Ф4.1 (тогда шаг несёт две несвязанные причины и его
дифф нечитаем).

**Р2. Политику несёт СХЕМА, и молчание схемы — ошибка генерации.** Аннотации
в JTD `metadata` проверены прогоном: jtd-codegen принимает ключи `x-…` молча
(exit 0) и в Rust не переносит (спайк §4) — то есть канал есть, и читать его
обязан наш слой. Правило одно, а не четыре: **везде, где нужна политика, схема
её называет, и отсутствие аннотации — ошибка генерации** (эту форму А.5 №3 уже
требует для коллекций; здесь она распространяется на всё остальное):
`x-vocabulary: open|closed` на каждом `enum`; `x-empty: omit|emit` на каждой
коллекции; `x-default: <литерал>` на каждом опциональном скаляре;
`x-rust-type: "<путь>"` там, где строка на проводе есть доменный тип в коде.
*Отвергнуто:* выводить политику из формы (закрытость enum'а не отличает
`PackageKind` от `NamingConvention` — измерено); умолчание «открыто, если не
сказано» (умолчание, которого автор схемы не видел, и есть та случайность,
которую запрещает директива усилий).

**Р3. Доменные типы СОХРАНЯЮТСЯ — генератор эмитит их по `x-rust-type`.**
*Почему:* генератор, чей выход строго хуже заменяемого им рукописного кода, —
не фундамент, а понижение, надетое на автоматизацию. Замена `Group` и
`semver::Version` на `String` сняла бы ровно ту типизацию, ради которой эти
newtype'ы заведены. *Отвергнуто:* оставить `String` и конвертировать на
границе — это прослойка совместимости между проводом и доменом, а прослойки
запрещены
[`##MIGRATION-TAXONOMY`](../../spec/common/PROP-044-change-native-formats.md#placement);
*отвергнуто:* двинуть дерево на `String` (регресс качества ради удобства
генератора). *Пересмотр:* если окажется, что доменный тип не выразим ссылкой
(например, требует дженерика) — доклад, а не молчаливый `String`.

**Р4. `Event` журнала становится СГЕНЕРИРОВАННЫМ, и его плечи `match`
переписываются тем же шагом.** *Почему:* иначе `journal.jtd.json` описывает
формат, чьи типы живут отдельно, и G9 («словарь существует ровно в одной
схеме») держится процедурой, а не машиной — а весь смысл фазы в том, чтобы
перестать держать законы процедурой. При Р2+Р3+Р5 сгенерированный `Event`
эквивалентен рукописному по типам и по проводу. *Цена, названная заранее:*
варианты выходят newtype'ами (`Published(EventPublished)`) вместо структурных
(`Published { entry }`) — на проводе то же самое, в Rust меняется КАЖДОЕ плечо
`match` в проекторе; это механическая правка, входящая в периметр шага.
*Отвергнуто:* оставить `Event` рукописным и внести его в белый список Ф4.3 —
это исключение на САМОМ НОВОМ формате дерева, то есть правило, рождающееся уже
с дырой.

**Р5. Преобразований у генератора СЕМЬ, а не четыре** (Приложение А.5
дополняется; порядок сохраняется):
1. закрытый enum → открытый — **по `x-vocabulary`, а не по факту закрытости**;
2. camelCase → snake_case (снимает `#![allow(non_snake_case)]` в обоих
   потребителях: `crates/vibe-wire/src/lib.rs:52` и одноимённый в engine-крейте);
3. политика пустого по `x-empty`;
4. `deny_unknown_fields` по реестру (`foreign_parsers = "none"`);
5. **`Option<Box<скаляр>>` → `скаляр` + `default` + именованный предикат** по
   `x-default` — иначе двухсоставная ось получает третье состояние; заодно
   снимается бессмысленный `Box` у скаляров;
6. **`DateTime<FixedOffset>` → `DateTime<Utc>`**;
7. **боксирование крупного варианта объединения** — измерено прогоном: на
   нагрузке настоящего размера clippy падает `large_enum_variant` и сам
   предлагает `Box`, а сгенерированный файл руками не правят.
   *Отвергнуто:* `#![allow(clippy::large_enum_variant)]` в сгенерированном
   модуле — подавление линта, который в этом дереве уже поймал реальный дефект
   (Ф3.1, вариант ~900 байт), и прецедента подавления в дереве нет.

**Р6. `xtask/src/codegen.rs` раскалывается в каталог-модуль ПЕРВЫМ делом Ф4.2.**
534 из 600 — постпроцессор «в несколько сотен строк» не влезает. Шов уже
готов: блок `format_id` (`:294-534`, ~240 строк). Прецедент формы в xtask есть
(`batch_review/`, `mirror/`). *Отвергнуто:* ужать постпроцессор под остаток в
66 строк (объём не довод — но и обратное верно: бюджет не повод писать хуже).

**Р7. Ф4.3 садится РЕХЕТОМ (К4), а «реестр + маркер» (К2) — именованный дефер.**
Правило белого списка существует и найдено — К2: файл с рукописным derive несёт
в себе тег формата, тег джойнится с `formats/REGISTRY.toml`, и если у записи
есть построенная JTD-схема, файл красный. Но К2 требует разовой волны
аннотирования всех 133 файлов, а Ф4.2 ровно эти файлы и мигрирует — аннотировать
их ДО миграции значит размечать то, что вот-вот изменится. Поэтому Ф4.3 ставит
рехет по крейтам против замороженной базовой линии (форма доказана соседом:
`conform-baseline.json` + шаг 5 панели): красный — любой рост счётчика.
Периметр гейта включает `xtask/` (иначе `xtask/src/sync_engines.rs` — тот самый
70-й файл — выпадает из гейта, который для него и существует).
*Триггер К2:* посадка Ф4.2, после которой мигрированные эмиттеры перестают
нести рукописный derive. *Отвергнуто:* К1 «по путям» — перечисление, надетое на
имена каталогов; К3 «по крейту-владельцу» — опирается на поле `owner`, которого
в реестре НЕТ (запись несёт шесть ключей: `corpus`, `epoch`, `foreign_parsers`,
`recoverable`, `schema`, `sunset`).

**Р8. Словарь живёт в ОДНОМ документе-словнике, и подстановку делает наш слой
ДО вызова jtd-codegen.** Замер 2026-08-15 нашёл, что G9 нарушен уже сегодня:
`package_kind` записан дословно в `schemas/list_report.jtd.json` и
`schemas/registry_sync_report.jtd.json`, то есть `entry.jtd.json` стала бы
ТРЕТЬЕЙ копией, а не первым нарушением. Починить это средствами JTD нельзя:
форма `ref` разрешается только против `definitions` того же документа —
межфайловых ссылок в языке нет (проверено прогоном). Значит разделение
словаря — восьмой механизм нашего слоя, ровно по букве PROP-044 §4.2 («что
язык схем выразить не может, эмитит наш генератор»): схема называет словарь
аннотацией `metadata."x-vocabulary-ref"`, слой подставляет определение из
одного словника. **Две сегодняшние копии уходят в ту же подстановку** — иначе
фаза закрывает G9 на новых форматах и оставляет открытым на старых. И
**валидацию ссылок слой делает САМ**: на висячей ссылке jtd-codegen не
отказывает, а ПАНИКУЕТ (`no entry found for key` + stack trace), то есть у
ошибки формы нет ни сообщения, ни рецепта — прямое противоречие
[`##AGENT-MESSAGES`](../../spec/common/PROP-044-change-native-formats.md#agents).
*Отвергнуто:* сложить все форматы в один JTD-документ ради общих
`definitions` — тогда путь схемы перестаёт нести эпоху (§4.6) и обесценивается
весь Ф4.0.

**Ф4.0 — Генератор видит подкаталоги (Р1). СЕЛА 2026-08-15** — три коммита:
`9c1ce20d` (раскол по шву `format_id`, чистый рефакторинг), `33b9ce59` (спуск
и зеркальный выход), `f1ba88e0` (отказ на сегменте, который не может быть
модулем). `schemas_under` стал рекурсивным и сортирующим; выход раскладывается
по относительному пути схемы; `mod.rs` синтезируется на КАЖДОМ уровне;
маршрут ключится ДОМОМ схемы, а не стемом; `generated_dir_for` удалена.

*Три поправки по факту исполнения — каждая меняет то, что следующий шаг
считает данностью.*

**(i) Маршрут по стему был вторым дефектом того же корня, и план его не
называл.** Схемы обоих домов сваливались в один плоский список, а дом, из
которого схема пришла, отбрасывался: вторая схема в engine-доме с любым
именем, кроме `specmap`, уехала бы в `vibe-wire`. Починено тем же шагом —
пары «дом → каталог выхода» стали явными.

**(ii) Молчание было и в сборе схем.** Прежний `filter_map(|e| e.ok())`
проглатывал ошибку обхода и отдавал пустой результат, который `check-codegen`
встретил бы зелёным, — ровно та болезнь, ради лечения которой шаг существует.
Ошибки теперь распространяются с контекстом.

**(iii) Имя схемы, не являющееся идентификатором Rust, роняло СБОРКУ ЧУЖОГО
КРЕЙТА, а не кодоген.** Найдено боссовой пробой: `by-cap.jtd.json` даёт
`pub mod by-cap;`, кодоген выходит с НУЛЁМ, а отказ приходит парсером в
`vibe-wire` — без имени схемы и без рецепта. По стему дефект существовал и до
фазы; каталоги его расширили, поэтому сторож лёг в шаг, который расширил.
Проверяется форма сегмента И **набор ключевых слов Rust** (`type`, `crate`,
`match` — слова, к которым автор схемы тянется естественно), отказ называет
схему, сегмент и переименование. Шесть будущих имён Ф4.1 (`entry`, `repomd`,
`by_name`, `by_cap`, `by_purl`, `journal`) закреплены тем же тестом как
законная сторона утверждения.

*Приёмка предъявлена обеими половинами.* Красное: тест спуска прогнан против
плоской реализации и показан упавшим (нашёл `a.jtd.json`, не нашёл
`sub/deep/b.jtd.json`). Зелёное: семь существующих целей не сдвинулись ни
байтом (`check-codegen: clean`), а проба `schemas/probe/e9/pathcheck.jtd.json`
легла в `generated/probe/e9/pathcheck/` с `mod.rs` на каждом уровне (проба
откачена). Панель — `self-check: all green`, реальный код выхода 0, 51 шаг.

**Р9. Ф4.1 режется НАДВОЕ, и порядок половин вынужденный.** Схема, ссылающаяся
на общий словарь, не может лечь раньше, чем ссылки заработают: `ref` на имя,
отсутствующее в локальных `definitions`, роняет jtd-codegen паникой. Значит:

- **Ф4.1a — словник и подстановка** (носитель Р8): `formats/vocabularies.json`,
  модуль подстановки в нашем слое, четыре именованных отказа вместо паники, и
  **две сегодняшние дублирующие схемы переводятся на словник тем же шагом**.
  Дом словника — `formats/`, а НЕ `schemas/`: сканер после Ф4.0 берёт
  `*.jtd.json` рекурсивно, и словник под `schemas/` генератор попытался бы
  собрать как отдельный формат.
- **Ф4.1a — СЕЛА 2026-08-15**, коммит `c7faa208`. Словник
  `formats/vocabularies.json`, модуль подстановки
  `xtask/src/codegen/vocabulary.rs`, четыре именованных отказа вместо паники
  бинаря, обе дублирующие схемы переведены. Решающее доказательство пришло
  зелёным: `check-codegen: clean` — схемы перестали дублировать словарь, а
  сгенерированный Rust побайтово тот же. Красное предъявлено на отказе по
  висячей `ref`. *Именованное следствие, а не дефект:* карта потеряла две
  записи (`list_report::package_kind`, `registry_sync_report::package_kind`) —
  специмап метит определения ВНУТРИ JTD-схем, а единственный дом словаря вне
  его периметра. Проба показала, что переименованием это не лечится (карта
  смотрит только в `schemas/`, а `check-codegen` от переименования падает —
  имя словника несущее). Починка требует тронуть движок дисциплины, что §2
  запрещает прямым текстом ⇒ **дефер по имени**.
- **Ф4.1a-2 — подстановка становится ТРАНЗИТИВНОЙ** (решение босса
  2026-08-15, до нарезки Ф4.1b). Разбор инвентаря показал то, чего план не
  видел: `by_name.jtd.json` и `journal.jtd.json` транзитивно содержат
  `VersionEntry` ЦЕЛИКОМ (`NameEntry` → `PackageEntry` → `VersionEntry`;
  `Event::Published { entry }`), а межфайловых ссылок JTD не имеет — значит
  тридцатиполевая структура с четырнадцатью вложенными типами была бы
  записана ТРИЖДЫ. Это болезнь G9 этажом выше: не словарь-строка, а составной
  фрагмент. Значит словник хранит и составные фрагменты, а запись словника
  вправе сама объявить `x-vocabularies` — резолвер замыкает набор транзитивно
  и отказывает на цикле. *Отвергнуто:* каждая схема перечисляет полное
  замыкание руками — это перечисление в другой одежде (тот же довод, которым
  отвергнут кандидат К1 в правиле белого списка): добавление поля, тянущего
  новый вложенный тип, потребовало бы править каждую схему, которая его
  тянет. *Отвергнуто:* оставить дублирование для составных и делить только
  словари-строки — тогда закон закрывается на дешёвом случае и открыт на
  дорогом.
  **Ф4.1a-2 СЕЛА 2026-08-15**, коммит `71e94e8f`. Замыкание транзитивно,
  цикл и самоссылка отказывают с называнием участников, недостающее имя
  называет ЦЕПОЧКУ, вставка отсортирована, `x-vocabularies` снимается с
  внедрённого фрагмента. Красное предъявлено полностью: все восемь новых
  тестов упали против непра́вленого резолвера. *Попутно найден живой дефект
  предыдущего шага:* проверка столкновения имён сравнивала с картой
  определений В ПРОЦЕССЕ заполнения, поэтому имя, названное в аннотации
  дважды, ложно срабатывало как столкновение с собственной вставкой
  подстановки; теперь снимок «своих» определений берётся до вставки.
- **Ф4.1b — шесть схем каталога** поверх работающей транзитивной подстановки.
  **Режется по два шага, и первый несёт метод проверки для всех остальных:**
  - **Ф4.1b-1 — запись версии и оракул.** `version_entry` со всем замыканием
    едет в словник (её транзитивно содержат ещё две схемы), а
    `schemas/index/e1/entry.jtd.json` — схема, чей КОРЕНЬ есть ссылка на
    фрагмент; форма проверена прогоном и даёт `pub type Entry = VersionEntry;`
    плюс саму структуру. **Сторож — дифференциальный оракул через ПРОВОД:**
    полностью заполненная рукописная запись → JSON → сгенерированный тип →
    JSON → равенство `Value`. Он и только он ловит пропущенное поле; сравнение
    идёт по проводу, а не по типам, потому что типы расходятся намеренно
    (`String` вместо `Group`, `Option<Box<bool>>` вместо `bool`) до тех пор,
    пока Ф4.2 не даст преобразования. Красное — удалить одно поле из
    фрагмента, показать падение, вернуть.
  - **Ф4.1b-2 — остальные пять схем** тем же методом. **СЕЛИ 2026-08-15:**
    `by_name`, `by_cap`, `by_purl` — `b000e51f`; `repomd` — `456c4ea9`.
    Семь красных доказательств за две посадки, из них два стоят отдельного
    упоминания: удаление поля из ОБЩЕГО фрагмента роняет оракул `by_name` на
    ТРЕТЬЕМ уровне вложенности (через пакет и версию) — это и есть свойство,
    делающее общий фрагмент безопасным для деления; и удаление целого плеча
    объединения роняет уже `from_value` («unknown variant»), то есть оракул
    сторожит полноту объединения, а не только поля внутри выжившего плеча.
    *Найдено попутно и записано как B-056:* у JTD нет 64-битного целого вовсе
    (генератор отвергает `uint64` и `int64`), а писатель объявляет `size: u64` —
    то есть наш писатель способен породить документ, который наша же схема
    объявляет невалидным. Развилка владельца, три выхода измерены.
  - **Ф4.2a — боксирование варианта объединения, ВПЕРЁД остальных
    преобразований** (решение босса 2026-08-15, по замеру). Схема журнала не
    может лечь раньше: измерено на пробе с настоящим фрагментом записи —
    сгенерированное объединение роняет `large_enum_variant`, clippy сам
    называет починку `Box<…>`, сгенерированный файл руками не правят, а
    подавления этого линта в дереве нет ни одного (его решали осознанным
    `Box`, и именно он поймал реальный дефект в Ф3.1). **Форма: боксируются
    ВСЕ плечи дискриминатора, единообразно.** *Почему не порог:* эвристика по
    размеру непредсказуема и поедет с версией clippy. *Почему не аннотация в
    схеме:* схема описывает ПРОВОД, а боксирование есть деталь представления в
    Rust; вносить её в описание формата значит смешивать два разных предмета —
    и это единственный довод, который здесь решает, потому что все прочие
    аннотации Р2 описывают именно формат. Провод не двигается: `serde`
    рендерит `Box<T>` ровно как `T`. Цена названа честно — одна аллокация на
    построение варианта, ничтожная для типов, которые разбирают и проецируют
    по разу.
  - **Ф4.1b-3 — схема журнала. СЕЛА 2026-08-15**, коммит `e0a2248c`. Все
    одиннадцать вариантов описаны и все одиннадцать упражнены; оракул несёт
    таблицу «плечо → число ключей на проводе», а не общий счёт, поэтому плечо,
    тихо потерявшее поле, падает на своей строке. Красное — четырежды, двумя
    сторонами и двумя механизмами: пропавшее ПОЛЕ терпимый читатель роняет
    молча и ловится сравнением, пропавшее ПЛЕЧО отвергается на `from_value` с
    перечислением уцелевших тегов. **Боксирование Ф4.2a подтвердилось на
    настоящей цели:** `large_enum_variant` не сработал.

    *Второй пол JTD, записанный, а не замазанный.* `Renamed` несёт кортежи
    Rust, а типа кортежа у JTD нет: `elements` описывает однородный массив
    любой длины, то есть схема принимает и пустой массив, и три элемента, и не
    закрепляет, какая позиция — группа. Записано в описании самого поля (что
    схема говорит, чего сказать не может, и что проверку арности несёт только
    Rust), плюс оракул пинит длину пары. Тот же класс, что B-056.

  **⇒ Ф4.1 ЗАКРЫТА: шесть схем из шести, у каждой свой оракул.** Всего по фазе
  предъявлено **тринадцать** красных доказательств. Сгенерированное дерево
  выросло с 8 подмодулей до 18.

  *Аннотации политики (`x-vocabulary`, `x-empty`, `x-default`, `x-rust-type`)
  пишутся уже в Ф4.1b, хотя их потребитель — Ф4.2. Это не машинерия впрок:
  схема есть единственный законный дом политики, и написать схему дважды
  дороже, чем написать её сразу верно. Но факт, что сегодня их никто не
  читает, обязан быть сказан вслух в каждом отчёте — иначе следующий читатель
  примет их за работающий механизм.*

*Главное доказательство Ф4.1a — зелёное, а не красное:* смысл шага в том, что
провод НЕ ДВИГАЕТСЯ. Схемы перестают дублировать словарь, а сгенерированный
Rust остаётся тем же до байта — это проверяется `check-codegen` на боссовой
стороне и модульным тестом «разрешённый `definitions.package_kind` равен тому,
что стоял инлайном» на воркерской. Красное отдельно требуется на отказе по
висячей `ref` — он сторожит поведение, которого сегодня нет.

**Ф4.1b — Схема каталога.** `schemas/index/e1/`: `entry.jtd.json`
(VersionEntry + вложенные), `repomd.jtd.json` (с тегированным объединением),

ошибок») прошла бы на фазе, не построившей НИЧЕГО — до Ф4.0 генератор
подкаталогов не видит, а «построил без ошибок» и «построил ноль целей»

доказать пробной правкой и откатить; словарь событий журнала описан во всех
**одиннадцати** вариантах (`Initialised`, `Published`, `Frozen`, `Yanked`,
`Removed`, `Renamed`, `Notice`, `ChannelSet`, `ChannelUnset`, `ForceReplaced`,
`EntrySetReplaced`) — схема, описавшая меньше, описывает формат, которого нет.

*Две последние схемы добавлены 2026-08-14 замером Ф0.3, который нашёл разрыв:
`by-cap/<slug>.jsonl` и `by-purl/<slug>.jsonl` — публикуемые поверхности со

(сегодня писатель `inverted.rs:88` — `kebab-case`, клиент
`index_client/wire.rs:94` — `lowercase`, совпадают случайно: значения
однословные, паритет-теста нет — живой дефект B7).*

**Ф4.2 — `vibe-wire-gen`.** По ветке из Ф0.2: постпроцессор выхода
jtd-codegen (или свой эмиттер) в `xtask/src/wiregen/` (developer tooling,

*Поправки по замеру 2026-08-15 — читать вместе с Р2–Р6 выше.* **(i)** Первым
делом шага — раскол `codegen.rs` в каталог-модуль по шву `format_id` (Р6);

а не текст→текст. **(iii)** Словарей, сводимых в одно определение, **пять**,
а не один: к `BindingSite` добавляются `PackageKind`, `NamingConvention`,

существует, вопреки записанному, так что его копия всё это время стояла без

**третьим** — `primary.jsonl.gz` (О5): сегодня он публикуется, а читается
только несжатый сосед. **(v)** Шов постпроцессора назван замером:
`xtask/src/codegen.rs:185-205`, между проверкой статуса (`:191-203`) и

проверяется — свести ДО того, как постпроцессор будет привязан к форме эмиссии,
не после.

*СВЕДЕНО 2026-08-17, и первая половина утверждения оказалась ЛОЖНОЙ.*
**Расхождения нет и не было:** бинарь отвечает `jtd-codegen 0.4.1`, и ОН ЖЕ
пишет в шапку `// Code generated by jtd-codegen for Rust v0.2.1` — проверено
прямо, прогоном этого бинаря по пробной схеме в scratchpad. Строка шапки
называет версию **Rust-таргета**, а не инструмента; пять сессий две версии
разных вещей читались как одна. Настоящее сведение при этом сильнее любого
сравнения строк и уже стоит в панели: зелёный `check-codegen` утверждает, что
закоммиченные артефакты **побайтово равны** тому, что пиненный бинарь эмитит
СЕЙЧАС. *Класс, шире случая:* это тот же дефект измерения, что и «пустой вывод
скрипта есть доказательство» (Р20), — величину сравнивали с величиной ДРУГОЙ
вещи, и никто не скормил инструменту случай, обязанный их различить.

*Вторая половина — «ни одним гейтом не проверяется» — верна и остаётся такой
НАМЕРЕННО.* Дом пина (`packages/org.vibevm.ai-native/jtd-codegen/v0.1.0/README.md`,
`##PINNED-VERSION`) говорит прямым текстом: бампить правкой этой одной строки,
**никогда не пересказывая число в дереве потребителя**, и «CI … does not enforce
a particular generator build». Константа версии в `xtask/` была бы второй копией
нормативного значения и молчаливой отменой записанного решения. Что сделано
вместо неё: отказ `check-codegen` перестал знать одну причину — он называет обе
(схемы двинулись против «генератор не тот») с их противоположными рецептами,
потому что прежний единственный рецепт («run codegen and commit») у
контрибьютора с другой сборкой на PATH вписал бы чужую эмиссию в дерево под
видом штатного дрейфа. Коммит `e8d8238f`; красное предъявлено правкой одного
описания схемы и откачено.

**Р10. Слой преобразований ключится ДОМОМ схемы — тем же ключом, которым Ф4.0
маршрутизирует выход.** Хостовый дом `schemas/` получает политику целиком (все
девять целей, включая семь плоских CLI-отчётов); дом движка не получает её
вовсе. *Почему это не бюджетная отговорка:* политика НАШЕГО провода не вправе
связывать публичный Rust-API чужого пакета с собственным поездом релизов —
именно это и запрещает §2, и именно поэтому запрет там сформулирован как
«вовсе». *Отвергнуто:* аннотировать схему движка и переписать его выход
(нарушение §2, плюс рябь в вендоренные зеркала через `sync-engines`);
*отвергнуто:* применять слой сквозь, но не требовать аннотаций у движка — тогда
правило рождается с дырой, а «ошибка генерации» перестаёт быть ошибкой.
*Триггер расширения:* принятие слоя кампанией самого движка.
**Поправка, которую это решение делает обязательной:** запись Р5 №2
(«snake_case снимает `#![allow(non_snake_case)]` в ОБОИХ потребителях, включая
engine-крейт») после Р10 ЛОЖНА — `allow` движка остаётся. Снимается ровно один,
и он не по-файловый, а crate-wide в РУКОПИСНОМ `crates/vibe-wire/src/lib.rs:52`
(в самих сгенерированных файлах его нет ни одного — измерено).

**Р11. Фрагмент `timestamp` переводится на `"type": "timestamp"`, и это правка
СХЕМЫ, а не обход преобразования.** Провод несёт RFC-3339, а схема сегодня
говорит `"type": "string"` — то есть недоописывает формат, который обязана
описывать. После правки генератор выдаёт `DateTime<FixedOffset>`, и его
переписывает то же плечо `x-rust-type`, что и остальные алиасы: №6 перестаёт
быть отдельным правилом и становится входной формой №8. *Почему не оставить
как есть:* тогда у времени в системе две законные записи — `"type": "string"` и
`"type": "timestamp"` — а вторая появится в первой же новой схеме, и разойтись
им ничто не мешает. Одна вещь пишется одним способом. *Цена, названная
заранее:* `crates/vibe-wire` получает зависимость `chrono`, которой у него
сегодня нет вовсе ⇒ `Cargo.lock` входит в периметр шага. *Что доказывает
безопасность:* провод не движется — это меряют шесть оракулов.

**Р12. Девятое преобразование: `HashMap` → `BTreeMap`, безусловное.**
PROP-044 [`##M-SCHEMA-DESCRIBES-FORM`](../../spec/common/PROP-044-change-native-formats.md#machinery)
перечисляет **`canonical ordering`** среди того, что эмитит наш слой, а
[`##M-CANONICAL-BYTES`](../../spec/common/PROP-044-change-native-formats.md#machinery)
требует «одно состояние — одна последовательность байт: sorted keys». Список
преобразований этого просто не выписал. *Почему без аннотации:* у канонического
порядка ровно один законный ответ — это ЗАКОН провода, а не выбор политики; тот
же довод, которым Ф4.2a обосновала безусловное боксирование. *Почему это
успевает стать дефектом:* оракулы к порядку ключей слепы ПО ПОСТРОЕНИЮ (они
сравнивают `serde_json::Value`, чьё равенство порядок-независимо — сказано в их
собственной шапке), поэтому мерцающий `rebuild --check` пришёл бы уже после
реэкспорта, без сторожа между. Ложится ДО реэкспорта.

**Р13. У `x-default` два значения, и отсутствие ключа остаётся ошибкой.**
`x-default: <литерал>` — отсутствие поля ЕСТЬ это значение, поле схлопывается в
скаляр с `default` и именованным предикатом (форма Р1 фазы Ф1.4).
`x-default: null` — отсутствие есть ФАКТ, поле остаётся `Option<T>` и теряет
бессмысленный `Box`. Отсутствие самого ключа на опциональном скаляре — ошибка
генерации, как и требует Р2. *Почему не «требовать литерал всюду»:* это
заставило бы выдумать умолчание для `license` и `resolved_commit`, где
отсутствие — законное третье состояние ФАКТА, а не третье состояние ОСИ (запрет
PROP-044 §2b — про булеву ось, а не про всякую опциональность). *Отвергнуто:*
«требовать аннотацию только там, где иначе появляется третье состояние булевой
оси» — правило по срезу сегодняшних полей, а не свойство системы; ровно тот
дефект, который запрещает `##VOLUME-OF-WORK-IS-NEVER-AN-ARGUMENT`
(`spec/boot/90-user.md`, директива усилий владельца 2026-08-09).

**Р14. Семь вложенных подсекций: `Option<Box<T>>` → `Option<T>`, и это НЕ
развилка — Приложение Б.2 её уже решило.** Б.2 ратифицирует: «пустая проекция
нормализуется в отсутствие ПРОЕКТОРОМ (писатель никогда не пишет
`{"provides":{}}`); читателю оба вида законны». Значит `Option` на стороне
ЧИТАТЕЛЯ верен и обязан остаться — он и есть способ принять `{}` от чужого
писателя; а нормализация пустого — работа проектора, а не skip-предиката типа.
Преобразование здесь только одно: снять бессмысленный `Box`. *Что это стоит и
когда:* при реэкспорте (Ф4.2c) рукописные `compatibility: CompatibilityEntry`
становятся `Option<CompatibilityEntry>`, и это двигает одиннадцать литералов
записи (Р4 фазы Ф1.4) плюс места чтения. Названо здесь, чтобы встретиться с
этим в плане, а не при сборке. *Отвергнуто:* эмитить `is_empty` для
сгенерированных структур и повторить рукописную форму — генератор начал бы
эмитить ПОВЕДЕНИЕ, а не форму, и семантика пустого объекта осталась бы
невыразимой.

**Р15. №4 остаётся правилом, но его сайты сегодня — ноль, и обе мины закрыты
явно.** Пасс осматривает 69 структур и не выдаёт атрибут ни одной (О8) — это
законно: политика реестровая, и запись `[format.config]` получит схему позже.
Две мины закрываются формой правила, а не молчанием: *(i)* когда одна схема
стоит за несколькими форматами с РАЗНЫМИ `foreign_parsers`, политика
неоднозначна — **громкий отказ, называющий схему и обе записи**, никогда не
«первая попавшаяся»; *(ii)* запись реестра, чья `schema` не существует на диске
(`handshake` сегодня), пассом **пропускается по имени с явной строкой в выводе**,
а не роняет сборку и не считается «нет схемы ⇒ политика не нужна». *Отвергнуто:*
отложить №4 до появления первого `none`-формата со схемой — правило, которого
нет в машине, держится процедурой, а вся фаза существует ровно затем, чтобы
перестать держать законы процедурой.

### Решения Р16–Р19 — приняты при нарезке Ф4.2b-1, по замеру слоя

*Босс перемерил дерево перед первой правкой пасса; замер дал две находки сверх
записанного (Р16, Р19) и потребовал решить четырнадцатую копию (Р17).
Исполнитель их НЕ переоткрывает.*

**Р16. Слой сшивается с выходом по МНОЖЕСТВУ wire-значений, а не по имени
типа.** Схемная сторона строит карту «множество значений → политика», и
сгенерированный enum находит свою политику по набору собственных
`#[serde(rename = …)]`. *Почему не по имени:* имя Rust-типа минтит генератор
(pascal_case определения плюс коллизионный суффикс — живой пример `KindName0`),
а варианты он сортирует по wire-строке, а не по порядку схемы (измерено:
`package_kind` объявлен `flow, feat, stack, tool, mcp, lang`, а вышел
`Feat, Flow, Lang, Mcp, Stack, Tool`). Обе величины принадлежат ФОРМЕ ЭМИССИИ,
которую пасс в собственном док-комментарии объявляет пиненной и потому не
вправе воспроизводить у себя. Множество значений обе стороны несут ДОСЛОВНО:
схема — массивом `enum`, выход — набором `rename`. Словарь и ЕСТЬ множество
своих значений. *Отвергнуто:* сшивка по pascal_case имени определения —
переизобретение правила именования генератора внутри пасса, который от этого
правила как раз и защищается. *Отвергнуто:* сшивка по порядку следования —
порядки разные. *Столкновение:* два сайта с одним множеством и РАЗНЫМИ
политиками — громкий отказ, называющий множество и обе политики; одно
множество с одной политикой законно (диамант подстановки словника доставляет
один фрагмент двумя маршрутами).

**Р17. `init_report.outcome_action` — ОТКРЫТЫЙ словарь.** Это та
четырнадцатая копия, которую §7 оставил долгом аннотации. *Почему:* реестр
исходов — растущее описание того, что команда сделала с файлом, и он вправе
пополниться (`replaced`, `skipped`); у незнакомого исхода есть очевидно
безопасное поведение — показать строку как есть; из значения не строится ни
путь, ни решение. *Отвергнуто:* закрытый — тогда отчёт, написанный более новым
`vibe`, роняет разбор у старого читателя без всякой выгоды, а PROP-044 §4.2a
делает терпимость структурной именно для этого случая. *Счёт после решения:*
из 14 копий **11 открытых** (PackageKind ×7, DeliveryMode ×3, OutcomeAction ×1)
и **3 закрытых** (NamingConvention ×2, BindingSite ×1). Строка внесена в
Приложение Б.1.

**Р18. Сторож числа: enum-сайтов схемы == словарных enum'ов в выходе.** Пасс
считает и то и другое и отказывает на расхождении. *Зачем:* без счётчика
пропуск дискриминаторных объединений остаётся тем СОВПАДЕНИЕМ, каким он был у
спайка Ф0.2 — там сканер не входил в объединение лишь потому, что между
`#[derive(…)]` и `pub enum` стоит `#[serde(tag = …)]`. Приложение А.5 №1 уже
требует, чтобы пропуск был НАЗВАННЫМ правилом с тестом; счётчик — та машина,
которая делает правило проверяемым: сдвинулась форма эмиссии, словарь молча
проскользнул мимо сканера — числа разошлись, генерация отказала. *Проверено
поимённо по всем 13 схемам* (сайтов на схему): install_plan 0, install_report 0,
uninstall_report 0, registry_publish_report 0, init_report 1, list_report 1,
registry_sync_report 1, by_cap 1, repomd 1, by_purl 2, by_name 2, entry 2,
journal 3 — сумма 14, ровно число копий в выходе.

**Р19. Порядок пассов — закон; и Р10 связывает ВЕСЬ слой, а не только новый
пасс.** *Порядок:* пасс, привязанный к форме эмиссии генератора, обязан
работать, пока файл ЕЩЁ ЕСТЬ выход генератора; открытие словарей вписывает в
файл рукописный Rust (`impl Serialize` / `impl Deserialize`), которого форма
эмиссии не содержит. Поэтому боксирование идёт первым, открытие вторым.
*Область:* Р10 говорит «дом движка не получает политику ВОВСЕ», а боксирование
— преобразование №7 списка Р5, то есть часть той же политики. Значит
пост-обработка ЦЕЛИКОМ не применяется к чужому дому. Сегодня это не двигает его
выход ни на байт: у схемы движка 4 enum-сайта и НОЛЬ `discriminator` (измерено),
то есть боксирование там и так было no-op — правка делает Р10 истинным в
машине, ничего не ломая, и проверяется побайтовым сравнением выхода движка до и
после. *Форма:* дома называют своего владельца (`FormatOwner::{Ours,Foreign}`)
в том же литерале, где названы их каталоги, а не классифицируются заново ниже
по стеку: третий дом обязан назвать владельца, а не получить его умолчанием.

**Р20. Rename снимается ТОЛЬКО тождественный — и это правило оказалось
старше собственного числа.** Пасс №2 переименовывает идентификатор поля в
snake_case и снимает `#[serde(rename = …)]` лишь там, где тот повторял бы
новое имя; rename, чья wire-строка ОТЛИЧАЕТСЯ от `snake_case(идентификатора)`,
несёт информацию и остаётся. Инвариант: **провод не двигается ни в одной
ветке** — либо идентификатор равен проводу и serde берёт его по умолчанию,
либо rename сохранён; третьей ветки нет.

*Почему это записано решением, а не деталью реализации.* Замер, из которого
резался шаг (находка `f4-transform-radius.md` §5), утверждал, что
исключений НОЛЬ и потому избыточны **все 309** полевых rename. Утверждение
ложно, и скрипт, на котором оно стояло, **не мог сработать ни на одном поле**
(шаблон требовал конца строки сразу после двоеточия; проверено прямо —
скрипту скормили поле с намеренно другим проводом, он промолчал). Исключение
одно: `schemas/registry_sync_report.jtd.json:48` объявляет свойство `ref` —
ключевое слово Rust, генератор эскейпит идентификатор в `ref_`, и
`snake_case("ref_") != "ref"`. Пасс, построенный по измеренному числу,
опубликовал бы `"ref_"` вместо `"ref"` — молчаливый перелом формата, у
которого НЕТ оракула, то есть в точности запрещённый
[`##LAW-NO-LYING`](../../spec/common/PROP-044-change-native-formats.md#laws)
класс. Правило спасло шаг там, где измерение солгало; поправка внесена в
находку, а живой случай закреплён собственным тестом.
*Следствие, шире этого шага:* свойство схемы, названное ключевым словом Rust
(`ref`, `type`, `match`, `crate`…), — постоянный класс, и всякое будущее
преобразование, трогающее ИМЕНА, обязано сверяться с проводом, а не с
правилом регистра. *Отвергнуто:* «снять все 309, замер же показал ноль
исключений» — правило по срезу, ровно то, что запрещает
`##VOLUME-OF-WORK-IS-NEVER-AN-ARGUMENT`.

**Р21. Обязательность коллекции ОГРАНИЧИВАЕТ её политику пустого, и это
снимает десять вопросов разом.** Для преобразования №3 (`x-empty`):

| требуемость | политика | что делает слой |
|---|---|---|
| обязательное | `emit` | ничего: эмиссия уже `Vec<T>`/`BTreeMap<…>` без skip |
| обязательное | `omit` | **ошибка генерации** |
| опциональное | `omit` | `Option<Box<C>>` → `C` + `default` + `skip_serializing_if = "<C>::is_empty"` |
| опциональное | `emit` | `Option<Box<C>>` → `C` + `default`, без skip |

*Почему обязательное + `omit` — ошибка, а не выбор:* в JTD члены
`properties` ОБЯЗАТЕЛЬНЫ, и писатель, опускающий пустую обязательную
коллекцию, породил бы документ, невалидный по его же собственной схеме —
ровно «неверный ответ, похожий на верный»
([`##LAW-NO-LYING`](../../spec/common/PROP-044-change-native-formats.md#laws)).
*Следствие для долга:* все десять неаннотированных сайтов — обязательные
(измерено), значит все десять получают `emit`, и не по вкусу, а потому что
второго законного варианта у них нет. Для них слой не меняет ни строки кода:
шаг покупает у них ЗАПИСАННОЕ решение. Пятнадцать `omit` — все опциональные,
и все пятнадцать схлопываются (13 `Vec`, 2 `BTreeMap`).
*Уточнение счёта, попутно:* сайт политики — это ПОЛЕ, то есть коллекционная
форма, стоящая значением члена `properties`/`optionalProperties`. Внутренние
узлы (тип значения карты) сайтами не являются — у них нет и не может быть
skip-атрибута; наивный обход даёт 33 узла там, где полей 31, и число находки
верно.

  JTD нет `nullable`, оказалось ложным — исправлено на месте (`351a9594`),
  разрешимая теперь правка записана как `BACKLOG.md` **B-078**.
  *Названный предел:* литерал, отличный от булева, требует эмиссии
  именованной функции умолчания; сайтов ноль, пасс отказывает громко.
- **Ф4.2b-6 — №4 (Р15), `deny_unknown_fields` по реестру. СЕЛА 2026-08-17**,
  коммит `0fd7ce2d`. **Пасс не изменил в сгенерированном дереве НИ ОДНОГО
  БАЙТА, и это доказанный правильный результат:** единственная роль `none` в
  реестре — `[format.config]`, у которой `schema = "none"`, поэтому прогон
  осматривает 69 структур и не выдаёт атрибут ни одной. Куплено то, ради чего
  фаза существует, — правило переехало из прозы в машину. Обе мины закрыты
  формой: расхождение ролей на одной схеме — громкий отказ (сайта нет,
  доказано тестом), а запись с непостроенной схемой пропускается ПО ИМЕНИ,
  строкой в выводе прогона: `[format.handshake] names schema
  schemas/hello/e1/hello.jtd.json, which no phase has built yet — no
  reader-strictness policy applied`. Реестровый загрузчик стал хранить путь
  `schema`, который прежде разбирал и выбрасывал: один загрузчик — одна
  правда о реестре.
- **Ф4.2b-7 — №8 (Р10/Р11), доменные типы. СЕЛА 2026-08-17**, коммит
  `c2c240b3` — **БЛОК Ф4.2b ЗАКРЫТ, семь шагов из семи.** Правая часть трёх
  скалярных псевдонимов, имя корня журнала, перевод фрагмента `timestamp` на
  `"type": "timestamp"`. Числа после шага: псевдонимов 15, из них три несут
  доменную правую часть, `Entry` не тронут; `pub type … = String` у
  Group/Version/Timestamp — 0; `pub struct Journal` — 0, `pub struct
  JournalRecord` — 1; `use chrono` в сгенерированном дереве — **0**; дом
  движка и `format_id/mod.rs` байт-в-байт (проверено `diff -r` и `cmp` против
  снимка ДО) — Р10 держится машиной, а не прозой. **Главное доказательство —
  зелёные пять `wire_parity_*`** на полностью заполненных фикстурах: типы под
  ними сменились, байты провода нет.

  *Четыре поправки по факту исполнения — каждая от дерева.* **(i) Дефектов
  данных оказалось ДВА, а не один.** Р22 называла только `group`; вторым
  оказалась аннотация самого `timestamp` — `chrono::DateTime<Utc>` — путь
  полуквалифицированный, разрешимый лишь пока в файле стоит чужой импорт. Это
  породило **Р23** (ниже). **(ii) Радиус ВНУТРИ `generated/**` шире, чем
  «правая часть»:** с `"type": "timestamp"` генератор добавляет строку
  `use chrono::{DateTime, FixedOffset};` — измерено прогоном настоящего
  бинаря до нарезки, — и самодостаточный путь осиротил ОБА её item'а. Пасс
  обязан снимать осиротевшее, иначе `unused_imports` под `-D warnings`
  краснеет на файле, который руками не правят. **(iii) Раскол по бюджету
  пошёл другим швом, чем угадал пакет:** родитель (`domain_types.rs`, 520
  строк) держит точку входа и перезапись эмиссии, ребёнок
  `domain_types/rulings.rs` (186) — то, что постановляет СХЕМА; имя файла
  следует содержанию, поэтому не `emit.rs`. **(iv) Форма отказа плечу ИМЕНИ
  чуть не съела сама себя:** сопоставитель объявления снимал `{` и оставлял
  хвостовой пробел, приклеенный к идентификатору, — на КАЖДОЙ настоящей
  строке объявления он возвращал «не узнал», карта объявлений выходила пустой
  и плечо ИМЕНИ отказывало на файле, где лежало ровно то, что оно искало.
  Поймано красным прогоном (6 упавших тестов из 176), не чтением диффа.

**Р22. У `x-rust-type` два плеча, и какое из них — решает ФОРМА определения.**
Аннотация стоит на определении; если определение выходит **псевдонимом**
(примитивная форма `type`), она задаёт его ПРАВУЮ ЧАСТЬ; если выходит
**структурой или перечислением**, она задаёт ИМЯ типа. Спутать нельзя: у
скалярного фрагмента аннотация не может называть имя псевдонима
(`pub type Group = Group;` бессмыслен), а у структуры не может называть тип —
её тип это она сама.

*Инвентарь (измерено, 8 аннотаций).* Плечо ИМЕНИ: `binding_site`→`BindingSite`,
`event`→`Event`, `naming_convention`→`NamingConvention`,
`version_entry`→`VersionEntry` — четыре уже удовлетворены; **корень журнала
→`JournalRecord` — единственное расхождение**, и токен `Journal` встречается в
сгенерированном файле ровно один раз. Плечо ПРАВОЙ ЧАСТИ: `group`, `version`,
`timestamp` — ни одно не удовлетворено (все три выходят `= String`).
Псевдонимов в дереве 15; `Entry` без аннотации и не трогается; употребления
полей (`: Group` 13, `: Version` 9, `: Timestamp` 7) не меняются — меняется
только правая часть.

*Дефект данных, который шаг обязан починить.* `formats/vocabularies.json`
у фрагмента `group` несёт `"x-rust-type": "Group"` — имя собственного
псевдонима, для скалярного плеча непригодное; её же `description` называет
верную цель. Исправляется на `"vibe_core::Group"`.

*Радиус впервые выходит за `generated/**`, и периметр обязан это назвать.*
`crates/vibe-index/tests/wire_parity_journal.rs:42` импортирует
`journal::Journal as GeneratedJournal` — одна строка. И `crates/vibe-wire`
получает три зависимости (`vibe-core`, `semver`, `chrono`), то есть
`Cargo.toml` **и `Cargo.lock`**; все три уже в `[workspace.dependencies]`.
**Цикла нет — измерено: `vibe-core` от `vibe-wire` не зависит**, гейта на
рёбра зависимостей в панели нет.

*Что меняется на проводе — ничего, и это меряют оракулы.* `vibe_core::Group`
несёт `try_from = "String"`, `semver::Version` и `chrono::DateTime<Utc>`
сериализуются строками. Меняется СТРОГОСТЬ чтения: невалидная группа или
версия теперь отказывают при разборе, а раньше проезжали строкой — ровно та
типизация, ради которой newtype'ы заведены (Р3).

**Р23. Аннотация `x-rust-type` называет САМОДОСТАТОЧНЫЙ путь, и пасс приводит
импорты в порядок — принято боссом 2026-08-17 по замеру, до нарезки.**
Самодостаточный = разрешимый БЕЗ импортов файла: `vibe_core::Group`,
`semver::Version`, `chrono::DateTime<chrono::Utc>`. *Почему правило, а не
удобство:* аннотация, чья разрешимость держится импортом ГЕНЕРАТОРА, ломается
в тот момент, когда сдвинется форма эмиссии, — ровно та связь, ради разрыва
которой слой и построен; и пока она полуквалифицирована, у одной вещи в схеме
две законные записи. *Замер, из которого это выросло:* прогон настоящего
`jtd-codegen 0.4.1` по пробной схеме с `"type": "timestamp"` эмитит
`use chrono::{DateTime, FixedOffset};` плюс `pub type Timestamp =
DateTime<FixedOffset>;` — то есть подстановка полного пути осиротила бы обе
импортные позиции, а `unused_imports` под `clippy -D warnings` уронил бы
панель на файле, который руками править нельзя.

*Следствие — форма правила у пасса.* Снимаются РОВНО те импортные items,
которые ЕГО собственная подстановка осиротила: item без единого оставшегося
употребления токена уходит, item с употреблением остаётся (неразборчивое
подчищение так же неверно, как его отсутствие), опустевшая строка уходит
целиком, незнакомая форма `use` — громкий отказ. Токен в `::`-квалифицированном
пути (`chrono::DateTime` внутри аннотации или дока) употреблением НЕ считается:
он называет путь, а не импортированное имя.

*И две формы вывода, которые диктует не вкус, а ПАНЕЛЬ.* Сгенерированный файл
руками не правят, значит написанное пассом обязано быть тем, что уже принимает
`cargo fmt --all --check` — первый шаг панели. Отсюда: braced-импорт, ужатый до
последнего выжившего, пишется БЕЗ скобок (`use a::b;` — `use a::{b};` rustfmt
переписал бы), а строка, снятая из промежутка между двумя пустыми, забирает
вторую пустую с собой. Обе формы записаны тестами воркера ДО того, как его
реализация им удовлетворила, и разошлись они только на прогоне.

*Отвергнуто:* эмитить короткое имя и дописывать под него импорт — тогда пасс
сам решает, что импортировать, то есть переизобретает правило именования
генератора, от которого как раз защищается (тот же довод, которым Р16
отвергла сшивку по имени типа). *Отвергнуто:* `#![allow(unused_imports)]` в
сгенерированном модуле — подавление линта, прецедента в дереве нет (тот же
довод, которым Ф4.2a отвергла подавление `large_enum_variant`).
- **Ф4.2c** — реэкспорт рукописных типов и сгенерированные ридеры трёх
  поверхностей без ридера (G11). Отдельный подшаг, потому что он меняет граф
  типов продукта: `vibe-index` получает РАНТАЙМНОЕ ребро на `vibe-wire`
  (сегодня оно dev-only и это записано в самом манифесте,
  `crates/vibe-index/Cargo.toml:51-55`).

*Именованный дефер с триггером:* имя ВАРИАНТА сгенерированного словаря
(`KindName0` для строки `"kind/name"` — коллизионный суффикс генератора)
`x-rust-type` не покрывает: аннотация называет ТИП. Сведение с рукописным
`NamingConvention` требует переименования варианта; триггер — Ф4.2c, где эти
два определения становятся одним. **Триггер сработал — см. Р27.**

### Решения Р24–Р27 — приняты БОССОМ по замеру Ф4.2c

*Дерево измерено 2026-08-17 перед нарезкой; находка —
[`harvest/f42c-reexport-radius.md`](harvest/f42c-reexport-radius.md). Замер
нашёл ЧЕТЫРЕ препятствия реэкспорту, из которых текст Ф4.2c выше не называет ни
одного, и все четыре меняют конструкцию подшага, а не его объём. Исполнитель
решения ниже НЕ переоткрывает.*

**Р24. Трейт-этаж эмитится БЕЗУСЛОВНО, и `Default` в него НЕ входит — это и
есть разделяющая линия.** Замер: рукописные типы выводят
`Debug, Clone, PartialEq, Eq` (+`Default` у восьми, +`Copy, PartialOrd, Ord,
Hash, ValueEnum` у `PackageKind`), сгенерированные — только
`Serialize, Deserialize`, 74 из 74.

*Почему безусловно, а не аннотацией.* Разделяющий вопрос
[`##WAL-C-SCHEMA-DESCRIBES-THE-WIRE`] один: говорит ли это что-нибудь о
ФОРМАТЕ? `Debug`/`Clone`/`PartialEq`/`Eq` — свойства представления в Rust,
провод о них не знает ничего. Значит тот же класс, что боксирование (Ф4.2a) и
канонический порядок (Р12): у вопроса ровно один законный ответ, и он —
безусловное преобразование, а не десятая аннотация.

*Почему `Eq` законен уже сегодня и что его сторожит.* Во всех схемах дерева
**ноль** float-типов (измерено; единственное вхождение — прозой внутри
`description`, объясняющей, почему `float64` отвергнут). Все поля — `String`,
`bool`, `u32`, коллекции и три доменных типа, и каждый из трёх выводит `Eq`.
*Именованный дефер с триггером:* первый float в любой схеме — тогда `Eq`
перестаёт быть выводимым, и шаг, который его вносит, решает, что делать. Строить
анализ достижимости float'а сейчас значит строить механизм под потребителя,
которого нет и которого дерево сознательно избегает (см. рулинг о потолке
размера, B-056).

*Почему `Default` — не форма, а СУЖДЕНИЕ.* «Есть ли у этого типа осмысленное
пустое значение» — утверждение о типе, а не о его форме: пустой `ProvidesEntry`
значит «ничего не предоставляет», пустой `VersionEntry` не значит ничего вовсе
(у него двадцать с лишним обязательных полей). Р14 уже провела ровно эту линию
для генератора — «генератор начал бы эмитить ПОВЕДЕНИЕ, а не форму». Значит
`Default` живёт рукописным `impl`-ом рядом с `generated/` (Р26), и сайтов у него
по всему воркспейсу **16**, все на семи подструктурах.
*Отвергнуто:* аннотировать `Default` в схеме — схема описывает ПРОВОД, а `{}`
на проводе выразим независимо от того, есть ли у типа пустое значение.
*Отвергнуто:* выводить `Default` там, где все члены опциональны, — вывод из
формы, ровно то, что Р2 запретила для словарей («закрытость enum'а не отличает
`PackageKind` от `NamingConvention`»).

**Р25. `ValueEnum` не переезжает, и `--kind` перестаёт быть `ValueEnum` —
потому что этого требует уже ратифицированная Б.1.** `clap::ValueEnum`
выводится только по вариантам без нагрузки, а `PackageKind` открыт с Ф4.2b-1
(`Unknown(String)`); плюс вывод трейта CLI-фреймворка в крейте провода затащил
бы `clap` в `vibe-wire` — в поверхность, которую PROP-044 §9 велит держать
подчёркнуто скучной.

*Куда девается роль.* Б.1 обосновывает открытость `PackageKind` дословно так:
«фильтры обязаны получить ветку `Unknown` (не молча-пусто: `vibe list --kind
plugin` с нулём результатов ГОВОРИТ „kind неизвестен этой сборке“)». То есть
ратифицированное поведение — принять незнакомый `--kind` и СКАЗАТЬ о нём, а не
отвергнуть аргумент силами `clap`. Значит `--kind` берёт строку и разбирается в
открытый `PackageKind` на границе, а ветка `Unknown` печатает именно то
сообщение, которого Б.1 требует. **Цена названа заранее:** `clap` теряет
shell-completion по `--kind` (значения перечисляются в help-тексте), и это
единственная user-facing потеря подшага.
*Асимметрия, которая тут не случайна, а есть закон:* незнакомое значение в
АРГУМЕНТЕ и незнакомое значение на ПРОВОДЕ — разные события; второе есть
нормальная жизнь (PROP-044 §4.2a), первое — сообщение пользователю, и оба
теперь обслуживаются одним типом с разными ветками.
*Не затронуто:* `vibe-cli` идёт другим путём — `vibe_core::PackageKind` через
`from_str` (`commands/list.rs:12,24`), `ValueEnum` там не участвует.

**Р26. Методы и трейт-`impl`'ы переезжают В `vibe-wire`, рядом с `generated/`,
и выбора здесь нет — его отнимает орфанное правило.** После реэкспорта тип
принадлежит `vibe-wire`, поэтому `impl Display for PackageKind` в `vibe-index`
становится незаконным (и трейт, и тип чужие). Переезжают: **15 inherent-методов
плюс `Display` ×2 и `FromStr` ×1**, плюс `Default`-`impl`'ы из Р24.

*Что это делает с крейтом, сказано вслух:* `vibe-wire` перестаёт быть
«только сгенерированным». Его честная форма — сгенерированное дерево ПЛЮС
рукописный слой поведения рядом; запрет Ф4.3 при этом не ослабляется, потому что
он запрещает рукописные `Serialize`/`Deserialize`-derive вне `generated/**`, а
`Display`, `FromStr` и `Default` таковыми не являются. Шапка крейта обязана
сказать это тем же коммитом — иначе следующий читатель примет рукописный файл
рядом с генерированным за нарушение.
*Отвергнуто:* оставить методы у потребителя через newtype-обёртку — обёртка
между проводом и доменом есть прослойка совместимости, запрещённая
[`##MIGRATION-TAXONOMY`](../../spec/common/PROP-044-change-native-formats.md#placement).

**Р27. Имя ВАРИАНТА объявляется схемой, картой по WIRE-ЗНАЧЕНИЮ, и это тот же
пасс доменных типов с третьим плечом.** Замер: артефактных имён в дереве **два**
(`repomd/mod.rs:55`, `journal/mod.rs:360`), оба — `KindName0` для строки
`"kind/name"`; рукописный двойник зовёт этот вариант `KindSlashName`
(`types/kinds.rs:110`). Суффикс минтит генератор, схлопывая `kind/name` и
`kind-name` в один идентификатор.

*Почему аннотация, а не правило.* Безусловного правила, дающего
`KindSlashName` из `"kind/name"`, не существует: его пришлось бы ВЫДУМАТЬ, а
выдуманное правило регистра внутри пасса — это переизобретение правила
именования генератора внутри пасса, который от него как раз защищается (Р16).
Идентификатор — имя, которое выбирает человек; выбранное имя объявляют, а не
выводят. Прецедент прямо рядом: `x-rust-type` объявляет имя ТИПА, хотя провод о
нём тоже не знает; имя варианта — то же самое этажом ниже.
*Форма:* `metadata."x-rust-variants"` — карта `wire-значение → идентификатор`,
и ключ есть ЗНАЧЕНИЕ, никогда не минтованное генератором имя (закон Р16: слой
сшивается по значениям). Значение без записи в карте оставляет имя генератора;
запись, чьего значения нет в словаре, — громкий отказ, называющий обе стороны.
*Что это закрывает:* после Р27 рукописный `NamingConvention` и сгенерированный
совпадают ПОИМЁННО, и пятый из пяти больных словарей (`SourceKind`) остаётся
единственным именованным дефером Б.1.

**Р28. Дедупликация выхода ложится ПЕРЕД реэкспортом, и порядок здесь
вынужденный.** Из трёх выходов, измеренных находкой, два отпадают не по вкусу:

*Выход «один модуль выигрывает» запрещён законом.* Корневые типы (`ByName`,
`Repomd`, `JournalRecord`) не дублируются вовсе, поэтому потребитель тянет
несколько модулей при любом выборе; а `by_name::PackageEntry.versions`
типизирован `by_name::VersionEntry`, номинально отличным от
`entry::VersionEntry`. Значит потребителю пришлось бы писать конвертеры между
типами, побайтово одинаковыми, — это прослойка совместимости между проводом и
доменом, прямо запрещённая
[`##MIGRATION-TAXONOMY`](../../spec/common/PROP-044-change-native-formats.md#placement).
Компилятор назвал цену поимённо: 35 сайтов модульной несовместимости в пробе B.

*Выход «оставить как есть» отказывается от цели фазы.* Рукописными остаются 23
типа-зеркала, и Ф4.3 не может закрыть `types/**` — то есть запрет рукописного
провода рождается с дырой ровно там, где фаза его строила.

*Значит общий модуль*, и тогда порядок вынужден: пока копий три, реэкспорт не
может ответить, на КАКОЙ `VersionEntry` переезжают методы (Р26). Это тот же
класс, что слот пасса в Ф4.2c-1: место шага ВЫВОДИТСЯ из ограничений, а не
выбирается.

**Р29. Общий модуль — не десятый пасс, а третья фаза прогона.** Измерено:
`rewrite_generated` работает над ОДНИМ файлом (`postproc.rs:121`), а
`Vocabularies::resolve` считает транзитивное замыкание для одной схемы и
выбрасывает его — состояние структуры четыре поля, ничего не накапливающих
(`vocabulary.rs:46`). Значит дедупликация требует прогонного состояния
«фрагмент → {схемы}» и порядка «собрать карту → эмитить общий модуль → эмитить
схемы с `pub use`». Знание для неё уже вычисляется и теряется — добывать его
заново не нужно, нужно перестать выбрасывать. *Названная цена:* `pub use` —
новый вид строки в сгенерированном дереве (сегодня их **ноль**), и каждый пасс
обязан его узнавать либо не трогать; первый прогон перепишет восемь модулей
разом, и `check-codegen` это увидит.

**Р30. Эпоха приезжает в ИМЯ фрагмента, а не в каталог общего дома.**
*Почему не каталог:* каталог-по-эпохе выглядел бы симметрично
`schemas/<формат>/e<N>/`, но эпоха есть свойство ФОРМАТА, а фрагмент общий для
форматов — `package_kind` втянут семью модулями, из которых два
(`list_report`, `registry_sync_report`) вообще вне эпох. Ключить общий дом
эпохой значило бы приписать фрагменту чужое свойство. *Почему имя работает:*
фрагмент, изменившийся в e2, есть ДРУГОЙ фрагмент — у него другое имя, он
ложится в тот же дом рядом, и миры разделены именем, а не каталогом; это тот же
закон, которым Р27 объявляет имя варианта («имя, которое выбирает человек,
объявляют»). *Триггер пересмотра:* первая схема второй эпохи, тянущая фрагмент
первой.

**Р31. Теряемые трейты разделены измерением на три класса, и каждый имеет свой
ответ.**

- `Ord` / `Hash` / `PartialOrd` — **0 сайтов**: не нужны никому. Комментарий
  `crates/vibe-index/src/scanner/manifest.rs:14`, называющий `Ord` причиной
  дублирования словаря, лжёт с момента написания и правится тем же шагом:
  оставить известную ложь рядом со свежей правдой значит завести документ,
  которому не верят (тот же довод, что Р6 фазы Ф1.4).
- `Copy` — **19 сайтов** у `PackageKind`, **0** у `DeliveryMode`. Восстановить
  нельзя по построению: у открытого словаря есть `Unknown(String)`. Значит 19
  сайтов переходят на `.clone()` либо на ссылку — механическая правка внутри
  периметра, и её число названо заранее, чтобы шаг не встретил его сборкой.
- `Default` — **15 сайтов**, восстанавливается рукописным `impl` рядом с
  `generated/`; это уже постановлено Р24 и здесь только получает своё число.
- `ValueEnum` — 3 сайта, снимается Р25.

**Р32. `Repomd` и `RepomdFileEntry` выходят из периметра Ф4.2c-3b именованным
дефером с триггером «рулинг владельца по B-056».** Проба C дала 40 ошибок, из
которых 26 — орфанные и 10 — форма варианта (структурные плечи против newtype с
боксом); но **прямую цену сужения `size: u64 → u32` измерить не удалось**: все
сайты употребления перекрыты ошибками формы, и сужение выстрелит только после
их починки. Реэкспорт манифеста, сделанный до рулинга, сузил бы разрядность
размера файла молча — а B-056 ровно об этом и стоит открытым. *Что дефер НЕ
означает:* манифест остаётся рукописным, поэтому Ф4.3 получит по нему
именованное исключение, и это исключение обязано нести триггер, а не жить
вечно. *Триггер:* рулинг по B-056 в любую сторону.

### Решения Р33–Р35 — приняты БОССОМ перед нарезкой Ф4.2c-3b

**Р33. Слой поведения живёт в `crates/vibe-wire/src/behaviour/`, файлом на
тему.** После реэкспорта тип принадлежит `vibe-wire`, поэтому `impl Display for
PackageKind` в `vibe-index` незаконен (орфанное правило) — это Р26. Здесь
решается только ГДЕ: отдельный каталог рядом с `generated/`, не внутри него.
*Почему рядом, а не внутри:* всё под `generated/**` руками не правится
никогда, и файл поведения там был бы первым исключением из правила, которое
Ф4.3 как раз собирается сделать машинным. *Почему каталог, а не один файл:*
переезжают 15 inherent-методов плюс `Display` ×2, `FromStr` ×1 и
`Default`-impl'ы восьми типов — в один файл это не уложится в бюджет 600
строк, а шов очевиден и совпадает со швом рукописной стороны (словари ·
проекции записи · агрегаты). **Шапка крейта обязана сказать это тем же
коммитом:** `vibe-wire` перестаёт быть «только сгенерированным», и следующий
читатель иначе примет рукописный файл рядом с генерированным за нарушение.

**Р34. Имя корневого типа схемы ОБЪЯВЛЯЕТСЯ аннотацией, а не подпирается
алиасом при реэкспорте.** Сгенерированный корень `by_name.jtd.json` зовётся
`ByName` (генератор минтит имя из стема), рукописный двойник —
`NameEntry`. Реэкспорт вида `pub use …by_name::ByName as NameEntry;`
работал бы, но прятал бы настоящее имя типа за алиасом потребителя — а закон
этого дерева обратный: **имя, которое выбирает человек, объявляют**
(Р22 для типа, Р27 для варианта). Значит `by_name.jtd.json` получает
`metadata."x-rust-type": "NameEntry"`, и переименование делает тот же пасс
доменных типов. *Механизм уже есть, это измерено, а не предположено:*
`rulings_from_doc` читает аннотацию и на КОРНЕ документа, не только в
`definitions` (`xtask/src/codegen/domain_types/rulings.rs:108`, ключ отказов
`(the root)`). *Цена:* правка схемы входит в периметр шага, а `check-codegen`
увидит переименование типа в двух модулях (`by_name` и любой, кто его тянет).

**Р35. `BindingSite` входит в шаг, хотя живёт не в `types/**`.** Из пяти
раздвоенных словарей Б.1 шаг сводит четыре, и `BindingSite` — единственный из
них, чей рукописный двойник лежит вне периметра, названного текстом Ф4.2c
(`crates/vibe-index/src/index/inverted.rs:89`). Оставить его значило бы
закрыть Б.1 на трёх словарях из четырёх и объявить это закрытием четырёх.
Сгенерированный живёт в `by_purl` (единственный модуль, поэтому в общий дом он
НЕ переехал — он не общий фрагмент), и реэкспорт берётся оттуда.
*Не входит:* `SourceKind` — именованный дефер Б.1, обе копии принадлежат
форматам, которых это ТЗ не описывает.

**Порядок шагов Ф4.2c (жёсткий; каждый — отдельный коммит). Перенарезан
2026-08-17 по замеру Р28: шаг `-3` разделился на `-3a` и `-3b`, и разделила его
не длина, а невозможность — пока фрагмент эмитится в восемь модулей, реэкспорт
не может назвать, какой из них он реэкспортирует.**

- **Ф4.2c-1 — трейт-этаж (Р24). СЕЛА 2026-08-17**, коммит `95feb37f`.
  Девятый пасс: `Debug, Clone, PartialEq, Eq` безусловно, `Default` — нет.
  Числа после шага: **74** типа с полным этажом, **11** открытых словарей с
  бессерде-этажом, два реестровых типа (`FormatId`, `ForeignParsers`) не
  тронуты, дом движка байт-в-байт, пять оракулов зелены.
  *Красное предъявлено в сильнейшей доступной форме:* этаж урезан на один
  трейт, дерево перегенерировано, и новый тест `vibe-wire` НЕ СОБРАЛСЯ —
  `error[E0369]: binary operation == cannot be applied to type Repomd`,
  четырежды.

  *Две поправки по факту, обе про соседей, а не про сам пасс.*
  **(i) Слот пасса оказался ВЫНУЖДЕННЫМ, а не выбранным**, и это открылось
  замером: `strictness` якорится на НЕТРОНУТУЮ строку derive, значит этаж
  обязан лечь после него; `open_vocabulary` читает ту же строку и решает, что
  сохранить, значит этаж обязан лечь до него. Между ними ровно один слот.
  **(ii) Открытие словаря снимало ЛИШНЕЕ, и это пришлось починить тем же
  шагом.** Пасс сбрасывал всю строку derive — верно, пока в ней не было
  ничего, кроме serde. Теперь он снимает только серде-пару: открытый словарь
  не имеет причин быть единственным сгенерированным типом, который нельзя ни
  напечатать, ни сравнить. Это тот же закон, который Р23 установила для
  импортов — снимать РОВНО то, что обязан, — применённый одним слоем выше;
  литерал этажа при этом живёт в ОДНОМ модуле и заимствуется вторым, потому
  что две копии якоря расходятся в сканер, который молча ничего не находит.

  *Побочный урок о фикстурах, стоящий записи:* пятнадцать тестов соседей
  покраснели, и ни один не был «удовлетворён» — их перенацелили. У
  `open_vocabulary` поправлен ВХОД (пасс больше никогда не получает нетронутую
  строку, значит его образцы обязаны это говорить), а у `domain_types`
  ожидания нормализуют этаж в ОДНОМ месте вместо восьми. Довод структурный, а
  не про объём: иначе каждый будущий пасс, трогающий все типы, правил бы
  ожидания всех остальных пассов, и эта связанность растёт как квадрат их
  числа.
- **Ф4.2c-2 — имя варианта (Р27). СЕЛА 2026-08-17**, коммит `dca804db`.
  Третье плечо пасса доменных типов плюс аннотация `x-rust-variants` у
  фрагмента `naming_convention`. Числа: `KindName0` — **0**, `KindSlashName` —
  **2**, провод цел (`#[serde(rename = "kind/name")]` на месте), дом движка
  байт-в-байт, пять оракулов зелены. *Красное* предъявлено на живом конвейере:
  ключ, называющий значение вне словаря, отказывает ДО чтения Rust и
  перечисляет значения, которые определение несёт.

  *Три поправки по факту, и первая — исправление конструкции, а не координаты.*
  **(i) Охват переименования оказался ДЕКЛАРАЦИОННЫМ, а не файловым.** Первая
  реализация переименовывала по всему файлу — как плечо ИМЕНИ ТИПА, и для типа
  это верно: его идентификатор уникален в файле по построению. Для ВАРИАНТА
  неверно: его идентификатор принадлежит своему enum'у, тот же токен в другом
  месте файла — другая вещь, и переписать его значило бы тихо править то, о чём
  никто не просил. Поймал тест, написанный по НАСТОЯЩЕЙ форме объединения;
  чинилась область видимости, а не фикстура.
  **(ii) Описание схемы едет в док-комментарий и проходит через ТЕ ЖЕ
  переименования, что и код.** Текст аннотации цитировал минтованный
  идентификатор — эмитированный док после пасса называл бы несуществующее.
  Правило для авторов схем записано рядом с самой аннотацией.
  **(iii) Отказы модуля указывали не на тот файл.** Они называли авторскую
  схему, тогда как общий фрагмент в неё ПОДСТАВЛЕН, и автор открыл бы файл, в
  котором аннотации нет, — тот же дефект, что рецепт, чинящий не то. Теперь
  называются оба возможных дома, а ключом для поиска служит имя определения.
- **Ф4.2c-3a — общий модуль сгенерированных фрагментов (Р28–Р30).
  СЕЛА 2026-08-17**, коммит `37496cab`. Прогон хостового дома стал
  трёхфазным: карта замыканий → эмиссия `generated/shared/` из
  синтетического документа (все фрагменты в `definitions`) → схемные
  модули плюс замена копий реэкспортом. Числа после шага: объявлений
  **102 → 58** при неизменных **58** уникальных именах, 62 блока стали
  `pub use` в восьми модулях (`journal` 600 → 274 строк), дом движка
  байт-в-байт, пять оракулов провода зелены, `vibe check` не сдвинулся.
  Четыре сторожа в машине: нет блока в общем доме · блок не побайтово
  равен · потребители фрагмента расходятся в роли строгости · счётчик
  «потерянные объявления == замыкание схемы». Красных **три**: сторож
  содержания и сторож счётчика — прогоном, сторож ролей — тестом (прогоном
  его сегодня не разбудить, и это сказано вслух).

  *Две поправки по факту, обе про соседей, а не про сам механизм.*
  **(i) Порядок пассов нельзя было повторить вторым прогонщиком.**
  Буквальный вызов `rewrite_generated` для синтетического документа
  невозможен: `apply_strictness` отказывает документу, которого реестр не
  называет. Первая реализация обошла это зеркальным конвейером — и тем
  завела ВТОРУЮ копию нормативного значения (`##NEVER-DUPLICATE-A-NORMATIVE-VALUE`),
  причём разошлись бы они ровно там, где шаг не переживает расхождения:
  вся замена стоит на побайтовом равенстве двух эмиссий. Сведено в один
  вход, слот строгости стал названной парой
  `StrictnessSource::{Registry, PreRuled}` — не `Option`, потому что
  `None` на месте вызова не говорит, ПОЧЕМУ реестр не спрашивают.
  Сведение доказано побайтово: перегенерация дала `diff -r` EXIT=0 против
  выхода до него.
  **(ii) Шаг разбудил дремавший закон о записи файлов.** Он поднял число
  записей ОДНОГО сгенерированного файла за прогон с одной до трёх
  (генератор → пассы → замена), и три прогона подряд упали с
  `os error 1224` («file with a user-mapped section open»), **каждый на
  РАЗНОМ модуле** — подпись гонки с чужим читателем, а не залипшего файла.
  Первое падение случилось внутри панели и оставило дерево полу-снесённым,

`cargo xtask wire-diff` + шаг панели (53 заголовка). Он задаёт ДВА разных
вопроса и держит их врозь: «каталог всё ещё проекция своего журнала?» —
переиспользованный `rebuild --check`, не второй проектор; «сдвинулись ли
байты корпуса против КОММИТА?» — git-дифф в форме `check-codegen`. Вердикт
затем берётся из флагов: до объявления публике — ОТЧЁТНЫЙ (зелёный, но
говорит вслух, что зелёное здесь не значит «ничего не изменилось»); при
закрытом окне — отказ; при открытом и `public = true` — требование записки,
добавленной ТЕМ ЖЕ изменением. Все пять строк таблицы вердиктов покрыты, три
из них — прогонами на намеренно сдвинутом байте.

*Три поправки по факту, каждая от дерева.* **(i) Старую записку невозможно
зачесть за новую по построению:** зонд спрашивает «добавлена ли записка
СЕЙЧАС» (untracked / staged-add), поэтому `001.md`, лежащая отслеженной и
чистой, для него невидима. **(ii) Красная проба сдвигает байт в ЖУРНАЛЬНОМ
шарде, а не в каталоге** — журнал есть вход проектора, поэтому `rebuild`
остаётся зелёным и под тестом оказывается ровно второй вопрос; сдвиг в
каталоге завалил бы первый и до вердикта дело не дошло бы. **(iii) Загрузчик
реестра расширен ключом `corpus` вместо второго парсера** — периметр пакета
этого файла не называл, но дерево несёт собственный закон «one loader, one
truth», и исполнитель верно предпочёл его букве периметра (§0.9).

**Ф5.2 — `wire-diff`.** `cargo xtask wire-diff`: пересобрать корпуса,
`git diff --exit-code -- formats/corpora/` ИЛИ непустой diff покрыт запиской
`formats/breaks/NNN.md`, на которую в том же коммите есть ссылка (проверка:
изменённые файлы корпуса + наличие новой записки). Шаг в self-check.
Приёмка: правка схемы без записки — красный; с запиской — зелёный
(доказать оба, откатить пробу).

**Ф5.3 — Окно перелома и публичный переключатель.** `formats/EPOCHS.toml`:
`public = false` (D13; строку меняет ТОЛЬКО владелец — комментарий в файле
говорит это прямо) и `break_window_open = true`. Шаги self-check: при
`public = false` — `wire-diff` отчётный (Ф5.2 не блокирует, записки
опциональны); при `public = true` И `break_window_open = false` — любые
изменения под `schemas/**|formats/**` красные; при `public = true` И окне
открытом — режим записок обязателен (Ф5.2 блокирует). Приёмка: все три
режима доказаны пробными правками (и откачены).

**Р38. Поверхность писателя — нормативное значение, и её вторая копия
запрещена.** Сегодня «какие файлы и каталоги в корне каталога принадлежат
писателю» сказано дважды и дословно одинаково — в `xtask/src/rebuild.rs:35,39`
и в `crates/vibe-index/tests/golden_corpus.rs:58,61`. Ф6.1 добавляет к этому
множеству `hello.json`, то есть впервые заставляет его ИЗМЕНИТЬСЯ. Значит
шаг сводит обе копии в ОДИН дом — в `vibe-index`, откуда их берут оба
потребителя (`xtask` уже зависит от `vibe-index` и уже импортирует
`vibe_index::index::memory::WriteCtx`; тест живёт внутри самого крейта).
*Почему это не аккуратность, а необходимость:* две копии разошлись бы ровно
там, где шаг этого не переживает — `rebuild --check` и тест золотого корпуса
задают ОДИН вопрос («каталог всё ещё проекция своего журнала»), и если один
белый список знает про `hello.json`, а второй нет, то один из них зеленеет над
настоящим расхождением. Это тот же закон, которым Ф4.2c-3a свела порядок
пассов в один вход
([`##NEVER-DUPLICATE-A-NORMATIVE-VALUE`](../../spec/boot/STATIC.md)).
*Отвергнуто:* поправить обе копии руками — это и есть запрещённая копия, просто
синхронизированная на один день. *Отвергнуто:* заменить белый список обходом
каталога — обход утянул бы `README.md`, `.gitignore` и `state/**`, а док
`rebuild.rs:126-134` обосновывает белый список ПОЛОЖИТЕЛЬНО («сравнивай
множество, которое писатель пишет», а не «исключай мир») и он прав.

**Р39. `hello.json` живёт ВНЕ карты `repomd.files`, и довод — слоистость, а не
удобство.** `repomd.json` — манифест ОДНОГО МИРА (`schemas/index/e1/`, эпоха 1).
Хэндшейк стоит НАД мирами: он к ним диспетчеризует. Положить надмировой файл
внутрь пер-мирового манифеста значит сделать одноразовый артефакт органом
целостности для единственного неодноразового — прямая инверсия
[`##ONE-ETERNAL-FILE`](../../spec/common/PROP-044-change-native-formats.md#truth)
(«всё остальное в системе одноразово именно потому, что эта вещь — нет»). И
это не абстракция: как только миров два, вопрос «чей repomd хэширует hello»
не имеет ответа, который не расходится, а мир, который закатывается, унёс бы
с собой орган проверки того, что его переживает.
*Цена названа честно:* `cli/verify.rs:78` ходит ТОЛЬКО по ключам карты
(измерено), поэтому хэндшейк остаётся вне машинной проверки целостности; и
строка `README.md`, которую пишет `init.rs:139` («manifest with sha256 of every
other file»), становится неточной — её правит тот же шаг, и она была неточной
уже сегодня, потому что `.gitignore`, `README.md` и `state/**` вне карты.
*Что цену обесценивает:* целостность СОДЕРЖИМОГО пакетов хэндшейк не охраняет
и не должен — она держится `content_hash` на выборке
([PROP-005 `##INTEGRITY-UNCHANGED`](../../spec/modules/vibe-index/PROP-005-package-index.md#optional)),
поэтому клиент, уведённый подменённым хэндшейком, всё равно не может получить
неверное содержимое незаметно.
*Прецедент, измеренный а не предположенный:* корневой файл вне карты в дереве
уже есть — `.gitignore` (`init.rs:110`) и `README.md` (`init.rs:127`).
*Отвергнуто:* внести в карту ради verify — покупает проверку ценой инверсии
слоёв, и покупка перестаёт работать в тот день, когда миров становится два.

**Р40. Хэндшейк — проекция РЕЕСТРА ФОРМАТОВ, а не журнала, и потому
детерминирован.** Возражение «`hello.json` окажется проекцией факта, которого в
журнале нет» снимается тем, что факт живёт не в журнале и не должен: эпоха —
свойство ФОРМАТА, а формат-реестр есть пункт (5) авторитетного ядра
([`##TRUTH-KERNEL`](../../spec/common/PROP-044-change-native-formats.md#truth)).
`FormatId::epoch()` уже сгенерирован из `formats/REGISTRY.toml`
(`crates/vibe-wire/src/generated/format_id/mod.rs:108-125`), поэтому
`##FORBID-SECRET-TRUTH` не задет: авторитетный факт лежит в ядре, а `hello.json`
— его проекция. Практическое следствие, ради которого это записано: содержимое
хэндшейка есть функция БИНАРЯ, а не времени — часов в нём нет, две сборки одного
состояния дают одни байты, и корпус его удержит.

**Р41. Хэндшейк ищется ПЕРВЫМ, и этого требует ключ `successor`, а не вкус.**
Измерено: `probe` сегодня определяет базу, спрашивая
`<base>/v1/index/repomd.json`, затем `<base>/repomd.json`, и читает только
СТАТУС. Соблазнительная дешёвая форма — спросить `hello.json` уже у
победившего кандидата (2+1 запрос вместо 2+2). Она отвергается: `successor` —
«внутриполосный указатель переезда» самого хэндшейка
([`##ONE-ETERNAL-FILE`](../../spec/common/PROP-044-change-native-formats.md#truth)),
и он имеет смысл ровно тогда, когда по старому адресу больше ничего нет. Если
искать хэндшейк только там, где уже нашёлся repomd, то переехавший индекс
провалит пробу repomd раньше, чем кто-либо прочтёт указатель, — то есть
единственный ключ, ради которого вечный файл вечен, становится декоративным.
Значит: `hello.json` спрашивается у ОБОИХ кандидатов первым, а проба repomd
остаётся запасным путём для индексов без хэндшейка (совместимость, которую
требует D8). *Цена названа заранее:* до двух лишних GET на индексе без
хэндшейка (таймаут 5 с — `index_client/mod.rs:41`), причём на мёртвом URL проба
repomd падает точно так же.

**Р42. `successor` в e1 ЧИТАЕТСЯ и НАЗЫВАЕТСЯ в отказе, но не следуется
автоматически.** Авто-переход требует сторожа циклов и правила доверия —
переход по указателю на ЧУЖОЙ хост есть расширение области действия, которое
дисциплина запрещает
([`##NEVER-LET-AN-INTEGRATION-ESCALATE-SCOPE`](../../spec/boot/STATIC.md)), — и
ни то ни другое сегодня не решено. Названный в отказе указатель делает
следующее действие человека одной командой, и это ровно та вырожденная первая
реализация, которую разрешает
[`##RISK-OVERENGINEERING`](../../spec/common/PROP-044-change-native-formats.md#risks).
*Триггер постройки авто-перехода:* первый настоящий переезд хэндшейка.

**Р43. Набор ключей вечного файла ПОЛОН с первого дня, и Приложение А.6
поправлено.** Схема e1 описывает все ключи формы D8 —
`{vibe, worlds[]{epoch, path, sunset?}, min_client?, notice?, successor?}` —
хотя вырожденная первая реализация пишет только `vibe` и один мир. *Почему:*
ключи хэндшейка никогда не меняют смысла, поэтому ДОБАВИТЬ ключ позже значит
изменить единственный файл, которому меняться нельзя; схема, описавшая меньше,
описывает другой формат.
**Поправка к самому плану, а не к дереву:** Приложение А.6 ниже перечисляет
`sunset` среди опциональных ключей ВЕРХНЕГО уровня, тогда как D8 и
[`##ONE-ETERNAL-FILE`](../../spec/common/PROP-044-change-native-formats.md#truth)
согласно кладут `sunset?` ВНУТРЬ мира. Правило старше собственного числа:
верна форма D8 плюс контракт, вольность прозы А.6 исправлена там же.

**Р44. `min_client` — доменный тип `semver::Version`; `sunset` — фрагмент
`timestamp`.** Терпимость, которой D8 требует от хэндшейка, доставляется
МЕХАНИЧЕСКИ записью реестра `foreign_parsers = "many"` (пасс строгости не
ставит `deny_unknown_fields`) — и она про НЕЗНАКОМЫЕ КЛЮЧИ, а не про право
соврать о типе знакомого. Поэтому действует уже установленный закон: имя и тип,
которые выбирает человек, ОБЪЯВЛЯЮТ (Р3, Р22, А.5а), и понижение до `String`
«на всякий случай» есть ровно то понижение, которое Р3 запрещает. Для даты
довод сильнее вдвое: `type: string` дал бы дате ВТОРУЮ законную запись в
системе и отменил бы Р11 («одна вещь пишется одним способом»).
*Отвергнуто:* обе строки — читается как исполнение D8, а на деле путает
терпимость к ключам с бестипностью значений.

**Р45. «Своя эпоха клиента» НЕ заводит нового числа.** Эпоха мира, который
клиент умеет читать, уже записана — в `formats/REGISTRY.toml` и оттуда
сгенерирована в `FormatId::epoch()`. Клиент обязан взять её ОТТУДА, а не
объявить у себя константу: вторая копия нормативного значения запрещена тем же
законом, что и Р38. *Цена, измеренная и названная заранее:* `vibe-registry`
сегодня зависит только от `vibe-core` (`crates/vibe-registry/Cargo.toml:15`) —
шаг добавляет ребро на `vibe-wire`, значит `Cargo.toml` **и `Cargo.lock`**
входят в периметр (правило «объявленная зависимость двигает лок»).
*И два семейства версий не смешивать:* `vibe: "hello/1"` — версия САМОГО
ФОРМАТА ХЭНДШЕЙКА (документ, которого клиент не понимает, есть громкий отказ),
`worlds[].epoch` — какой МИР КАТАЛОГА клиент умеет читать. Оба нужны, и они
отвечают на разные вопросы.

**Р46. Отказ хэндшейка — домашний `thiserror`, чьё СОДЕРЖАНИЕ вычисляется;
каталога рецептов Ф6.1 не заводит.** Довод по существу, а не по объёму: каталог
рецептов существует затем, чтобы рецепт жил РЯДОМ С ФОРМАТОМ и менялся вместе с
ним. Содержание отказа хэндшейка — не свойство версии формата, а результат
сравнения В МОМЕНТ ВЫЗОВА (какие миры этот индекс предлагает против того, какую
эпоху понимает эта сборка), поэтому у него нет дома в статическом каталоге:
каталог здесь не лишний, а неверный. Форма — домашний стиль дерева («violates
`spec://…`; fix: …»), перечень миров и рецепт строятся из самого документа.
*Нужен ли каталог рецептов КАРАНТИНУ (Приложение А.7 требует его дословно) —
решается при нарезке Ф6.2 по трём вариантам, измеренным находкой
[`f6-2-…-appendix.md`](harvest/f6-2-quarantine-answer-surface-appendix.md) §5.*

**Р47. Опциональная дата вынудила шаг ПЕРЕД схемой, и интерим-форма
отвергнута.** Замер Ф6.1b нашёл то, чего не знал ни один текст плана: JTD
`"type": "timestamp"` в ОПЦИОНАЛЬНОМ члене не проходит слой преобразований.
Отказ дословно — «the alias `WorldSunset` resolves to `DateTime<FixedOffset>`,
which is no primitive — the pass has no class for it and refuses to guess»
(воспроизведён боссом собственным прогоном, а не принят с чужих слов). Причина
— расхождение двух половин ОДНОГО пасса: схемная сторона зовёт член `timestamp`
скаляром (`optional_shapes.rs`, `ShapeClass::Scalar`), а рустовая сторона
(`is_primitive` в `optional_shapes/emit.rs`) перечисляет рустовые записи всех
форм JTD `type` — `String`, `bool`, все числа — и **не несёт единственной:
`DateTime<FixedOffset>`**. Список был задуман полным и был полон ровно до тех
пор, пока ни одной схеме не понадобилась опциональная дата: обязательная сюда
не доходит, потому что перекладывается только опциональная нагрузка.

*Почему интерим-форма отвергнута, хотя работала.* Воркер, следуя клаузе пакета
«обе формы отказали — не изобретай третью», оставил генерирующуюся форму
`"type": "string"` с тем же `x-rust-type` — рустовый тип и провод при этом
выходят В ТОЧНОСТИ те же. Босс её не принял, и довод не в качестве работы, а в
том, что она восстанавливает состояние, которое Р11 уже устраняло: тогда у даты
в схемах ДВЕ законные записи, и разойтись им ничто не мешает. Схема, говорящая
`string` там, где провод несёт RFC-3339, недоописывает формат
([`##M-SCHEMA-DESCRIBES-FORM`](../../spec/common/PROP-044-change-native-formats.md#machinery)),
и хуже всего это именно в ВЕЧНОМ файле: следующий автор схемы увидел бы там
прецедент писать дату строкой.

*Значит место шага снова ВЫВЕДЕНО, а не выбрано* — пятый раз за кампанию: схема
в истинной форме не может лечь раньше, чем пасс научится её форме. *Отвергнуто:*
сажать интерим и завести долг в `BACKLOG` — долг был бы записан в том же файле,
который его порождает; *отвергнуто:* убрать `sunset` из e1 как невыразимое —
набор ключей вечного файла полон с первого дня (Р43), и урезать его ради
удобства инструмента значит менять формат под инструмент.

*Цена, названная заранее и уплаченная:* тест не влез в
`optional_shapes/tests.rs` (592 строки при бюджете 600), поэтому файл расколот
по шву ОТВЕТСТВЕННОСТИ — «что пасс эмитит, когда стороны согласны» осталось в
`tests.rs`, «на чём стык отказывает, когда они расходятся» уехало в
`optional_shapes/tests/stitch.rs`. Раскол вскрыл относительный `include_str!`,
сломавшийся от переезда файла на уровень глубже, — дефект, который переезд
ОБНАРУЖИЛ, а не создал.

**Р48. Маркер `specmark::scope!` в `crates/vibe-index/tests/` не ставится, и
это применение измеренного прецедента, а не отмена правила.** Пакет велел
новому `.rs` нести `scope!` «тем же юнитом, что соседи по крейту»; воркер
исполнил правило и честно назвал расхождение: соседей с маркером нет ни одного.
Замер босса — **1 файл из 21**, и этот один только что создан. Тот же случай
разбирался в Ф4.2c-4, где маркер был снят с теми же словами. Значит правило
«новый файл несёт `scope!`» связывает `src/` продуктовых и движковых крейтов,
где оно и было оплачено сиротами в карте, а интеграционные тесты этого крейта
живут без него единообразно
([`##RULE-UNIFORMITY-IS-LOAD-BEARING`](../../spec/boot/STATIC.md): исключение
либо помечено, либо распространяется как ложный обучающий сигнал). *Следствие
для будущих пакетов:* клауза о `scope!` пишется с оговоркой «если соседи по
КАТАЛОГУ его несут — проверь прогоном, а не допущением».

**Р49. Карантин переезжает из пути ЗАГРУЗКИ в путь ОТВЕТА, и запись больше не
выбрасывается.** Замер Ф6.2 нашёл, что две поверхности расходятся об одной
записи: CLI грузит каталог с диска и карантинит, СЕРВЕР поднимается из журнала
и не карантинит никогда (Ж7), поэтому сервер отдал бы карантинную версию как
обычную, а сырой маршрут `by-name/{name}` — запись дословно.

*Почему проверка переезжает в ответ, а не в проекцию.* Карантин есть
утверждение ЧИТАТЕЛЯ о паре «запись × сборка», а не свойство записи. Журнал —
наша истина, и проекция обязана построить каталог, а не решать, чем читателю
позволено пользоваться. Значит место проверки — там, где формируется ОТВЕТ, и
тогда CLI и сервер отвечают одинаково ПО ПОСТРОЕНИЮ, независимо от того, как
индекс попал в память. Это и растворяет расхождение в корне: две поверхности
разошлись ровно потому, что проверка жила в ОДНОМ из двух путей загрузки.
*Отвергнуто:* карантинить в проекции — переоткрывает Ж7, краснит
`project_tests.rs:90` и рассинхронизирует золотой корпус (журнал записал
версию, проекция её теряет).

*Следствие, которого находка не называла и которое делает решение вынужденным:*
чтобы ответ мог рассказать о карантинной версии, её нельзя ВЫБРАСЫВАТЬ, а
сегодня `load_from` именно это и делает (`memory.rs`, `pkg.versions.retain`).
Возражение «оставленная запись утечёт в запись каталога» **измерено и не
подтвердилось**: у `iter_versions()` всего четыре потребителя, два из них — сам
`write_to`, но после Ф3 пути «прочитал → записал» не существует (мутации строят
состояние из журнала, `load_from` остался только у семи читающих глаголов).
Мина Ф1.4 «карантин на чтении стирает записи при следующей записи» снята
конструкцией, а не заплатой.

*И живое расхождение, найденное тем же замером:* `latest_stable` берётся ПОЛЕМ
из файла каталога, который писала проекция, а проекция не карантинит. Значит
пакет, чья единственная версия карантинна, уже сегодня отдаёт `latest_stable`,
указывающий на версию, которой эта сборка пользоваться не может, при пустом
списке версий. Выбрасывание оставляет агрегат указывающим в никуда — довод
против «выбрасывать», который чтением не виден.

*Что это значит для формы шага:* `load_from` перестаёт молча отбрасывать и
начинает ПОМЕТИТЬ; всякая отвечающая поверхность спрашивает именованный
предикат и говорит `unavailable {name, version, missing, recipe}` вместо
молчания. Умолчание обязано быть безопасным: потребитель, который не спросил,
не должен случайно получить версию, которой пользоваться нельзя, — форму этого
умолчания выбирает нарезка шага и обязана назвать её вслух.

**Р50. Рецепт принадлежит ВОЗМОЖНОСТИ, а не формату, — и потому каталога
рецептов Ф6.2 не заводит.** Находка поставила развилку тремя вариантами: (A)
новый файл данных под `formats/`, (B) поле рецепта в `formats/REGISTRY.toml`,
(C) литерал по месту. Все три отвергаются одним доводом: **они предполагают,
что рецепт есть свойство ФОРМАТА**, а он свойство ВОЗМОЖНОСТИ. Отказ карантина
отвечает на вопрос «эта запись требует возможности X, которой у сборки нет —
что делать», и ответ есть функция X, а не функция того, каким форматом записан
каталог.

*Значит дом рецепта уже существует и он единственный:* реестр возможностей
ЧИТАТЕЛЯ — `crates/vibe-index/src/index/quarantine.rs`, где живёт `UNDERSTOOD`
и где док прямо обещает «the list grows as capabilities land». То, что решает,
что понято, решает и что сказать, когда не понято. Форма: вместо голого
`&[&str]` — таблица «возможность → что она значит → что делать», и рецепт для
возможности, которой в таблице нет вовсе, генерируется общим правилом
(«эта сборка не знает возможности X; обнови vibe»).

*Почему это исполняет букву А.7, а не обходит её.* А.7 требует «рецепт из
каталога рецептов, не литерал по месту»; каталог рецептов — это и есть
названная таблица, а «по месту» запрещено ровно затем, чтобы текст не
расползался по N поверхностям. После Р50 поверхностей по-прежнему N, а текст
один. *Отвергнуто:* завести файл под `formats/` — тогда рантайм впервые станет
читать формат-реестр (сегодня его читают только гейты сборки), и ключом будет
формат, то есть рецепт станет одним на все причины; *отвергнуто:* литерал по
месту — N копий текста.

**Р51. `--log-level` складывается с `VIBE_LOG` в ОДИН рычаг тем приёмом,
который в дереве уже доказан.** Закон одного рычага установлен решением Р3
фазы Ф1.4 («цепочка `VIBE_LOG`, потом `RUST_LOG` отвергнута как второй рычаг в
костюме совместимости»), поэтому вопрос не «добавлять ли флаг», а «как флаг и
переменная становятся одним». Из четырёх измеренных композиций выбрана та, где
флаг ЗАПИСЫВАЕТ переменную до установки подписчика, а `EnvFilter` по-прежнему
читает ровно одно место.

*Почему именно она.* Она одна оставляет переменную окружения ПОЛНОЙ правдой о
наблюдаемом поведении: посмотрев на `VIBE_LOG`, оператор всегда объясняет, что
видит. Композиция «флаг перекрывает переменную» ломает ровно это — установленная
переменная перестаёт объяснять вывод, и по внешнему виду процесса не понять,
что её перекрыли. Прецедент формы в дереве есть и он с комментарием SAFETY:
`crates/vibe-cli/src/main.rs` уже так делает. *Цена названа:* запись в
окружение видна дочерним процессам (у `serve --auto-commit-push` это git,
который её игнорирует), и запись обязана произойти ДО появления потоков, то
есть в самом начале `main`.

*Место флага — ГЛОБАЛЬНЫЙ аргумент `Cli`, не аргумент `serve`.* D11 требует
подписчика для КАЖДОЙ подкоманды; флаг, живущий у одной, противоречил бы
собственному решению, ради которого заводится.

**Порядок шагов Ф6.2 (жёсткий; каждый — отдельный коммит):**

- **Ф6.2a — загрузчик перестаёт выбрасывать, заводится именованный предикат.**

## 10. Приёмка всего ТЗ (прогоняется целиком, по порядку)

**Предсказания (фальсифицируемы; проверяются в отчёте кампании):**

## 11. Смертность этого плана (закон «план временный», применённый к себе)

Стоячий закон проекта: план — временный документ; содержимое по мере
исполнения переезжает в спеки; утверждения цитируют якоря спек и никогда —
строки плана; закрытая строка — могильник. Для ЭТОГО плана исполнимо так:

1. **По мере исполнения.** Посадка каждой фазы включает её спек-дифф (карта —
   Приложение Б.5), и в том же коммите секция фазы в этом файле СВОРАЧИВАЕТСЯ
   в могильник по образцу закрытых строк `BACKLOG.md`: «Closed <дата> by
   <коммиты>. The ruling and its reasoning now live in <якоря спек>». Контент
   не живёт в двух местах даже один день.
2. **При закрытии плана.** Отчёт кампании сверяет предсказания P1–P6; из
   `spec/common/PROP-044` УБИРАЮТСЯ обе ссылки на этот файл (в `##PURPOSE` и
   `##SOURCES`) — заменяются якорями спек, куда легло содержимое; после этого
   на план не ссылается ни одна спека и ни один живой план, и файл целиком —
   могильники + отчёт. Дальше он удаляем.
3. **Названный пробел машинерии (дефер, не работа этого ТЗ):** «спека не
   ссылается на ЗАКРЫТЫЙ план» сегодня держится процедурой (этим разделом и
   законом отчёта кампании), чекера нет. Норма без чекера дрейфует — гейт
   «реестр закрытых планов → grep по spec/** → красный» дёшев и ложится в
   панель, когда появится первый закрытый план этой волны. Ссылки на АКТИВНЫЙ
   план законны (их держат WAL и `CONTINUE.md`) — гейт обязан различать.

**А.5 wiregen** (`xtask/src/wiregen/`) — **СЕМЬ** преобразований выхода
jtd-codegen, в этом порядке. *(Было четыре; №5–№7 добавлены 2026-08-15 по
замеру — решение Р5 §7. Вход конвейера — `(схема + реестр + сгенерированный
Rust)`, а не только Rust: измерено, что политика в сгенерированном коде следа
не оставляет.)*

**Сквозной закон аннотаций (Р2):** везде, где нужна политика, её называет
СХЕМА, и отсутствие аннотации — ошибка генерации. jtd-codegen ключи `x-…`
в `metadata` принимает молча и в Rust не переносит — проверено прогоном.

1. Закрытый enum → открытый: `pub enum PackageKind { Flow, …, Lang, Unknown(String) }`
   + ручные `impl Serialize/Deserialize` в том же генерируемом файле
   (`Unknown` пишет исходную строку как есть; известные — как раньше).
   **По `metadata."x-vocabulary": "open"|"closed"`, а НЕ по факту закрытости:**
   генератор выдаёт `PackageKind` (открыт) и `NamingConvention` (закрыт)
   синтаксически неразличимыми, отличить их по выходу невозможно.
   **Тегированные объединения этим преобразованием НЕ трогаются** — правило
   именованное, с тестом: сегодняшний сканер пропускает их случайно (между
   `#[derive(…)]` и `pub enum` стоит `#[serde(tag = …)]`, и распознаватель
   возвращает `None`), а совпадение — не механизм.
2. camelCase-поля → snake_case (снимает `#![allow(non_snake_case)]` в ОБОИХ
   потребителях: `crates/vibe-wire/src/lib.rs:52` и engine-крейт).
3. По `metadata."x-empty"` схемы: `"omit"` → `Vec<T>` + `skip_serializing_if
   = "Vec::is_empty"`; `"emit"` → `Vec<T>` без skip; отсутствие аннотации на
   коллекции — ОШИБКА генерации (решение обязано быть записано в схеме).
4. По реестру: `foreign_parsers = "none"` → добавить `#[serde(deny_unknown_fields)]`.
5. **`Option<Box<скаляр>>` → `скаляр` + `#[serde(default, skip_serializing_if
   = "<именованный предикат>")]`** по `metadata."x-default"`. Без этого
   `frozen`/`yanked` получают третье состояние на оси, которую PROP-044 §2b
   объявил двухсоставной, — и решение Р1 фазы Ф1.4, отвергшее `Option<bool>`
   ровно по этой причине, было бы отменено генератором. Домашняя форма —
   пара «default + skip» (35 мест в `types/entry/**`, ни одного `default` без
   парного skip).
6. **`DateTime<FixedOffset>` → `DateTime<Utc>`.** JTD `timestamp` даёт
   `FixedOffset`; дерево живёт на `Utc` (26 вхождений в
   `crates/vibe-index/src`).
7. **Боксирование крупного варианта объединения.** На нагрузке настоящего
   размера clippy падает `large_enum_variant` и сам называет починку
   (`Published(Box<EventPublished>)`); панель гоняет `clippy --workspace
   --all-targets -- -D warnings`, а сгенерированный файл руками не правят.

**А.5a Доменные типы (Р3).** По `metadata."x-rust-type": "<путь>"` строка на
проводе эмитится доменным типом (`Group`, `semver::Version`, `PackageKind`,
`NamingConvention`), а не `String`. Без этого «замена рукописных типов
реэкспортом сгенерированных» есть понижение типов по всему индексу.

**А.6 `hello.json`:**

```json
{"vibe":"hello/1","worlds":[{"epoch":1,"path":"."}]}
```

Клиент (`index_client`): `GET hello.json` → 404 ⇒ сегодняшний путь без
изменений; 200 ⇒ выбрать мир своей эпохи; своей нет ⇒ отказ с перечнем
миров и рецептом.

**Ключи — поправка 2026-08-17 (Р43): прежняя строка этого абзаца
перечисляла `sunset` среди опциональных ключей ВЕРХНЕГО уровня, чего D8 и
[`##ONE-ETERNAL-FILE`](../../spec/common/PROP-044-change-native-formats.md#truth)
не говорят ни один.** Верная форма:

- верхний уровень: `vibe` (обязателен), `worlds` (обязателен),
  `min_client?`, `notice?`, `successor?` — absent-если-нет;
- внутри мира: `epoch` (обязателен), `path` (обязателен), `sunset?` —
  absent-если-нет.

Набор ключей ПОЛОН в схеме e1 с первого дня, хотя вырожденная первая
реализация пишет только `vibe` и один мир (Р43): ключи вечного файла не
меняют смысла, поэтому добавить ключ позже значит изменить единственный файл,
которому меняться нельзя. Типы: `min_client` — `semver::Version`, `sunset` —
фрагмент `timestamp` (Р44). Порядок обращения — хэндшейк спрашивается ПЕРВЫМ, у
обоих кандидатов `probe`, и проба `repomd.json` остаётся запасным путём (Р41);
`successor` читается и называется в отказе, но автоматически не следуется
(Р42).

**А.7 Карантин:**

```rust
pub struct Quarantined { pub group: Group, pub name: String, pub version: Version, pub missing: Vec<String> }
```

`Index` несёт `quarantined: Vec<Quarantined>` (в память при load/project, в
файлы НЕ пишется); любой ответ по имени с карантинными версиями включает
`unavailable {version, missing, recipe}`; recipe — из каталога рецептов, не
литерал по месту.

**А.8 Слои исполнения.** Это ТЗ — план; на каждую фазу босс режет ПАКЕТ по
транспортному закону зоны (`SUBAGENT-LAUNCHERS.md`): контекст компилируется в
пакет (точные файлы из фазы + формы из этого приложения + self-verify

## Приложение Б. Пофактные решения (иначе их переизобретёт исполнитель)

**Б.1 Политика по каждому словарю (для Ф4.1/Ф4.2).** Открытость решается по
вопросу «ветвится ли потребитель, и есть ли у незнакомого безопасное

| словарь | политика | почему |

Скобка «сегодняшний код сортирует `PathBuf` до нормализации — подозрение
ревьюера на расхождение Windows/Unix» **неверна**, и следующий читатель не
должен строить по ней. `Ord` у `Path` в std — **покомпонентный**: разделителя
он не видит вовсе, поэтому рецепт 0 платформенно стабилен, и подозрение
ревьюера не подтвердилось. Рецепты различает не разделитель, а порядок «по
компонентам» (рецепт 0) против «по нормализованным байтам» (рецепт 1), и
расходятся они ТОЛЬКО когда сосед продолжает имя каталога байтом **ниже**
`/` (0x2F) — `spec-x.md`, `-`=0x2D. На байте, который называл этот абзац
(между 0x2F и 0x5C, то есть `specX.md`), рецепты **совпадают**, то есть
фикстура такой формы не доказывала бы ничего. Практическое следствие, оплаченное
регрессией: реализация, сортирующая строку вместо `PathBuf`, тихо меняет хэш
всякого дерева с каталогом-префиксом соседа — ни один golden этого не ловит,
поймал потребитель (`vibe check`, счётчик `local_source_freshness`).

**Б.4 До-эпохи (для Ф1.2).** «Эвристика ровно один раз в истории» означает:
манифест без `epoch` навсегда читается **замороженным ридером №0** —
сегодняшней формой разбора. Ридер №0 после заморозки не редактируется; его
корпус — три реальных манифеста из `fixtures/` (снять копии при постройке).

**Б.5 Спеки, которые двигаются (спек-дифф входит в посадку фазы;
предъявляется владельцу вместе с фазой — ратификация PROP-044 покрывает
