## 2. Решения — с отвергнутыми вариантами {#decisions}

- **D1 · Публичный переключатель не трогается.** Решение: `public = false`
  на весь релиз; закрытая альфа ≠ публичное представление (рулинг §0.2 —
  по букве PROP-044 этот факт объявляет только владелец, и тег его не
  подразумевает). Отвергнуто: флип `public = true` — включил бы
  обязательства wave 3 (кодмоды, параллельные эпохи, sunset), которых нет.
  Пересмотр: слово владельца о публичном представлении.
- **D2 · 64-битные числа на проводе кодируются строкой — общим правилом**
  (B-091, вариант б; рулинг §0.12). Десятичная строка без знаковых
  сюрпризов, как protobuf-JSON. Отвергнуто: (а) потолок `u32` и в коде —
  вечный потолок ради бедности генератора; (в) пустая схема `{}` —
  замером даёт `Option<Value>`, теряя и тип и обязательность. Пересмотр:
  jtd-codegen научится 64-битным (проверять при его бампе).
- **D3 · `RepomdFileEntry` получает тег в обоих вариантах, repomd
  генерируется целиком** (B-073, вариант 2; рулинг §0.12). Пока
  `public = false` перелом бесплатен и безмиграционен. Отвергнуто: (1)
  рукописный остров навсегда с записанной причиной — остров остаётся
  классом дефектов; (3) отложить — переносит перелом на послепубличное
  время, где он дорог. Пересмотр: не предвидится.
- **D4 · `[[registry]].index_url` строится** (B-083; рулинг §0.12) —
  настройка проекта едет с проектом; env-переменная остаётся
  переопределением. Отвергнуто: понизить до env — непереносимо между
  машинами и оставляет пример спеки ложью.
- **D5 · «Единственная точка доверия» сужается до правды** (B-084; рулинг
  §0.12): спека описывает то, что есть (хэш содержимого сверяется при
  заборе; манифест сверяет операторский `verify`), потребительская
  сверка — пост-1.0. Отвергнуто: строить сверку сейчас — тянет реестр
  возможностей читателя в общий дом (архитектурный вопрос класса B-080).
- **D6 · HTTP-ручка reindex отзывается** (B-085; рулинг §0.12):
  переиндексация — операторский глагол; рецепт-хук из спеки убирается.
  Отвергнуто: построить маршрут — сетевой триггер тяжёлой перестройки
  есть DoS-рычаг, потребитель сегодня один. Пересмотр: первый оператор,
  которому нужен сетевой триггер.
- **D7 · Лестница конфигурации `vibe-index` строится целиком** (B-086;
  рулинг §0.12): флаг → env → `state/config.toml` → умолчание, у каждого
  значения видимый источник (provenance в `--help`/`config`-выводе — без
  него лестница добавляет способ ошибиться, не добавляя способа
  проверить). Отвергнуто: сузить норму — моя рекомендация, отвергнута
  владельцем; полнота выше экономии (`##EFFORT-IS-NOT-A-CONSTRAINT`).
- **D8 · Версия 1.0.0 — у продукта И у всех канонических пакетов** (рулинг
  §0.11). Дальше — рост третьей компоненты (1.0.1, 1.0.2, …). Почему:
  корпоративные CI/CD-контуры режут 0.x — проверено практикой владельца.
  Отвергнуто: пакеты остаются на 0.x (рекомендация босса) — отвергнута
  тем же CI/CD-доводом. Закон именования цел: слоты v1.0.0 свежие,
  ни одна координата `name@version` не переиспользуется.
- **D9 · Публикация — GitHub `vibespecs`, чистый лист, dotted-имена**
  (`NamingConvention::Fqdn`, PROP-008). GitVerse-зеркала пакетов в 1.0.0
  не публикуются (реестр = GitHub по PROP-000 §7 постуре; GitVerse API
  не умеет org-scoped создание). Пересмотр: появление второго хоста
  реестра.
- **D10 · Фаза T отменена, фаза F остаётся, G расщеплена** (рулинги §0.7,
  §0.8). F пишется в prose-judgement форме — без T у него нет измеренного
  покрытия, и это записывается в самом отчёте, не маскируется. G: вариант
  А (альфа-слой) едет релизом; G-полная (пакет `org.vibevm.doc`,
  `docs-legacy/`) — пост-1.0. Отвергнуто: тянуть полную G до релиза — её
  предпосылки (суд-разметка audience) сдвинули бы релиз на месяцы.
- **D11 · Дистрибутив Windows-only** (рулинг §0.9); форма выбирается
  замером в С9 (кандидат: zip с `vibe.exe` + `install.ps1` поверх
  существующего `vibe self` / first-run механизма, установка в
  `~/.vibe/opt` по рулингу §0.4). Linux/Mac — после гейта, другая машина,
  вне марафона.
- **D12 · Марафон: /goal + хуки + 90% компактификации.** Сводка
  компактификации имеет авторитет WAL — ниже файлов и команд; после
  каждой компактификации хук вбрасывает порядок перечитывания и живое
  состояние git. Блокер-протокол: §5.4.
- **D13 · Транспорт воркеров: claudez2 → claudez, до 5 параллельных на
  лаунчер** (рулинг §0.16). Конфликтоопасные многоместные правки — одним
  потоком (стоячее правило лаунчеров); ревью, вердикты, спеки, планы и
  коммиты не делегируются никогда. Механики — `SUBAGENT-LAUNCHERS.md`
  (босс читает ЦЕЛИКОМ до первого фан-аута).
