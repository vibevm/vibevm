## Расхождения — по одному подразделу на каждое

### 1. `##INDEX-OPTIONAL` (PROP-005:43) — класс: `stale`

**Спека говорит** (дословно):
> Consumers detect a registry's index by HTTP GET on a well-known path (`<index-base>/repomd.json`); 404 → fall back to the live `git ls-remote` path that exists today.

**Дерево говорит** (`crates/vibe-registry/src/index_client/mod.rs:129-131, 195-197`, дословно):
> The eternal handshake `hello.json` is asked FIRST, at BOTH candidate bases (`<base>/v1/index` then `<base>`), before any `repomd.json` probe

> // No handshake anywhere — today's `repomd.json` path, byte
> // for byte: the compatibility surface for indexes without a
> // handshake.

**Что верно ТЕПЕРЬ** (одно предложение — факт, не формулировка для спеки):
Потребитель детектит индекс сперва GET `<база>/hello.json` на двух кандидатах (`<base>/v1/index`, затем `<base>`), и лишь при отсутствии хэндшейка пробует `repomd.json` — тот остался совместимостным хвостом для до-хэндшейковых индексов.

**Как проверить заново** (одна команда):
```
grep -n "asked FIRST\|compatibility surface" crates/vibe-registry/src/index_client/mod.rs
```

### 2. `##INDEX-OPTIONAL` (PROP-005:43) — класс: `silent`

**Спека говорит** (дословно):
> 404 → fall back to the live `git ls-remote` path that exists today. No registry is required to have an index.

**Дерево говорит** (`crates/vibe-registry/src/index_client/mod.rs:111-117` и `crates/vibe-registry/src/multi_registry_resolver/mod.rs:389-392`, дословно):
> - [`ProbeOutcome::Refused`] — the index is there but this build
>   cannot use it: it refused us (401/403), OR its handshake
>   publishes no world this build reads (an unparseable body, an
>   unknown handshake format, foreign epochs — each reason names
>   the facts and the fix).

> // The index is there but refused us (401/403) —
> // surface it, unlike the silent Absent fall-through,
> // so a private index is not mistaken for a missing one.

**Что верно ТЕПЕРЬ**:
У пробы есть третий исход — `Refused` (индекс есть, но недоступен по 401/403 либо непрочитаем): он НЕ замалчивается, а всплывает `tracing::warn` в резолвере; молчаливый откат действует только для `Absent`.

**Как проверить заново** (одна команда):
```
grep -n "Refused\|surface it, unlike the silent" crates/vibe-registry/src/index_client/mod.rs crates/vibe-registry/src/multi_registry_resolver/mod.rs
```

### 3. `##INDEX-URL-DEFAULT` (PROP-005:96, вместе с `##INDEX-URL-CONFIG` PROP-005:82) — класс: `false`

**Спека говорит** (дословно):
> **Configurable but defaulted.** A `[[registry]]` block can pin a custom index location:

> Default: `<registry-url>/index`. Resolver tries the default location when `index_url` is unset; 404 / connect-failure on the index → silent fallback to live ls-remote (no error message; the operator did not promise an index).

**Дерево говорит** (`crates/vibe-core/src/manifest/project.rs:108-110`, `crates/vibe-registry/src/multi_registry_resolver/mod.rs:373-378`, `crates/vibe-registry/src/index_client/mod.rs:564-571`, дословно):
> #[serde(deny_unknown_fields)]
> pub struct RegistrySection {

> // PROP-005 §2.10 slice 10 — when an upstream index is
> // configured for this registry via env vars, attach the
> // probed client.
>             if let Some(url) = crate::index_client::index_url_for(&reg.name) {

> pub fn index_url_for(registry: &str) -> Option<String> {
>     …
>     std::env::var(format!("VIBEVM_INDEX_URL_{suffix}"))

**Что верно ТЕПЕРЬ**:
У `[[registry]]` нет поля `index_url` (полный набор полей — `name`, `url`, `r#ref`, `naming`, `auth`, `token_env`, `enabled`; блок `deny_unknown_fields`, так что TOML-пример из спеки сегодня — отказ парсинга), дефолт `<registry-url>/index` нигде не композируется, и резолвер подключает индекс-клиент только по env-переменной `VIBEVM_INDEX_URL_<REGISTRY>`.

**Как проверить заново** (одна команда):

### 4. `##INDEX-FILE-LAYOUT` (PROP-005:113–127) — класс: `stale`

**Спека говорит** (дословно, фенсед-блок):
> ```
> <index-root>/
> ├── repomd.json                                # manifest — hashes & metadata for all other files
> ├── primary.jsonl                              # one line per (group, name, version)
> ├── primary.jsonl.gz                           # gzipped variant
> ├── by-name/
> │   └── <name>.json                            # candidate set — every (group, name) sharing one bare name
> ├── by-cap/
> │   └── <capability-slug>.jsonl                # provides-index — pkgrefs that advertise this capability
> ├── by-purl/
> │   └── <purl-slug>.jsonl                      # describes-index — pkgrefs that describe this PURL
> └── README.md                                  # human-readable "what is this directory" pointer
> ```

**Дерево говорит** (`crates/vibe-index/src/index/mod.rs:39-46, 52-57`, `crates/vibe-index/src/index/memory.rs:321-326`, `crates/vibe-index/src/journal/store.rs:26-30`, дословно):
> **A whitelist, and deliberately not a directory walk.** The data
> directory also carries `README.md` and `.gitignore` (written once by
> `init`) and the whole of `state/` — the journal, the server lock, the
> scanner checkpoint.

> pub const WRITER_FILES: [&str; 4] = [
>     "hello.json",
>     "repomd.json",
>     "primary.jsonl",
>     "primary.jsonl.gz",
> ];

> // The eternal handshake lands last, after the manifest, and
> // stays OUTSIDE its `files` map (Р39)

> /// default sits under the data directory's gitignored `state/`, which
> …
>     data_dir.join("state").join("journal")

**Что верно ТЕПЕРЬ**:
Корень каталога индекса сверх перечисленного несёт `hello.json` (вечный хэндшейк — «the file a client reads first», пишется писателем после манифеста) и дерево `state/` (журнал `state/journal`, `server.lock`, `checkpoint.json`, org-cache), а также `.gitignore` от `init` — блок §2.4 всего этого не показывает.

**Как проверить заново** (одна команда):

### 6. `##REPOMD-TRUST-POINT` (PROP-005:169; рядом `##TWO-INTEGRITY-LAYERS` PROP-005:334) — класс: `false`

**Спека говорит** (дословно):
> `repomd.json` is the **single point of trust**. A consumer fetches it once (with a small ETag round-trip later), then fetches whichever sub-files it actually needs, verifying each against the recorded `sha256`.

**Дерево говорит** (`crates/vibe-registry/src/index_client/mod.rs:293, 307-322` — потребитель идёт сразу за `by-name` без чтения `repomd` и без проверки хэша; `crates/vibe-index/src/cli/verify.rs:1-2`, дословно):
> let url = format!("{}/by-name/{}.json", self.file_base, name);

> //! `vibe-index verify <data-dir>` — recompute file hashes and check
> //! `repomd.json` integrity.

**Что верно ТЕПЕРЬ**:
Единственный shipped-потребитель (`vibe-registry::index_client`) не читает `repomd.json` дальше пробы существования и не сверяет sha256 подобранных файлов с манифестом (греп `sha256|etag` по `index_client/` — ноль); сверка хэшей с `repomd.json` существует только как операторский глагол `vibe-index verify`, не как потребительский путь.

**Как проверить заново** (одна команда):
```
grep -rni "sha256\|etag" crates/vibe-registry/src/index_client/ ; grep -rn "sha256" crates/vibe-registry/src | wc -l
```

## Контроли пустого вывода

Каждый ноль, прочитанный как доказательство, сопровождался тем же инструментом на заведомо ненулевом случае (§0.7):

1. **«`crates/vibe-index/schemas/` не существует»** (якорь №5, выживший подпункт): glob `crates/vibe-index/src/**/*.rs` и `ls crates/vibe-index/` дают полный список (`Cargo.toml README.md docs fixtures src tests`) без `schemas/`; контроль того же инструмента — glob `schemas/**/*` в корне репозитория возвращает 14 файлов, включая всё семейство `schemas/index/e1/`. Ноль — работа инструмента подтверждена.
2. **`deny_unknown_fields` в vibe-index — 0** (якорь №8): контроль — тот же паттерн по `crates/vibe-core/src` → 47 попаданий в 18 файлах (например `manifest/project.rs:109`). Ноль реален.
3. **Вызовы часов в `index/` и `types/` — 0** (якорь №9): паттерн `Utc::now|SystemTime::now|Instant::now|Local::now|OffsetDateTime::now`; контроль — тот же паттерн по `crates/vibe-index/src/scanner` → 3 попадания (`org_walk.rs:338`, `manifest.rs:389`, `mod.rs:51`; первые два — код в `#[cfg(test)]`, третий — доктест-комментарий, что совпадает с фильтром панели по форме строки). Ноль реален; `journal/` тем же паттерном даёт только комментарии-докблоки.
4. **`sha256|etag` в `index_client/` — 0** (находка №6): контролей два — тот же паттерн по `crates/vibe-registry/src` → 43 попадания в 11 файлах (механика content_hash), и по `crates/vibe-index/src/index` → 39 попаданий в 8 файлах (писатель считает хэши). Ноль реален.

## Что измерить из этого сегмента нельзя

- Числа §1 (латентность 30–60 s, лимиты GitHub 60/5000 req/h, «~5× compression typical») — сетевые/эмпирические утверждения; деревом не проверяются (пиннинг уровня gzip при этом проверяем и подтверждён: `primary.rs:4, 62-67`).
- Достижимость raw-URL GitHub/GitVerse и зеркал (§2.2 `##REPO-HTTP-FETCHABLE`, `##REPO-MIRRORABLE`, `##REPO-CLONEABLE`) — внешняя инфраструктура; в дереве видна только композиция URL.
- Будущие поведения, честно помеченные планом: `##TRIGGER-HTTP` «in v1 — v0 just blocks», `##WRITE-AUTO-COMMIT` (`@status:spec/done` для v1), `##TRIGGER-GIT-HOOK`/`##TRIGGER-CRON` (документируемые, не поставляемые) — по §1 не расхождение.
- Отрицательное утверждение `##INDEX-OPTIONAL` «No registry is required to have an index» — утверждение о развертывании, а не о коде; код-сторона (индекс строго опционален, `Absent` → прежний путь) подтверждается (`multi_registry_resolver/mod.rs:375-401`).
- «`vibe-index` lives at `crates/vibe-index/` as a workspace member» (§ status-line) и судьба «семи wire-отчётов» как точного счёта — счётно лишь вместе с генезисом файлов; без git-истории (запрещена) невозможно установить, был ли когда-либо верен контраст «семь против нуля»; деревом опровергнут сам контраст (находка №5), а не число.

## Счёт
