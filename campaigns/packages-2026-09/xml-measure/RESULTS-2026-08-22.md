# §5a — замер динамических роутеров во внешних агентах: результаты

Дата: 2026-08-22. Контракт: `vibevm/vibespecs/common/PROP-045-xml-spec-sources.xml`
§5a (`##AGENT-ROUTER-MEASURE`, `##AGENT-ROUTER-MODEL-TIERS`). Форма
диалекта на момент замера: **финальная** — именные секции и именные
факты (`fact="true"`), рецепт `specdoc/3`; замер сознательно шёл ПОСЛЕ
посадки переходов, чтобы мерить то, что шипится.

## Стенд

- Полигон: проект с redbook-замыканием (30 пакетов из каталожного
  реестра-копии) + три пробных пакета `org.vibevm.probe/*`; в INDEX —
  3 динамические записи: `router-win` и `router-aux` (`when =
  "os:windows"`, активны), `router-nix` (`when = "os:linux"`,
  НЕАКТИВНА — негативный контроль). Ответы на контрольные вопросы
  существуют только внутри динамически включаемых файлов (маяки).
- Три материализации одного дерева: `xml` / `markdown` / `mixed`
  (probe-исходники MD ⇒ в mixed остаются `.md`, в xml становятся
  `.xml`). Пост-ассерты стенда подтвердили закон расширений в путях
  INDEX для каждого варианта.
- Probe-промпт не называет форматов файлов вообще («выполни бут по
  CLAUDE.md»); каждый прогон — свежая копия полигона; скоринг по
  артефактам (маяк + путь-источник в ответной строке).

## Перечисление тиров (enum-tiers, живые пинги)

Установленный codex (v0.148.0, ChatGPT-аккаунт) обслуживает ровно два
тира: `gpt-5.5` и `gpt-5.6-sol`. Кандидаты `gpt-5.5-codex`,
`gpt-5.1-codex-mini`, `codex-mini-latest` — не сервятся (ошибка на
пинге). Ось effort использована как вторая «ось простоты»: слабый
инструмент — `gpt-5.5` @ `low`, потолок — `gpt-5.6-sol` @ `xhigh`.
Claude-семейство: лейн claudez (GLM, слот `big`).

## Вывод

- **Дельта XML − MD = 0** на каждом лейне и каждом тире: оба агентских
  семейства читают динамические записи INDEX над XML-материализацией
  так же безошибочно, как над Markdown; mixed — тоже без потерь.
- **Негативный контроль чист во всех ячейках**: `when = "os:linux"`
  корректно пропускается на Windows-сессии, маяк неактивной записи не
  утёк ни в один ответ; агенты сами объясняют пропуск условием из
  INDEX (см. transcripts — формулировки точны вплоть до цитаты
  `when = "os:linux"`).
- **Слабый инструмент не слабее**: gpt-5.5 @ low (наказ владельца —
  простые модели первыми) прошёл 2 полных свипа без единого промаха —
  формат-трение у финального диалекта ниже порога чувствительности
  даже дешёвого тира.
- Пути-источники цитируются с точным материализованным расширением
  (`.xml` в xml-варианте, `.md` в markdown и в mixed для MD-исходников)
  — агенты читают именно материализованные файлы, а не пересказывают.

## Динамическая загрузка ломается? Нет. Рекомендации

Отказов не найдено; анализ дефектов не требуется. Рекомендации по
итогам замера:

1. **Форма шипится как есть** — XML-материализация готова быть целевой
   по умолчанию в будущем (курс PROP-045 «Mixed input → чистый XML»).
2. Генерируемая шапка INDEX (комментарий с семантикой `when`) достаточна:
   все шесть агентских прогонов вывели правило пропуска только из неё —
   отдельной документации динамической полосы агентам не нужно.
3. Стенд остаётся многоразовым регрессионным инструментом: любое будущее
   изменение диалекта/лоадеров — один `setup.sh` + свип слабого тира
   (`gpt-5.5/low`) как самый чувствительный детектор.
4. Единственный найденный за замер подводный камень — вне агентов, в
   CLI: `vibe progress … --campaign <id>` трактует значение как путь
   от cwd (создался мусорный каталог в корне при голом `<id>`);
   заведено как кандидат в BACKLOG.

динамическую загрузку, ни негативную дисциплину. Строки в
`runs/scores.csv`: `20260822T0834…Z…0836…Z`.

## Угрозы валидности

Одна ОС (Windows), один негативный класс условий (`os:*`), 1–2 прогона
на ячейку, один хост-репозиторий. Для целей §5a (готовность финальной
формы) этого достаточно; расширение — по мере надобности тем же стендом.
