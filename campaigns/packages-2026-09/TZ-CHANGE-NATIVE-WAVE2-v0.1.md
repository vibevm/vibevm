## W1. `vibe.toml` — честный налог стабильности, выплаченный до конца

### Философия

Манифест — самый дорогой формат системы: авторский, невосстановимый, живёт
в чужих репозиториях, читается агентами как файл (худший квадрант §5). Ему
одному PROP-044 назначает налог стабильности (§6.2) — и первый ТЗ заплатил
только первый взнос (эпоха-поле Ф1.2, ридер №0 Б.4). Этот слайс доплачивает:
строгость, которая ПОМОГАЕТ автору (did-you-mean в нашем пространстве имён —
в рукописном файле незнакомый ключ это опечатка, автор рядом); резерв,
который мы никогда не тронем; схема как единственный источник формы; кодмод
как единственный способ миграции (G15: правка документа на месте, никогда
сериализация из структуры — она убивает комментарии и порядок автора).

### База (проверено 2026-08-13)

| факт | где |
|---|---|
| Строгий парс манифеста (`deny_unknown_fields`), поля эпохи нет до Ф1.2 | `crates/vibe-core/src/manifest/document.rs:66`; `package.rs` (`PackageMeta`) |
| Манифестов в дереве 172, авторских 44 — корпус для репетиций кодмодов | замер G4 2026-08-09 (первое ТЗ B13) |
| `toml_edit` уже в workspace — движок правки-на-месте есть | `Cargo.toml:121` (`toml_edit = "0.23"`), `vibe-core` его уже тянет |
| Прецедент отказа-с-рецептом на легаси-значение | `Materialization` manual `Deserialize` (`package.rs`, тест `materialization_refuses_the_legacy_snapshot_name_with_the_recipe`) |
| Маршрутизация генератора расширяема по stem | `xtask/src/codegen.rs:66` (`generated_dir_for`) |

### Шаги

**W1.1 — Схема манифеста.** `schemas/manifest/e1/package.jtd.json` (+
вложенные: requires/provides/…), запись в `formats/REGISTRY.toml`
(`recoverable = false`, `foreign_parsers = "many"` — худший квадрант, ровно
поэтому создание НОВЫХ форматов в нём требует владельца; этот — резидент).
Схема описывает ФОРМУ; политика (строгость, did-you-mean, резерв) — в
генераторе/обвязке, не в схеме. Словари манифеста (kind и др.) — из единого
источника Ф4.1 (G9), не дубликат.

**W1.2 — Did-you-mean строгость.** Слой над строгим парсом: незнакомый ключ
в НАШИХ таблицах → ошибка с ближайшим известным ключом (расстояние
Левенштейна ≤2 — подсказка, иначе просто перечень легальных) и `spec://`-
якорем. Реализация — свой deserializer-обёртка или post-parse валидация по
схеме W1.1; НЕ ослаблять `deny` (авторский файл, автор присутствует —
асимметрия с машинным каталогом принципиальна).

**W1.3 — Резерв-секция.** РЕШЕНО: таблица `[reserved]` в `vibe.toml`
принимается, сохраняется round-trip'ом, НИКОГДА не интерпретируется и не
валидируется вглубь; любые наши будущие ключи обязаны появляться ВНЕ её.
Тест: манифест с `[reserved] anything = "x"` парсится, кодмоды (W1.5) её
не трогают байт-в-байт.

**W1.4 — Записка за новый ключ.** Периметр Ф5.2 расширяется: изменение
`schemas/manifest/**` требует `formats/breaks/NNN.md` (в допубликационном
режиме — отчётно, по Ф5.3). Сообщение гейта называет цену: «новый ключ
манифеста — многолетнее обязательство» (§6.2).

**W1.5 — Кодмод-движок (G15).** Новый маленький крейт `vibe-codemod` (или
модуль в `vibe-core`): `pub trait ManifestCodemod { fn id(&self) -> &str;
fn apply(&self, doc: &mut toml_edit::DocumentMut) -> Result<Applied> }`;
раннер `vibe migrate [--dry-run]`: идемпотентность обязательна (повторный
прогон = пустой дифф), правка ЧЕРЕЗ `toml_edit` (комментарии/порядок
выживают — тест с комментированным манифестом), сериализация-из-структуры в
кодмод-путях запрещена grep-гейтом панели (шаг self-check: `to_string(` на
Manifest-типах в `vibe-codemod` — красный; сообщение цитирует G15).
Репетиция: прогон `--dry-run` всех зарегистрированных кодмодов по 172
манифестам дерева — шаг приёмки (0 неожиданных диффов на идемпотентном
наборе). Первый кодмод — тривиальный образец: `ensure-epoch` (добавить
`epoch = 1` там, где поля нет; в допубликационном режиме законен и как
массовая правка — D13).

**W1.6 — Спека и суд.** PROP-044 §6.2 факты `FMT-MANIFEST` — статус на
impl/done в частях, которые сели; спек-дифф + суд + seal; Ф4.3-белый список:
манифест ВЫЧЁРКИВАЕТСЯ из исключений `#[derive(Serialize/Deserialize)]`
только когда типы манифеста переезжают на генерацию — это НЕ этот слайс
(осознанно: рукописные типы манифеста остаются, но их ФОРМУ сторожит схема
W1.1 через паритет-тест «рукописный тип ⊇ схема»; полный переезд — вместе с
проекцией волны 3). Записать это исключение в Ф4.3-списке с датой пересмотра.

### Приёмка W1

```bash
cargo test -p vibe-core manifest                 # did-you-mean, [reserved], round-trip
cargo run -q -p vibe-cli --bin vibe -- migrate --dry-run   # 172 манифеста, 0 сюрпризов
bash tools/self-check.sh ; echo "EXIT=$?"        # EXIT=0; G15-гейт доказан пробой (и откатом)
```

**Запреты W1:** не ослаблять deny; не сериализовать манифест из структуры
нигде в кодмод-путях; не заводить новые ключи манифеста самим этим слайсом;
`[reserved]` не интерпретировать никогда.

## W2. `vibe.lock` — свобода по построению (D9)

### Философия

Локфайл — самый дешёвый формат (§6.3): восстановим одной командой, один
парсер — наш. Значит его эволюция не должна стоить НИЧЕГО: сегодняшний отказ
по `schema_version != 5` задаёт пользователю вопрос про черновик. D9 (РЕШЕНО
первым ТЗ): валидность = точная тройка (эпоха, хэш генератора, id рецептов);
несовпадение → молчаливая перегенерация; `--locked` превращает её в громкий
отказ для CI. Следствие лестницы §5: волатильным фактам место именно здесь.

### База

| факт | где |
|---|---|
| Сегодня: version 5, `!=` → отказ; перегенерация каждым install | `crates/vibe-core/src/manifest/lockfile.rs:50`, `:430` (замер B14 первого ТЗ) |
| Флага `--locked` НЕТ в CLI (проверено grep 2026-08-13) — вводится этим слайсом | `crates/vibe-cli/src/cli/*.rs` |
| Рецепт хэша с Ф1.3 несёт id (`sha256-tree/1:`) | `formats/hash_recipes/1.toml` (после Ф1.3) |

### Шаги

**W2.1 — Тройка валидности.** В `[meta]` локфайла: `catalog_epoch`,
`generator_hash` (РЕШЕНО: sha256 от (версия крейта генератора + байты всех
схем, по которым сгенерированы wire-типы) — стабильно между машинами,
меняется ровно когда меняется генерация; вычисляется в build.rs/`xtask
codegen` и включается константой), `hash_recipes` (список id из Ф1.3).
Чтение: несовпадение ЛЮБОГО члена тройки — не ошибка, а сигнал «перегенерируй
молча» (лог info). Старые локфайлы v5 без тройки читаются и молча
перегенерируются один раз.

**W2.2 — `--locked`.** Флаг у `install`/`update`/`reinstall`: при нём любое
«надо перегенерировать» (тройка, отсутствие лока, дрейф канала S4.5) —
громкий отказ с перечнем причин и рецептом («запусти без --locked локально;
закоммить свежий лок»). Имя `--locked`, НЕ `--frozen` — слово занято
пакетами (D9/D14).

**W2.3 — Схема локфайла.** `schemas/lockfile/e1/…` + запись в реестре
(`recoverable = true`, `foreign_parsers = "ours"`). По роли из реестра
генератор даёт локфайлу строгий разбор (D9-совместимо: строгость дешёвая,
потому что несовпадение = перегенерация, не отказ пользователю).

**W2.4 — Переезд типов.** Типы записи локфайла (`LockedPackage` и вложенные)
переезжают на генерацию из W2.3 (реэкспорт + impl-файлы рядом — образец
Ф4.2); `lockfile.rs` остаётся оркестрацией чтения/записи. Белый список
Ф4.3 сокращается: локфайл вычеркнут. (Это БЕЗОПАСНЕЕ манифестного переезда:
один парсер — наш, формат восстановим.)

**W2.5 — Спека и суд.** PROP-044 `##FMT-LOCKFILE` → impl/done; PROP-002
§2.7 (schema v5) — supersession-запись; суд тем же заходом.

### Приёмка W2

```bash
# лок со старой тройкой: install молчит и перегенерирует; --locked падает с рецептом
cargo test -p vibe-core lockfile
cargo test -p vibe-cli --test cli_registry_mgmt   # install/update пути живы
bash tools/self-check.sh ; echo "EXIT=$?"
```

**Запреты W2:** не спрашивать пользователя про лок никогда (либо молча, либо
`--locked`-громко); не называть флаг `--frozen`; тройку не расширять «на
вырост».

## W3. Показ замороженности на каждой поверхности (D14-обязательство)

### Философия

Урок Maven, записанный рулингом D14: «мутабельность, которую человек не
видит, — мутабельность, которая его удивит». Ф1.4 кладёт поле — этот слайс
выполняет обязательство: **каждая поверхность, показывающая версию,
показывает статус**. Периметр назван рулингом дословно и не сокращается по
сегодняшней надобности.

### База и гейт

Гейт: Ф1.4 (поле `frozen` в записи каталога и манифесте) посажена. Периметр
(D14, дословно): `vibe list/show/tree/search/outdated`, план и отчёты
install, MCP-инструменты (`query`/`select`/`explain`/`query_package`), TUI,
HTTP-ответы сервера, узкая проекция (последняя — волна 3, отметить как
исключение с триггером, не молчать). Machine-JSON несёт поле ПО СХЕМЕ
(автоматически из Ф4) — этот слайс про ЧЕЛОВЕЧЕСКИЕ рендеры и про то, что
поле реально доезжает.

### Шаги

**W3.1** — инвентарь рендеров версии: grep по перечисленным командам, где
печатается `version` (в т.ч. таблицы TUI `commands/tree/tui/**`). Таблица
«поверхность → файл:строка → как покажем» кладётся в отчёт слайса ДО правок.
**W3.2** — рендер: суффикс `frozen`/`snapshot` у версии (человеческие
поверхности — всегда; формат согласовать один: `1.2.0 [frozen]` /
`1.2.0 [snapshot]` — единый хелпер в одной ячейке, не пять копий строки —
G9-дух). Yanked/tombstone из Ф1.4 — тем же заходом (`[yanked]`).
**W3.3** — e2e-тест на каждую поверхность периметра (фикстурный каталог с
замороженной и незамороженной версией; MCP — через существующие
инструментальные тесты). **W3.4** — спек-дифф: D14-строка обязательства →
impl/done с перечнем файлов; суд.

**Приёмка:** каждая команда периметра в фикстуре печатает статус; панель.
**Запреты:** не сокращать периметр «этой команде не надо»; не плодить
формат-строку по месту (один хелпер).

## W4. Не-каталожные форматы и два остаточных гейта

### Философия

§6.5: «поверхности, которые никто не инвентаризовал, — тоже форматы». Семь
CLI `--json`-отчётов, MCP-схемы (буквально контракт с чужими агентами),
skill/subskill-файлы — каждому запись, схема под НАШИМ генератором, корпус и
wire-diff-покрытие; иначе их сломают, не заметив (`##FMT-UNINVENTORIED`).
Плюс два гейта §8, не покрытых первым ТЗ: G12 и G13.

### База

| факт | где |
|---|---|
| 7 отчётных JTD-схем уже существуют, но вне политики генератора | `schemas/*.jtd.json`; маршрутизация `xtask/src/codegen.rs:66` |
| `package-tree.schema.v1.json` — восьмой формат (`vibe load --json`) | `crates/vibe-cli/resources/package-tree.schema.v1.json` |
| MCP-схемы живут в коде | `crates/vibe-mcp/src/tools.rs` |
| Subskill-записи в локфайле | `lockfile.rs:335-361` (`LockedSubskill`) — их ФАЙЛОВЫЙ манифест ищется по `vibe skill`-машинерии (`commands/skill/`) |

### Шаги

**W4.1 — Отчёты CLI под политику.** Семь схем переезжают в
`schemas/reports/e1/**`, перегенерация через wiregen Ф4.2 (открытые словари,
политика пропуска по `"x-empty"`, строгость по роли `foreign_parsers`);
записи Ф1.1 дополняются `corpus`-путями. Корпус на отчёт: один
фикстурно-собранный образец + пересборочный тест (Ф5.1-образец), wire-diff
Ф5.2 расширяет периметр на `schemas/reports/**` + `formats/corpora/reports/**`.

**W4.2 — MCP-схемы.** Извлечь из `tools.rs` в `schemas/mcp/e1/*.jtd.json`;
`tools.rs` потребляет сгенерированное (описания инструментов — из schema
metadata, не строками по месту); запись в реестре
(`foreign_parsers = "many"` — это контракт с чужими агентами); корпус =
голдены ответов инструментов.

**W4.3 — Skill/subskill-файлы.** Их файловый формат (манифест skill'а) —
схема + запись + корпус из реальных примеров дерева.

**W4.4 — G12: корпуса эпох у клиентов.** Тест-семейство в
`vibe-registry`/`vibe-index`: клиент читает корпуса ВСЕХ поддерживаемых эпох
(сейчас — e1) из `formats/corpora/**`; на sunset (когда появится) тот же
тест переворачивается в утверждение текста отказа с рецептом. Сейчас — один
живой мир: тест = «клиент читает корпус e1 + hello» (связка с Ф6.1-e2e),
каркас на будущее — параметризация по мирам из `formats/EPOCHS.toml`.

**W4.5 — G13: схема-правки отдельным коммитом.** Механизм (РЕШЕНО): xtask-гейт
`check-schema-commit` — по `git diff --name-only HEAD~1..HEAD`: если коммит
трогает `schemas/**` или `formats/**` И одновременно `crates/**` (вне
`**/generated/**`) — красный с цитатой G13. В self-check — advisory (панель
проверяет дерево, не историю); обязательным — в CI-скрипт зеркал, когда CI
появится; до тех пор — шаг ручной приёмки фазы. Записать честно оба режима.

**Приёмка W4:** `cargo xtask wire-diff` покрывает отчёты+MCP+skill; пробная
правка схемы отчёта без записки — красная (в допубликационном режиме —
отчётная, Ф5.3); G12-тесты зелёные; G13-гейт доказан пробным смешанным
коммитом в ветке (и откатом). **Запреты:** не переписывать содержимое
отчётов «раз уж переезжаем» (перенос формы ≠ перелом провода — wire-diff
обязан быть пустым на переезде); MCP-описания не терять (они уезжают в
metadata схем).
