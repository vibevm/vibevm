## Alternatives and boundaries

1. **Recommended:** upstream-supported seam in a new explicitly admitted native revision. Scope includes native review/version maintenance and provider-free qualification. No upstream edits, network publication or new version adoption is authorized by writing this packet.
2. **Owner-directed maintained patch/package:** only after explicit owner authorization and architect contract identifying canonical source, license, update policy and installed-runtime admission. This is a maintenance commitment, not permission to hand-edit installed code or materialized dependencies. Same native authorization/cleanup invariants apply; no global monkeypatch.
3. **Explicit owner scope disposition:** owner may decide a bounded supported product contract. Record exact excluded user journeys and the conflict with current first-class mandate; architect/builder cannot choose this unilaterally or label temporary read fallback full parity.

No credible wall-clock or monetary estimate is asserted before native owner/contract is selected. Main cost drivers are native lifecycle/security review, update maintenance, and finite actual qualification—not token costs for another broad proof matrix. Existing private runtime artifacts and accepted source receipts can be reused; real credentials/providers remain unnecessary and unauthorized.
