`pub(crate) fn run(ctx: &output::Context, selected: &Selected, check: bool) -> Result<()>`:
- composed = super::compose_launch_flags(ctx, selected, HarnessKind::Claude, None, &[])?;
- lane = if let Some(u) = &composed.undeliverable { Err(u.sentence()) } else if let Some(p) = &composed.lane { Ok(p.as_path()) } else { Err(READ_DELIVERY.to_owned()) };
- outcomes = refresh_agent_types(selected, lane, if check { SyncMode::Check } else { SyncMode::Write })?;
- build the report;
- if ctx.is_json() { ctx.emit_json(&report)?; } else { print one line per type };
- then apply the exit rule.

**Decisions already made.**
- PromptCommand variant:
```
    /// Write this node's generated subagent types (`vibe-worker`,
    /// `vibe-executor`) into `.claude/agents/`, or with `--check` report
    /// whether the files there are current, writing nothing.
    Types {
        #[arg(long, value_name = "REL")]
        node: Option<String>,
        #[arg(long, default_value = ".")]
        path: PathBuf,
        /// Report only, write nothing; exits non-zero when a type file is
        /// stale, missing or not generated by vibe.
        #[arg(long)]
        check: bool,
    },
```
- READ_DELIVERY (a const in types.rs): "this node delivers its lane to `claude` by `read`, so there is no lane file to give a worker type".
- Report: wire::PromptTypesReport { protocol: PROTOCOL.to_owned(), node: selected.node_rel.clone(), harness: "claude", mode: "write" or "check", directory: CLAUDE_AGENT_TYPES_DIR, types: outcomes mapped to wire::AgentType { name, file, status: status.as_str().to_owned(), reason } }. Use the exact generated field and type names that the lead names in the packet.
- Human output: one stdout line per type, `format!("{:<11} {}", status.as_str(), file)`, followed by `format!("  ({reason})")` on the same line when there is a reason.
- Exit rule in write mode (this entry): after printing, if any outcome is Foreign, bail!("`{file}` was not generated by vibe, so vibe leaves it alone; rename or delete it and run `vibe prompt types` again") for the first foreign file. Unavailable is not an error. In check mode this entry only prints; SAT-5 adds its exit rule.
- A node that has not opted in fails through compose_for_launch's existing refusal, and nothing is written. A lane that is stale on disk is undeliverable, so the worker type is removed or reported unavailable with the `vibe prompt build` sentence. This command reads the lane on disk and does not build, like `vibe prompt flags`.
- Hidden prerequisite: the lead's generated module vibe_wire::generated::prompt_types must be on the branch. Do not write wire code yourself; if it is missing, stop (rule 9).
