```
    <p><SYS-WORKER-PREFIX-DELIVERY fact="true" status="spec/done">**Owner decision 2026-11-22 — a worker that needs full project context receives the composed agent lane from the launcher, and every same-type worker of one wave receives the same bytes.** Four decisions, each stated so it is not re-argued. **(1) Only the launcher produces a worker prefix.** `vibe agent claude --worker-prefix` passes Claude Code's `--append-subagent-system-prompt-file` naming the same composed lane file the parent launch passes to `--append-system-prompt-file`, and `vibe prompt flags --harness claude --workers` prints that flag; there is no second composition, and nobody assembles a worker system prompt by hand, because a hand-assembled prompt differs per worker and any difference before the prefix makes every worker write it to the cache again. **(2) One generation per wave.** The lane is composed once, at the parent's launch (`#SYS-AGENT-LANE`), and every worker that session starts receives those bytes; an edit reaches workers only through a new launch. **(3) A quiet worker or an executor on a packet never gets it, and `#SYS-WORKER-EXCLUSION` stays true for them.** The flag reaches every subagent of the session it is passed to, so a session launched with `--worker-prefix` starts only full-context workers, and a lead that dispatches quiet workers or packet executors does so from a session launched without it. **(4) Parent and worker do not share a cache; same-type workers of one wave do.** A subagent's system prompt is its own, so the only claim is that workers of one type in one wave share one prefix. Measured 2026-11-22 (`campaigns/sys-prompt-2026-11/WORKER-PREFIX-MEASUREMENT.md`): five same-type workers whose prefixes were byte-identical wrote the prefix to the cache once and read it four times, about 3.6 times cheaper than five workers whose prompts differed before it. **Claude Code only, print mode only.** The flag is hidden and marked internal in Claude Code 2.1.330; it sets CLAUDE_CODE_ENABLE_APPEND_SUBAGENT_PROMPT itself, propagates to nested subagents, and does not reach a subagent started with an isolated context. Claude Code 2.1.330 describes `--append-subagent-system-prompt-file` as working only with `--print`, so `vibe agent` refuses `--worker-prefix` when neither `-p` nor `--print` appears before the first `--` (after it, `-p` is a prompt, not print mode) rather than pass a flag the session ignores, and refuses it for every other harness kind, none of which has such a flag; both are refusals of an argument, not delivery failures, so `#SYS-SOFT-LAUNCH` does not turn them into a bare start. A launch that delivers no lane — a soft launch, or a project that has not opted in — passes no worker flag either.</SYS-WORKER-PREFIX-DELIVERY></p>
```
