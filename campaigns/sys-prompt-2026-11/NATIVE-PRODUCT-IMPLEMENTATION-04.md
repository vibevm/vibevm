## Initial product asset review findings

The first Rust asset publisher passed `Some(0o600)` unconditionally to strict safefs publication. Correct this through the established platform contract: Unix exact mode0600, non-Unix no Unix mode request; do not weaken safefs or claim Windows ACL equivalence. Keep immutable full-digest names, foreign-byte refusal and no-follow publication.

The first Pi carrier library used a fixed named inline extension path for owned-error filtering and ordinary UTF-8 string reads. Before production admission, reject collision with another loaded extension identity and validate prefix encoding/binding strictly rather than silently replacing invalid UTF-8 bytes. Source re-review confirms platform-conditioned mode selection, fatal UTF-8 decoding and loaded-extension/owned-handler identity checks were added; terminal tests are still required. Preserve the related reload boundary: native session_start handler exceptions are reported and swallowed, so failed reattachment must not leave a later turn without admission. Initial bootstrap must perform explicit admission before entering a native mode, and reload failure must retain a named refusal at the actual pre-submission owner. These are bounded concrete review findings, not an invitation to introduce a generic extension/security framework. Report their actual tests and disposition. Library exports alone are not an executable native CLI bootstrap or completion of launch support.
