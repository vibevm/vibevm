# Explicit fixed Validate through the local CLI frame

`vibe machine session --root <absolute> --fixed-validate issue --ttl-ms N`
creates one host-owned finite C1 grant. `--fixed-validate reattach` looks up
that grant and never falls back to issuance. Four positive CLI flags grant the
captured script and the three supported control modes; absent grants are
denied. The default command remains the pure planner. The CLI derives a stable
physical-root target, one project-local principal, current target OS and a
versioned policy source before reading frames. This is a cooperative project
lease boundary, not hostile cross-user authentication.

The fixed runner negotiates only its registered lifecycle action formats. A
client still resolves a typed selection and exact approval before submit.
The first process's provider result, C1 key/run and lifecycle marker/report
survive EOF. A reattached process gets fresh outer session/context/target IDs;
its old question and accepted reference do not become authority. A cold stale
submit returns `UnknownReference` with retained run provenance and truthful
uncertainty. Active owner death returns recovery-required uncertainty and does
not redispatch. Explicit force follows the separately accepted owner rule;
trace, deploy profile and general phases remain unavailable.

Focused Linux proof: real CLI fixed child-process family **14/14**, CLI parser
**3/3**, pure/MCP coexistence binary family **5/5**, native clap inventory
**1/1**, and direct fixed owner **5/5**. The process fixture checked issue,
reattach, one namespace/run/counted script effect, lost reply, killed owner,
expired/retired grant, malformed frame, foreign root, policy disagreement and
no ambient HOME/CWD writes. The 14 current source SHA256 observations are bound
in `formats/capability-coverage/machine-session-source-delta.json`; the
historical selected source capture is not relabelled as current. No full gate
panel, mutation campaign, public push or 1.1.0 release was run.
