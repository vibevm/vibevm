## 1. Goal {#goal}

`vibe progress report` grows an evidence column fed by a real specmap-backed
`EvidenceProvider`, so a reader sees marker-vs-reality without opening the
cache.

## 2. Contract {#contract}

> The specmap side supplies, per unit, the `implements` / `verifies` edge
> counts and their provenance refs; the report joins them to the marker.
> — `spec://org.vibevm.core/vibevm/modules/vibe-progress/PROP-043#evidence`

> `report` — views, audiences, per-file and project rollups, explicit vs
> computed, xml / md / json forms.
> — `spec://org.vibevm.core/vibevm/modules/vibe-progress/PROP-043#tool`

Anchors realised: `EVIDENCE-SPECMAP`, `CMD-REPORT`.

## 4. Required behavior {#behavior}

1. In `progress-core`: add an optional evidence column to the report path.
   `Row` gains `evidence: Option<Evidence>`. `rows()` gains a
   `&dyn EvidenceProvider` parameter (pass `&NoEvidence` at every existing
   call site that has no provider — the separability law: the core must
   still build and run with no provider at all).
2. Each renderer prints the column only when at least one row carries
   evidence — an evidence-less run must produce **byte-identical** output to
   today's. `render_md`: a right-most column `evidence` holding
   `impl=<n> ver=<n>`; `render_xml`: an `<evidence implements="n"
   verifies="n"/>` child of the row element; the json form: an `evidence`
   object, omitted when absent (`skip_serializing_if`).
3. When `mismatch(&marker, &ev)` returns `Some(msg)`, the row is flagged —
   md: a trailing `⚠` in the evidence cell; xml: a `mismatch="<msg>"`
   attribute; json: a `mismatch` string field.
4. In the vibe-cli adapter: implement `SpecmapEvidence`, a provider that
   loads the host `specmap.json` once and answers `evidence_for(unit_addr)`
   by counting the `implements` and `verifies` edges whose spec side equals
   `unit_addr`, with the code-side locators as `refs`. Address matching is
   exact on the full `spec://…#anchor` string; a unit with no edges returns
   `None`, never `Some(zeros)` — "no data" and "zero edges" are different
   claims and the report must not merge them.
5. Wire it into the `report` subcommand: if `specmap.json` is readable, use
   `SpecmapEvidence`; otherwise `NoEvidence`, printing nothing about it (a
   missing index is not an error — most consuming projects have none).

Edge cases: a malformed `specmap.json` is a hard error naming the file, not
a silent fall-through to `NoEvidence` — a corrupt index must not read as an
absent one. A unit address that appears in the index with zero edges of both
kinds returns `Some(Evidence::default())`, which is a real answer.
