## A0.6 Рёбра из документов {#a0-6}

**Что подтвердилось.** Сегодня ни один документ не производит рёбер карты:
рёбра дают только Rust-сканер и JTD-сканер вендоренного движка
(`core-ai-native-specmap`), а глагол `documents` существует и применяется
(243 ребра, все из кода). Пин `~rN` на ребре необязателен; ребро без пина
физически не может стать suspect — это в точности D-18. Проверка
существования якоря уже есть: `dangling-edge` в движке плюс хостовый
resolve-гейт `cargo xtask specmap --check` для собственного пространства
имён, то есть опечатка в `rule` покраснит панель без нового гейта.

**Решение (F-10, F-28).** Элемент `rule` читается **хостовой стороной**:
новый хостовый модуль сканирует страницы документации и внедряется в
движок через публичный шов `CodeScanner` (`build_with_scanner`,
`check_with_scanner`, `write_with_scanner`, `CompositeScanner`), созданный
именно для чужих сканеров. Движок и его шесть вендоренных копий не
правятся, `sync-engines` не запускается, R-21 не задействован. Три условия:
страницы документации лежат **вне** `spec_roots` (иначе движковый `xmlspec`
уронит `<rule>` как чужой элемент); политика скана страниц живёт в
хостовом файле, не в `specmap.toml` (`deny_unknown_fields`); инъекция
сканера дублируется в обеих точках `xtask/src/specmap.rs` (основной проход
и resolve-гейт), иначе гейт покрытия будет зелёным по пустоте.

**Уточнения к вижену.** (1) Хвост ребра — `CodeItem` с сентинельным
`crate_name = "<doc>"` по прецеденту JTD-сканера (`"<schema>"`): wire-схема
движка не меняется. (2) Страницы пишутся в диалекте PROP-045 с закрытым
словарём документации (D-10), значит расширяется **хостовая** реализация
диалекта `vibe-specdoc` — а не движковая; паритет двух реализаций держится
тестами, и это уже принятая в проекте практика. (3) Доставка карты
doc-пакета (`package.specmap.json`) сегодня ручная (`vibe specmap --path`
перед публикацией); `install` карт не строит — шаг войдёт в чеклист
публикации doc-пакета (фаза 3) и в регламент.

**Фон.** `cargo xtask specmap --check` на `b1291b06` красный без наших
правок: карта не сведена (20 новых узлов, 3 новых ребра, 8
`unbumped-hash`). Это долг предыдущей кампании; в фазе 1 перед первым
коммитом карта пересобирается отдельным атомом, и дифф читается как данные
(J-026).

## A0.1, A0.2, A0.3 Виды, wire-словарь, манифест {#a0-1}

**Что подтвердилось.** Из 114 файлов с `PackageKind::X` исчерпывающих
матчей пять в продукте — `package_ref/kind.rs` (закрытый enum ядра, руками),
`vibe-wire/src/behaviour/vocabularies.rs` (рукописный слой `as_str`/`known()`/
`from_str` над сгенерированным открытым типом; `known()` — шесть значений
буквой), `vibe-wire/src/generated/shared/mod.rs` (генерат — только через
`cargo xtask codegen`), `vibe-cli/src/commands/extensions.rs` (два конвертера
в локальные `ManifestKind`/`ReportPackageKind`), `vibe-index/src/scanner/manifest.rs`
(граница closed→open) — плюс исчерпывающий матч в тесте
`open_vocabulary.rs`. Остальные 108 — фикстуры и ассерты. Ядро и wire —
два несвязанных пути: `vibe-index` реэкспортирует сгенерированный тип, а
парити-тест выведен из эксплуатации; форму словаря пинуют три статических
теста с зашитой шестёркой. `BootCategory::App` уже существует в соседнем
enum (полоса boot-сниппета) и разведён по своим матчам. Манифест парсится в
приватный `ManifestWire` (`deny_unknown_fields`) и конвертируется в
публичный `Manifest` двумя `TryFrom`; `min_vibe_version` — чистый транзит в
индекс и post-publish-хук, нигде не сравнивается с версией `vibe`.

**Решения.** (1) A2.1 правит ровно шесть мест переписи плюс `known()` и три
теста; `ManifestKind`/`ReportPackageKind` проверяются в том же пакете
(вероятно, тоже растут). (2) Break-заметки: `formats/EPOCHS.toml` держит
`public = false` и `break_window_open = true` — до публикации «breaking is
free AND unmigrated», заметки становятся обязательными только при
`public = true` (флаг переключает только владелец), а `cargo xtask
wire-diff` в этом состоянии **сообщает**, не требует. Значит для `doc`/`app`
и для новых ключей манифеста заметка не обязательна; корпуса (13 на
`version_entry`) обновляются, wire-diff читается как данные. Одна короткая
заметка `formats/breaks/005.md` на семью ключей документации всё же
пишется в A2.2 — как запись для будущего кодмода, не как гейт. G7/§4.7 —
не вопрос владельцу. (3) Новые ключи `vibe.toml` (`title`, `abstract`,
`[[documents]]`, `[documentation]`, `[translates]`, `[media]`) подпадают под
§6.2 `FMT-MANIFEST` по духу (минимальная поверхность, генерируемая
документация ключей); кодмод не нужен (старые файлы не меняются).
(4) Все новые поля — в `ManifestWire` и `Manifest` и в оба `TryFrom`;
`[[documents]]` — `Vec<DocumentDecl>` в новом `package/document.rs` по
образцу `skill.rs`; `[documentation]` — одиночная структура по образцу
`Compatibility`; `[translates]` — отдельное поле рядом с `describes`
(`describes` держит PURL внешней библиотеки, не координату пакета);
`[media]` — структура с тремя путями. (5) **F-05 к владельцу,
переформулирован:** старый `vibe` откажет пакету с новыми полями по
`deny_unknown_fields` независимо от `min_vibe_version`; вопрос — поднимать
ли версию `vibe`, чтобы поле говорило правду. Рекомендация: поднять до
`1.1.0` в атоме A2.1 и писать `min_vibe_version = "1.1.0"` в doc-пакетах;
проверка `min_vibe_version` в коде — отдельный вопрос в BACKLOG (сегодня
поле декларативное).

## A0.14 Дисциплина TypeScript {#a0-14}

**Что подтвердилось.** `vibe bin exec typescript-ai-native -- floor`
работает из корня пакета при трёх предусловиях (`--assume-yes` для сборки,
lock схемы 7, сборка инструмента в слоте пакета); дешевле маршрут A/B —
готовый бинарник хоста `vibevm/vibedeps/org.vibevm.ai-native.typescript-ai-native-lang/1.0.0/target/release/typescript-ai-native.exe floor --path <пакет>`.
Семь шагов: `prettier → tsc → tests → eslint → conform → specmap →
test-gate`; инструменты берутся только из `node_modules/.bin` пакета.
Флаги `tsconfig` не гейтятся механически — только через `tsc --noEmit`.
Объединённый `tsconfig` (стартер Qwik 2.0.0-beta.43 + двенадцать флагов
GUIDE §1 + `verbatimModuleSyntax` + `types: ["node"]`) даёт `tsc` зелёный;
структурный гейт и specmap понимают `.tsx`. Конфликты: `node --test` не
грузит `.tsx` и ищет только `*.test.ts`/`*.spec.ts`;
`exactOptionalPropertyTypes` против необязательных JSX-пропов (лечится
условным спредом); `noPropertyAccessFromIndexSignature` требует
`process.env["X"]`; `tmp/`, `dist/` — в ignore prettier и eslint.
`research/ts-demo` на HEAD красный на трёх шагах, lock схемы 6, `tsconfig`
ниже пола; панель `self-check.sh` его floor не гоняет — гейт фазы 1 не
задет.

**Решения (F-18).** (1) Web-пакет генерируется `typescript-ai-native init`,
не копируется из `ts-demo`; дословно переносятся `.prettierrc.json`,
`eslint.config.js` (с новыми `ignores`), скрипт `floor`, форма
`conform.toml`/`specmap.toml`. (2) `tsconfig` — полный пол GUIDE §1 плюс
блоки Qwik (`jsx`, `jsxImportSource`, `moduleResolution: "Bundler"`,
`paths`); `exactOptionalPropertyTypes` остаётся. (3) Все семь шагов floor
остаются: юнит-тесты чистой логики — `.test.ts` без JSX; поведение
компонентов проверяется тестом паритета островов на стороне Rust (A4.15)
и сборкой; `floor_disable` не используется. (4) Панель зовёт floor
маршрутом A/B из корня хоста; web-пакет — vibe-пакет в
`vibevm/vibepacks/org.vibevm.doc/web/`, но `vibe bin exec` внутри него не
обязателен. (5) Резолв eslint-плагина — X-014, решается в A4.1.

чёрном»). В тёмной палитре лендинга нет промежуточного тона между
`--dim`/`--faint` и `--cream` — дыра палитры, не выбора. Источник
`anthropic.css` сам называет фоном страниц `--ivory-100` (`--page-bg`);
привязка `--ivory-50` к документации файлом не подтверждается.
`apca-w3` — **AGPL v3**: воркер верно отказался вносить его в дерево.

**Решения (D-21 уточнено на месте с датой).**

1. **Пороги по ролям, а не по именам:** `--text` ≥ 75; `--text-2` и
   `--text-3` (подписи, eyebrow, мета-строки) ≥ 60; интерактивные контуры
   (фокус, границы полей, кнопки) ≥ 45 — они рисуются `--accent` или
   `--text-2`, не линиями; **разделители `--line`/`--line-strong` —
   декоративны и из гейта выведены** (APCA для несущественных разделителей
   порога не требует); акценты — by design; номера абзацев `pNN` с
   `opacity .5` — декоративны, как акценты.
2. **Недостающие тона чеканятся:** там, где палитра источника не даёт
   тона, закрывающего порог (тёмные `--text-2`, `--text-3`; светлый
   `--text-3`), в `palette.css` заводится новый тон на том же тёплом хью с
   суффиксом `-docs`, ближайший к исходному, который проходит порог;
   точные hex подбирает аудит в A4.13, а не глаз. Ориентиры: светлый
   `--text-3` темнее `#8E8D85` примерно до `#77766E`; тёмный `--text-2`
   светлее `#A8A197` примерно до `#C2BBAE`, тёмный `--text-3` — до
   `#A39C8F`. Замена одного семантического токена другим (например,
   `--text-3` → `--muted`) отвергнута: она сливает роли.
3. **Один `--bg` на тему:** светлый `--bg` = `--ivory-100 #FAF9F5`;
   отдельного фона для страниц документации нет; `--ivory-50` остаётся в
   палитре как `--bg-paper` для карточек-«листов», если понадобится, но
   не как второй фон страницы.
4. **APCA считается собственной реализацией** опубликованной формулы
   SAPC/APCA 0.1.9 (W3C draft, константы публичны) в аудите web-пакета —
   без зависимости от `apca-w3` (AGPL) и без копирования его кода (закон
   лицензий: permissive-only); образец из `oleg-guru` берётся как приём,
   не как файл (R-28). Проверка — те же 64 пары, числа обязаны совпасть с
   отчётом воркера в пределах 0.1 Lc.
5. Механизм `@media (prefers-color-scheme: dark)` + `[data-theme]`
   подтверждён без расхождений — норма для `tokens.css` пакета `design/`.

## A0.7, A0.11 Локальный сервер и оболочка {#a0-7}

**Что подтвердилось.** Сервер индекса — axum 0.8.9 (workspace `axum =
"0.8"`), tower 0.5, tower-http 0.6 (`cors`, `trace`); один `build_app` с
плоским списком маршрутов, `ApiError` в форме RFC 7807, слои `rate_limit →
cors → trace`; статики нет, файлы читаются целиком на каждый запрос; тесты —
`tower::ServiceExt::oneshot` над `Router` без TCP. Переиспользовать из
`vibe-index` нечего: `AppState` держит `RwLock<Index>`, крейт тянет
`reqwest`, `flate2`, `walkdir`. Проба на той же версии axum: привязка
только к `127.0.0.1` со свободным портом; строка CSP проверена в ответе;
`ServeDir` отбивает `../`, `..%2F`, `%2e%2e%2f`, листингов не умеет, но по
умолчанию отдаёт `index.html` каталога и редиректит без слэша. **Форма
`vibe-index` — `data_dir.join(<захват>)` в `by-name`/`by-cap`/`by-purl` —
от обхода не защищает:** роутер сопоставляет сырой путь, `Path`
декодирует `%2F` после матчинга; на идентичном маршруте пробный сервер
отдал файл вне корня (200). На живом `vibe-index` не подтверждено
(бинарника нет, сборка запрещена). Встраивание: `include_dir` 0.7.4 и
`rust-embed` 8.12.0 оба MIT; `rust-embed` без `debug-embed` читает с диска
в debug (измерено); ни один не заказывает пересборку при изменении
каталога и не отличает пустой каталог — `build.rs` обязателен. Релизные
активы: `DISTRIBUTIONS.json` → фрагмент платформы → `vibevm-<версия>-<цель>.zip`;
проверка размера и `sha256` одной функцией; структура ZIP — закрытое
множество имён; схема манифеста `deny_unknown_fields`, версия ровно 1.
Store версий: `~/.vibe/opt/vibevm/versions/<kind>/<id>/<instance>/`,
экземпляры неизменяемы.

**Решения.**

1. **Отдельный крейт `vibe-doc-server`** (форма `vibe-index` повторяется,
   код не импортируется): `vibe-doc` → `vibe-doc-shell` → `vibe-doc-server`;
   axum не попадает в `vibe-doc`, `vibe-mcp` и генератор сайта.
2. **CSP заголовком** (не `<meta>`):
   `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; media-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors <origin|'none'>`;
   `frame-ancestors` — параметр запуска `vibe doc serve --frame-ancestor
   <origin>` (webview VS Code меняет origin от окна к окну), без параметра
   `'none'`; CORS-слоя нет вовсе; `x-content-type-options: nosniff`.
3. **Статика оболочки** — `ServeDir::new(root).append_index_html_on_directories(false)`
   для оболочки из store и точное совпадение по списку для встроенной;
   страницы — только собственными маршрутами; `cache-control: immutable`
   для имён с хэшем, `no-store` для страниц (ETag по хэшу — если рендер
   окажется дорогим).
4. **Параметры запуска** (базовый путь, тема, язык, origin хоста) — блоком
   `<script type="application/json" id="vibe-doc-config">` в странице, без
   `'unsafe-inline'`. Таблица маршрутов и деление контракта встраивания на
   стороны — по находке (D-09, §7.3, §7.5 подтверждены).
5. **`include_dir` 0.7.4** для встраивания; `build.rs`: `rerun-if-changed=shell`,
   при `embedded-shell` — проверка `shell/index.html` и остановка с
   рецептом `cargo xtask embed-doc-shell`; `cargo:rustc-env=VIBE_DOC_SHELL_SHA256`
   — пин D-12 п. 5; один тип `Shell` с тремя источниками и `provenance()`.
6. **Оболочка — отдельный релизный актив** `vibevm-doc-shell-<версия>.zip`
   без цели платформы, с отдельным манифестом `DOC-SHELL.json` рядом с
   `DISTRIBUTIONS.json` (та же форма `{schema_version, product, repository,
   version, tag, source_commit, asset{name,size,digest}}`, та же проверка
   `require_digest`); в `DISTRIBUTIONS.json` поле не добавляется — сломало
   бы `self update` у всех `vibe 1.0.0`. Хранение — общий контент-адресуемый
   `~/.vibe/opt/vibevm/doc-shell/<sha256>/`, не внутри экземпляра
   (экземпляры неизменяемы); в экземпляре — `DOC-SHELL.lock.toml`,
   записанный при стейджинге. Команда `vibe doc shell install
   [--assume-yes]` с согласием по образцу `install/confirm.rs`; при
   отсутствии — запасная оболочка и подсказка. Проверка релиза
   (`xtask/src/dist/release.rs`, «двенадцать активов») расширяется на
   тринадцатый — A5.x.
7. **BACKLOG P1 (X-017):** обход путей в `vibe-index`; проверка — один
   тест `oneshot(GET /v1/index/by-name/..%2F..%2Fsecret.json)`; лечение —

## A0.4 Точки расширения пивота {#a0-4}

**Что подтвердилось.** `Block` — пять вариантов без идентичности и без
serde; добавление вариантов ломает только исчерпывающие `match` (два
внешних: `vibe-facts/src/report.rs`, `vibe-workspace/src/vibedeps/derived.rs`
— компилятор перечислит работу). Диспетчер `xml_in` проверяет литеральные
имена раньше именованных секций; писатель держит чёрный список имён в
`anchor_is_elementable`. `md_in` расширять не нужно и нельзя (роды блоков
Markdown закрыты в `progress-core`): авторинг документации — только XML.
Загрузчик `load.rs` чист и решает по расширению; `PackageKind` в
`vibe-specdoc` не приходит по закону отделимости.

**Решения (все — детали D-10, правятся в вижене на месте с датой).**

1. **Словарь — параметр читателя (F-08).** `Vocabulary::{Spec, Doc}`
   (умолчание `Spec`); аддитивные `from_xml_with`, `load_spec_text_with`,
   `project_spec_text_with`; поле `Parser::vocab` — три плеча диспетчера.
   Отображение «kind пакета → словарь» делает вызывающая сторона, ближайшая
   точка — `vibedeps/derived.rs` (`package: &str` уже в руках). Элемент
   жанра в словаре `Spec` — громкая ошибка с жанровым сообщением («открыт
   только в пакетах kind `doc`»), не игнор: тихих пропусков в диалекте нет.
2. **`when` — обёртка слота.** `Section.blocks` и `SpecDoc.preamble`
   становятся `Vec<BlockNode>`, `BlockNode { when: Option<Cond>, block }`;
   так `when` ложится и на `p`, и на `table`, как требует D-10. `Cond` —
   закрытый список (ОС, агент) с `parse` и подсказкой `nearest`. Правка
   механическая (48 упоминаний в крейте, две внешние сигнатуры).
3. **Коллизия имён.** `example`, `rule`, `derived`, `run` уже живут в
   корпусе как именованные секции (8 канонических файлов). Снимается
   дискриминатором по образцу `fact="true"`: **блок жанра никогда не несёт
   `title=`, именованная секция несёт его всегда**. `<example title="…">`
   остаётся секцией в любом словаре, `<example>` без `title` — блок в
   словаре `Doc`. Писатель от словаря не зависит: чёрный список не
   растёт, один IR пишется в одни байты в обоих словарях (снимает открытый
   вопрос 2 находки).
4. **Черновик вариантов принят** с поправками: `Example { run, expect:
   Option }`, `ExampleRef { ref }`, `Rule { address }` (текст цитаты — не
   состояние пивота, подставляется на сборке; адрес отбрасывает `~rN`),
   `Derived { command, lang }` (текст не хранится), `Note { kind, body:
   Unit }`, `Figure { media, caption: Unit }`, `Prompt { body, needs,
   outcome: Unit, asserts }` (`asserts` ≥ 1). Тексты `run`/`expect`/`body`/
   `assert` — как `Fence::text`; CDATA разрешается в них явным списком.
   `Note` и `Figure` держат `Unit`, а значит адресуемы якорем факта.
5. **Markdown-проекция doc-жанра — необратима, и это записано.**
   `md_out` получает лучшую проекцию для каждого блока (пример → два
   fence, `rule` → цитата с адресом, `derived` → помеченный fence,
   `note` → цитата, `figure` → строка картинки, `prompt` → fence и список);
   обратный разбор даёт другой IR (`Conversion::IrDivergent`), что
   закрепляется тестом-ожиданием `doc_genre_is_not_round_trippable_through_markdown`.
   Проекция нужна: хостовые сканеры (`facts check`, `progress`) читают XML
   только через неё (D-14 — документация наблюдаема).
6. **Правила нормализации `expect`** — в `vibe-doc`, не в пивоте
   (подтверждает A0.12).
7. **Адресуемость детей `prompt`** (`assert`, `needs`) в первой волне не
   вводится: `pNN` нумерует блоки; дети адресуются позицией в родителе
   при цитировании человеком — в отложенное (DEFERRALS).

**REVIEW.** Kind `doc` в коде отсутствует (`PackageKind` — шесть видов):
это не противоречие, а предпосылка фазы 2 (A2.1). Секции `[media]` в
манифесте нет — та же фаза (A2.3).

**Тесты.** Список существующих тестов на расширение и тринадцать новых
(имена в находке) переходят в пакет атома A2.8 как критерии приёмки.

## A0.25 Нумерация блоков {#a0-25}

**Что подтвердилось.** У блоков пивота нет идентичности (адресуемы только
заголовок, секция и факт); канонический обход — предпорядок в глубину
(преамбула, затем секция: её блоки, потом подсекции) — совпадает у трёх
реализаций (`xml_out`, `md_out`, `vibe-facts`). Диалект запрещает блок
родителя после вложенной секции, поэтому лексикографический порядок пути
блока совпадает с порядком чтения. Атрибутов у `<p>` нет вовсе — номер не
может просочиться в пивот незаметно.

**Решения.** (1) `BlockPath { section: Vec<u16>, block: u16 }` и чистая
функция `number_blocks(&SpecDoc) -> Numbering` в `vibe-doc`, вызываемая
после раскрытия `derived` и до бэкендов; `Numbering::{get, label,
path_of, none}`. (2) Бэкенды `vibe-doc` принимают `(doc, numbering)`
рядом; `to_xml`/`to_markdown` пивота не меняются, `Numbering` в пивот не
переезжает — F-43 закрыт без правки. (3) Правило: каждый блок потока
получает номер (абзац, список целиком, таблица целиком, цитата, fence,
блоки жанра, `derived` после раскрытия); пункты списка, ячейки, дети
`prompt` и заголовки — нет. (4) **Нумерация идёт до фильтрации `when`**:
`p12` значит одно и то же в сборке для любой ОС и агента и в переводе;
пропуски в выводе приняты (правка D-22 п. 1 на месте с датой). (5)
Перевод зеркалит дерево блоков (D-18), значит номера совпадают по
построению; `example ref` занимает свой слот. (6) `pNN` показывается
читателю по D-22; `path_of` нужен ссылке «для агента» и проверке
переводов.

## A0.8, A0.17, A0.20 Store, in-tree пакеты и хост {#a0-8}

**Что подтвердилось.** Store — `crates/vibe-registry/src/store.rs`:
`<store>/<группа>/<имя>/v<версия>/` плюс sidecar `v<версия>.sha256` рядом;
write-once для нашего кода, но мутабельный источник обновляет запись по
хэшу (`insert_current_at`); корень store движется только с `$VIBE_SETTINGS`
(своего env-переключателя нет — слово владельца в коде). `vibe cache add`
считает замыкание существующим резолвером, реестр берёт из проекта
(project-local `vibevm/vibepacks` первым) или из `~/.vibe/registry.toml`;
vibe-embedded не подключает; флага `--registry` нет. Живая проба: `vibe cache
add --offline org.vibevm.world/multi-user-planning@1.0.0` из корня хоста —
`1 fetched`, дерево пакета дословно, 27 файлов. Git-источники по `branch`
работают и для `file://`, и для голого пути, видят только закоммиченное,
`--offline` не мешает. **Корень хоста — `[project]`, не `[package]`**
(B-031 дал ему полное имя, не сделал пакетом): взять хост как пакет нельзя
ни из store, ни из lock, ни из реестра. In-tree пакеты — мутабельные слоты
одной версии; версия не меняется, содержимое — да.

**Решения (D-07 и D-16 уточнены на месте с датой).**

1. **Канал хоста — выкладка на диске.** Рендерер сайта работает в
   каталоге, куда деплой сделал `git checkout main && git pull` (чистое
   дерево); документацию ядра он читает как in-tree пакет через
   project-local реестр (`LocalRegistry` над `vibevm/vibepacks`) или
   прямо по каталогам, а сам хост — как **проект** (уровень 0: `README.md`,
   `vibevm/vibespecs/**`, boot-сниппет, манифест `[project]`). Git-источник
   по ветке и клон в `$VIBE_REGISTRY_CACHE` не нужны — репозиторий уже на
   диске; `cache add` на сервере не нужен.
2. **Предмет `org.vibevm.core/vibevm` в `[[documents]]`** — координата
   проекта (B-031), не пакета реестра; `vibe check` не требует, чтобы
   предмет был выбираем из реестра, — проверяет форму координаты; сайт
   знает координату хоста из конфигурации.
3. **Ключ кэша рендера — внутренний хэш содержимого источника**
   (sidecar `recorded_hash` для store, пересчёт для выкладки), никогда
   `(группа, имя, версия)`: у in-tree пакетов версия стоит, содержимое
   идёт. Наружу это не показывается (D-27): пользователь видит версию и
   текущий текст.
4. **Локальный читатель** прогревает store командой
   `vibe cache add --offline <координата>` из корня проекта с in-tree
   пакетами или обычным `vibe cache add` из реестра; источники `vibe-doc` —
   store (`lookup`/`list_all`), lock (`Lockfile::read` + `slot_abs_path`),
   реестр (`resolve_and_fetch`), выкладка (`LocalRegistry`).
5. **Дефект продукта — в BACKLOG (фаза 1):** `cache add` печатает «already
   present — bytes untouched (write-once)», хотя запись заменена по хэшу
   (`add.rs:70` считает `was_present` до выборки). Сайт на строку отчёта не
   опирается.

**Открытое.** Цена полного клона хоста на сервере не измерена — не нужна
при чтении выкладки. Правило «install не гонится за HEAD, update гонится»
значимо только при настоящем `vibe install` на сервере, которого не будет.

## A0.12 Раннер примеров {#a0-12}

**Что подтвердилось.** Изоляция — три переменные продукта
(`VIBE_SETTINGS`, `VIBE_REGISTRY_CACHE`, `VIBEVM_SEARCH_CACHE_DIR`), из
которых несущая одна: `VIBE_SETTINGS` уводит весь `~/.vibe`; значение
обязано быть в нативном написании (Python/CI не конвертируют POSIX-путь).
Настоящая гарантия — tripwire `tools/user-home-tripwire.sh` в панели.
Макет (`findings/A0.12-runner-mock.py`, stdlib) прошёл семь примеров,
включая офлайн-установку из `fixtures/registry` и провальный пример с
непустым stderr; негативный контроль кусается. Два прогона установки трёх
пакетов дали побайтово одинаковый вывод — сортировка блоков пока не
понадобилась. В продукте нет цветов (ANSI-правило — страховка), CRLF в
потоках нет (правило нужно для `expect`-файлов из git). **Валидатора JTD в
`vibe-wire` нет**: схемы — вход кодогенерации, serde молча игнорирует
лишние поля. `vibe install --json` печатает поток из трёх документов; у
`install:plan` схема расходится с эмиттером (`plans` против `packages`),
`install:closure-diff` схемы не имеет, конверт `invoked_by`/`unattended`
не объявлен ни в одной схеме.

**Решения (D-10 уточнено на месте).** (1) Страница несёт `run`, `expect`
(stdout) и необязательный `stderr`; атрибут `exit` (по умолчанию 0);
отсутствующий `stderr` — утверждение «пусто». (2) Фикстура — каталог с
деревом и `example.toml`: правила нормализации объявлены и видны в ревью,
карта «документ `--json` → JTD-схема» по полю `command`; шаблонов `match`
нет — любая недетерминированная строка закрывается именованным правилом
`replace`, которое видно в диффе (R-07). (3) cwd — песочница; команда
не называет путей; поведенческие переменные вычищаются; флаги `--offline`,
`--assume-yes` стоят в самом примере. (4) Раннер несёт tripwire на
неизменность исходного дерева и настоящего дома. (5) Валидатор JTD (восемь
форм RFC 8927) пишется в `vibe-doc` (A2.9); документ без схемы — «не
проверен», не «прошёл». (6) Примеры документируют не-TTY ветку; PTY в
первой волне нет. (7) Фикстуры, порождённые `vibe init`, получают
нейтрального автора (иначе в пакет попадёт имя оператора). (8) Раздельный
захват потоков — принятая потеря; чередование — отложено.

**BACKLOG (через DEFERRALS X-008…X-010):** схема `install_plan` против
эмиттера; конверт `invoked_by`/`unattended` вне схем; `install:closure-diff`
без схемы.

## A0.28 Цена рендера хоста {#a0-28}

**Что подтвердилось.** `vibe self install latest` внутри чекаута собирает
**рабочее дерево как есть** (`crates/vibe-cli/src/commands/vvm/mod.rs:222`,
`source.rs:88–96`): теги не читаются, git даёт только ярлык версии и
провенанс; вне дерева `latest` — `refs/remotes/origin/main`, тоже ветка
(PROP-019 `SEL-LATEST`). Значит «текущее состояние `main`» на сервере — это
буквально выкладка, и синхронизация выкладки с `origin/main` — обязанность
деплоя, а не `vibe` (D-16 подтверждено). Замеры на Ryzen 9800X3D (кэш
реестра прогрет): release — холодная 6m 42s, инкрементальная после правки
одного файла 3m 50s (57 % холодной: `Cargo.toml` `lto = "thin"`,
`codegen-units = 1` — одна последовательная кодогенерация, ядра не
помогают), no-op 5.8 s, `vibe-index` дополнительно 6m 06s; dev — холодная
1m 42s, инкрементальная 22.5 s, и `vibe --help` **побайтово совпадает** с
release-бинарником. Оценка для четырёхъядерного сервера (порядок величины,
не факт): холодная 20–40 мин один раз, инкрементальная 6–16 мин,
docs-only коммит — секунды; раз в час влезает с запасом.

**Решения.**

1. **Рендерер собирает `vibe` профилем `dev`** (`cargo build -p vibe-cli
   --locked`), не через `vibe self install`: вывод derived-блоков идентичен,
   инкрементальная сборка дешевле в десять раз, второй бинарник
   `vibe-index` не нужен; цена — 103 МБ бинарник и 7 ГБ кэша на постоянном
   томе рендерера. Паритет dev/release для `--help` закрепляется тестом
   рендерера (A5.x), чтобы решение не жило на одном замере.
2. **Дебаунс пересборки хоста — 5 минут** на dev-профиле (10 — если
   владелец предпочтёт release); опрос ветки — раз в час по умолчанию
   (вопрос владельцу, п. 4 ниже); две сборки одновременно cargo сам
   сериализует на блокировке каталога — таймауты рендерера это учитывают.
3. **Постоянные тома рендерера:** `CARGO_TARGET_DIR` и кэш реестра crates.io;
   тулчейн — канал `stable` из `rust-toolchain.toml`; первая загрузка 573
   пакетов — сеть один раз.
4. **`derived.json` от сборки продукта** (вариант б находки: сайт без
   тулчейна Rust) — только по слову владельца; в DEFERRALS как X-023.
5. Числа — замер, не норма: в PROP-057 они не входят; в A5.1 они становятся
   конфигурацией по умолчанию.

**REVIEW.** Нет. Побочное наблюдение: незакоммиченные правки рабочего
дерева попадают в `self install latest` — так задумано (PROP-019 §2.7),
для рендерера значимо только чистотой выкладки.
