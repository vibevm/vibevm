## 0. Как пользоваться этим планом {#how-to-use}

- **Кто исполняет.** Центральный агент в репозитории vibevm, под владельцем.
  В волне A (находки, контракт, проза) это Fable; в волне B (вся разработка)
  — Opus 5 в режиме High, а Fable возвращается только в названных точках
  (§6.0); в волне C (русская адаптация) — снова Fable. План написан в
  расчёте на модель слабее той, что его писала: там, где решение очевидно
  сильной модели, здесь оно записано явно. Это контракт, а не
  снисходительность.
- **Что читать до первого шага.** Сначала `VISION.md` целиком, потом этот
  документ целиком, потом §2 «Загрузка» буквально. Только после этого — фаза 0.
  Перед первым атомом фазы 3 — `STYLE.md` целиком, ещё раз.
- **Решения не пересуждаются.** `VISION.md` §5 (`D-01` … `D-25`) — закон плана.
  Единственное решение с оговоркой — D-21 (дизайн): оно объявлено
  предварительным и пересматривается на дизайн-ревью A4.14 рукой владельца,
  а не твоей.
  Если факт в коде противоречит решению, ты **не** переписываешь решение сам:
  ставишь маркер `<!-- REVIEW: … -->` в плане, записываешь находку в леджер
  фазы 0 и задаёшь владельцу один вопрос с вариантами и рекомендацией.
- **Размер атома — один коммит.** Атом закрыт, когда его команда проверки
  зелёная, дифф прочитан тобой целиком, коммит сделан. Каждая посадка: дифф →
  `cargo fmt --all` → specmap, если трогались спеки или код → стейдж → гейты
  атома → коммит. Полная панель — только на границах фаз.
- **Формат атома.** Цель · Читать сначала · Делать · Проверять · Готово когда ·
  Развилки · Риски · Коммит. Если у атома нет какого-то поля, оно не нужно, а
  не забыто.
- **Холодный старт.** Этот план плюс леджер `campaigns/docs-2026-09/LEDGER.md`
  и журнал `JOURNAL.md` (до фазы 1 — в папке вижена, потом рядом с леджером)
  — единственный указатель возобновления. Ничто, что должно пережить сессию,
  не остаётся в чате.
- **Журнал ведётся в атоме.** Красная проба, ложное срабатывание,
  опровергнутое предсказание, обходной путь, удачный приём — запись в
  `JOURNAL.md` в том же атоме, с полем «→ регламент» (R-33). Регламент
  сопровождения `MAINTENANCE.md` пишется из журнала в фазе 6, не из памяти.

### 2.3 Особенности этой машины {#boot-quirks}

Из `vibevm/vibespecs/boot/90-user.xml`, по смыслу:

- Правки файлов — только редакторскими инструментами; PowerShell 5.1 портит
  UTF-8 без BOM при round-trip. Порча лечится `git restore`.
- `tools/self-check.sh` — через Git Bash, не WSL; смотри РЕАЛЬНЫЙ код выхода:
  `bash tools/self-check.sh; echo "EXIT=$?"`; никогда не через `| tail`.
  Панель обрывается на первом красном; зелёный хвост — единственное
  доказательство. Счётчик `[N/47]` печатает лексическое число шагов, не
  покрытие.
- Коммиты только через heredoc: `git commit -F - <<'MSG' … MSG`.
- Windows UAC блокирует тестовые исполняемые файлы с `install` в имени —
  не называй так бинарники тестов.
- `bash … > "$VAR/file"` с пустым `$VAR` пишет в `/file` и тихо не выполняет
  команду — задавай путь на той же строке.
- `vibe` из PATH — это `~/.vibe/opt`, релиз 1.0.0 от 2026-08-20, **без**
  новых команд. Для всего в этом плане используй `target/debug/vibe.exe`
  после `cargo build -p vibe-cli`, или `cargo run -p vibe-cli -- …`.
- SSH к серверу — **только** нативный Windows OpenSSH
  `"C:/Windows/System32/OpenSSH/ssh.exe"`; Git-Bash-овый `ssh` подключается,
  но глотает stdout, и команда выглядит «зависшей». На сервере — `docker
  compose` (v2, плагин), не `docker-compose`; если после `git pull` правки не
  видны в контейнере — `docker compose build --no-cache <service>` только для
  сервисов сайта документации.
- Документ инфраструктуры `C:\Users\olegc\git\infra\main\main.md` —
  приватный: читать можно и нужно (A5.6), цитировать в артефакты репозитория,
  леджер и чат нельзя (R-25). Лежащий рядом `secrets.local.md` не открывать
  никогда (R-12).
- Локальный DNS дев-машины переписан VPN-резолвером: публичные записи
  проверяются не `nslookup` локально, а с сервера или внешним резолвером.
- Каталоги `C:\Users\olegc\git\talks\2026.08.08-agents-talk\`,
  `C:\Users\olegc\git\oleg-guru\`, `C:\Users\olegc\git\v\vibevm-org\` из этой
  кампании только читаются (R-28). `vibevm-org` — источник содержания и
  адресов лендинга для переноса (A4.16) и эталон для теста паритета (A4.17);
  его старая сборка для сравнения делается в копии в scratch-каталоге, не в
  самом репозитории. Единственная правка — финальный коммит снятия с
  эксплуатации (A5.8) после слова владельца.

### 2.5 Git-правила {#boot-git}

Четыре правила `CLAUDE.md` действуют дословно: человеческое авторство (ни
одного упоминания модели или инструмента в коммитах, ветках, комментариях,
README), Conventional Commits с телом «почему», один коммит — одна мысль,
автономия на рутине и стоп на красных линиях (переписывание истории,
force-push, большие бинарники, CI/подписи/секреты, всё, что дорого откатить).

Форма темы коммита — **почему**, не что. Примеры для этой кампании:

```
docs(spec): admit doc and app kinds so documentation ships as packages
feat(core): teach PackageKind the doc and app kinds
feat(wire): widen package_kind vocabulary for doc and app
feat(core): let a package name its official documentation and translations
feat(core): carry a documentation card in the manifest
feat(specdoc): give the documentation genre its five elements
feat(doc): render islands from the pivot so web and local share one content path
feat(doc): run documented examples so the docs cannot lie
feat(doc): check translations page by page
feat(doc): gate documentation on spec obligations
chore(docs): archive the 1.0.0 alpha layer under docs-legacy
feat(xtask): embed the docs shell into vibe at release time
```

Тело — две-пять строк «почему», с адресами `spec://…` там, где есть якорь.

### 2.6 Отчётность владельцу {#boot-reporting}

- Режим `auto`: телеграфный трекинг; несжимаемый пол — блокеры, развилки
  владельца, инциденты, TL;DR на границе фазы, полный ответ на прямой вопрос.
- Идентификаторы расшифровываются на месте: не «B-112», а «B-112, долг по
  старой диаграмме раскладки в VIBEVM-SPEC».
- Сперва простыми словами суть проблемы и суть рекомендации, технические
  детали — отдельным блоком после. Номера разделов спек в чат не приводить.
- Объём работ не является доводом. Никогда.

### 2.7 Делегирование и пакет воркера {#boot-delegation}

**Разделение труда — слово владельца 2026-09-10.** Центральная сессия
(Fable) работает **оркестратором**: всё программирование — крейты, линтер,
оболочка, тесты, фикстуры, скрипты, конфигурации — выдаётся пакетами агенту
`opus5` (Claude Opus 5, определение в `.claude/agents/opus5.md`) в режиме
рассуждения **High**. Всё умное и творческое — статьи и страницы, адаптации на
русский, смысл дизайн-системы (роли токенов, что за чем идёт на странице),
информационная архитектура, глоссарий, формулировки решений, ревью чужой
работы — центральная сессия делает **сама**. Никаких других лаунчеров для
этой кампании, пока владелец не скажет иначе; отставленные лаунчеры из
леджера `CLAUDE.md` не вызываются.

**Экономия токенов — цель, а не побочный эффект.** Fable используется только
там, где нужна именно Fable; механическую работу делают другие модели. Три
яруса:

| Ярус | Кто | Что |
|---|---|---|
| Суждение и текст | центральная сессия (Fable) | решения, ИА, страницы и адаптации, смысл дизайна, чтение findings и диффов, приёмка, вопросы владельцу |
| Код и точные пробы | `opus5`, режим High | крейты, линтер, оболочка, тесты, фикстуры, скрипты, спайки с кодом и сборкой (A0.7, A0.10–A0.12, A0.17, A0.20, A0.28); в волне B — вся разработка как центральная сессия (§6.0) |
| Механика | дешёвая модель (Sonnet 5 или Haiku 4.5 через `Agent` с `model`) | переписи и инвентари (`grep`-цензы A0.1–A0.6, A0.13), листинги, сверки констант (A0.22), прогон скриптов со сбором вывода (A0.23), проверка ссылок, конвертации форматов, машинный черновик адаптации, скриншоты |

Правило чтения: центральная сессия **не читает большие файлы ради
пересказа** — это пакет воркеру «прочитай и выпиши факты по списку
вопросов»; сама она читает выписку и принимает решение. Исключение — то, что
меняет решение или текст: спорный дифф, страница на стиль-ревью, спека, на
которую ложится норма. Режим High задаётся определением агента
(`effort: high` во frontmatter `opus5.md`); если строки нет — это правка
рукой владельца, не самовольная (репозиторий на момент написания плана был
только для чтения).

**Что делегировать** (после того, как контракт заморожен): регрессионный
инвентарь legacy-документации; фикстуры примеров и их ожидаемый вывод;
механическое добавление веток `match` с тестами; компоненты Qwik-оболочки
после заморозки контракта острова; линтер стиля и его тесты; зеркала блоков
и `example ref` для адаптаций — каркас без текста.

**Что не делегировать никогда:** поправки спек, записи решений, семантику
kind, wire-контракты, ревью делегированного, любые правки `plan.toml`,
правки авторского движка карты, **и всю прозу документации** — страницы,
первые абзацы, `title` и `abstract`, глоссарий, FAQ, текст скилла, адаптации
на другие языки (R-29, `STYLE.md` §12). Прозу пишет сильнейшая модель в
центральной сессии; черновик воркера, если он всё же появился, переписывается
целиком, не редактируется.

**Приёмка делегированного:** отчёт воркера — свидетельство, не приёмка. Ты
читаешь дифф как чужой PR, применяешь его сам, гоняешь гейты, коммитишь.
Воркер git не трогает.

Каждый пакет воркера несёт дословно:

> «Ты работаешь в СУБАГЕНТСКОМ режиме: твой экранный текст не читает никто,
> деливерабл — только артефакты. НЕ пиши на экран ничего сверх предписанного
> заданием. Предписанное ОБЯЗАТЕЛЬНО и не отменяется этой клаузой:
> heartbeat'ы `echo "PROGRESS: …"` перед каждым шагом, файл отчёта
> `WORKER-REPORT-<id>.md` по шаблону (решения, отклонения, вывод
> самопроверки), финальный `echo "TASK-DONE"`. Запрещено: приветствия,
> пересказ задачи, промежуточные рассуждения в чат, финальное резюме
> сделанного (оно живёт в отчёте, не в чате).»

Шаблон пакета — §12.

### 2.8 Чеклист нового крейта {#boot-new-crate}

Каждый новый крейт (`vibe-doc`, `vibe-doc-shell`, `vibe-doc-server`) заводится
так, и ни один пункт не пропускается:

1. Посмотри `cargo xtask add-cell --help` и используй его, если он заводит
   крейт по дисциплине; иначе — по образцу ближайшего тонкого крейта
   (`vibe-trace` для библиотеки, `vibe-index` для сервера).
2. `Cargo.toml` корня: член workspace (список `members` идёт двумя копиями —
   найди обе через `grep -n "crates/vibe-trace" Cargo.toml`), `license-file.workspace`,
   `publish = false`.
3. Первая строка `src/lib.rs` после doc-комментария:
   `specmark::scope!("spec://org.vibevm.core/vibevm/common/PROP-057#<якорь>")`.
4. Один `thiserror`-enum ошибок на слой; сообщения цитируют нарушенный
   `spec://`; `unwrap` и `expect` в доменной логике запрещены.
5. Публичные швы несут doctest канонического использования.
6. Периметр conform: проверь `conform.toml`, попадает ли крейт под gated
   и что говорит `cargo xtask conform check`.
7. `cargo xtask specmap` после первых тегов; ноль suspects.

## 5. Непереговорные правила кампании {#rules}

Нарушение любого — стоп и откат атома.

- **R-01** Документация цитирует якорь и никогда не пересказывает нормативное
  значение: число, флаг, путь, имя поля. Если проза требует упомянуть значение,
  в той же фразе стоит адрес источника.
- **R-02** Ни одна страница документации не попадает в `STATIC.xml`,
  `INDEX.md`, boot-сниппет. Doc-пакет не имеет `[boot_snippet]`.
- **R-03** Сгенерированное не правится руками: `STATIC.xml`, `INDEX.md`,
  `formats/EPOCHS.toml`, `crates/vibe-wire/src/generated/**`, `specmap.json`,
  навигация, манифесты страниц, `llms*.txt`, плейсхолдеры, превью.
- **R-04** Wire меняется только через JTD: словарь или схема → `cargo xtask
  codegen` → корпус → `wire-diff`. Новый машинный формат регистрируется в
  `formats/REGISTRY.toml`.
- **R-05** Новая ветка `PackageKind` добавляется в **каждый** `match`;
  подстановочная ветка `_ =>`, скрывающая kind, запрещена. Индексная сторона
  (`vibe-index`, открытый словарь с `Unknown(_)`) остаётся открытой — это её
  закон.
- **R-06** Якоря неизменяемы; переименование — tombstone. Это относится и к
  якорям страниц документации, как только они опубликованы, и к якорям
  переводов, которые обязаны совпадать с источником.
- **R-07** Каждый `example` исполняется в панели. Пример без `expect` — не
  пример. Слабить `match`, чтобы позеленело, запрещено; чинится нормализация
  или продукт.
- **R-08** `derived` генерируется на сборке и не коммитится как текст
  страницы; `expect` коммитится как золотой вывод.
- **R-09** Локальный режим не обращается в сеть и не грузит внешние ресурсы,
  кроме явно подтверждённого пользователем скачивания оболочки (D-12, п. 3).
  Публичный сайт не грузит скрипты с чужих CDN.
- **R-10** В пакет не кладутся артефакты сборки. Web-пакет публикуется
  исходником. Картинки в `[media]` — исходник, в лимитах D-20.
- **R-11** Любая правка `DEV-GUIDE.md` или `RUNTIME-GUIDE.md` идёт в том же
  коммите, что и изменение, которое её потребовало (Node для сборки сайта,
  новые команды `vibe doc`, `vibe cache add` для документации).
- **R-12** Секреты: токены публикации не печатаются и не читаются в контекст.
  Файл `~/.vibe/github.publish.token` не открывается инструментами чтения.
- **R-13** Решение владельца, требующее его руки (правка `VIBEVM-SPEC.md`,
  версия `vibe`, хостинг, ссылки хоста), оформляется как один вопрос с готовым
  диффом или вариантами — и ожидание. Не имитируй согласие.
- **R-14** `plan.toml` правится только центральным агентом, только без
  живого конфликта, только с последующим обновлением `GOAL.md`.
- **R-15** Никаких `unwrap`/`expect` в доменной логике новых крейтов без
  `#[spec(deviates, reason)]`; ошибки — один `thiserror`-enum на слой,
  сообщения цитируют нарушенный `spec://`.
- **R-16** TS-код web-пакета проходит семишаговый floor дисциплины до
  коммита; `any`, непроверенный `as`, `!`, `@ts-ignore` в доменном коде
  запрещены.
- **R-17** Регрессионный список legacy закрывается до гейта фазы 3: у
  каждого факта старой документации — «перенесён», «снят: причина» или
  «регрессия: атом».
- **R-18** Перевод зеркалит дерево источника файл в файл и не авторит
  примеры: только `example ref`. Расхождение наборов якорей — ошибка проверки,
  не предупреждение.
- **R-19** Картинки: только PNG, JPEG, WebP; SVG запрещён; лимиты D-20
  проверяются сигнатурой и размерами, не расширением файла.
- **R-20** Локальный сервер слушает только `127.0.0.1`, отдаёт файлы только из
  известных корней, без листинга и обхода путей, с CSP без внешних источников.
- **R-21** Движок карты вендорится: правки — только в авторском движке в
  `vibevm/vibepacks/org.vibevm.ai-native/…`, затем `cargo xtask sync-engines`.
  Правка хостовой копии откатывается.
- **R-22** Новый крейт заводится по чеклисту §2.8 целиком.
- **R-23** Официальность нигде не хранится как флаг: она вычисляется из
  схождения рёбер при каждом рендере. Поле `official = true` в манифесте или
  индексе — ошибка проектирования.
- **R-24** Ничто в кампании не трогает хостовый nginx, порты, сертификаты,
  compose-блоки соседних сайтов и VPN сервера. Атом, которому это «нужно»,
  останавливается **до** действия и задаёт владельцу вопрос тремя пунктами:
  что происходит, что предполагалось сделать, почему это задевает. В режиме
  `/goal` — немедленное завершение цели с тем же сигналом. Сомневаешься,
  заденет ли, — считай, что заденет. Обходных «аккуратных» способов не
  искать.
- **R-25** Из приватного документа инфраструктуры в вижен, план, пакеты,
  коммиты, леджер и чат не переносится ничего, кроме ссылки на файл и номеров
  разделов: ни адресов, ни портов, ни имён VPN-компонентов, ни путей сервера.
  Перед импортом любого документа кампании в репозиторий —
  `grep -nE '([0-9]{1,3}\.){3}[0-9]{1,3}|xray|reality|x-ui|:3300|/opt/' <файл> | grep -vE '127\.0\.0\.(1|11)\b'`;
  любая оставшаяся строка — стоп (loopback-адреса локального читателя и
  резолвера Docker — не инфраструктура).
- **R-26** Номера блоков `pNN` присваиваются Rust-конвейером на сборке и
  присутствуют одинаково в HTML-острове, `.md`, `.xml` и `llms-full.txt`.
  Клиентский скрипт номера не считает и не переписывает. Ссылка «для агента»
  несёт версию, не `latest`.
- **R-27** В оболочке цвета только через семантические токены; литерал цвета
  в компоненте — ошибка ревью. Две карты значений (светлая, тёмная) живут в
  одном файле палитры; APCA-аудит обеих тем — шаг floor web-пакета.
- **R-28** Каталоги `talks/2026.08.08-agents-talk/`, `oleg-guru/`,
  `vibevm-org/` из этой кампании не правятся, кроме финального коммита
  снятия `vibevm-org` с эксплуатации (A5.8, после слова владельца).
  Заимствуется приём, а не файл: CSS и JS oleg.guru и дизайн-системы
  переписываются под Qwik и токены, не копируются. Исключение — содержание
  лендинга: строки `i18n.ts`, тексты, адреса, корневые файлы переносятся
  дословно (D-28), потому что это авторский текст владельца, а не приём.
- **R-29** Проза документации пишется сильнейшей моделью в центральной
  сессии (по слову владельца — Fable, Astra, Sol), никогда воркером. Это
  страницы, первые абзацы, `title` и `abstract`, глоссарий, FAQ, текст
  скилла и адаптации. Черновик воркера переписывается целиком. В волне B,
  где центральная сессия — Opus, проза уже написана (фаза P): Opus правит
  её только в одну-две строки по линтеру, остальное — в очередь «нужен
  автор» для точки возврата Fable (§6.0); проза, написанная Opus вне
  очереди, откатывается.
- **R-30** Страница коммитится только после самоправки по `STYLE.md` §2–§8
  и зелёного `vibe doc check --style` (A2.25). Страница с отсылкой «см.
  спецификацию» вместо объяснения, с термином до его введения или с
  заголовком «Overview/Summary/Conclusion» не коммитится. Ложное
  срабатывание линтера чинится в правиле линтера с записью в BACKLOG, а не
  обходом в тексте.
- **R-31** Английский — исходный язык; `vibevm-docs` несёт `lang = "en"`.
  Адаптация зеркалит блоки (R-18) и свободна в предложениях; терминология —
  по глоссарию адаптации; шутки заменяются эквивалентом или снимаются, не
  переводятся; машинный перевод — только черновик, который переписывает та
  же модель, что пишет источник.
- **R-32** Оркестратор и исполнители. Код пишет агент `opus5` в режиме High
  по пакету с точным периметром, самопроверкой и критериями приёмки (§12);
  механику — переписи, инвентари, прогон скриптов, сверки — дешёвая модель;
  центральная сессия сама не пишет код и не делает переписи, кроме правок в
  одну-две строки при приёмке. Творческое — текст, адаптации, смысл дизайна,
  ИА, решения — не выдаётся никому. Отчёт исполнителя — свидетельство; дифф
  читается как чужой PR, гейты гоняет и коммитит центральная сессия. Мерило:
  токены Fable тратятся только там, где нужна Fable.
- **R-33** Журнал. Каждая красная проба, ложное срабатывание линтера или
  гейта, опровергнутое или подтверждённое предсказание, обходной путь,
  удачный приём и любая «интересная находка» записываются в `JOURNAL.md` в
  том же атоме: дата, тип, `J-NNN`, что случилось, свидетельство,
  «→ регламент». Гейт фазы не проходит с пустым журналом за фазу и с
  записями старше месяца без поля «→ регламент». Правило регламента без
  ссылки на запись помечается «гипотеза». Журнал только дописывается.

## 6. Фазы {#phases}

### 6.0 Три волны и точки возврата Fable {#waves}

По слову владельца (2026-09-10, `VISION.md` D-29) кампания идёт тремя
волнами, и центральная сессия в них разная:

| Волна | Центральная сессия | Что делается | Фазы и атомы |
|---|---|---|---|
| **A — тексты** | Fable; механика — дешёвая модель, пробы с кодом — `opus5` | находки, контракт, **вся проза документации ядра на английском**, приёмка прозы владельцем | фаза 0 (спайки), фаза 1 (контракт: PROP-057 и поправки — их пишет Fable), **фаза P** (проза: P.1–P.9) |
| **B — разработка** | Opus 5 (High) как центральная сессия; Fable — только в точках возврата | механика, сайт, лендинг, деплой, репетиции сопровождения | фазы 2, 3 (механические части), 4, 5, 6 |
| **C — адаптация** | Fable | русская адаптация документации ядра и всё, что покажет проверка волны B | A3.14 и то, что накопится в отложенном |

Порядок: 0 → 1 → P → **передача** (§12.1) → 2 → {3, 4 параллельно после
A2.13 и A2.14} → 5 → 6 → **передача** → C. В фазе 4 атомы A4.6–A4.8 ждут
подтверждения D-12; остальные — нет.

**Точки возврата Fable в волне B** — заранее названные и батчами, не по
одной правке:

| Точка | Когда | Что делает Fable | Кто готовит |
|---|---|---|---|
| F1 | после A2.25 (линтер) и A2.9 (раннер) прогнаны по прозе фазы P | переписывает страницы, которые линтер и раннер поставили в очередь «нужен автор» (не правки в одну строку — их делает Opus) | Opus: очередь с причинами |
| F2 | дизайн-ревью A4.14 | смысл токенов и компонентов, если владелец меняет систему; формулировка итога в D-21 | Opus: три страницы в двух темах, скриншоты, APCA |
| F3 | стиль-ревью A3.16 после механики, если оно понадобилось | правки по замечаниям владельца | Opus: страницы в `.md` и в читателе |
| F4 | фаза 6: A6.1, A6.4 | консолидация журнала, регламент как норма, changelog пакета, страница «How this manual is maintained» | Opus: репетиции A6.2–A6.3, метрики |

Вне точек возврата Opus **не переписывает прозу**: строка с запрещённым
словом или лишним термином правится на месте (одна-две строки, R-32),
всё крупнее — в очередь для F1/F3 с причиной. Проза, написанная Opus вне
очереди, откатывается (R-29).

## 7. Каталог типичных развилок {#forks}

Формат: ситуация → как решать. Если ситуации нет в каталоге — REVIEW-маркер
и вопрос владельцу, не импровизация.

- **F-01 Компилятор ругается на неисчерпывающий `match` в незнакомом крейте.**
  Это ожидаемо. Открой файл, пойми, что делает ветка для `Tool`, и напиши
  осмысленную ветку для `Doc`/`App`. Никогда `_ => {}`.
- **F-02 Где живёт словарь kind для wire.** Не в `schemas/` и не в
  `vibe-core`: ключ `package_kind` в `formats/vocabularies.json`, из него
  `cargo xtask codegen` порождает `crates/vibe-wire/src/generated/shared/mod.rs`.
  Правишь словарь, не сгенерированный файл.
- **F-03 Wire-diff красный после словаря.** Обнови корпуса в
  `formats/corpora/**`, где встречается kind; перегенерируй; если diff
  показывает смену формы, а не значения, — остановись: это не то изменение.
- **F-04 Старый `vibe 1.0.0` из PATH отказывает на манифесте с новыми полями.**
  Это правильно (`deny_unknown_fields`). Используй `target/debug/vibe.exe`.
  Для пакетов ставь `min_vibe_version` по A0.3.
- **F-05 Какую версию должен нести `vibe`, вводящий новые поля манифеста.**
  Вопрос владельцу: поднять версию workspace до 1.1.0 при посадке фазы 2 или
  оставить 1.0.0. Рекомендация: 1.1.0, чтобы `min_vibe_version` не врала.
- **F-06 Что делает `vibe install org.vibevm.core/vibevm-docs`.** Отказ с
  сообщением: «пакеты kind doc не устанавливаются в проект; прогрей:
  `vibe cache add …`; читай: `vibe doc serve`». Цитата якоря PROP-057.
- **F-07 Хочется хранить связь и в lock-файле.** Нет: doc-пакеты не в
  проекте. Локальный читатель находит документацию по связи над store.
- **F-08 Как включать словарь документации в пивоте.** Параметр загрузчика,
  выставляемый по kind содержащего пакета; для документа без пакета (тесты)
  — явный флаг. Не атрибут в корне документа: он дублировал бы kind.
- **F-09 Нужен ли парсер Markdown для новых элементов.** Нет. Документация
  авторится в XML; проекция в Markdown односторонняя.
- **F-10 Кто пишет рёбра `documents`.** Сканер документов читает элементы
  `rule`; `vibe specmap` doc-пакета несёт их в карте пакета; сайт и `explain`
  читают карту. Не вручную, не из HTML. Где живёт сканер — по A0.6 и R-21.
- **F-11 Скилл `vibevm` уже существует.** Не дублировать. Отдельный
  `vibevm-docs` в doc-пакете плюс одна строка-указатель в встроенном.
- **F-12 Где жить `to_html`.** В `vibe-doc`, не в `vibe-specdoc`: пивот
  остаётся без знаний о HTML; остров — продукт конвейера, а не диалекта.
- **F-13 `llms.txt` — это формат?** Да: его читают чужие парсеры. Регистр в
  `formats/REGISTRY.toml` со `schema = "none"`.
- **F-14 Как получить TypeScript-типы из JTD.** `jtd-codegen` умеет
  TypeScript; добавь цель в `xtask codegen` с той же проверкой дрейфа
  `check-codegen`.
- **F-15 Резолвер `/doc/resolve` статический или серверный.** На публичном
  сайте — статическая карта редиректов, если хостинг статический; иначе

- **F-16 Ошибка `vibe` не цитирует `spec://`.** Не чини в этой кампании;

  `design/` (D-21, D-28). Нужное значение берётся из токена или добавляется

- **F-76 Что делать с репозиторием `vibevm-org` после переключения.** До
  слова владельца — ничего: он боевой, пока домен обслуживает Astro-лендинг.
  После — только A5.8: коммит-указатель; архивация рукой владельца.
- **F-77 Промпт на странице сценария без ассерта.** Ошибка линтера (D-30):
  придумай команду, которая обязана пройти после работы агента (`vibe
  check`, `test -f …`, `vibe explain …`). Не придумывается — значит,
  результат неопределён, и страницу надо переписать, а не промпт.
- **F-78 Хочется написать раздел «руками» для полноты.** Не пиши, если
  ручной путь никто не пройдёт (D-30): раздел отсутствует, а не заполняется.
  Если сомневаешься — спроси себя, кто и зачем сделает это руками.
- **F-79 Промпт получился под конкретного агента** («используй свой
  инструмент Bash», «вызови tool X»). Перепиши нейтрально: что сделать и
  какой результат, не как. `needs` называет скилл и MCP, не агента.
- **F-80 Прогон промптов красный из-за поведения агента, а не продукта.**
  Не чини промпт под конкретный прогон: посмотри хвост вывода, найди, что
  агент не понял, и дай ему это в промпте или в `needs`. Два падения одного
  промпта подряд на двух раннерах — запись в журнал и переписывание
  страницы.
- **F-69 Хочется показать читателю «доступна новая версия vibe».** Нельзя:
  незнание о смене версии — фича проекта по слову владельца. Показываются
  только даты рендера и последнего чтения.
- **F-70 История хоста переписана, и коммит из состояния билдера исчез.**
  Ничего не делать: билдер помнит только «отрендерено ли текущее»;
  следующий опрос ветки даст новое содержимое, оно и рендерится.
- **F-36 README обычного пакета хочет проверяемый пример.** Не поддержано
  (D-10); fence рендерится как есть; запрос — в BACKLOG как триггер.
- **F-37 Оболочки нет в бинарнике и скачать нельзя (офлайн, отказ).** Работает
  запасная оболочка; читатель сообщает об этом одной строкой; никаких попыток
  тихо выйти в сеть.
- **F-38 Не уверен в имени краулера для `robots.txt`.** Не пиши по памяти:
  открой документацию провайдера в день сборки, запиши источник и дату в
  леджер.
- **F-39 Хочется хранить `official = true` где-нибудь.** Нельзя (R-23).
  Официальность вычисляется из схождения рёбер при каждом рендере.
- **F-40 Предмет назвал `primary`, а в его группе ещё есть `<имя>-docs`.**
  Объявление заменяет соглашение целиком: `<имя>-docs` без упоминания в
  `[documentation]` — community.
- **F-41 Атом требует правки хостового nginx, compose соседей, порта,
  сертификата или чего-либо из VPN.** Стоп до действия. Вопрос владельцу
  тремя пунктами: что происходит, что предполагалось сделать, почему это
  задевает. В `/goal` — завершить цель с тем же сигналом. Обходных
  «аккуратных» способов не искать (R-24).
- **F-42 Хочется вставить в репозиторий или леджер фрагмент `main.md` «для
  удобства».** Нельзя (R-25). Переносятся только путь к файлу и номер
  раздела.
- **F-43 Куда положить нумерацию блоков — в пивот или в рендер.** В рендер
  (`vibe-doc`): номер — свойство проекции, round-trip пивота не меняется;
  бэкенды получают номера параметром. Не в `vibe-specdoc` (A0.25).
- **F-44 Перевод совпал по якорям, но разошёлся по числу блоков.** Ошибка
  проверки (R-18 расширен блоками, A2.23): перевод чинится под источник;
  объединять или дробить абзацы в переводе нельзя.
- **F-45 SSH-команда «висит» или молчит.** Ты вызвал Git-Bash-овый `ssh`.
  Используй `"C:/Windows/System32/OpenSSH/ssh.exe"` (§2.3).
- **F-46 Хочется подключить `anthropic.css` или `article.html.tpl` файлом.**
  Нет (R-28): переносятся токены и приёмы; компоненты пишутся на Qwik и
  семантических токенах.
- **F-47 Хочется Tailwind в оболочке.** Нет (D-21): Tailwind остаётся на
  лендинге; в оболочке — токены и компоненты.
- **F-48 Какую тему включать по умолчанию.** До дизайн-ревью — системную
  (`prefers-color-scheme`); после — как решит владелец (`VISION.md` §10 п. 7).
- **F-49 Docker на сервере пишет `CACHED` для `COPY`, правки не видны.**
  `docker compose build --no-cache <service>` только для сервисов сайта
  документации; чужие сервисы не пересобирать.
- **F-50 Ссылка `latest#pNN` ведёт не на тот блок.** Так задумано: `pNN`
  живёт по версии (R-26). Проверь, что кнопка «для агента» копирует адрес с
  версией, а не `latest`.
- **F-51 Хочется «Ask AI» как чат на сайте.** Не в этой волне (D-21): `.fab`
  — «для агента», адреса и копирование.
- **F-52 Владелец на дизайн-ревью меняет шрифты или цвета.** D-21 правится на
  месте с датой; затем один атом: карта значений в `tokens.css` и три
  `@font-face`-блока; компоненты не трогаются — это и гарантирует R-27.
- **F-53 Клиентский код «для скорости» хочет пересчитать номера абзацев сам.**
  Запрещено (R-26): номера приходят из острова; скрипт только вешает
  обработчики на готовые `.p-anchor`.
- **F-54 Воркер прислал страницу документации «готовую».** Это черновик по
  определению (R-29): перепиши целиком, не редактируй; фикстуры и `expect`
  из его работы бери.
- **F-55 Линтер стиля ругается на термин, который «все знают».** Введи его
  глоссой в той же фразе или ссылкой на глоссарий. «Все знают» — тот самый
  ложный посыл, ради которого линтер существует.
- **F-56 Хочется написать «см. PROP-NNN» вместо объяснения.** Объясни на
  странице своими словами, потом процитируй через `rule`. Отсылка —
  дополнение, не замена (`STYLE.md` §2).
- **F-57 Шутка не переносится на русский.** Замени эквивалентом или сними;
  переводить нельзя (R-31, `STYLE.md` §6 и §10).
- **F-58 Страница получилась длиннее одного присеста.** Это две страницы:
  раздели по понятию, на первой оставь одну фразу-связку.
- **F-59 Не знаешь, лишнее ли слово.** Убери. Если фраза не потеряла смысла,
  слово было лишним (`STYLE.md` §3).
- **F-60 Линтер стиля срабатывает ложно второй раз на одном правиле.** Не
  правь текст под линтер: запись в BACKLOG и правка правила (R-30).
- **F-61 Находка не ложится ни в одно правило регламента.** Запиши её с
  полем «наблюдение без действия: причина». Месячная петля вернётся к ней;
  пустое поле — нарушение R-33, выдуманное правило — хуже.
- **F-62 Устаревшую цитату хочется «починить», сдвинув пин без чтения.**
  Нет: прочитай дифф факта между ревизиями, поправь прозу коридора, потом
  сдвинь пин. Пин без правки прозы — запись в журнал как неудача.
- **F-63 Хочется поправить `derived` руками, «там одна буква».** Нельзя
  (R-03): чинится генератор или его источник; иначе следующая сборка
  вернёт ошибку.
- **F-64 Мелкая правка тянет за собой другие страницы.** Это не мелкая
  правка: строка долга `docs:` с атомом; в недельной петле не делать.
- **F-65 Продукт меняет команду, а страницы для неё ещё нет.** Коммит
  продукта несёт либо страницу, либо строку долга с адресом изменения —
  это привычка, закреплённая чекбоксом в шаблоне pull request'а, не гейт:
  панель печатает дрейф числом и не краснеет; полная сверка подберёт то,
  что привычка пропустила (D-26, J-013).
- **F-67 Хочется добавить в панель шаг, который краснеет от дрейфа
  документации.** Нельзя: замков нет по слову владельца. Дрейф — число в
  выводе панели и метка на странице. Красным бывает только внутренняя
  поломка документации: пример-golden, `derived`, цитата на исчезнувший
  факт.
- **F-66 Пятая мелкая правка одной страницы.** Страница уходит в очередь
  чтения вслух (правило пяти правок); правку делать можно, чтение — до
  следующей.

## 9. Скрипт приёмки {#acceptance}

Запускать из корня репозитория в Git Bash; каждая строка обязана вернуть 0.

```bash
set -e
cargo build -p vibe-cli
V=target/debug/vibe.exe
D=vibevm/vibepacks/org.vibevm.core/vibevm-docs/v0.1.0
R=crates/vibe-doc/tests/fixture/translations/adaptation   # фикстура фазы 2; боевая адаптация — волна C (D-29)
$V --help | grep -q ' doc '                                   # команда есть
$V init --help | grep -q 'flow, feat, stack, tool, mcp, lang, doc, app'
grep -q '"doc"' formats/vocabularies.json && grep -q '"app"' formats/vocabularies.json
cargo xtask check-codegen && cargo xtask wire-diff
$V doc check --path $D --examples --citations --derived --coverage --media --style --min 100
$V doc check --path $R --translations --media --style || true   # фикстура намеренно расходится в одном блоке (F-44): вывод читается, гарантию держит следующая строка
cargo test -p vibe-doc translation
$V doc manifest --path $D --llms full | head -1 | grep -q .
$V doc manifest --path $D --json | grep -q '"primary"'
$V progress report --view doc --audience user | grep -q .
$V progress report --view doc --audience agent | grep -q .
cargo run -p vibe-cli -- facts check --exhaustive
cargo xtask specmap --check
cargo xtask sync-engines --check
test -d docs-legacy && ! test -d docs
grep -q 'vibevm-docs' README.md && grep -q 'vibe doc' RUNTIME-GUIDE.md
bash tools/self-check.sh; echo "EXIT=$?"
```

Фазы 4–5 добавляют: сборка web-пакета статическим адаптером с зелёным
линтером ссылок и `hreflang`-пар; `vibe doc serve` с оболочкой отвечает на
`/`, на адрес страницы и на тот же адрес с языковым сегментом без сети
(`VIBE_OFFLINE=1`), слушая только `127.0.0.1`; тест паритета зелёный; билдер
пересобирает ноль пакетов при неизменном индексе; для одного пакета полки
показывают официальную и community-документацию со звёздочками в правильных
местах. Третья редакция добавляет: набор номеров `pNN` одной страницы
совпадает в острове, `.md` и `.xml` (`$V doc build --format md … | grep -c
'^\[p'` равно числу блоков в `.xml`); тест A4.15 «только loopback» зелёный;
APCA-аудит обеих тем зелёный; дизайн-ревью записано в D-21 с датой; после
деплоя `curl -sI https://vibevm.org/doc/ | head -1` даёт `HTTP/2 200`, а
`curl -sI https://vibevm.org/doc | grep -i '^location'` не содержит
`http://`; в леджере — ноль правок вне контейнеров сайта.

## 13. Отчёт владельцу и стоп-триггеры {#reporting}

**Стоп и вопрос владельцу, всегда:** правка `VIBEVM-SPEC.md`; версия `vibe`
(F-05); ссылки хоста (F-35); серверные шаги деплоя (A5.6 п. 3); **любая
правка хостового nginx, портов, сертификатов, compose соседей или VPN —
стоп до действия, тремя пунктами (R-24, F-41)**; коммит в чужой репозиторий
(A5.8); дизайн-ревью (A4.14) — ждать решения; любая красная линия git;
подозрение на секрет или деталь инфраструктуры в контексте (R-12, R-25);
живой конфликт писателей плана; красный спайк, меняющий решение владельца;
подтверждение D-12 до атомов A4.6–A4.8; картинки ядра; **точки возврата
Fable** F1–F4 — Opus останавливается, собирает очередь и зовёт владельца,
не пишет прозу сам; начало волны C — слово владельца после проверки волны B.

**Границы фаз:** TL;DR из трёх строк: что село, что подтвердилось или
опроверглось, что дальше. Панель — код выхода в отчёте. Четвёртая строка —
журнал: записей за фазу по типам и сколько из них уже изменили регламент.

**Никогда:** «шаг N сел — продолжать?» на рутинной работе. Продолжать.
