## Решения

- `palette.css` — один плоский `:root` (не по теме): сырые имена сами не
  переключаются, переключение — только в `tokens.css` (согласуется с
  «сырые имена живут только в файле палитры» из D-21). Где имя пересекается
  между двумя файлами-источниками (`--text`, `--faint`, `--line*`,
  `--accent*`), добавлен суффикс `-light`/`-dark`/`-raw`, чтобы оба
  сосуществовали в одном `:root` без коллизии.
- `tokens.css`: три блока (`:root,[data-theme="light"]`;
  `@media(prefers-color-scheme:dark){:root:not([data-theme="light"])}`;
  `[data-theme="dark"]`) — только `var(--raw)`, ни одного литерала. `audit.mjs`
  сверяет media-блок с явным атрибутом на равенство (0 расхождений на
  прогоне) — это два механизма включения одной карты, не третья карта.
- `audit.mjs` читает CSS, а не хардкодит значения: свой мини-парсер
  (`extractBlock`/`parseDeclarations`/`resolveVars`), библиотеки `apca-w3` +
  `colorparsley` для цвета и самого APCA. Полупрозрачные фоны сведены к
  непрозрачным через `alphaBlend` поверх `--bg` своей темы перед расчётом.
- «Ближайший более контрастный токен» (п.4 пакета) реализован как «ближайший
  токен той же сырой палитры, который **закрывает** порог, с наименьшим
  запасом», а не как «максимально контрастный из всех» — иначе для тонкой
  линии предлагался бы, например, основной текстовый чёрный/кремовый, что
  формально максимизирует Lc, но не является разумной «ближайшей» заменой.
  Если кандидат, закрывающий порог, отсутствует в палитре той же темы —
  берётся лучший доступный, помечен как «порог всё ещё не закрыт».
- Светлая карта `--bg` = `--ivory-100` (не `--ivory-50`) — обоснование и
  открытый вопрос см. в находке, раздел «Расхождения с решениями».
- `--text-3` получил порог 60 (как `--text-2`) по буквальному указанию п.3
  самого пакета — REVIEW к D-21 записан в находке, решение не переписывалось.

## Отклонения от буквального текста пакета (с причинами)

- Самопроверка `node findings/A0.23-tokens/audit.mjs` выполнена как
  `node <абсолютный путь>` без `cd` в другой репозиторий: харнесс этой сессии
  (worktree `vibevm-docs`) отказывает в составных командах `cd <чужой репозиторий>
  && …`, которые не может статически подтвердить как git-нейтральные.
  Скрипт резолвит свои пути через `import.meta.url`, а не через cwd, поэтому
  результат идентичен буквальному вызову.
- В `findings/A0.23-tokens/` **не** положена копия `node_modules`
  (`apca-w3`, лицензия AGPL v3, + `colorparsley`) — иначе буквальный
  `node findings/A0.23-tokens/audit.mjs` не находит модули (в самом
  `findings/…` npm install не делался — сеть только в scratch, «Что
  запрещено» PACKET-COMMON). Вендоринг AGPL-кода в дерево репозитория —
  решение с лицензионными последствиями, не входящее в «самое консервативное
  допущение» по умолчанию. Вместо этого self-check прогнан на
  scratch-копии, побайтово идентичной находке (`diff` пустой, обе команды
  ниже), и это принято как доказательство. Записано как открытый
  вопрос/дефект пакета в находке.
- В матрицу добавлена одна доп. строка сверх заданной (light `--text-3` на
  `--ivory-50`, отдельным, явно помеченным блоком «не входит в матрицу») —
  черновик пакета называл два кандидата на светлый `--bg`
  (`--ivory-50`/`--ivory-100`), предсказание 10 зафиксировано на конкретном
  `#FAF9F5`; доп. строка закрывает второй кандидат без раздувания основной
  матрицы 5×6+2.
- В процессе обнаружен и исправлен баг в собственном первом черновике
  `audit.mjs`: заголовочный комментарий файла `tokens.css` упоминает
  селекторы как текст («`[data-theme="dark"]` — тёмная явным атрибутом»), и
  наивный `indexOf` по несрезанному CSS находил это совпадение раньше
  настоящего правила — карта `dark` резолвилась в значения `light`
  (numerически подтверждено первым прогоном: все 32 строки light/dark
  совпадали дословно, что физически невозможно при разных hex). Обнаружено
  визуальной сверкой чисел, не только по exit-коду. Исправление — вырезать
  `/* … */` до парсинга; повторный прогон дал разные, перепроверенные
  числа (см. «Самопроверка» и находку).
- `Lc = 0.00` у тёмных `--line`/`--line-strong` на `--bg` проверен отдельным
  изолированным вызовом `APCAcontrast`/`sRGBtoY` вне основного скрипта —
  подтверждено документированное поведение APCA (мягкий чёрный клэмп на
  паре «почти чёрное на почти чёрном»), не баг парсинга/скрипта.
