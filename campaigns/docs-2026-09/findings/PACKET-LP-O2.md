## Что сделать (дизайн — центральной сессии, исполняй его)

1. **Оглавление-путь.** Когда исходное издание объявило главы, колонка
   «Contents» строится двумя видами:
   - *путь* (по умолчанию): главы в объявленном порядке; заголовок главы —
     номер и название («1 Getting started»), номер акцентным цветом
     (`--accent`), табличные цифры; глава с `appendix` — без номера;
     страницы главы в её порядке, текущая подсвечена как сейчас; список
     `pinned` в этом виде не показывается;
   - *разделы*: ровно сегодняшний вид (`pinned` + разделы), без изменений.
   Построение — в `contents.ts` рядом с `contentsOf()` (новый вид — новые
   поля результата, сегодняшний не ломать); компонент `Contents` получает
   оба набора и переключатель. Без глав — ничего не меняется, переключателя
   нет.
2. **Переключатель вида.** Над списками — компактный сегментный
   переключатель из двух кнопок: EN «In order» / «By section», RU «По
   порядку» / «По разделам»; группа с подписью EN «Contents view» / RU «Вид
   оглавления»; кнопки с `aria-pressed`; видимое кольцо фокуса. Внешне — как
   существующие `tab-pills` дизайн-системы (те же токены; семантику вкладок
   не копируй, если она не подходит). Выбор — настройка читалки
   `vibe-doc:contents` = `path` | `sections` через `storage.ts`
   (`##READER-SETTINGS`); применяется **до первой отрисовки** без мигания:
   сервер рендерит оба вида, CSS показывает один по атрибуту на `<html>`,
   атрибут ставит скрипт, уже инлайнящийся до стилей (`theme-init.js`) или
   его сосед того же рода. Ничего не гидратируется; скрипты читалки — как
   соседние модули `reader/*.ts`. На узком экране (колонка сворачивается в
   блок над текстом) переключатель внутри блока.
3. **Пейджер.** Новый компонент дизайн-системы
   `web/design/src/components/pager/` (`index.tsx`, `styles.css`, экспорт как
   у соседей): в конце страницы, стоящей на пути, — две ссылки-карточки:
   слева «← Previous» / «← Назад» и название предыдущей страницы, справа
   «Next →» / «Дальше →» и название следующей, выровнено вправо. Если сосед
   в другой главе — над названием подпись главы: EN «Chapter 3 · Everyday
   work with packages», RU «Глава 3 · Повседневная работа с пакетами»; для
   приложения — его название без номера. Первая страница — только «Дальше»,
   последняя — только «Назад». Карточки: фон `--bg-raise`, граница `--line`,
   радиус `--radius-md`; подпись мелкая, `--text-2`; название `--text`; hover —
   `--line-strong` и сдвиг стрелки на 2px (без сдвига при reduced motion);
   две колонки, на ширине меньше 640px — одна под другой. Место — последний
   блок колонки чтения, после всего, что страница несёт (после блока
   процитированных правил), перед подвалом. Адреса соседей — в языке, который
   читают (`addressOf(library, lang, document)`), в том числе для страниц с
   откатом на источник.
4. **Страница пакета.** Полка «Pages» при объявленных главах — по главам в
   порядке пути (заголовки как в оглавлении), подпись полки EN «In the
   order of the learning path» / RU «В порядке учебного пути» вместо
   нынешней про закон слоёв; первая карточка полки «Documentation» и ссылка
   «Начать отсюда» / «Start here» ведут на первую страницу пути (сейчас —
   на `view.pages[0]`, первую по закону слоёв). Без глав — как сейчас.
5. **Строки интерфейса.** Все новые строки EN/RU — тем же механизмом, что
   соседние строки хрома (`site-language.ts`), и строками в
   `campaigns/docs-2026-09/INTERFACE-COPY.md` в его формате.
6. **Фикстуры.** Фикстурное руководство сайта (`web/site/src/fixtures/…`,
   см. README там же) получает главы в исходном издании и названия глав в
   переводе (одна глава — `appendix`); сохрани фикстурный пакет **без** глав,
   чтобы проверить откат. Если фикстуры генерируются конвейером — генерируй
   тем путём, который описан в README.
7. **Теги.** Новые модули и компоненты — `@scope
   spec://org.vibevm.core/vibevm/common/PROP-057#NAV-CHAPTERS-READER` (или
   `#READER-SETTINGS` для хранения выбора), как помечены соседи.
