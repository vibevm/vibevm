## Цель — четыре атома, четыре коммита

**A4.6 Встраивание.** `cargo xtask embed-doc-shell`: собирает web-пакет
встраиваемым адаптером (`pnpm --dir <пакет> build:embedded`, порядок
сборок из A0.10/P4-O1) и копирует выход — шаблон маршрута с местом под
остров, скрипты, стили, шрифты — в `crates/vibe-doc-shell/shell/`
(каталог в `.gitignore`); крейт `vibe-doc-shell` включает каталог в
бинарник через `include_dir` за фичей `embedded-shell`; `build.rs`
объявляет `rerun-if-changed=shell`, при включённой фиче и пустом
каталоге падает с рецептом, экспортирует дайджест оболочки константой
`VIBE_DOC_SHELL_SHA256`; запасная оболочка без скриптов (голый HTML со
стилями токенов — читать можно, фич нет); пин координаты и content hash
оболочки в `doc-shell.lock` рядом с `Cargo.toml` (`schema`, координата
`org.vibevm.doc/web`, версия, `sha256`); шаг панели «embedded shell
matches pin» при включённой фиче (без фичи — шаг печатает, что оболочка
запасная, и зелёный); для сборок без фичи — `vibe doc shell install
[--assume-yes]`: скачивание оболочки из релизных активов по явному
согласию (по образцу `vibe self install`: `DOC-SHELL.json` той же формы,
что `DISTRIBUTIONS.json`, проверка размера и дайджеста), в
content-addressed каталог `~/.vibe/opt/vibevm/doc-shell/<sha256>/`; при
отказе или офлайн — запасная оболочка; **никогда автоматически**. Один тип
`Shell` с тремя источниками (встроенная, из store, запасная) и
`provenance()`. Коммит:
`feat(xtask): embed the docs shell into vibe at release time`.

**A4.7 `vibe doc serve` с оболочкой.** Сервер отдаёт статику оболочки из
бинарника или store, вклеивает остров, отрендеренный конвейером Rust, на
каждый запрос страницы; источники страниц — store, lock, реестр (как
сейчас); базовый путь конфигурируем (`--base`, по умолчанию `/doc/`);
язык из `[i18n].preferred` проекта или флага (семантика P2-O8: флаг
заявляет язык и отказывает с координатой адаптации); **только
`127.0.0.1`**, файлы только из известных корней, без листинга и обхода
путей (сохранить декодирование-до-маршрутизации P2-O8), CSP без внешних
источников с `sha256` **каждого** инлайн-скрипта оболочки (после P4-O2
их два: тема и отключение восстановления прокрутки; X-035: хэши
считаются из байтов оболочки при старте, не хардкодятся); `postMessage`-контракт по
отчёту P4-O2 (`{"open": "spec://…"}` внутрь, `{"openFile": "…"}` наружу,
`settings`/`theme`); `--frame-ancestor <origin>` как сейчас; резолвер
`/doc/resolve?uri=spec://…` — маршрут сервера (F-15). Тесты: обход путей
(три написания), привязка к loopback, CSP несёт хэш скрипта и ни одного
внешнего источника, `provenance()` в `--json` ответе `vibe doc serve
--print-shell` (или эквивалент — назови в отчёте). Коммит:
`feat(doc): serve the documentation locally with the embedded shell`.

**A4.8 Паритет.** Над фикстурным пакетом (`crates/vibe-doc` голдены или
`examples/` руководства — выбери и назови) собрать остров через
статический путь (`vibe doc build --format html`) и через сервер
(`GET` страницы у `serve`), сравнить остров байт в байт; тест в
`vibe-doc-server` и шаг панели. Предсказание 6 (паритет сломается на
первом изменении оболочки, если тест не сравнивает байт в байт) — число
в отчёт. Коммит: `test(doc): pin island parity across shell adapters`.

**A4.15 Тест «ни одного внешнего запроса».** Единственное исключение из
«web-пакет не править»: **один новый файл** `site/tests/local-reader.spec.ts`
в web-пакете (Playwright там уже стоит — смотри `site/tests/*.spec.ts` и
`site/playwright.config.ts` как образец; ничего существующего в пакете не
менять, `package.json` не трогать). Тест поднимает собранный `vibe` с
встроенной оболочкой (`vibe doc serve --path <руководство> --port <свободный>`;
путь к бинарнику — переменная окружения `VIBE_BIN`, по умолчанию
`target/debug/vibe.exe` от корня репозитория; без бинарника тест
**пропускается с внятной причиной**, не падает), открывает страницу
документации и страницу пакета в headless-браузере, перехватывает **всю**
сеть (`page.on('request')`, включая шрифты, стили, скрипты, картинки,
`fetch`) и утверждает: каждый запрос — на `127.0.0.1` того же порта;
ни одного запроса к `fonts.googleapis.com`, `fonts.gstatic.com`, CDN и
любому внешнему хосту; в DOM нет тега аналитики (`umami`,
`data-website-id`, `script[src*="//"]` на чужой хост — D-24); консоль без
ошибок CSP. Отдельный кейс: та же страница через `vibe doc build --format
html` (статический вывод, открытый как `file://`) — тоже без внешних
запросов. Шаг панели в `tools/self-check.sh` после сборки оболочки:
`pnpm --dir <пакет> exec playwright test tests/local-reader.spec.ts`
(с `VIBE_BIN`); шаг пропускается там, где нет Node, с печатью причины.
Число перехваченных запросов и их хосты — в отчёт. Коммит:
`test(doc): pin the local reader to loopback resources`.

В дереве может одновременно работать P4-O3 (`site/src/seo/**`,
`site/tests/**`, `tools/*.mjs`): твой файл — новый, коммить его только
явной формой с путями; если P4-O3 уже добавил `site/tests/local-reader.spec.ts`
или тест того же смысла — не дублируй, расширь его отдельным коммитом и
скажи в отчёте.

## Хвост: картинки карточки в манифесте страниц (тем же коммитом, что A4.7)

P4-O2 не смог показать плейсхолдер, различающийся по координате (D-20):
манифест страниц не несёт адресов картинок карточки, а второй генератор
хэша на TypeScript положил бы одно правило в два языка. Схема
`schemas/doc_manifest.jtd.json` получает у пакета поле `media` с тремя
адресами (`icon`, `banner`, `preview`) — сгенерированные плейсхолдеры или
скопированные картинки `[media]` под их хэшированными именами, как их
кладёт `vibe doc build`; `cargo xtask codegen` обновляет Rust и TypeScript
(`site/src/generated/doc-manifest.ts` — единственный файл web-пакета,
который ты трогаешь, и только генератором); `vibe doc manifest --json` и
`build` заполняют поле; тест в `vibe-doc`. Оболочке P4-O2 останется
прочитать поле — это отдельная правка после тебя, не твоя.
