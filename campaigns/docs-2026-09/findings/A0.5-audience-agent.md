отбирает маркеры с `actionstage="doc"` независимо от их `stage`/`state`/`action`.
Строки собирает `rows()` (`report.rs:116-227`): сначала фильтр по `view`,
затем (если задан) — по `--audience` через `audience_matches`. Рендер —
`render_md`/`render_xml` (`crates/progress-core/src/report/render.rs`) либо
сырой JSON-массив `Row` при `--json` (сборка в `report_body`,
`crates/vibe-cli/src/commands/progress.rs:156-177`). Сегодня `--view doc`
выдаёт ровно тот же построчный список маркеров/файлов, что и любой другой
view (`done`/`todo`/`qa`/`remove`/`terminal`) — навигацию по дереву
маркеров, а не агрегат «что ещё недокументировано»: точные образцы вывода —
`report.rs:274-280` (md-заголовок таблицы) и `report.rs:282-293` (xml

`documents`-рёбрам. Ближайшая релевантная декларация — факт
`DOC-COVERAGE-RATCHET` (`vibevm/vibespecs/modules/vibe-progress/PROP-047-progress-campaigns.xml:224-225`):
спека уже называет идею doc-view-closure-гейта («ratchets like specmap
orphans»), но `report.rs`/`render.rs` её не реализуют — `--view doc` сейчас
это фильтр по одному атрибуту (`actionstage=doc`), не гейт покрытия.

  сценарии не в компетенции этого спайка.

  `audience` нет, то есть такого снапшота сегодня нет. Если он появится —
