# A0.17 In-tree пакет → store до публикации

Дата: 2026-09-11
Дерево: b1291b06

## Ответы

### 1. Попадает ли in-tree пакет в store командой `cache add` из корня хоста

Да. Точная команда, которая сработала (выполнена из
`C:\Users\olegc\git\v\vibevm-docs`, в изолированном окружении):

```bash
vibe.exe cache add --offline "org.vibevm.world/multi-user-planning@1.0.0"
```

Код выхода `0`. Флаг `--offline` не обязателен для успеха, но обязателен, если
сеть трогать нельзя: без него резолвер дополнительно опрашивает объявленные в
корневом `vibe.toml` сетевые реестры (`https://github.com/vibespecs`,
`https://gitverse.ru/vibespecs`) ради объединения множества версий
(PROP-030 `##ENUM-UNION`,
`vibevm/vibespecs/modules/vibe-registry/PROP-030-embedded-registry.xml:130–134`).

### 2. Через какой источник

Через **project-local реестр** (PROP-030 §3.3), а не через vibe-embedded
(PROP-030 §2) и не через `--registry`.

- Project-local — это `<корень проекта>/vibevm/vibepacks`, открытый как
  `LocalRegistry`: `crates/vibe-package-source/src/builder.rs:187–198`
  (`if !options.no_prefer_local && let Some(root) = project_packages_root(project_root)`),
  `crates/vibe-package-source/src/project_local.rs:31`,
  `vibe_core::layout::current_packages_root()` — `crates/vibe-core/src/layout.rs:165`
  (флаг `USE_NEW_LAYOUT = true`, `:148`) → `vibepacks_root()` — `:90` →
  `vibevm/vibepacks`.
- Раскладка local-реестра — `<root>/<group>/<name>/v<version>/`
  (`crates/vibe-registry/src/local_registry.rs:171–173`, разбор `v`-префикса —
  `:85`), и `vibevm/vibepacks/org.vibevm.world/multi-user-planning/v1.0.0/`
  ей отвечает буква в букву.
- Этот источник **не** привязан к тому, установлен ли сам `vibe` из исходников,
  и **не** гасится переменной `CI` — он свойство проекта
  (`crates/vibe-package-source/src/project_local.rs:11–16`).
- vibe-embedded здесь исключён двумя независимыми способами. Во-первых,
  `cache add` передаёт `embedded_root = None`
  (`crates/vibe-cli/src/commands/cache/add.rs:118`). Во-вторых, даже для
  install-семейства обнаружение гасится, если бинарь запущен не из слота VVM:
  `discover_embedded_root` в `crates/vibe-cli/src/main.rs:97–104` зовёт
  `commands::vvm::embedded_root_at(self_loc.as_ref()?.root.clone())`, а
  `self_loc` строится `derive_self` (`crates/vibe-cli/src/commands/vvm/selfloc.rs:22`),
  который требует путь вида
  `…/opt/vibevm/versions/<branch|tag|commit>/<id>/<instance>/vibe.exe`.
  Проба велась бинарником `target/debug/vibe.exe`, то есть vibe-embedded
  недоступен в принципе.
- Флага `--registry` у `cache add` нет вовсе (см. `vibe cache add --help`;
  в заглушке аргументов `registry: None` —
  `crates/vibe-cli/src/commands/cache/add.rs:168`).

Контрольная проба, доказывающая, что источник именно project-local: та же
команда с `--path`, указывающим на проект **без** `vibevm/vibepacks`, падает с
кодом `1` и сообщением «не резолвится офлайн». Вторая контрольная: без проекта
вовсе (`--path` в каталог без `vibe.toml`) команда падает с
«no registry configured for a projectless registry fetch», то есть уходит на
ветку `projectless_resolver` (`crates/vibe-cli/src/commands/cache/add.rs:134–155`),
где источником был бы `~/.vibe/registry.toml`.

## Расхождения с решениями

Нет. Решение D-16 («doc-пакет ядра до публикации должен попадать в store
командой из корня хоста») подтверждается живой пробой.

Смежное наблюдение, не противоречащее решениям, но существенное для фазы 3:
in-tree пакеты объявлены владельцем как **мутабельные слоты одной версии**
(комментарий в `vibevm/vibepacks/org.vibevm.world/multi-user-planning/v1.0.0/vibe.toml:1–4`:
«maintains its 1.0.0 package family as mutable in-tree development slots … do not
mint patch versions merely to move the dogfood tree forward»). Store это
выдерживает: путь project-local-выборки использует
`store::insert_current_at` (`crates/vibe-registry/src/local_registry.rs:197`),
который заменяет запись при расхождении content-hash
(`crates/vibe-registry/src/store/refresh.rs:24–56`, PROP-011 §2.6). Но строка
отчёта `cache add` при этом всё равно скажет «already present — bytes untouched»
— подробности и проба в `A0.8-store-and-sources.md`, раздел «Расхождения».

## Открытые вопросы

- Повторный `cache add` того же in-tree пакета после правки его файлов живьём не
  проверялся: фаза 0 запрещает менять файлы репозитория, а мутабельный слот
  лежит внутри него. Механизм подтверждён на суррогатном пакете в scratch
  (пробы B2/B4 в `A0.20-host-from-source.md`) и на коде
  `local_registry.rs:197` → `refresh.rs:24`.
- Не проверялось, какой источник победит, если один и тот же координат есть и в
  `vibevm/vibepacks`, и в опубликованном реестре: по PROP-030 §3 при
  embedded-first (умолчание для source-install) выигрывает локальный, но у
  `cache add` embedded отсутствует, а project-local стоит первым в семье
  (`crates/vibe-package-source/src/builder.rs:180–198`).
