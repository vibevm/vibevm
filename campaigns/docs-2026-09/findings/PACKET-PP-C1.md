## Что проверяем

44 страницы документации в
`vibevm/vibepacks/org.vibevm.core/vibevm-docs/v0.1.0/vibevm/vibespecs/**/*.xml`
(диалект XML: элементы `p`, `table`/`tr`/`td`, `example` с `run`/`expect`,
`rule ref="spec://…#ANCHOR"`, `derived`, `prompt` с `needs`/`outcome`/`assert`,
именованные секции с `title=`; инлайн — Markdown: `` `код` ``, `*курсив*`,
`[ссылка](путь)`).

## Сделать

1. **Цитаты (P.7).** Собрать все адреса `spec://…#ANCHOR` из атрибутов `ref`
   элементов `rule` (и из текста `spec://` в прозе). Для каждого разрешить
   документ и якорь:
   - `spec://org.vibevm.core/vibevm/<путь>/<DOC>#A` → файл
     `vibevm/vibespecs/<путь>/<DOC>-*.xml` (или `<DOC>.xml`; `<DOC>` — префикс
     имени файла, например `common/PROP-000` → `vibevm/vibespecs/common/PROP-000.xml`,
     `modules/vibe-workspace/PROP-009` → `vibevm/vibespecs/modules/vibe-workspace/PROP-009-loading-model.xml`);
   - `spec://org.vibevm.world/addressable-specs/flows/addressable-specs/<DOC>#A` →
     `vibevm/vibedeps/org.vibevm.world.addressable-specs/1.0.0/vibevm/vibespecs/flows/addressable-specs/<DOC>.xml`;
   - `spec://org.vibevm.ai-native/core-ai-native/mechanisms/PROP-014#A` →
     `vibevm/vibedeps/org.vibevm.ai-native.core-ai-native/1.0.0/vibevm/vibespecs/mechanisms/PROP-014-*.xml`.
   Якорь `A` существует, если в файле есть элемент с именем `A` (именованный
   факт или секция: `<A ` или `<A>`), либо `id="A"`, либо для Markdown-файлов
   `{#A}` или `@fact:A`. Регистр значим. Записать таблицу: страница, адрес,
   файл, найден/не найден; для ненайденных — три ближайших похожих якоря из
   того же файла (по подстроке или расстоянию Левенштейна).
2. **Запрещённые слова (P.6).** Список —
   `vibevm/vibepacks/org.vibevm.core/vibevm-docs/v0.1.0/style/banned.en.txt`
   (строки без `#`). Для каждой страницы: вхождения по целым словам без учёта
   регистра в тексте вне `run`/`expect`/`assert`/атрибутов (для многословных
   фраз — как фраз). Таблица: страница, слово, фраза-контекст (до 120
   знаков). Заметь: слова вроде `just`, `simply`, `multiple`, `specific`,
   `certain`, `various` в списке помечены как фильтры — их всё равно
   перечислить, решает центральная сессия.
3. **Длина фраз.** В абзацах внутри секций с `title`, начинающимся на
   «By hand», и в `prompt`/`outcome`: фразы длиннее 20 слов; в остальных
   абзацах — длиннее 25 слов, только если абзац описательный технический
   (содержит хотя бы один `` `код` ``); абзацы длиннее 6 фраз. Таблица с
   номером фразы и её началом.
4. **Заголовки.** Секции с `title` из списка: Overview, Summary, Conclusion,
   Next steps, Key takeaways, Introduction, а также `title`, заканчивающиеся
   на `?`. Таблица.
5. **Знаки.** Восклицательные знаки в прозе; эмодзи (не-ASCII символы вне
   кириллицы/латиницы/типографики «»—…); жирный `**…**` в прозе; более одного
   тире `—` в абзаце. Таблица.
6. **Термины до введения.** Список терминов — заголовки `title=` секций
   страницы `glossary/index.xml`. Для каждой страницы (кроме глоссария):
   первое вхождение каждого термина (по словоформам: термин и термин+s) —
   в первом абзаце страницы (первый `<p>` до первой секции) термины
   запрещены вовсе; на остальной странице первое вхождение термина должно
   быть либо в `*курсиве*`, либо в `[ссылке](…)`, либо в предложении с
   пояснением («, the …», «: …», «that is», «which is»). Таблица: страница,
   термин, где встретился впервые, признак пояснения найден/нет. Не
   считать вхождения внутри `` `кода` `` и атрибутов.
7. **Ссылки между страницами.** Все `[текст](путь.xml)` — путь существует
   относительно файла. Таблица ненайденных.
8. **Идентификаторы примеров и промптов.** `example id` и `prompt id` —
   уникальны внутри страницы; у каждого `example` есть `run`; у каждого
   `prompt` — хотя бы один `assert`, кроме помеченных `assert="none"`.
9. Скрипт(ы) — в scratch; приложить к отчёту о работе целиком (они станут
   первыми фикстурами линтера A2.25).
