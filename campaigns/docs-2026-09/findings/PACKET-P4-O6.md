# PACKET-P4-O6 — библиотека страниц из данных: сайт рендерит издания из деревьев `vibe doc build`, локальный ридер читает манифест читателя

##subagent-quiet-clause

Ты — воркер кампании документации, исполнитель уровня `opus5`. Boot-лейн
репозитория не читать. Твоя инструкция — этот файл и ровно те файлы,
которые он называет. Предусловия: в ветке P4-O3 (`8482e33e`, `f8240086`,
`39c9c850` — статический адаптер, агентские поверхности, короткая голова
локального ридера) и P4-O4 (`0cae55ca`…`b1ea7057` — оболочка в бинарнике,
`vibe doc serve` с оболочкой, паритет, loopback-тест); проверь
`git log --oneline -40`.

## Почему пакет существует

Статический сайт сегодня печёт **одну фикстурную островную страницу** в
каждый адрес (`site/vite.config.ts` читает `src/fixtures/island.html` в
`__VIBE_ISLAND_HTML__`) и строит библиотеку страниц из **фикстурных
манифестов** (`site/src/lib/library.ts` импортирует `fixtures/manifest.json`
и `manifest-ru.json`). Настоящее руководство попадает в выход только копией
поверхностей (`.md`, `.xml`, `llms`), строка сборки так и говорит:
«1 tree(s) the page library does not carry». Локальный ридер по той же
причине показывает навигацию, мета-строку, переключатель версий и блок «для
агента» фикстуры, с которой оболочку собрали (отчёт P4-O4, «что не
сделано» 1–2). Сайт, который нельзя выложить с настоящими страницами, — не
сайт; это последний пробел фазы 4 перед сборкой сайта реестром (P5-O1).

## Цель — два атома, два коммита

**Атом 1 — статическая сборка рендерит каждое издание из деревьев.**
`VIBE_DOC_OUT` (уже есть: список деревьев через разделитель платформы)
становится источником **библиотеки страниц**, а не только поверхностей:
для каждого дерева с `manifest.json` — издание; страницы издания — адреса
`##SITE-MOUNT` в обоих написаниях версии (нумерованное и `latest`, как
решил P4-O3), язык — из манифеста (адаптации — под координатой источника
с языковым сегментом, D-06); остров каждой страницы — байты
`<страница>/index.html` её дерева (`html`-проекция; если у координаты
несколько деревьев, остров ищется в каждом, как P4-O3 ищет поверхности);
страница пакета — из манифеста издания (полки, карточка, аннотация — то,
что оболочка P4-O2 и так строит из библиотеки); фоллбэк адаптации — как
сейчас (`##READER-LANGUAGE-SWITCH-KEEPS-PLACE`). Без `VIBE_DOC_OUT` —
фикстура, как сегодня (тесты и `pnpm build:static` без окружения не
меняют поведения). Гейт числа страниц (`onStaticGenerate` против
ожидаемого) считает страницы изданий из деревьев. `tools/lint-links.mjs`
над руководством: каждая внутренняя ссылка острова (глоссарий, соседние
страницы, `.md`/`.xml`) должна резолвиться в файл выхода — если остров
ссылается по форме, которую сайт не несёт, это находка в отчёт с числом,
не исключение в `EXCEPTIONS`. Коммит:
`feat(web): render every edition from the documentation trees`.

**Атом 2 — локальный ридер читает манифест читателя.** Во встраиваемой
конфигурации оболочка при старте маршрута берёт `<base>manifest.json`
(сервер уже отдаёт его) и строит из него навигацию, мета-строку,
переключатель версий и языков, блок «для агента», адреса `.md`/`.xml`,
карточку и полки страницы пакета; поле `media` читается оттуда же
(картинки лежат под `<base>…/media/<хэш>.<ext>` — проверь, что сервер их
отдаёт, иначе — плейсхолдер и строка в отчёт). Остров страницы приходит с
сервера в отданной странице; **ссылки между страницами — обычные переходы**
(полная загрузка: сервер рендерит на запрос), никакой клиентской
перерисовки острова — это закрывает А-4 отчёта P4-O4 (второй маркер
острова в `qwik/state`). Страница пакета: если сервер отвечает `302` на
первую страницу для `<base><координата>/<версия>/` (решение 6 P4-O4),
оставь так и запиши, что для страницы пакета нужен серверный маршрут
(правка Rust — не твоя). После правок — `cargo xtask embed-doc-shell`
(на общем `target/`, он тёплый) перепиновывает оболочку: `doc-shell.lock`
меняется — коммить его вместе с атомом; `cargo test -p vibe-doc-server
-p vibe-doc-shell --features vibe-doc-shell/embedded-shell` зелёный
(паритет A4.8 и loopback A4.15 не сломаны). Коммит:
`feat(web): read the served manifest in the local reader`.

## Тесты

Node-тесты (`pnpm floor`): библиотека из деревьев — по фикстурному
дереву `site/src/fixtures/doc-build`, которому ты **добавляешь**
`manifest.json` и острова `index.html` страниц, скопированные байт в байт
с голденов конвейера `crates/vibe-doc` (назови файлы-источники); адреса,
оба написания версии, язык, остров, страница пакета; без `VIBE_DOC_OUT` —
прежнее поведение. Playwright: `site/tests/local-reader.spec.ts` (или
сосед) — навигация локального ридера над `vibe doc serve` руководства
показывает **заголовки руководства**, а не фикстуры; переход по ссылке
даёт страницу руководства. Живой прогон: `VIBE_DOC_OUT` = три дерева
руководства (`html`, `md`, `xml`) → `node tools/build.mjs static` →
число страниц = 2 × (48 + 1) + `/doc/` + каталоги языков + 4 маршрута
лендинга (или назови своё и объясни), `lint-links` — числа, `parity`
зелёный, `du -sh dist`. Форма запуска под MSYS — отчёт P4-O3, А-4.

## Что не трогать

Rust-код, кроме запуска `cargo xtask embed-doc-shell` и тестов двух
крейтов (никаких правок в `crates/**`, `xtask/**`, `schemas/**`);
`site/src/generated/**` — только генератором; лендинг (`/`, `/ru/`) и
`tools/parity.mjs` — паритет обязан остаться зелёным без новых правил;
PROP-файлы и вижен; ничего на сервере (R-24). В дереве параллельно
работает P5-O1 в `crates/**` (реестровый билдер) — его файлы не стейджить;
он зовёт `node tools/build.mjs static` в своих гейтах, поэтому **каждый
твой коммит оставляет пакет собираемым**: сборка и пол — до коммита, не
после.

## Правила репозитория

Conventional Commits с телом «почему»; **коммитить только явной формой
`git commit -m … -- <свои пути>`**, новые файлы сначала `git add -- <файл>`;
никаких трейлеров и упоминаний моделей; `git push` не делать; секреты и
`infra/` не читать; отчёт `campaigns/docs-2026-09/findings/WORKER-REPORT-P4-O6.md`
(не коммитить — вносит центральная сессия): решения, вывод гейтов
дословно, числа страниц и ссылок, что не сделано и почему; ни одного
пути вне репозитория, IP и секретов.
