# A0.7 HTTP-сервер локального читателя

Дата: 2026-09-11
Дерево: b1291b06

## Ответы

### 1. Как устроен сервер индекса

**Фреймворк и версия.** axum. Пин в корневом манифесте — `axum = "0.8"`
(`Cargo.toml:269`), крейт берёт его через workspace
(`crates/vibe-index/Cargo.toml:40`). Рядом `tower = "0.5"`
(`crates/vibe-index/Cargo.toml:42`) и `tower-http = { version = "0.6",
features = ["cors", "trace"] }` (`crates/vibe-index/Cargo.toml:43`).
Фактически разрешается axum 0.8.9 (проверено в пробном крейте с тем же
`"0.8"`). `hyper` прямой зависимостью не объявлен нигде — он приходит внутри
axum. Ни один другой крейт рабочего пространства не зависит от axum в
продуктовом коде: остальные вхождения — тестовые серверы-заглушки
(`crates/vibe-cli/tests/cli_search.rs:223`,
`crates/vibe-publish/tests/github_release.rs:114` и т. п.).

**Сборка приложения.** Одна функция
`build_app(state: AppState) -> Router` (`crates/vibe-index/src/server/mod.rs:44`),
плоский список маршрутов, `.fallback(unknown_route)` (`mod.rs:109`), затем три
слоя в порядке `rate_limit → cors → TraceLayer` (`mod.rs:110-112`) и
`.with_state(Arc<AppState>)` (`mod.rs:113`). Состояние — `AppState`
(`crates/vibe-index/src/server/state.rs:24-42`): `RwLock<Index>`, счётчики,
и два «шва» как трейт-объекты (`Box<dyn TokenStore>`, `Box<dyn RateLimiter>`).

**Стиль ошибок.** Тип `ApiError`
(`crates/vibe-index/src/server/error.rs:12-25`): `status: StatusCode`,
`kind: &'static str`, `title`, `detail: String` плюс опциональное расширение
`unavailable`. Конструкторы `not_found` / `bad_request` / `internal` /
`unauthorized` / `forbidden` / `unavailable` (`error.rs:27-92`). Маппинг в
HTTP — через `impl IntoResponse` (`error.rs:109-120`): тело RFC-7807
problem-details, сериализуется `axum::Json`, то есть заголовок
`content-type: application/json` (не `application/problem+json`). Обработчики
возвращают `Result<Response, ApiError>`. Текст `detail` везде построен по
шаблону «что нарушено (`violates spec://…`) + fix:» — это норма дерева.

**Статика.** Её нет. Фича `fs` у `tower-http` не включена, `ServeDir` в
дереве не встречается. Файлы индекса читаются с диска на каждый запрос
целиком в память: `serve_file`
(`crates/vibe-index/src/server/routes/index_files.rs:128-163`) — `tokio::fs::read`,
явный `content-type` аргументом, `cache-control: no-cache`. Ни `ETag`, ни
`Last-Modified`, ни `Range`, ни сжатия. Единственное исключение — заранее
сжатый файл: маршрут `primary.jsonl.gz` вручную ставит
`content-encoding: gzip` (`index_files.rs:62-66`).

**Привязка адреса.** `crates/vibe-index/src/cli/serve.rs:23-24`: clap-аргумент
`--bind ADDR` типа `SocketAddr` со значением по умолчанию `127.0.0.1:8412`
(комментарий там же называет это `local-only`). Далее
`tokio::net::TcpListener::bind(args.bind)` (`serve.rs:121`),
`app.into_make_service_with_connect_info::<SocketAddr>()` (`serve.rs:136`) —
именно это даёт middleware адрес пира, — `axum::serve` (`serve.rs:137`) и
`tokio::select!` с `ctrl_c` для остановки (`serve.rs:138-147`). Функция `run`
синхронная и сама строит multi-thread-рантайм (`serve.rs:111-117`).

**Middleware.** Ровно три слоя (см. выше). CORS сейчас максимально широкий:
`allow_origin(Any).allow_methods(Any).allow_headers(Any)` (`mod.rs:46-49`).
Rate-limit — собственная функция `rate_limit_middleware` через
`middleware::from_fn_with_state` (`mod.rs:51-52`, тело `mod.rs:128-170`):
выбирает корзину по bearer-токену, иначе по IP, освобождает
`/healthz` / `/readyz` / `/metrics`, при отказе отдаёт 429 с
`retry-after` и `x-ratelimit-*` (`mod.rs:172-201`). **Аутентификация слоем не
является**: это помощник, вызываемый внутри обработчика —
`require_writeable(&state, &headers)`
(`crates/vibe-index/src/server/routes/packages.rs:513-538`).

**Как тестируются маршруты.** Через `tower::util::ServiceExt::oneshot` прямо
по `Router`, без TCP-слушателя. Объявление в шапке
`crates/vibe-index/tests/server_e2e.rs:1-3` («no actual TCP listener bound —
so the tests run hermetically and cheaply»), импорт
`crates/vibe-index/tests/server_e2e.rs:11`, конструктор запроса
`fn req(method, uri)` — `server_e2e.rs:148`, первый тест
`healthz_returns_ok` — `server_e2e.rs:157`. Тот же приём в
`crates/vibe-index/tests/rate_limit_e2e.rs:11` и
`crates/vibe-index/tests/auto_publish.rs:17`. Состояние тесты строят
`AppState::new(tmp.path(), true, idx)` над `tempfile::tempdir`
(`server_e2e.rs:79-135`). Отдельного крейта-хелпера (`axum-test`) нет;
`tower` объявлен обычной зависимостью именно ради `ServiceExt`.

### 2. Новый крейт `vibe-doc-server` или модуль внутри `vibe-doc`

**Рекомендация: отдельный тонкий крейт-поверхность `vibe-doc-server`.**
Крейт `vibe-doc-shell` для встраивания оболочки уже назван решением
(D-12 п. 1), так что раскладка получается трёхчастной: `vibe-doc` (чистая
логика) → `vibe-doc-shell` (байты оболочки) → `vibe-doc-server` (axum).

Факты за:

- **Переиспользовать из `vibe-index` нечего.** Публичны `ApiError`,
  `TokenStore`, `RateLimiter`, `AppState`
  (`crates/vibe-index/src/server/mod.rs:15-20`), но `AppState` держит
  `RwLock<Index>` (`state.rs:30`), а сам крейт тянет `reqwest`, `flate2`,
  `vibe-wire`, `walkdir`, `chrono`
  (`crates/vibe-index/Cargo.toml:24-50`). Зависимость `vibe-doc-server →
  vibe-index` ради ~120 строк формы роутера и типа ошибки обошлась бы всем
  этим. Дерево уже принимало такое решение осознанно в обратную сторону:
  хэшер контента намеренно продублирован между `vibe-index` и
  `vibe-registry` (комментарий `crates/vibe-index/Cargo.toml:58-61`).
  Значит, повторяем **форму**, а не импортируем код.
- **Закон omnichannel уже так и выглядит.** `crates/vibe-index/src/server/`
  — тонкая поверхность над `index::Index`; обработчик не содержит домена.
  Для документации то же: `vibe-doc` знает store, проекции и остров, сервер
  умеет только маршруты, коды и заголовки.
- **`vibe-doc` линкуют не только сервером.** Его же будут использовать
  генератор статического сайта, MCP-инструмент `read_doc` и `vibe doc build`.
  Если HTTP-слой лежит модулем внутри `vibe-doc`, axum + hyper + tower
  попадают в каждого из них. Замер чистой сборки только
  `axum + tower-http + tokio + hyper` в пробном крейте — **18,7 с**
  (`Finished dev profile … in 18.69s`), и это на прогретом реестре.
- **Фича-флаг внутри `vibe-doc` хуже отдельного крейта.** Фичи в cargo
  аддитивны на всё рабочее пространство: любой участник, включивший `serve`,
  включает его всем сборкам в графе. Прецедента фича-гейтов в дереве нет —
  у `vibe-cli` секции `[features]` вообще нет. Отдельный крейт даёт
  `cargo build -p vibe-doc-server --features embedded-shell` как единственную
  релизную ручку.

Факты против (записаны честно):

- `vibe doc serve` — подкоманда `vibe` (D-09), значит `vibe-cli` всё равно
  получит axum транзитивно; аргумент «держим axum подальше от бинарника
  `vibe`» не работает. Выигрыш остаётся в том, что axum не попадает в
  `vibe-doc`, `vibe-mcp` и генератор сайта.
- Плюс один участник workspace (33 → 34 в `members`, `Cargo.toml:8-39`) и
  ещё один `Cargo.toml`, где надо не забыть `license-file.workspace = true`
  (образец: `crates/vibe-index/Cargo.toml:7`).
- Дублирование ~120 строк (роутер, `ApiError`, тестовый `req`-хелпер). Это
  копия формы, не логики; расхождение форм между двумя серверами дереву не
  вредит, поскольку контракты у них разные.

### 3. Проба на той же версии axum (0.8.9)

Пробный крейт: `<scratch>/vibe-docs-phase0\P0-O3\probe\`.

**Привязка только к 127.0.0.1 со свободным портом.** Работает:
`SocketAddr::from((Ipv4Addr::LOCALHOST, 0))` → `TcpListener::bind` →
`listener.local_addr().unwrap().port()`. Слушающий сокет — только на
петле, не на `0.0.0.0` (см. «Свидетельства», вывод `netstat`).

**Предлагаемая строка CSP** (проверена в ответе сервера целиком):

```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; media-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
```

Пояснения к каждому ограничению: `default-src 'self'` закрывает всё, что не
перечислено; `img-src 'self' data:` нужен инлайн-иконкам и SVG-спрайтам, без
`data:` они не отрисуются; `font-src 'self'` достаточен, так как шрифты
самохостятся в бандле (D-12 п. 8), внешних шрифтовых сервисов нет;
`connect-src 'self'` запрещает `fetch`/`WebSocket` наружу; `object-src 'none'`
и `base-uri 'none'` убирают два классических вектора инъекции;
`form-action 'none'` — читатель ничего не отправляет.
**`frame-ancestors` — единственная часть, которая обязана быть параметром
запуска**: по D-09 локальный сервер отдаёт её для origin запустившего хоста,
поэтому в автономном режиме это `'none'`, а при запуске из webview —
конкретный origin хоста. `frame-ancestors` игнорируется в `<meta>`, поэтому
ставить CSP только заголовком.

Ставится слоем `tower_http::set_header::SetResponseHeaderLayer::overriding`
поверх всего роутера — заголовок появляется в том числе на 404 и 304
(проверено). Фича `set-header` у `tower-http` для этого включается
дополнительно к нынешним `cors, trace`.

**Защита от `..` — три механизма, все измерены.**

1. **Ручной лексический join (рекомендуется для оболочки).** Разбор по `/`,
   каждый сегмент обязан быть ровно одним `Component::Normal`, отказ на `\`
   и `\0`, финальная проверка `out.starts_with(root)`. Отбил все три формы:
   `../`, `..%2F`, `%2e%2e%2f` → 404.
2. **`tower_http::services::ServeDir`.** Отбил все формы. Механизм — в
   `ServeVariant::build_and_validate_path`
   (`tower-http-0.6.11/src/services/fs/serve_dir/mod.rs:455-494`): сперва
   percent-decode, затем по компонентам — `Prefix | RootDir | ParentDir`
   отвергаются, `Normal` принимается только если сам не разбирается на
   несколько компонентов (защита от `foo/c:/bar`), и на Windows
   дополнительно отвергаются зарезервированные DOS-имена (`CON`, `NUL`, …).
   Симлинки при этом **не** проверяются — переход по ним разрешён.
3. **Форма, которую применяет `vibe-index`, от `..` НЕ защищает.** Маршрут
   `/v1/index/by-name/{name}` с одним сегментом и `data_dir.join(name)`
   (`crates/vibe-index/src/server/routes/index_files.rs:112-126`) проходим:
   axum-роутер сопоставляет маршрут по сырому пути, а экстрактор `Path`
   percent-декодирует захват, поэтому `%2F` внутри одного сегмента
   превращается в разделитель уже после матчинга. В пробе идентичный маршрут
   на том же axum вернул **200 и содержимое файла вне корня**
   (см. «Свидетельства»). Для `vibe-index` это ограничено расширением
   (обработчик требует суффикс `.json` / `.jsonl` перед join), то есть
   читается любой `*.json` относительно data-dir, но это всё равно выход за
   корень. Те же три обработчика:
   `index_files.rs:80-94` (`by-cap`), `index_files.rs:96-110` (`by-purl`),
   `index_files.rs:112-126` (`by-name`). **Локальный читатель эту форму
   повторять не должен**, и это же стоит завести как дефект `vibe-index`.

**Отказ на листинг каталога.** `ServeDir` вообще не умеет листингов — API
такого метода не имеет (`serve_dir/mod.rs:66-247`). Каталог без
`index.html` → 404 (проверено: `/static/assets/` → 404). Но по умолчанию
`append_index_html_on_directories = true`, поэтому каталог **с**
`index.html` отдаёт этот файл (`/static/` → 200), а `/static/assets` без
слэша отвечает 307-редиректом. Для читателя это надо выключать явно —
`ServeDir::new(root).append_index_html_on_directories(false)` — и отдавать
страницу только собственным маршрутом.

**Побочный факт в пользу `ServeDir` для «оболочки из store».** Он бесплатно
даёт `last-modified`, ответ 304 на `If-Modified-Since`, `accept-ranges: bytes`
и определение mime по расширению; `ETag` не выставляет. Есть
`precompressed_gzip()` — отдаёт `foo.js.gz`, если клиент принимает gzip.

### 4. Таблица маршрутов

Подписи функций `vibe-doc` предложенные (крейта ещё нет: в
`crates/vibe-cli/src/cli.rs:141-423` подкоманды `doc` нет).
`Store` — машинный store документации, lock текущего проекта или приватный
реестр (D-09); `PageRef` — координата «пакет + версия + язык + страница».

| Маршрут | Функция `vibe-doc` (предполагаемая подпись) | Что отдаёт |
|---|---|---|
| `GET /doc/<группа>/<имя>/<версия>/<lang>/<страница>` | `render_page(&Store, &PageRef, &RenderOpts) -> Result<Island>` | `text/html`: шаблон оболочки, в слот вклеен остров; заголовки CSP + `cache-control: no-store` |
| `GET /doc/…/<страница>.md` | `project_page(&Store, &PageRef, Projection::Markdown) -> Result<String>` | `text/markdown; charset=utf-8` |
| `GET /doc/…/<страница>.xml` | `project_page(&Store, &PageRef, Projection::Xml) -> Result<String>` | `application/xml; charset=utf-8` |
| `GET /doc/manifest.json` | `manifest(&Store, &ManifestQuery) -> Result<Manifest>` | `application/json`: страницы, статусы, языки, аудитории, жанры, якоря (то же значение, что печатает `vibe doc manifest --json`, §7.3) |
| `GET /doc/llms.txt`, `llms-full.txt`, `llms-small.txt`, `llms-medium.txt` | `llms(&Store, Tier, Option<Lang>, Scope::All) -> Result<String>` | `text/plain; charset=utf-8` |
| `GET /doc/<lang>/llms*.txt` | то же с `Some(lang)` | `text/plain` |
| `GET /doc/<группа>/<имя>/llms.txt` | то же со `Scope::Package(pkg)` | `text/plain`: каталог документаций пакета |
| `GET /doc/resolve?uri=spec://…` | `resolve(&Graph, &SpecUri) -> Result<Resolution>` | `application/json`: адрес + одношаговый подграф (ядро существующего `vibe explain`, `crates/vibe-cli/src/cli.rs:366`) |
| `GET /shell/<путь>` | `vibe_doc_shell::Shell::asset(&self, rel: &str) -> Option<Vec<u8>>` | статика оболочки из бинарника или из store; `cache-control: immutable` для имён с хэшем |
| `GET /healthz` | — | `{"status":"ok"}`; форма взята у `vibe-index` (`routes/health.rs:16-23`) |
| `GET /doc/what` | `Shell::provenance()` | `application/json`: что несёт сервер — встроенная оболочка, оболочка из store или запасная, плюс пин (D-12 п. 5) |

Контракт встраивания (§7.5) по сторонам:

| Сообщение | Кто исполняет | Комментарий |
|---|---|---|
| относительные адреса, базовый путь | **сервер** (параметр запуска) + клиент | базовый путь подставляется в `<base>` и в конфиг оболочки |
| `{ "open": "spec://…" }` (внутрь) | **клиент** | хост шлёт в iframe; оболочка резолвит через `GET /doc/resolve` |
| URL-фрагмент как «открой адрес» | **клиент** | без участия сервера |
| `{ "openFile": "<путь>" }` (наружу) | **клиент** | путь приходит в островe как атрибут локальной ссылки; сервер файл не открывает |
| `{ "theme": "dark" \| "light" }` | **клиент**; стартовое значение — **сервер** | тема параметром запуска попадает в конфиг оболочки |
| `{ "settings": {…} }` в обе стороны | **клиент** | сервер состояния чтения не хранит |
| `{ "prompt": "<текст>" }` (наружу) | **клиент**; текст — из острова | сервер отдаёт текст блока `prompt` внутри острова (D-30) |
| `frame-ancestors` | **сервер** | единственная часть контракта встраивания, живущая в заголовке |

Параметры запуска (базовый путь, тема, язык, origin хоста) удобнее всего
отдавать одним блоком `<script type="application/json" id="vibe-doc-config">`
внутри страницы: это не требует ни внешнего запроса, ни `'unsafe-inline'`
в `script-src`, поскольку блок не исполняется.

```rust

    let path = root().join(&name);

```

Ручной безопасный join, отбивший все три формы (`probe/src/shell.rs:59-72`):

```rust
pub fn safe_join(root: &Path, rel: &str) -> Option<PathBuf> {
    if rel.contains('\0') || rel.contains('\\') {
        return None;
    }
    let mut out = root.to_path_buf();
    for seg in rel.split('/').filter(|s| !s.is_empty() && *s != ".") {
        let mut parts = Path::new(seg).components();
        match (parts.next(), parts.next()) {
            (Some(Component::Normal(name)), None) => out.push(name),
            _ => return None,
        }
    }
    out.starts_with(root).then_some(out)
}
```

## Расхождения с решениями

Нет. Ни один факт кода не противоречит D-09, D-12 или §7.3/7.5.

Два замечания, которые решениями не покрыты и требуют решения владельца, а
не переписывания D-NN:

- `frame-ancestors` для webview VS Code: origin webview'а вида
  `vscode-webview://<uuid>` меняется от окна к окну, поэтому «origin хоста,
  который его запустил» (D-09) должен быть **параметром запуска**
  `vibe doc serve --frame-ancestor <origin>`, а не константой. Без параметра
  — `'none'`.
- CORS в `vibe-index` открыт настежь (`server/mod.rs:46-49`). Для локального
  читателя слой CORS не нужен вовсе: единственный потребитель — та же
  страница. Отсутствие `CorsLayer` строже, чем любая его настройка.

## Открытые вопросы

- Обход путей в `vibe-index` подтверждён на идентичном по форме маршруте в
  пробном крейте с той же версией axum, но **не** на живом `vibe-index`:
  бинарника `target/debug/vibe-index.exe` в дереве нет, а `cargo build`
  внутри репозитория пакетом запрещён. Проверка — один тест на
  `oneshot(req(GET, "/v1/index/by-name/..%2F..%2Fsecret.json"))` в
  `crates/vibe-index/tests/server_e2e.rs`.
- Кэширование страницы (не статики): `no-store` выбран как безопасный
  умолчательный вариант, но если остров дорого рендерить, понадобится
  `ETag` по контент-хэшу страницы из store. Стоимость рендера неизвестна —
  конвейера ещё нет.
- Нужен ли читателю `HEAD`/`Range` для крупных вложений (картинки, PDF в
  будущем). `ServeDir` их даёт, ручной обработчик — нет.
