## 2. Статический адаптер: выход, размеры, команды

Интеграция называется **`ssg`**, а не `static`:
`pnpm exec qwik add static` → `❌ Error: Invalid integration: static`.
Шаблон адаптера лежит в
`node_modules/@qwik.dev/core/dist/starters/adapters/ssg/adapters/ssg/vite.config.ts`.

Рабочий конфиг (`site/adapters/ssg/vite.config.ts`, целиком):

```ts
import { ssgAdapter } from "@qwik.dev/router/adapters/ssg/vite";
import { extendConfig } from "@qwik.dev/router/vite";
import baseConfig from "../../vite.config.ts";

export default extendConfig(baseConfig, () => {
  return {
    build: { ssr: true, rolldownOptions: { input: ["@qwik-router-config"] } },
    plugins: [ssgAdapter({ origin: "https://vibevm.example" })],
  };
});
```

Команды:

- сборка — `pnpm build` (= `qwik build`; сам находит `adapters/*/vite.config.ts`
  и запускает SSG). Скрипт `build.server` = `qwik check-client src dist && vite build -c adapters/ssg/vite.config.ts`.
- предпросмотр — `pnpm preview` (= `qwik build preview && vite preview --open`);
  для проверки именно статики поднимался собственный тупой сервер:
  `node serve-static.mjs site/dist 4181`.

## 3. Базовый путь: один на всё приложение

**Ответ на вопрос пакета: один base на всё приложение. Разбиение
`/` + `/ru/` + `/doc/…` делается структурой каталога `src/routes/`, а не base.**

Механика в 2.x изменилась: `basePathname` **убран из типов** плагина —
`QwikRouterVitePluginOptions extends Omit<PluginOptions, 'basePathname'>`
(`node_modules/@qwik.dev/router/lib/vite/index.d.ts`, объявление
`QwikRouterVitePluginOptions`). Значение берётся из собственного `base` Vite:

```js
// node_modules/@qwik.dev/router/lib/vite/index.mjs:617-618
if (typeof opts.baseUrl === "string") opts.basePathname = opts.baseUrl;
if (typeof opts.basePathname !== "string") opts.basePathname = viteBasePath;
```

Рабочая конфигурация — одна строка в `site/vite.config.ts`:

```ts
const SEG = process.env.VD_BASE;
const BASE = SEG ? `/${SEG}/` : "/";
export default defineConfig(({ command, mode }): UserConfig => {
  return { base: BASE, plugins: [qwikRouter({ … }), qwikVite(), …] };
```

**Вариант A, `base: "/"` (принят).** `src/routes/index.tsx` → `/`,
`src/routes/ru/index.tsx` → `/ru/`, `src/routes/doc/guide/index.tsx` →
`/doc/guide/`, `src/routes/doc/ru/guide/index.tsx` → `/doc/ru/guide/`.
Сгенерировано 7 страниц, файлы ложатся ровно по маршрутам. Никакой настройки
base для этого не нужно.

**Вариант B, `base: "/doc/"`.** base — это **префикс монтирования всего
приложения**, он накладывается поверх файловых маршрутов:

```
$ grep -o 'q:route="[^"]*"\|canonical" href="[^"]*"' dist/doc/guide/index.html
q:route="/doc/doc/guide"
canonical" href="https://vibevm.example/doc/doc/guide/"
$ cat dist/sitemap.xml        # выдержка
<url><loc>https://vibevm.example/doc/doc/guide/</loc></url>
<url><loc>https://vibevm.example/doc/ru/</loc></url>
```

При этом файлы на диске остаются по маршрутам без префикса
(`dist/doc/guide/index.html`), то есть выход рассчитан на монтирование каталога
`dist` в точку `/doc/` — модель согласованная, но она удваивает `doc/`, если
каталог `doc/` уже есть в `src/routes/`. Для документации под `/doc/`
отдельным приложением надо: маршруты в корне `src/routes/`, `base: "/doc/"`,
раздача `dist` из `/doc/`.

Что base **переписывает**: `q:base` (`/doc/build/`), все `modulepreload`/`src`
на чанки, путь к `assets/*-bundle-graph.json`, `canonical`, `sitemap.xml`, и
абсолютные `url(...)` внутри CSS, проходящего через Vite
(`url(/fonts/vibe-serif.woff2)` → `url(/doc/fonts/vibe-serif.woff2)`).

Что base **не переписывает**: атрибуты в JSX и `href` у `<Link>`. В сборке
с `base: "/doc/"` из `<Link href="/doc/guide/">` получилось буквальное
`href="/doc/guide/"` (а маршрут при этом `/doc/doc/guide`), а
`<link rel="icon" href="/favicon.svg">` из `src/root.tsx` осталось
`href="/favicon.svg"`. Вывод: при непустом base все ссылки и ручные абсолютные
пути надо писать уже с префиксом.

- `https://json.schemastore.org/web-manifest-combined.json` — поле `$schema`

выше — не запись сетевой панели, а полный набор адресов, объявленных разметкой

время исполнения, в чанках не найдено (`(none)` выше).

## 5. Прототип оболочки и вес состояния острова

Прототип: `<scratch>/vibe-docs-phase0\P0-O5\qwik-probe\`.
Запуск: `cd qwik-probe/site && pnpm build`, затем
`cd .. && node serve-static.mjs site/dist 4181` → `http://127.0.0.1:4181/doc/guide/`.
Разработка: `cd qwik-probe/site && pnpm dev`.

Острова (все в пакете `design`):

- `design/src/lang-switch.tsx` — переключатель языка. Работает без JS: это два
  обычных `<a>` с посчитанными на сервере адресами (`/doc/guide/` ↔
  `/doc/ru/guide/`). Остров нужен ровно для одного: **сервер не видит
  фрагмента**, поэтому `#p12` переносится обработчиком клика на клиенте.
- `design/src/reader-settings.tsx` — панель настроек чтения (кегль,
  интерлиньяж, тёмная тема) на `useSignal` + `useVisibleTask$`, пишет
  `localStorage` и CSS-переменные на `document.documentElement`.
- `design/src/toc.tsx` — оглавление: список статический, живая только отметка
  «вы здесь» через `IntersectionObserver` в `useVisibleTask$`.

API 2.x подтверждён по `node_modules/@qwik.dev/core/public.d.ts` (93 экспорта);
хуки: `useSignal useStore useComputed$ useTask$ useVisibleTask$ useOn
useOnDocument useOnWindow useContext useContextProvider useStyles$
useStylesScoped$ useResource$ useSerializer$ useConstant useId useServerData`.

Как остров выглядит в HTML (`dist/doc/guide/index.html`):

```html
<nav :="dJ_0" class="vd-bar" aria-label="language"><span :>Язык / Language:</span>
<a href="/doc/guide/" : aria-current="true" q-e:click="q-DpPehYXq.js#s_7YAzxfvw3To">EN</a>
<a href="/doc/ru/guide/" : aria-current="false" q-e:click="q-DpPehYXq.js#s_7YAzxfvw3To">RU</a></nav>
```

Обработчик вынесен в отдельный чанк `dist/build/q-DpPehYXq.js` (852 B целиком,
вместе с функцией отрисовки компонента):

```js
p=(e,t)=>{let n=globalThis.location?.hash??``;
n&&!t.href.includes(`#`)&&(e.preventDefault(),globalThis.location.assign(t.href+n))}
```

**Где в HTML сериализуется состояние.** Четыре блока в конце `<body>`, плюс
атрибуты на `<html>` (`q:container="paused"`, `q:base`, `q:route`,
`q:manifest-hash`, `q:instance`):

- `<script type="qwik/state">` — граф состояния (основной вес);
- `<script type="qwik/vnode">` — компактное описание vnode-дерева;
- `<script q:func="qwik/json">` — инлайн-функции QRL
  (`document["qFuncs_<instance>"]=[…]`);
- `<script>(window._qwikEv||(window._qwikEv=[])).push("e:click","d:qinit",…)</script>`
  — регистрация типов событий;
- плюс `<script type="module" async q:type="preload">` со списком чанков.

Измерения (`node measure.mjs`, считает байты блоков `qwik/*` целиком):

| страница | острова на странице | HTML | gzip | `qwik/state` | все `qwik/*` | доля HTML |
|---|---|---|---|---|---|---|
| `/bare/` | нет (свой `layout!.tsx`) | 10 487 B | 3 561 B | 3 074 B | 3 768 B | 35,9 % |
| `/doc/plain/` | только переключатель языка из макета | 10 378 B | 3 504 B | 2 999 B | 3 661 B | 35,3 % |
| `/doc/guide/` | + оглавление + панель настроек | 12 559 B | 4 302 B | 4 244 B | 5 251 B | 41,8 % |
| `/doc/ru/guide/` | то же, русский текст | 14 697 B | 4 507 B | 4 311 B | 5 318 B | 36,2 % |

Читается так:

- **Нуля не бывает.** Страница вообще без островов несёт 3 768 B блоков
  `qwik/*` (≈1,1 кБ в gzip): роутер (`useQwikRouter`, `useLocation`,
  `DocumentHeadTags`) сам по себе резюмируемое состояние. Это пол для любой
  страницы документации.
- Два дополнительных острова (оглавление + панель настроек) стоят
  **+1 590 B сырых** блоков состояния; вместе с их разметкой страница
  потяжелела на 2 181 B сырых и 798 B в gzip.
- Русская страница тяжелее английской на 2 138 B почти целиком за счёт
  UTF-8 кириллицы в тексте, а не состояния (разница `qwik/*` — 67 B).

## 6. Три острых угла

**Угол 1 — SSG молча генерирует не то при нестандартных настройках, и код
выхода всё равно 0.**

- `trailingSlash: false` в `qwikRouter()` → сгенерирована **одна** страница из
  семи (`- Generated: 1 page`, только `dist/index.html`), ни одной ошибки,
  `EXIT=0`. То есть единственный поддерживаемый в бете режим — адреса с
  завершающим слэшем. Комментарий в типах честно предупреждает: «Defaults to
  `true`. (Note: Previous versions defaulted to `false`)» — но обратный режим
  сломан.
- Неверный base даёт **ноль страниц** и пустой `sitemap.xml` при `EXIT=0`:
  «`SSG results` / `- Duration: 93.5 ms`» без строки `Generated`. Проверять
  сборку надо по числу файлов, а не по коду выхода.
- Перечислением маршрутов занимается `traverseRouteTree(routes, [], "/", [])`
  (`node_modules/@qwik.dev/router/lib/ssg/index.mjs`, `loadStaticRoutes`), то
  есть от жёсткого `"/"`, а фильтр строится от base:
  `createRouteTester(opts.basePathname || "/", opts.include, opts.exclude)`
  (там же, строка 30). Фильтр срезает `basePathname.length - 1` символов с
  начала пути (`lib/chunks/routes.mjs`, `createRouteTester`) — две разные
  системы координат в одном проходе.

**Угол 2 — переименования и типы, расходящиеся с рантаймом (миграция с 1.x).**

- Пакеты: `@builder.io/qwik` → `@qwik.dev/core`, `@builder.io/qwik-city` →
  `@qwik.dev/router`. Старые имена в 2.x оставлены только как `@deprecated`:
  `qwikCity`, `QwikCityPlugin`, `QwikCityVitePluginOptions`, `staticAdapter`
  (`lib/vite/index.d.ts`, `lib/adapters/ssg/vite/index.d.ts`).
- Интеграция CLI переименована `static` → `ssg`; `qwik add static` падает с
  `Invalid integration: static`. При этом путь импорта
  `@qwik.dev/router/adapters/static/vite` работает (алиас на `ssg`).
- `basePathname` **удалён из типов** плагина, но продолжает читаться в
  рантайме (`index.mjs:617`). Документация ведёт к `basePathname`, типы — нет,
  фактический рычаг — `base` у Vite. Недокументированное расхождение.
- Сборка на Vite 8/rolldown: в конфиге адаптера `rolldownOptions`, а не
  `rollupOptions`. Пакет `@qwik.dev/optimizer` едет по своей линии версий
  (`2.1.0-beta.8` при ядре `2.0.0-beta.43`).
- `qwik add <x> --yes` **не** пропускает подтверждение — CLI всё равно ждёт
  TTY, в неинтерактивной среде ничего не создаёт и возвращает 0. Конфиг
  адаптера пришлось положить руками.
- `pnpm install` на чистом клоне завершается с **кодом 1**:
  `[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: @parcel/watcher@2.6.0,
  sharp@0.34.5`. Нужен явный `allowBuilds` в `pnpm-workspace.yaml` (pnpm сам
  дописывает туда заготовку). Со `sharp: false` и `@parcel/watcher: false`
  сборка проходит полностью — оба нужны только оптимизации картинок и вотчеру.

**Угол 3 — в выход попадает лишнее, и часть путей не переписывается.**

- `dist/q-manifest.json`, 54 707 B — метаданные оптимизатора в публичном
  каталоге; ни одна страница их не запрашивает. 18 % веса `dist`.
- `public/manifest.json` из стартера тянет `$schema` на `schemastore.org`, а
  ядро — адрес `qwikdev-build-v2.qwik-8nx.pages.dev` в тексте ошибок (§4).
- `<Link href>` и абсолютные пути в JSX не получают префикс base, тогда как
  `url()` в CSS — получает (§3). Итог: под непустым base ссылки надо писать
  вручную с префиксом, и это не проверяется ни типами, ни сборкой.
- Отдельно, **не вина Qwik, но ловушка на этой машине**: Git Bash (MSYS2)
  переписывает всё, что похоже на POSIX-путь, и в аргументах, и в переменных
  окружения. `VD_BASE=/doc/ pnpm build` доехало до SSG как
  `"basePathname": "/Program%20Files/Git/doc/"` (видно в сгенерированном
  `node_modules/.cache/qwik-router-ssg-*/run-ssg.js`, сохраняется флагом
  `QWIK_ROUTER_KEEP_SSG_BUILD=1`). Любой сценарий развёртывания, передающий
  базовый путь строкой, должен это учитывать.

## 7. Соображения для встроенного адаптера (Rust-сервер без Node)

Что статический сервер обязан уметь, чтобы отдать этот же выход:

1. **Индексы каталогов.** Каждый маршрут — `<путь>/index.html`. Запрос
   `/doc/guide/` → `dist/doc/guide/index.html`.
2. **Редирект на завершающий слэш.** `trailingSlash: true` — единственный
   рабочий режим (§6). `/doc/guide` обязан отвечать 301/308 на `/doc/guide/`,
   иначе относительные пути в документе разъедутся. В пробном сервере это
   `serve-static.mjs` строки с `res.writeHead(308, { location: p + "/" })`.
3. **Правильные MIME.** Модульные скрипты браузер не исполнит без
   JS-типа: `text/javascript` для `/build/*.js`, `application/json` для
   `/assets/*-bundle-graph.json` (он подгружается как
   `<link rel="preload" as="fetch" crossorigin="anonymous">` и затем `fetch`),
   `text/css`, `font/woff2`, `image/svg+xml`, `application/xml` для sitemap.
4. **Заголовки кэша.** `/build/**` и `/assets/**` — имена с хэшем, можно
   `Cache-Control: public, max-age=31536000, immutable`; HTML —
   `max-age=0, must-revalidate`. Это же требует README адаптера.
5. **Диапазоны и HEAD** для шрифтов — обычная гигиена статики.
6. **404.** Файл `404.html` генерируется только если в `src/routes/` есть
   маршрут 404 (`addToQueue(dirPathname + "404.html")` в `lib/ssg/index.mjs`
   срабатывает по узлам `_4`/`_E`); в пробе такого маршрута нет, и файла нет.
   Встроенному серверу нужен свой ответ на неизвестный путь.
7. **Никакого SSR, куки, эндпоинтов.** Пока в маршрутах нет `routeLoader$`,
   `routeAction$`, `server$` и `onRequest`, серверу не нужно ничего, кроме
   отдачи файлов. Конвенции `q-data.json` из 1.x в выходе нет: переходы SPA в
   2.x тянут чанк маршрута из `/build/` (`fetch(d, {signal, cache, headers})`
   в клиентском чанке), то есть снова обычный статический файл.
8. **Заголовок `X-Qwik-fullpath`.** Клиент способен его отправлять (строка
   найдена в `dist/build/*.js`); сервер должен его игнорировать, но кэш,
   ключующийся только по URL, обязан о нём знать.
9. **База.** Если встроенный сервер монтирует документацию под `/doc/`,
   собирать надо отдельной конфигурацией с `base: "/doc/"` и маршрутами в
   корне `src/routes/`, а раздавать `dist` из `/doc/` (§3). Смешивать в одном
   выходе корневой лендинг и документацию под непустым base нельзя.
10. **Отсекать от раздачи** `q-manifest.json` (54 кБ метаданных) и, при
    желании, `manifest.json`/`sitemap.xml`, если встроенный сервер отдаёт
    только документацию.

## 8. Расхождения с решениями

Нет. Все требования пакета проверены и выполнимы на Qwik `2.0.0-beta.43`:
одно приложение, два пакета в pnpm-workspace, статический адаптер, острова,
собственные шрифты, отсутствие чужих CDN. Единственная поправка к постановке
не является расхождением с решением: «настраиваемый базовый путь» в Qwik — это
**один** префикс на всё приложение; раздельные `/`, `/ru/` и `/doc/…` в одном
выходе достигаются структурой `src/routes/`, при `base: "/"`.

## 9. Открытые вопросы

1. **Живой браузер не запускался.** Панель Browser не пускает к локальному
   серверу, расширение Chrome не подключено. Поэтому §4 — проигранный набор
   объявленных адресов, а не запись сетевой панели; и перенос `#p12`
   переключателем языка подтверждён по коду выпущенного чанка и по разметке
   (`q-e:click="q-DpPehYXq.js#s_7YAzxfvw3To"`), но не кликом в браузере.
   Нужна отдельная проверка на машине с браузером: клик RU на
   `/doc/guide/#p12` должен привести на `/doc/ru/guide/#p12`.
2. **`trailingSlash: false` сломан** — не проверено, баг это беты или
   намеренное сужение. Стоит завести вопрос в апстриме перед тем, как
   закладываться на адреса без слэша.
3. **Почему `pnpm --version` внутри рабочего пространства даёт 11.24.0**, а
   снаружи 10.33.2, установить не удалось: ни `packageManager`, ни `.npmrc`,
   ни `engines` в пакетах нет. Это машинная особенность, но воспроизводимость
   сборки она задевает.
4. **MDX.** `qwikRouter()` принимает `mdx`/`mdxPlugins` (в зависимостях уже
   есть `@mdx-js/mdx`, `remark-gfm`, `rehype-*`), но на этой пробе MDX не
   проверялся — а именно он будет нести документацию.
5. **Стабильность беты.** `2.0.0-beta.43` при `create-qwik@latest = 1.20.0`:
   двойка ещё не рекомендуется по умолчанию. Срок выхода 2.0 стабильной не
   выяснялся.
