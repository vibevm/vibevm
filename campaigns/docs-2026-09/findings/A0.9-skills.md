## Ответы

**Где живёт текст встроенного скилла `vibevm` и как он попадает в бинарник.**
Файл `crates/vibe-mcp/src/skill_template.md`. Он вендорится в бинарник на
этапе компиляции через `include_str!` в `crates/vibe-mcp/src/install.rs:25`:
`pub const SKILL_TEMPLATE: &str = include_str!("skill_template.md");`.
Подстановок в шаблоне нет (ships verbatim) — байты идентичны тому, что видит
агент. Тест `crates/vibe-mcp/src/install.rs:181-195`
(`skill_template_carries_its_contract`) и
`crates/vibe-mcp/src/install.rs:203-215`
(`every_served_tool_is_named_in_the_skill_template`) пином удерживают
контракт содержимого (обязательные подстроки, каждый MCP-инструмент из
`default_tools()` должен быть назван в шаблоне).

**В какие каталоги проецирует `vibe skill install`.** Единственное место,
знающее целевые каталоги — `Agent::skill_path` /
`crates/vibe-agent-projection/src/agents.rs:317-410`; CLI
(`crates/vibe-cli/src/commands/skill/mod.rs`) и MCP-путь установки
(`crates/vibe-mcp/src/install.rs::install_skill`, строка 91:
`agent.skill_path(scope, project_root)?`) только вызывают его.

- Claude Code: project → `<project_root>/.claude/skills/<name>/SKILL.md`;
  user → `<home>/.claude/skills/<name>/SKILL.md` (`agents.rs:324-330`,
  `agents.rs:345-353`).
- OpenCode: project → `<project_root>/.opencode/skills/<name>/SKILL.md`;
  user → `<home>/.config/opencode/skills/<name>/SKILL.md` — намеренно
  XDG-путь даже на Windows, НЕ `%APPDATA%` (комментарий `agents.rs:280-289`
  указывает, что это проверено эмпирически) (`agents.rs:331-336`,
  `agents.rs:354-367`).
- Codex: project → `<project_root>/.agents/skills/<name>/SKILL.md`; user →
  `<home>/.agents/skills/<name>/SKILL.md` (`agents.rs:337-341`,
  `agents.rs:368-376`).
- Cursor и Claude Code Desktop: всегда `Ok(None)` — `supports_skill()`
  (`agents.rs:233-238`) возвращает `false` для обоих: у Cursor
  JSON-config-only конфигурация, у Desktop — GUI-конфиг, файлового
  загрузчика скиллов нет.
- Имя каталога-скилла для builtin — константа
  `SKILL_NAME: &str = "vibevm"` (`agents.rs:128`); для пакетных скиллов имя
  берётся из `SkillDecl.name`.

**Как объявляется `[[skill]]` с `path` в `vibe.toml`.** Структура `SkillDecl`
— `crates/vibe-core/src/manifest/package/skill.rs:61-94`. Поля: `name:
String` (обязательное, kebab-case ≤64 байт — имя каталога
`.<agent>/skills/<name>/`), `path: PathBuf` (обязательное, относительно
корня пакета — файл/каталог с телом скилла), `source: Option<String>`
(опц., имя `[[embedded_source]]`), `description: Option<String>` (опц.),
`agents: Vec<String>` (опц., пусто = все агенты с `supports_skill() ==
true`), `include: Vec<String>` (опц., glob-паттерны, пусто = всё поддерево
`path`), `resources: Vec<SkillResourceDecl>` (опц., `[[skill.resource]]`).
Пример из in-tree пакета,
`vibevm/vibepacks/org.vibevm.ai-native/rust-ai-native-lang/v1.0.0/vibe.toml:56-59`:

```toml
[[skill]]
name = "rust-ai-native-sweep"
path = "vibevm/vibespecs/skills/rust-ai-native-sweep"
description = "The recurring AI-Native discipline sweep: floor gates, ..."
```

**Путь скилла в doc-пакете (по образцу существующих).** По тому же паттерну
(`path = "vibevm/vibespecs/skills/<name>"` внутри пакета) doc-пакет должен
держать тело скилла в собственном дереве, например
`vibevm/vibespecs/skills/<имя-doc-пакета>/SKILL.md`, и объявить в своём
`vibe.toml`:

```toml
[[skill]]
name = "<имя-doc-пакета>"
path = "vibevm/vibespecs/skills/<имя-doc-пакета>"
description = "..."
```

**Способ добавить одну строку во встроенный `vibevm` (файл, место).** Файл —
`crates/vibe-mcp/src/skill_template.md` (не сам doc-пакет: это
скомпилированная в `vibe-mcp` константа, `crates/`). Строка добавляется
прямо в тело markdown-шаблона (естественное место — новый короткий абзац
рядом с началом, после вступления, например в духе "project-specific
documentation for vibevm lives in the `<doc-package>` skill/package — see
…"); правки требуют пересборки `vibe-mcp`/`vibe-cli` и не должны ломать
существующие ассерты в `crates/vibe-mcp/src/install.rs:181-243` (они
проверяют наличие подстрок, а не отсутствие новых). Это правка в `crates/`
— вне рабочего дерева задачи, только фиксирую расположение.

## Открытые вопросы

- Итоговое имя скилла doc-пакета (совпадает ли с именем самого пакета,
  например `vibevm-docs`) этим спайком не зафиксировано — задание просит
  только путь по образцу, не точное имя.
- `SKILL_TEMPLATE` — один безусловный скомпилированный `&str`; в отличие от
  `[[boot_snippet.fragment]]` у пакетных манифестов, у него нет механизма
  `when = "installed:<pkg>"`. Как сделать "одну строку" в builtin-скилле
  условной (показывать её только когда doc-пакет установлен), а не всегда —
  вне кода, прочитанного в этом спайке; возможно, ответ не нужен и строка
  просто безусловна ("see docs if you have them installed").
