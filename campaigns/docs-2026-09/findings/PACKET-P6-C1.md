## Что аудитировать (`MAINTENANCE.md` §2.3 п. 2, зона `campaigns/docs-2026-09/`)

Пакет руководства: `vibevm/vibepacks/org.vibevm.core/vibevm-docs/v0.1.0/`
(страницы — `vibevm/vibespecs/**/*.xml`, глоссарий —
`vibevm/vibespecs/glossary/index.xml`, манифест страниц — собери
`target/debug/vibe.exe doc manifest --json --path <пакет>`). Бинарник
дерева собран: `target/debug/vibe.exe`.

1. **Команды.** `target/debug/vibe.exe --help` и `--help` каждой
   команды верхнего уровня (список — из `vibe --help`): у каждой ли
   команды есть страница, которая её выводит (`<derived kind="cli-help"
   ref="vibe <команда> --help"/>` в `reference/commands.xml` или другой
   странице) или рассказывает (упоминание в прозе с `rule`). Отдельно:
   подкоманды второго уровня (`vibe doc build`, `vibe mcp install`, …) —
   какие упомянуты в прозе, какие нигде (X-046: третий уровень `--help`
   не выводится — это известно; нужен список).
2. **Поля манифеста и lock-файла.** `target/debug/vibe.exe doc surface
   --record probe --path <пакет> --out <scratch>` (или как называется
   запись снимка — смотри `vibe doc surface --help`) даёт список полей;
   какие поля `vibe.toml` не названы ни на одной странице (grep по
   страницам с учётом `reference/manifest.xml`, где часть выводится
   `derived` из схем — эти считаются покрытыми).
3. **Виды пакетов.** Восемь видов из `VIBEVM-SPEC.md` §4.1 — у каждого
   есть страница или раздел (`model/packages-and-kinds.xml` и авторские
   страницы).
4. **Глоссарий: одно слово — одно значение.** Для каждого термина
   глоссария — есть ли на страницах употребления в другом смысле
   (пример из журнала: `fact` в обычном смысле, `index` как `INDEX.md`,
   `store` как файл настроек); синонимы одного понятия (два слова для
   одного — `manual`/`documentation`, `registry`/`catalogue`, …) —
   список с примерами страниц и `pNN` (номера блоков печатает
   `target/debug/vibe.exe doc build --format md --out <scratch>` — в
   md-проекции каждый блок начинается с `[pNN]`).
5. **Лестница.** Термин впервые введён там, где его ищут: для десяти
   самых частых терминов — какая страница вводит термин первой по
   порядку навигации (манифест страниц), и совпадает ли это с
   глоссарной статьёй и с ожиданием читателя-новичка.
6. **Дубли и мёртвые страницы.** Пары страниц, рассказывающих одно и то
   же (по совпадению цитируемых `rule` — считай пересечение множеств
   `spec://` адресов по страницам, порог 60 %); страницы, на которые не
   ссылается ни одна другая страница и ни одна полка навигации.
7. **Бюджеты `llms`.** Размер `llms-small.txt`, `llms-medium.txt`,
   `llms-full.txt` из `vibe doc build --format md` в словах и в
   приблизительных токенах (слова × 1,3); сравни с бюджетами, которые
   называет PROP-057 `##SEO-LLMS-FILES` и соседние факты (найди числа в
   `vibevm/vibespecs/common/PROP-057-documentation-packages-and-site.xml`;
   если бюджет не назван числом — так и напиши).
8. **Промпты.** Не прогонять (нужен агент); только перечислить 20
   промптов страниц с их `assert`-командами и отметить те, чьи
   `assert` ссылаются на команды, которых нет в `vibe --help`.

## Форма отчёта

Заголовок, дата, бинарник (`vibe --version`); по пункту — таблица
находок с адресом (`страница#секция` или `pNN`), числом и предложением
(«правка», «долг `docs:` с severity», «наблюдение без действия: причина»);
в конце — восемь чисел одной таблицей (сколько команд без страницы,
полей, видов, терминов в чужом смысле, синонимов, дублей, мёртвых
страниц, превышений бюджета). Пиши по-русски, коротко, без рекомендаций
общего характера.
