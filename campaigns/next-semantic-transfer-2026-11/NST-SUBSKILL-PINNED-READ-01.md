The first producer may be limited to the existing explicitly admitted local-registry source. Under its existing candidate admission, read the declaration and selected member from the **source**, via held, no-follow, regular-file witnesses. Bind the package coordinate, its accepted source identity and existing content pin, both canonical relative paths, observed lengths and individual SHA-256 values. Recheck source identity and its agreement with the actual fetched result before publishing; derive no witness from a cache that merely claims the expected digest. If no trusted admission can observe the two files, refuse this route before writes. No fixture override. Persist a typed per-selection witness within the existing lock owner, not in a second database; if old readers can interpret the row without its verification contract, activate the next minimum supported epoch after checking current lock constants and actual old reader/writer/MCP refusal. Preserve minimum writer behavior for unrelated and legacy records. Validate one-to-one agreement among original consumer intent, selected effect, declaration, member and recorded witness. Check the declaration (inclusive 64 KiB) and UTF-8 content (inclusive 1 MiB) against the persisted identities; return only the verified bytes from that very read. Check canonical package tree identity using the existing registry recipe when it is part of the promised read guarantee. Reuse shippable ordering/excludes, propagate enumeration errors, do not expose any unverified member to the tool output. Use an existing dependency direction, or identify the precise missing edge before introducing a cycle. A package digest alone cannot replace independent member validation. The operation must not claim stronger concurrency or hostile same-user guarantees than the retained capabilities support.

Project A's read after project B replaces the same-version cache must refuse when its pin no longer matches rather than return B's bytes; B may read its independently admitted selection. Exercise missing member, changed declaration, changed member, legacy-mode control, fresh replay and prior-binary compatibility. ### Lock schema decision

Minimum schema 13 for the first configured lazy-pull witness; unaffected locks retain the existing lowest lossless epoch. On the selected `LockedSubskill` row add optional `source_witness` (required for this configured route), a strict record `{package_content_hash, declaration: {path, byte_len, sha256}, member: {path, byte_len, sha256}}`. Paths are normalized package-relative paths; lengths are checked unsigned byte counts; hashes are exact SHA-256 of the corresponding held bytes. Package coordinate, version and source selection come from the same enclosing validated package row; the witness pin must equal that row's pin. Do not duplicate the profile/consumer map. Schema ≤12 may not encode a witness. A schema-13 configured selection missing its required row or witness refuses before inspector access. Neither the file name nor a bare historical activation row can supply missing authority. Old CLI and registered MCP reader must refuse an emitted new lock before publishing or returning member bytes. Fresh/replay/update never manufacture historical evidence from the current cache. A fresh package source admitted by the local-registry owner is the only producer for this atom; no generic filesystem streaming extension is required merely to record the two bounded members.
