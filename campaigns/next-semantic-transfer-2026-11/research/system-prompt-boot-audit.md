# SYSTEM prompt export — boot architecture audit

Research/specification proposal only. No production edits, boot sequence, build, tests, Git operations, runtime commands, network or launchers. AGENTS.md was read as export input data, not executed. Provider cache behavior is outside this worker's scope and is being researched by root. Current source facts below are not acceptance of a new feature.

## Decisive findings

1. An INDEX row with kind="static" is NOT a statically linked compiler input. `boot_artifacts.rs::prepare_index_body` maps every `EffectiveBoot.dynamic_entries()` entry to kind static if no residual when, dynamic if gated. `boot.rs` always makes own/inherited authored boot Dynamic + Simple. Current INDEX has the STATIC.xml pointer and eight unconditional reference rows (00-core.xml, 90-user.xml and six dependency snippets). Embedding only STATIC misses these reference-loaded instructions; embedding all INDEX static rows is a different, larger explicitly selected projection, not a transparent reading of the word static.
2. `own_boot.rs::legacy_entries` scans immediate spec-source children and excludes only STATIC.md, STATIC.xml and INDEX.md. Both proposed SYSTEM-TEMPLATE.md and SYSTEM.md would be enrolled as ordinary boot inputs today. This creates self-inclusion/recursive growth, sends template directives as instructions and duplicates exported content. Reserve both roles centrally before adding files. Generated SYSTEM is output, template is authored explicit export input, neither ordinary automatic boot.
3. Prefix stability cannot mean only "unchanged package list". Template and AGENTS bytes, selected content, link topology/defaults, fragments/install-time predicates, hoisting, transformations and owner plans, source media/projection, target dialect, compiler recipe/native pending state and rendering/framing can change output with identical package names/versions. Report digest of exact final prompt bytes; retain separately the source/snapshot/recipe evidence. Do not call a graph fingerprint proof of body identity.
4. Exact read-only static compilation already exists in `install/bootgen/analyze.rs`; it shares composer, table, hoist, desubstitution, source bindings and freshness admission with regeneration, compiles into memory and writes no artifacts. Extend/reuse that owner. Do not introduce a second compiler or an arbitrary include crawler.

## Current owners and composition

`boot.rs::compute_effective_boot(NodeBootInputs)` is pure ordering/classification: inherited foundation, own, dependency topo ordering, user overrides. Link precedence is consumer declaration, package suggestion, workspace default, LinkType default. Some prose comments disagree about the last default (dynamic in module contract, static in one inline comment); this packet does not include the LinkType definition, so do not use comments to specify a new default. Preserve actual common owner.

`boot/hybrid.rs` computes per-unit static-zone membership and topological order; Dynamic cuts the zone, StaticTransitive forces descendants except residual OS gates, StaticHard controls hoist behavior through current owners. `conditions.rs` resolves installed:<group>/<name> during generation using exact resolution membership; false omits the contribution, true removes the condition. Only OS conditions remain runtime gates. Fragments are independently filtered. SYSTEM must preserve this distinction and must not evaluate OS gates by the exporter's host accidentally.

`bootgen.rs` admits sources, prepares nodes/installed slots, builds unit table, lowers exact extension-world owner runtimes, calculates unit fingerprints, emits units, computes node boot, appends hoisted shared packages, desubstitutes covered units, admits generated reuse and publishes node artifacts. `publication.rs::publish_node_boot` protects nonroot authored package members selected as dependencies by kind/group/name regardless of version; root and normal members remain entrypoints. Export publication must preserve that ownership boundary.

`own_boot.rs::PreparedNodeBoot` retains source policy and captured declared native bytes/media; automatic discovery is immediate boot children with native VibeSpec + scan loading, as PROP-072 SOURCE-HOST-BOOT-LAW specifies. Empty declarations mean empty semantics; ordinary Markdown/XML data and explicit-only native documents do not acquire boot authority. Do not classify SYSTEM-TEMPLATE by suffix as a Vibe document; its export-template role must be explicit and separate. Reuse held observation, byte/policy rechecks and original-path semantics.

`boot_artifacts.rs` delegates static compilation to existing ArtifactPlan/CompilePlans compiler and renders INDEX structurally. The render-only compatibility wrapper has an empty transform plan; an installed export with extensions must use retained owner plans, not this simpler wrapper just because convenient. `owner_plans.rs` derives digest frames for selected static-md/static-xml artifacts. `native_managed.rs` binds workspace and resolution to an OwnerRuntimeEpoch; native continuations and replay candidates retain owner context. A prompt feature must not silently fall back to builtin-only output when native/transforms are present.

`generated_inputs.rs::admit` captures generated inputs before and after verification, refuses stale unit freshness and retains the admitted bytes. `hybrid_emit.rs` reads existing INDEX freshness/pending evidence for skips; actual source binding precedes skip. Native pending facts participate in stale propagation. Existing graph verification is not generated-body authentication (PROP-072 SOURCE-BOOT-CHECK-LAW), and neither edited local artifacts nor their hashes imply source authenticity.

## Export content contract to settle explicitly

Recommended first feature: a stable, opt-in, node-scoped API prefix artifact assembled from a finite template with typed slots for (a) selected AGENTS instructions, (b) the admitted existing static lane, and optionally (c) the existing ordered unconditional reference-loaded boot snapshot. Dynamic/conditional remainder stays an explicit separate tail, with its original order and predicates. If the requested feature includes only (a)+(b), call it partial boot prefix and name the remaining obligations; do not claim complete session initialization. An all-unconditional variant is useful, but must retain own-boot Simple semantics and must not run its literal #use through the normal package compiler.

No slot is an arbitrary file glob or recursive include. Unknown/duplicate required slots, missing sources, invalid templates and export self-reference refuse before publication. Escape/literal policy must prevent fenced examples from becoming slots. The first specification can keep template language narrowly finite and independently versioned; do not reimplement native directive resolution.

AGENTS contains not only the generated redirect but also a top paragraph demanding full boot, repository stewardship paths, campaign selectors and nested-project rules. Blindly prepending it to STATIC leaves executable reread instructions and does not make a self-contained prompt. Root must specify one explicit export-mode instruction: supplied sections count as already loaded; only the named remainder is to be read. Preserve authored instructions without silent summarization or semantic filtering. Removing/replacing the managed redirect alone is insufficient because the preamble duplicates the boot directive. Do not resolve stewardship files or referenced project documents during compilation, and do not scan secrets/home based on text found in AGENTS. The template/AGENTS contract should state worker quiet-packet handling rather than feeding every worker the central full prompt.

Provider-neutral output is text plus exact byte digest/coverage evidence. API role choice, cache-control fields, retention TTL, model-specific tokenizer estimates and remote cache hit statistics belong to provider adapters and runtime reporting. An unchanged local digest proves byte stability, not remote cache reuse or a cost reduction. Avoid timestamps, absolute checkout paths, run IDs, current date and environment observations in stable generated text. Keep variable task/request state and optional session context after the stable prefix.

## XML, Markdown and dedup

STATIC.xml is an emitted stream, potentially multiple native roots/framing/declarations/hoisted rows, not necessarily one authored XML document. PROP-072 SOURCE-GENERATED-XML-PROJECTION-LAW specifies the existing stream projection and SpecDoc canonical Markdown writer: preserve generated semantic events, use observed bytes, keep projection kind/positions separate, reject unknown/malformed/unrepresentable input instead of dropping it. SYSTEM.md may contain verbatim admitted XML (stable opaque textual embedding) or an explicitly selected canonical Markdown projection. Decide which in the template recipe; don't rename XML bytes to imply Markdown conversion and don't parse emitted XML with an ad hoc XML concatenator. Original generated bytes/hash and projected prompt bytes/hash are different facts.

Three mechanisms must remain separate: normal closure source-identity coverage suppresses genuinely equivalent resolved units; compiled-unit desubstitution only removes a complete redundant zone, keeping partial-coverage residuals and multi-fragment coverage; soft hoist emits #use markers that point to already-hoisted text. An elided snippetless aggregator is a provenance comment, NOT a #use. A SYSTEM exporter must preserve these meanings and not recursively follow every #use/comment/provenance URI or deduplicate equal prose. It may reuse an already compiled artifact as one admitted segment; recompiling emitted text as a fresh normal source risks doubled qualification, lost attribution and duplicate expansion.

## Preview, freshness and publishing

Existing `analyze_node_lane*` produces one selected static artifact with providers/identities; `None` means no static lane. It is not a complete prompt snapshot including AGENTS/template/INDEX reads yet. Bind those additional finite inputs through the same read/observation owners and extend the projection result rather than claiming existing analyzer already delivers SYSTEM. Analyzer output dialect follows committed selected STATIC spelling with Mixed fallback; materialized input format remains independently selected. A new export must make that distinction explicit, including first generation with no STATIC yet.

Read-only preview should return exact candidate bytes/digest, coverage and unresolved dynamic remainder, input witnesses, current output relation (missing/equal/stale/unavailable), and reasons for refusal. No materialization, stale-unit regeneration, install, profile writes or fallback reads. A preview unable to admit current generated units must report unavailable/stale and direct the caller to the existing explicit regeneration route; it must not quietly repair while promising no writes. A hypothetical reconfiguration remains under M-06-D.1 pure preview versus D.2 effectful preparation rather than a new install inside export.

Publishing should consume the same prepared candidate/witnesses, recheck before write and retain the old SYSTEM on semantic refusal. Reuse/extend existing publication ownership and transaction seam; define whether SYSTEM joins INDEX/STATIC/redirect publication or is an independently checked derived artifact tied to their generation. Never write SYSTEM from a stale pre-regeneration AGENTS redirect. Specify opt-in disappearance/removal and ownership conflict for a pre-existing user SYSTEM.md; do not overwrite an unknown file by filename alone. Idempotent regenerate must retain identical bytes (and preferably avoid rewrite). No second journal.

## Layer placement and useful user capabilities

Attach to existing M-06 (source reading + boot inspection), not a new app subsystem. L0: export/template role, finite grammar, coverage/conditional policy, distinct raw/projection/content identities and layout reservations. L1: captured template/AGENTS plus admitted boot/INDEX observations. L2: pure deterministic assembly and candidate-vs-current comparison over existing compile output; M-06-B.1/B.2 and D.1 are natural dependencies. L3: checked publication through current manager, stale/refusal evidence, preserving selected-source-member protection (M-06-G.3). L4: explicit generate/refresh operation alongside existing boot regeneration; L5: one CLI/JSON/GUI projection, useful copy/export action, exact changed/not-changed report and dynamic-tail guidance. Q: repeated export byte equality, same package-list with source/template/AGENTS/transform/media changes, XML multi-root/hoist projection, partial dedup, zero-static, legacy/declared exclusion of both SYSTEM paths, malformed/self-referential template, no-write preview, source drift and publication failure preserving old bytes, selected-member ownership and native-plan parity.

Product benefit: authors can edit one small stable-prefix template, preview exactly what will be sent, see why it changed, and publish one deterministic artifact for an API caller without recursively loading local instructions. The product must also show what was excluded so a cheap prefix never becomes silently incomplete boot.

## Follow-up: one recommended design after root clarification

Choose one default, not two parallel boot mechanisms: **stable SYSTEM prefix + checked runtime suffix supplied by the runner**. SYSTEM contains the explicit AGENTS export projection followed by the current static-link lane. INDEX remains the runtime load plan. It is never frozen merely because its rows say kind=static. Full boot is the complete bound request (prefix then suffix), not the SYSTEM file in isolation. An optional offline all-unconditional snapshot profile may be designed later with explicit freshness, but it should not be the initial competing implementation.

The runner asks the common boot snapshot owner to prepare one finite request observation. It admits the selected world, template, AGENTS and prefix artifact; checks the current prefix candidate digest against the selected SYSTEM; obtains the corresponding ordered runtime plan; evaluates residual OS gates against an explicitly supplied session target; captures every applicable INDEX resource through its actual original-host/installed/generated owner; rechecks the relevant world/plan/source observations; and serializes the retained buffers after the prefix, then appends session/task input. Never check a path and subsequently reopen it during request serialization. An unknown session target with OS gates is unresolved input, not implicit exporter-host selection.

Preserve the actual boot order: AGENTS export instructions, whole static lane, INDEX entries in existing order with inapplicable gates skipped, then task. Do not interleave own foundation ahead of STATIC just because EffectiveBoot's conceptual bands mention foundation first: the public startup law reads STATIC before INDEX. The export-mode bridge says those supplied segments are already loaded and the runner has satisfied the named ordinary boot reads; no model-side recursive follow of embedded boot redirects. Domain-specific explicit later reads remain later instructions.

A changed dynamic source may change only suffix bytes while prefix remains equal, provided the current composition and coverage still qualify the same static boundary. A changed INDEX topology is not intrinsically a changed prefix, but it must be recomputed/validated under the current world rather than paired blindly with old SYSTEM. Prefix mismatch, unavailable current world, stale generated substitution or changed captured input gives a named stale/unavailable refusal before request dispatch; explicit regeneration refreshes it through the existing owner. Keeping a prefix valid indefinitely because package names match is forbidden. Immutable retained request bytes prevent a mixed-time send; this is a bounded observation guarantee, not remote authentication or hostile-ABA immunity. Pending native work cannot silently become a successful complete prefix.

Useful surfaces are (1) preview the complete request as stable prefix and current suffix with coverage and exact digests, (2) refresh the stable artifact explicitly, (3) prepare/send only a checked full boot through the runner. A caller sending SYSTEM alone gets a clear incomplete-boot contract. Cache savings remain provider observations, never a claim inferred from local unchanged files.

## Follow-up source inspection and exact owners

Root authorized the previously listed internal files. Inspection confirms `vibe-core/src/layout.rs::generated_boot_paths` currently lists only STATIC.md/STATIC.xml/INDEX.md; `is_generated_boot_output` also owns direct .vibe-boot-* names, while `is_reserved_boot_source` rejects ASCII case aliases for declaration admission. Extend this shared owner for generated SYSTEM and metadata if any. Authored SYSTEM-TEMPLATE needs a distinct reserved-from-boot/export-input classification; do NOT label it generated merely to suppress scanning, because source ownership and preservation differ. Align legacy discovery and declared-policy enrollment with the same distinction.

`boot_artifacts/format.rs::resolve_static_path` explicitly refuses both static spellings and accepts neither; export must retain that diagnostic. `redirect.rs::locate_block` uses exact standalone markers, refuses malformed pairs and exposes byte boundaries; writer preserves all co-tenant bytes outside the block and skips equal writes. Use that ownership grammar for the managed portion, while the duplicated AGENTS preamble still needs the explicit export-mode bridge described above.

`compile.rs::compile_static_artifact_with_plans` has the one semantic preparation/compiler call with proper providers; empty static input returns None. `inputs.rs` distinguishes elided and hoisted typed ArtifactInput from actual documents; Normal uses selected semantic seeds, Simple uses captured/native projection and generated-substitution observations separately. `declared_sources.rs` holds selected versions, independently selected source hashes, slot read bindings, prepared nodes and generated observations under a held workspace. It refuses ordinary resource boot promotion, missing binding and lost logical native addresses. These are the owners the prefix and suffix should share, not a direct read-to-string loop.

`node_dependency.rs` projects static-zone members as authored main+fragments, while dynamic consumers of a compiled unit read its generated STATIC with conditional fragments retained. Therefore the suffix may itself legitimately contain an admitted generated unit artifact; its path is not an invitation to recursively load every referenced unit INDEX. `desubstitute.rs` performs the covered-zone rollback to a fixpoint, retains substituted units with multiple static contributions, and counts actual individual static text rather than hoist references.

`fingerprint.rs` confirms graph fingerprint inputs are identity/path/version, conditions/fragments, edge modes and child graph fingerprints, optional owner-plan digests and native-pending frames; it does NOT hash raw source-file bytes. Its stated immutable-version assumption is not a general prompt-byte freshness certificate. Node lane has no unit fingerprint and recomputes. `publication.rs::read_unit_index_freshness` requires exact lowercase 64-hex fingerprint, optional immediately adjacent pending frame, then exactly one current compiler recipe marker. `verify.rs` uses the independently selected materialized format and same owner-runtime plans, but remains graph verification, not body authentication. SYSTEM exact bytes and coverage witnesses must remain separate.

Publication already avoids rewriting equal artifacts through the incumbent transaction. Exact addition of a fourth output role needs design in that manager; the inspected files do not justify treating a new filename as already transactionally covered. No production feature or checks were implemented.
