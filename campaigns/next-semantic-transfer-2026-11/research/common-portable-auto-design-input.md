## Exact existing seam

`operations/planning.rs::plan_option_with_modes` builds the requirement callback for `steps::plan`. For fresh planning it calls `deps::resolve_requirement(ctx,index,owner,spelling,scope,step,accept_license)`; for retained planning it first looks up `operation.children` by authored requirement plus step and calls `pending::resolve_binding`. This is the correct dispatch point for an optional finite imported binding context. It must remain absent for ordinary installs.

`operations/deps.rs::resolve_requirement` parses the authored range, then **first** selects the newest non-superseded installed matching version. Only after no installed match does it call the package resolver and select the default host installer. Therefore wrapping `ctx.resolver` alone cannot enforce an imported exact version/configuration: an installed different satisfying version bypasses it completely. The imported binding must be checked before that shortcut. The function already receives parent owner, spelling, scope and step, so it can identify the precise requiring edge without a new dependency resolver API family.

`steps/plan.rs::PlannedDependency` currently contains `package` (authored requirement), `scope`, `step`, `key` (actual exact installation), `installed`, `hidden`, `commands`, `option`, and optional `resolved`. It has no configuration request/basis or portable-row identity. `steps::plan` collects option requirements, then includes requirements returned by `decide` **only for steps that run**. Keep this actual planner as the sole authority for active target edges.

`deps::install_required` deduplicates execution by exact `dependency.key`, follows a previously bound exact child first, skips an installed dependency, otherwise constructs `InstallRequest` with selected option, hidden, `Mark::Auto`, license and `RequiredBy`; all other fields come from Default. That is the exact request-construction seam for a classified public rich configuration. Do not schedule automatic rows as top-level manual imports.

`pending/checkpoint.rs` serializes each PlannedDependency into `ApplicationPendingChild` before child effects: authored requirement, exact key, scope/step, option/commands/hidden, installed, selected source, record identity, target=None and completed flag. It currently omits rich configuration binding. The child checkpoint later saves its actual configuration in `ApplicationPendingRequest.configuration`, but that is **after** the parent has chosen its dependency and cannot reconstruct a missing pre-child request after a crash.

`pending/dependencies.rs` already supplies the generation and identity protections needed here:

- `resolve_binding` preserves exact key and source; it validates scope/step, completed publication record, or the installed dependency's exact record identity, and refuses a newly appeared installation where the parent had planned missing.
- `bound_child` repairs the backward-child/forward-parent crash cut only for this exact parent, Install kind, matching option and source, then checks platform/arch against admitted source. It currently does not compare an imported configuration binding because none exists.
- `link_child` and `ack_child` update all same-key bindings; `ack_child` verifies the child's completed publication identity and keeps its work until the parent finishes. This is one physical exact-key child serving multiple authored edges, not one child per spelling/range.

`portable/continuation.rs::prepare_import` currently accepts only selected manual candidates, persists their rows as Manual, and reduces automatic entries to `Vec<String>` keys for notes. CLI `commands/app/portable.rs:139` filters candidates to Manual before resolving/classifying. Thus automatic public values are not presently preclassified against their selected target definitions. A rich format must classify included automatic definitions before storing them, even when the target planner ultimately does not need an orphan row.

## Proposed minimal data and ownership additions

These are semantic field proposals, not chosen Rust names or epochs.

| Owner | Proposed data/role | Why needed |
|---|---|---|
| New portable envelope | Exact row identity, role Manual/Auto, typed original+basis/path-origin/secret obligations; source requirement edges `(owner exact key, authored requirement, step, scope, selected exact key)` | Distinguishes multiple possible versions of one dependency and retains source closure evidence without equating range spelling with identity. |
| Existing PreparedImport/cohort | Classified public automatic rows keyed by stable document-row identity; target source/option/definition; accepted original/basis/path bindings; finite edge-to-row bindings | One existing durable document owns public import input, including not-yet-instantiated descendants. No second config store. |
| Scoped operation context | Optional immutable view of that exact cohort's classified dependency bindings | Ordinary calls use None; imported children inherit it. A resolver wrapper alone is insufficient. |
| PlannedDependency | Optional typed imported configuration binding, including exact auto-row reference and accepted target public configuration/basis identity | Bridges planning to request construction without an out-of-band key lookup that could select a different row later. |
| ApplicationPendingChild | Persist the same binding/reference and its accepted public identity alongside existing exact key/source/option/record identity | Crash before child creation must retain the request to create; resume cannot take new defaults or reread FILE. |
| ApplicationPendingOperation | A validated finite import-scope reference for descendants not planned until later; actual child request still stores its normal configuration | Direct child resume must reconstruct import context even if initiated separately from cohort resume. |

The import-scope reference should identify the existing cohort home/generation and the immutable classified input/table identity, not the original filesystem import path. Root may use a typed reference or embed the required finite subtable in existing pending context. Prefer one immutable cohort table plus validated references; do not introduce a sidecar database. Mutable results/cursor must not participate in the immutable input identity. Accepted later review decisions need explicit versioned entries/bindings, not silent overwriting of input already used by a child. Retain the cohort until its descendant dependency operations settle under existing parent ownership; missing/tampered scope is a continuation refusal, not permission to install with defaults. Completion-only continuation that consumes no further dependencies should not acquire irrelevant new input requirements.

Only the accepted public target request/basis enters the child request. Secret obligations remain metadata; actual secrets use the existing exact child ephemeral resupply path. `configuration` is **not** populated by naively treating exported original as a fresh replacement: use the rich import reassessment adapter proposed in the parent design. A per-id target path binding also comes from that adapter. Child checkpoint then saves a normal B ConfigurationRecord; subsequent maintenance is independent of the import file/cohort.

## Source export closure

Within the existing home lock, start from the chosen manual root records. Walk `Installation.lifecycle.requires` by its recorded exact `Requirement.key`, keeping each edge's `package` spelling, scope and step. Use visited exact keys to terminate; do not repeatedly resolve newest versions on the source host. Traverse unconfigured intermediate nodes as well: a configured auto grandchild behind a legacy dependency is still part of the required configured closure. “Configured” must include retained legacy effective public parameters/features and known secret-origin metadata, not only `configuration.is_some()`. A straightforward bounded closure can include all reachable Auto records with their honest common-original or legacy-effective projection; each is a recorded requirement, unlike an orphan. Include configured Auto nodes reached from roots and enough exact intermediate identity/edge information to bind them (a legacy-effective row for a required legacy bridge is sufficient; it must not invent original intent). Do not include disconnected orphan autos in default export.

Run the new completion check across roots and included closure, not roots alone. A missing referenced record, inconsistent exact edge, or unfinished selected operation needs an actionable refusal/review; silently pruning it cannot claim faithful full export. Historical edges are evidence of what A used, not an instruction to execute a currently skipped B step. `--all` includes its additional selected rows, but Auto still means dependency-supplied: an unused orphan auto is reported unused, never gratuitously installed or promoted to Manual.

This is traversal of finite recorded application edges, not a new package solver. Source graph anomalies must be reported; the existing cycle detection during installation remains authoritative for actual execution. Read-only source validation must not require A payload paths to exist merely to inspect public intent.

## Target admission and execution rules

1. **Preclassify all included rows.** Resolve exact exported package identities and target installer choices; classify parameter privacy and validate original/basis before public persistence or any row effects. Build a finite classified table. Source resolution refusal for a required automatic row propagates to its consuming root with the exact edge; a required root must not fall back to an unconfigured default dependency. An unused `--all` Auto row can be reported unavailable/unused, but cannot authorize unsafe persistence of now-secret values.
2. **Map active target edges using the ordinary planner.** For an unchanged source edge, bind its selected exact dependency key. Recheck that this version satisfies the target authored range, group/name and target option/platform constraints. If target installer/configuration changes the edge set, a source row can be matched only when unambiguous and semantically valid; ambiguity or changed binding becomes a concrete target review question. Do not pick the first matching name, highest exported version or first document row. Edges no longer active leave their auto rows unused. Newly active dependencies without exported configuration use ordinary dependency planning, disclosed as target-added behavior under the same target review.
3. **Preempt installed-first for a bound import edge.** Search the exact imported key, not arbitrary installed versions satisfying the range. If absent, resolve that exact key and selected option, with target source/definition re-admission. If present, require settled state and semantic agreement with the accepted target row before returning `installed=true`. Compare complete canonical original and reviewed basis/path realization/secret-origin obligations, not just effective features. Preserve exact record identity in the parent binding.
4. **Existing same-key mismatch is a question/refusal, not implicit replacement.** Do not silently mutate a shared dependency to satisfy one importing root. Offer the existing normal modify/reconfigure path for the actual dependency, then replan import, or an explicit decision to retain current target configuration with honest report that source configuration was not applied. `--skip-installed` alone cannot claim the dependency constraint was met. Any retain decision must be consistent for every consuming imported root. A currently Manual installation satisfying an Auto requirement stays Manual; fresh dependency installations are Auto. Reuse does not demote existing user ownership.
5. **Carry accepted binding through PlannedDependency.** `install_required` uses its exact choice and rich public configuration when constructing the child request, while preserving `Mark::Auto`, existing `RequiredBy`, parent target, license policy, progress and exposure. Ordinary dependency records with no imported binding use today's default request. No secret map is inherited/broadcast from the manual root.
6. **Checkpoint before child execution.** Save configuration binding together with the parent edge. On retained planning, `pending::resolve_binding` reconstructs it; it must not consult a newly changed default or a re-read portable file. Before repairing/adopting a child, compare the child's stored rich request/basis identity with the retained binding as well as today's parent/source/option checks. The identity is of public input only, never a secret hash. Existing exact-generation and publication-record checks remain.
7. **Propagate scope through descendants.** Nested `OperationContext {progress, ..*ctx}` currently preserves ordinary context; the new optional finite binding view should follow it. Direct child resume restores it from validated pending import scope. Grandchildren not planned at the original root checkpoint can then find their classified rows without a second scheduler. Every actual dependency still enters through `steps::plan` → `resolve_requirement` → PlannedDependency → `install_required`.
8. **Settle and report actual use.** Mark an auto row applied only after its dependency completes or an installed exact record is admitted as matching. Record which requiring edges consumed it. Source rows bypassed by changed target conditions, unneeded `--all` rows, and intentionally retained mismatches are explicit dispositions. They are not top-level cursor jobs. Arrangement continues after manual rows and their dependency work settle.

## Shared dependencies and conflict policy

One exact key can serve `tool@^1` and `tool@>=1.2,<2` when both admit the chosen version. These are distinct constraints/edges with a shared physical installation identity. Do not compare authored range strings to decide whether two dependency instances are the same. Existing `done.insert(key)` and same-key `link_child` make this distinction operationally important.

Before effects, normalize all included rows that target the same exact key and detect incompatible intended configurations/installer selections/path bindings. Reject conflicting duplicate rows with both row IDs and consumers; never let document order choose. Equivalent original+basis/binding rows may share one accepted table entry while preserving all provenance row IDs. Equal effective feature sets alone are insufficient if dormant/original/default semantics differ. Public secret obligations can be combined only when semantically compatible; supplied runtime values are neither compared nor cached.

At each parent plan, verify every repeated same-key dependency agrees on the selected installer and accepted configuration identity **before** `install_required` deduplicates. Across manual roots, use the same immutable cohort agreement. The first root may install the child; a later root reuses the settled exact record after verifying the agreed configuration. No simultaneous multiple parents are added to one live child generation. If the first parent parks, the cohort remains on that root; a second root does not steal or share its unfinished child.

Different exact versions remain distinct keys. Each must satisfy its own consumer constraints; normal storage/command/exposure collision checks still apply. This atom must not invent a global version solver to reconcile conflicts. A target mapping requiring incompatible versions or one exact key with incompatible configuration is a concrete refusal/review, not permission to choose a compromise silently.

Visibility is also observable: today's `install_required` deduplicates by key and uses the first planned hidden value; `hidden` for a fresh dependency is currently `scope == Build`. For imported shared rows, choose one target visibility decision consistently before deduplication. The default should honor a Runtime consumer's exposure requirement while carrying explicit source hidden intent into review; it must not let edge order silently pick hidden state. This is a bounded imported-agreement rule; the general mixed-scope ordinary-installer behavior is outside this read-only atom. Held/hidden lifecycle restoration must be applied by the existing installation/lifecycle owner once, not by promoting the auto row to a manual cursor job. `InstallRequest` currently has hidden/mark but no held field, so held restoration requires an explicit existing-lifecycle step after successful dependency admission.

## Actual unsupported cases and decisive next tests

Current code cannot express any rich automatic-row request, cannot bind an exported exact version before installed-first, and cannot persist that request on a missing child's parent binding. Those are concrete implementation gaps, not evidence that the surrounding cohort/dependency mechanism is unusable.

Bounded refusal/review cases for the proposed atom: incompatible original controls after target installer change; ambiguous source-edge mapping; exact imported version outside target authored range; same-key conflicting rich rows; required auto package unavailable; installed same-key mismatch; pending work owned by another generation; missing immutable scope on resume; privacy reclassification; unresolved target paths or secret resupply. Each needs a precise edge/row/parameter outcome, not blanket “automatic dependencies unsupported.” Exact target installer mapping, path rebind and ephemeral secret supply are supported design paths, not exceptional workarounds.

Recommended discriminators (not run here):

- A manual root → unconfigured bridge → configured Auto grandchild; default new export includes necessary closure but not an orphan, and `--all` includes the orphan without installing it gratuitously.
- B already has a newer satisfying version; imported edge pins older exact configured key. Confirm installed-first cannot silently choose newer; incompatible authored range refuses.
- Two roots with different compatible range spellings bind one exact Auto key and identical rich intent; one child installation, both recorded edges, Auto remains Auto. Existing Manual equivalent remains Manual.
- Same-key original/dormant/path or installer conflict is detected before first root effects. Equal effective-only rows with different original semantics still conflict.
- Existing same-key different configuration refuses with modify/review path; `--skip-installed` does not report full transfer success. Pending same-key cannot bypass generation checks.
- Crash after parent checkpoint but before child creation, then direct child/root resume after original FILE deletion; saved rich binding survives. Backward-link repair rejects a child with the wrong public config basis despite matching source/option.
- Park child for exact secret resupply; subsequent roots and arrangement do not overtake it, no secret leaks into cohort, and normal fresh unrelated installs are unchanged.
- New process on B performs modify/update/repair of imported Auto; original/dormant/default/path semantics survive independently of the settled cohort. Source removed/changed target edge reports unused or newly introduced dependency honestly.

Format impact is real: rich cohort automatic rows, pending child config binding and pending import scope require generated-schema/reader/corpus assessment under root's PROP-044 decision. This report assigns no epoch and proposes no source patch. The default export closure ruling should be recorded in the final accepted portability contract; it is no longer an open product decision.
