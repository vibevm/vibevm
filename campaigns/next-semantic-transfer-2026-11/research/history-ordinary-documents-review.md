# Ordinary documents: six bounded history reviews

## Scope and conclusion

Source `7fe6376ccef7f321302a8f18610fcb0c9cc2686f`; main `ee3031c5150403b7cf693c77d467eb01c3e8a67b`. All **32 changed-path memberships** across the six supplied commits were read as full diffs, including small Cargo/campaign-projection changes. This does not mean their complete historical files, downstream subsystems or whole product were audited. JSON records exact diff/blob hashes and the separately bounded final/main reads. No builds, tests, services, network, Git/product edits, worktrees or other agents; only `/tmp` reports. Dirty prototype files and the active app candidate were not read. Historical execution claims were not promoted to new proof.

There are three different results: (1) a useful pure ordinary-document inspection implementation with some internal consumers but no completed public named-export read, (2) a Vibe nested-item repair already present in main, and (3) an inline-code fact-duplicate correction absent from main, where current permanent grammar conflicts with an intentional older test/code policy. ## D1 — Ordinary CommonMark is a separate selected interpretation, not a replacement Vibe frontend

`d00908242bf2ca41de4dad8122376719a207b6cf` adds `crates/vibe-specdoc/src/commonmark.rs` and its tests. `CommonMarkDoc::parse` uses `pulldown_cmark::Parser::new_ext(...).into_offset_iter()` and enables only `ENABLE_TABLES`. It retains the original UTF-8 string and original byte spans; it never calls `from_markdown`, `parse_document` or a directive/fact engine.

Actual structure is deliberately partial: Document, heading-based Section, Fence, Link, Text and InlineCode. Paragraph/list/blockquote/table container events and other unmatched events are ignored; there are no list/table/quote AST nodes. Heading ancestry is the document-wide heading-level stack, not a retained CommonMark block-container hierarchy. Raw HTML arrives as inert Text. Inline code is its own node; escaped/entity-normalized event text can differ from its raw source slice. Exact raw retrieval must use the retained source and spans, not reconstruct bytes from Text/title/label strings. Soft/hard breaks add a display space while retaining their original event span.

Headings include ATX and setext. Titles/labels are whitespace-normalized parsed text; a heading containing inline code contributes its visible text to the title, not a Vibe identifier. `heading(title)` searches the whole snapshot and refuses multiple equal titles. The later export path provides direct-child selection; the two lookup semantics are distinct. NodeId is an arena ordinal with no durable resource/snapshot binding by itself. Heading spans and section spans are byte ranges; no original line/column mapping is supplied here. A section includes its heading and following subordinate content until the next equal/higher heading.

The three original tests inspect real event results: outer four-backtick fence hides inner headings/links, setext and duplicate headings behave explicitly, and `@requires`, `#use`, `@fact` in prose/table code remain ordinary. They do not establish full CommonMark/GFM conformance. This is **CommonMark plus table parsing**, not all GFM features (task-list/strikethrough options are not enabled). The parser algorithm is unchanged at the final pin apart from exposing export helpers.

Dependencies are concrete: workspace pin `pulldown-cmark = "=0.13.4"`; specdoc adds its workspace edge. The commit's Cargo.lock adds pulldown-cmark 0.13.4, pulldown-cmark-escape 0.11.0, getopts 0.2.24 and unicase 2.9.0; other listed dependencies were already present. Main's workspace/specdoc manifests have no pulldown-cmark edge at the comparator. Review feature selection and the resulting lock rather than copying an old lock wholesale.

**Final consumers:** facts `scan/declared.rs::observe_declared_document` selects Commonmark from an authored descriptor, parses it and returns Structure; `scan/declared/walk.rs` retains that document observation but emits facts only from Facts variants. `specdoc::captured::inspect_captured` and workspace `extract_source::structured_view` also invoke this parser. `AnalysisCapture::inspect` exposes a library DocumentPreview, but its `outline`/`select` and CapturedView's Outline branch still require a Vibe view. Derivative compatibility checks a retained result's heading through `CommonMarkDoc::heading`; that is a different global-title compatibility predicate, not named-export navigation.

**Main difference:** main still uses the Vibe adapter over progress-core. `project_spec_text_with` dispatches XML to the Vibe pivot and otherwise returns Markdown text; it is not an ordinary-document classifier. Main's held read and unique Vibe anchor selection are real, already accepted owners to preserve. New ordinary inspection must be an explicit separate operation/interpretation, not a change to every `.md` suffix or existing `#embed` behavior.

## D2 — Nested-item repair is already in main; the corpus change is not CommonMark support

`722a0f2ee971ce9e4bbcc586cbddd0d882c8810f` changes **Vibe** `md_in.rs::Adapter::item_unit`: `list_marker_len` already includes indentation, so slicing `line[indent + mlen..]` double-counted it and could cut a multibyte character or miss a nested task box. The repaired code uses `line[mlen..]` and restores one task-box prefix. Both new regressions exercise public `from_markdown → to_xml`, including Greek characters and no doubled `[ ]`.

Main `md_in.rs:379–392` already has the same repair, with a more detailed causal comment, and `tests/nested_item_multibyte.rs` contains both test names and equivalent assertions. Final prototype retains the repaired method. This is **already-present behavior**, not another required transfer or evidence that main needs the new CommonMark parser to handle nested list conversion.

The same commit updates docs corpus from the old 1.0.0/49-page inventory to 1.1.0/54 pages and introduces precise tripwire exceptions: a plain legal page lacks Doc-only vocabulary; one tutorial projection fails because quoted `@fact:ONE-IDEA` is counted twice. That records two different conditions rather than declaring every page roundtrippable. Later D6 removes the duplicate-related exception after fixing the anchor checker. Do not transplant those corpus counts or the prototype's versioned documentation path into current main.

## D3 — Authored exports resolve exact captured sections; names are not byte evidence

`e8f1bfe797c2955c354cc5835e5f195aa7a607ee` adds `SourceExport` to core and `commonmark/export.rs` to specdoc. Authored syntax is exactly:

```toml
[[package.source_exports]]
name = "intro.v1"
file = "docs/guide.md"
headings = ["Guide", "Introduction"]
```

Closed row keys are `name`, `file`, `headings`. Name uses `[A-Za-z][A-Za-z0-9._-]*`; file must be an exact normalized package-relative declarant path; headings must be a nonempty root-to-section list of nonempty, control-free, whitespace-normalized titles. PackageMeta deserialize **and serialize** reject duplicate names. Missing rows default to empty and are omitted on serialization, preserving old declarations. A row alone does not establish file existence, selected interpretation or trust.

`resolve_export` walks each title among direct child sections; duplicate siblings refuse, while equal leaves under different parents can be disambiguated by a full chain. It returns name, snapshot-local NodeId, exact section byte span and `sha256:<hex>` of the complete original UTF-8 source. It has no expected-old-hash argument: calling it on a changed document returns a new hash/span, it does not itself reject “staleness.” The tests explicitly assert those change. Any stale-use refusal belongs to the owner joining this result to the previously observed bytes. There are no line numbers in this value.

The core and specdoc name/title validators repeat a small lexical rule because the pure parser intentionally does not import manifest types; this avoids a crate cycle. Their narrow duplication is not evidence for a new generic validation framework. The commit adds `sha2.workspace=true` to specdoc and its lock edge; main already has sha2 elsewhere, but not that specdoc edge.

**Surviving joins, inspected directly:**

- `vibe-facts/src/scan/declared/export.rs::resolve_declared_export` checks that the exact row is authored, chooses the exact file descriptor, requires Commonmark + text/markdown, checks provenance/resource/descriptor index, recomputes SourceFileWitness from the parsed source, and compares the resolved hash. Its tests substitute a stale witness, wrong resource, absent observation and ambiguous headings. The returned group/name+export identity still requires its owner context; it is not the selected version proof by itself.
- `vibe-workspace/.../extract/export.rs::WitnessedSourceWorld::read_export` revalidates the world, resolves the captured manifest's exact named row, joins descriptor output mapping to original file, calls extract_source, requires CommonMark, checks hash/span and revalidates again. It returns original captured bytes under recipe `commonmark-export/1`, `SpanBasis::CapturedBytes`, UTF-8. Its test checks literal `@fact` content and excludes the next sibling section.
- `vibe-spec/src/resolver/resource.rs::canonical_export_resource` constructs a `resource://` identity only after checking selected dependency package/version and authored export name. It does not read the heading/body; self-export authority is refused in this constructor.

Repository Rust reference searches found these export joins and canonical_export_resource only at definitions/tests, not a production invocation. This does not rule out external library users. More decisively, the public `SourceQueryService::query` body calls `canonical_vibe_resource`, then accepts only `StructuredView::Vibe`; ordinary interpretations return UnsupportedInterpretation. Neither the raw constructor nor read_export is connected by that public query. CapturedSectionSource likewise only admits Vibe IR for compiler sections. Therefore the primitive and witness joins are implemented, but a public named CommonMark export journey is not established.

Main has none of this exact `source_exports`/CommonMark API in the inspected crates. Its accepted `DocTree::resolve_unique_path` is unique **Vibe anchor** selection, not ordinary heading export identity; reuse its ambiguity policy lesson, not its parser semantics.

## D4 — The export contract preceded implementation; it carries a host obligation, not a completed route

## D5 — XML-data inspection preserves raw bytes; optional structural success is deliberately weaker than a Vibe/schema proof

`b66ea01be2709edd6f6104f143c89c0071a89bb0` adds `xml_data.rs`, tests and module export. It reuses the existing quick-xml dependency; no new parser package is added.

`inspect_xml_data(&[u8])` always returns the same borrowed raw bytes, with Xml outline or Unavailable(issue). `preserve_opaque` returns NotRequested without parsing. UTF-8 is required for inspection; a valid UTF-8 buffer declaring another encoding gives UnsupportedEncoding, invalid bytes give InvalidEncoding. An initial BOM is stripped only from the inspection view. DOCTYPE and unknown/general external entity references are refused; allowed predefined/numeric references are checked without file/network/entity resolver. Root balance, second roots, invalid XML 1.0 characters, duplicate attributes via quick-xml checks and late declaration are checked. No reserialization occurs.

Actual bounds are 4 MiB raw, depth64, 10,000 elements and 1 MiB counted text. These restrict optional inspection, not raw access. `text_bytes` counts event source spelling, including text whitespace and entity-reference spelling; it is not decoded visible-text length. The result is root name plus counts, not an element-position tree, namespace/schema validation or complete data-model proof. Tests retain BOM/comments/whitespace/entities byte-for-byte and cover malformed/non-UTF8/DOCTYPE/depth/elements/text limits. No fresh results or hostile-parser resource benchmark is claimed.

Final xml_data.rs is byte-identical. It is called through `inspect_captured` and `extract_source::structured_view`, so it is not merely an unused helper. In contrast the facts declared reader intentionally returns XmlData/Opaque as Raw without inspection. `preserve_opaque` itself has only test references in the searched Rust tree; production capture paths retain raw bytes through their own wrapper/NotRequested variants. There is no need to copy an unconsumed wrapper just to preserve that invariant.

Public source query still refuses non-Vibe views. Main has quick-xml and byte-preserving raw reads, but no optional ordinary XML-data inspector at these paths. Its `vibedeps/derived.rs::transform_file/is_spec_document` still chooses `.md/.xml` under specs-root or root README and calls the Vibe converters; rejected parses copy verbatim, successfully parsed Markdown may convert. An explicit inspector therefore does **not** by itself implement package-wide ordinary-data preservation through install/facts/boot. That larger behavior needs a consistent opt-in classification boundary, preserving current legacy files until deliberately migrated.

## D6 — Inline-code duplication is an actual current grammar/test conflict, not grounds to erase real duplicates

`8a4c096f305479f9c56e86db6c7421956174ba24` removes the second raw `@fact` token scan in progress-core's duplicate checker. Only parsed unit/fact anchors remain definitions; ordinary duplicate-ID and marked-unit checks remain. The reusable token grammar for real anchors remains; the deleted helper existed specifically for the raw additional scan. Source final anchor files are byte-identical to this change.

Main still intentionally contains `parse/anchors.rs::definition_form_used_as_inline_citation_is_a_duplicate` (line137): real `@fact:SAME` plus `@fact:OTHER see \`@fact:SAME\`` must produce one DuplicateId naming lines3/5. The preceding production comment requires code-formatted citations to use legacy `##ID`; raw definition spelling is counted despite the parser having masked it. This is evidence of an older deliberate diagnostic policy, not merely a test accidentally left over.

Root directed a further bounded read of main `BACKLOG.md:1269–1282`, B-092 (quoted fact text counted as another definition). Its August20 disposition explicitly records expanding DuplicateId into inline code and changing three quotations to `##ID`. The evidence was lexical grep; the record itself says no consumer had been shown resolving a wrong address. This is a genuine historical policy tension with the permanent grammar, not an accidental stale expectation. The causal chain is concrete: lexical duplicate concern → quote-versus-definition convention → extra raw scan overriding parsed opacity → a tutorial projection becomes unparsable → a corpus exception → prototype removal of the extra scan. Preserve B-092 as historical evidence and record any chosen compatibility correction; do not erase it or claim the old policy never existed.

However, the **current pinned permanent contract** `PROP-043-facts-markup.xml#PARSE-FACT-ANCHORS` (641–645) explicitly says an opener inside code spans/fences is opaque. `PARSE-MARKDOWN-FIRST` additionally confines markup to text nodes, and the first-token fact-anchor grammar is explicit. The old raw duplicate policy is inconsistent with that present opacity rule. Root should resolve this as a concrete grammar/diagnostic correction, preserving evidence of the previous behavior; this audit does not change or accept it.

The actual affected consumer chain is main `vibe_specdoc::from_markdown → progress_core::parse_document → check_anchor_laws`; error_count causes from_markdown to refuse. Main `vibe_facts::observe_authored_source` invokes `project_spec_text` then from_markdown and turns that refusal into an Invalid source observation; `scan_authored_facts` returns typed SpecParse. Thus a quoted anchor can invalidate an otherwise legitimate document or its XML→Markdown projection. Source D2 first recorded that tutorial exception; D6 removes it after fixing the underlying checker rather than rewording quoted documentation to satisfy the defect.

**Do not broaden opacity incorrectly.** Main's `blank_inline_code` matches runs of equal backtick width; unmatched runs are literal and mask nothing. D6 does not change that algorithm. Existing tests `any_delimiter_width_leaves_the_trailing_marker_visible` and `an_unterminated_code_span_swallows_nothing` preserve outside markup. Real first-token `@fact` anchors outside spans still come from parsed facts; `duplicate_definition_reports_both_lines` remains a negative control. A stray backtick is not authority to hide following fact/status syntax. Source adds paragraph/table quote controls but does not prove all backtick/escaping cases; retain the incumbent parser, do not add another inline scanner.

This correction needs no new dependency, manifest key, source descriptor or CommonMark parser. It is independently useful for existing Vibe conversion/fact consumers. The old diagnostic behavior changes, while actual definitions remain unique. A runtime discriminator should run public from_markdown and scan_authored_facts on the SAME/OTHER fixture, then verify that two real SAME definitions still refuse and unmatched/mixed-width backticks do not suppress outside markup. No such test was run in this audit.

## Next concrete decision and complete consumer

Recommend two distinct dispositions for root: **already-present** for the nested-item fix; a separately reviewed existing-consumer **inline-code opacity correction** for D6. Do not hold either hostage to the broader ordinary-source system.

For the next ordinary-document feature, choose an explicit **read-only ordinary resource inspection operation** over one caller-authorized root and exact relative file, with caller-selected CommonMark or XML-data interpretation. It should return raw bytes (or a lossless byte representation), snapshot hash, structural availability, and a request-local heading path/byte slice for CommonMark. Reuse main's held shared-inode source reads; do not pass this input through project_spec_text/from_markdown, infer interpretation from suffix, or enable resource text as compiler directives. A real CLI entry plus its library owner is the minimum complete consumer; `vibe skill list` currently only exposes declared inventory and does not inspect a file, so adding a parser behind that list without a selectable read operation would be incomplete. No new CLI spelling is claimed to exist here.

Request-local selection can precede `package.source_exports`; durable exports should wait for a selected-package/resource public route, exact capture recheck and explicit format compatibility decision. This avoids forcing the prototype's source-query world, document-analysis host or transport machinery into a one-file inspector, while preserving their useful identity distinctions.

**Discriminating runtime scenario for that feature:** inspect one held shared-inode README containing literal `#use`, repeated `@fact`, a GFM table, nested/duplicate headings, multi-width fenced code, Unicode and CRLF. Select `Guide → Introduction`; assert exact original byte slice/hash and that duplicate siblings refuse without hiding raw bytes. Retarget a descendant symlink and replace the file during the read to exercise main's existing refusal boundary. Then inspect malformed/unsupported-encoding/DOCTYPE XML and assert raw-byte identity survives unavailable structure, without network/file entity resolution. Assert unchanged source inode/bytes, manifest, lock, boot artifacts and path inventory. A legacy Vibe document must retain its existing fact/anchor behavior except the separately reviewed quoted-code correction. This is a proposed bounded feature gate, not executed evidence or campaign acceptance.
