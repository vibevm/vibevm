# Bounded history audit: machine / migration / observability policy

## Scope and evidence

Read-only audit of exactly 25 commits supplied in `/tmp/nst-history-machine-policy-input.json`; all changed-file diffs were read in full, including all three release-impact records. Source: `7fe6376ccef7f321302a8f18610fcb0c9cc2686f`; comparator: `90e3e3f26`. Git objects were read through `/fast/git/vibevm`, never through the source working files. No build, test, service, Git mutation or product write occurred. The five dirty source files are excluded. The accompanying JSON preserves one full SHA per input row, exact changed paths, the substantive change, bounded classification, inspected source observations, main comparison and remaining uncertainty. ## F1 — Status is scoped in the prose; an accepted label alone loses that scope

`bd5f645278852197bd715346cb22539f490add2a`, `vibevm/vibespecs/common/PROP-080-machine-operations-and-observability.xml`, adds domain-authority and observability obligations explicitly as future extraction/facade work. Existing resolver/compiler/registry/journal owners remain authoritative; a second universal graph/parser/scheduler is forbidden. Implementation gap, contextual participation, observation outcome/completeness, authorization and redaction are independent. This is useful protection against empty-looking results and fabricated availability. It is also very broad scope: every meaningful state/decision/refusal receives an owned inspection, plus a finite authority map. The commit does **not** deliver that closure.

`dc1fc9de708f1398612ff00ecc4a0254fcf4bc94` creates three `vibevm/vibespecs/changes/*/release-impact.json` records: `architecture-law-traceability`, `mailbox-proof-citation`, and `role-classification-eto-laws`. The first two explicitly have no runtime/user effect; the third accepts desired source policy while retaining runtime guards, calculator, external services and final documentation as due. Its `acceptance.state=accepted` means the source contribution, not implemented architecture. The final pinned evidence files `docs/releases/developer-preview-1-to-2/evidence/architecture-{source-review,verification,central-review}.md` were read: the verification describes one unchanged mailbox test and source/index checks, and the central review is conditional on a later final native record/evidence/delta check. All three final file SHA-256 values match the record. Those files are absent at the record-creating commit (git show exit 128), added later at `62161a91c`; final provenance exists, but acceptance was not self-contained in that original commit.

**Causal finding:** source-law review was packaged in the same accepted/evidence vocabulary as delivery, with the limiting semantics in free text. A consumer that counts `accepted` or passing graph edges as features will inflate status. The actual record and later evidence deliberately resist that inference; this batch does not prove the authors claimed complete runtime delivery. Main lacks this exact PROP-080 path, but already has domain owners, MCP tools, package execution and trace ownership. Transfer the specific guarantees required by chosen consumers, and retain source-policy versus executable-claim distinctions; do not make universal observability or its complete map a prerequisite merely because this contract names it.

`ecaca53663949f9513fa28d59db0a526143391d6` changes PROP-044 application reports to **required nullable** evidence, including barrier binding. `6cb74b58ee0d773e57cf09dd952966f0e34b594c` adds explicit CLI mutation and MCP composition-root grant: absolute project/recovery-store roots, finite file allowlist, no ambient HOME or payload-root authority, store/cache disjointness, truthful pending/refused/uncertain results. `9c1f497c48530625f6976786baddddfc4a8bbb4d` then closes a real representational hole: an invalid **post-execution** report cannot become an empty preflight or an unchecked normal result. The migration renderer preserves diagnostic-only evidence, and `tools/output.rs:124–239` adds `structured_present` without treating `Value::Null` as absence.

**Main and transfer:** main already has `ToolOutput::executed` and `executed_failure` (`crates/vibe-mcp/src/tools/output.rs`); the semantic delta is structured preflight and an explicit absent-structured executed channel, not inventing the whole tool seam. This audit did not review all planner recipes, filesystem admission internals, journal recovery or CLI/MCP test bodies, and does not certify portable mutation safety. Current source supports implementation presence, not completion of all transport/native obligations.

## F3 — Identity layers prevent a demonstrated wrong join; framing is a separate optional reach

`aa34969920a72ee29a8be5fb01333409aba2b07c` adds PROP-080 logical/captured/observed/occurrence identity, non-atomic composite snapshots, projection-bound paging and opaque source locations with explicit position basis. `1fa6b91f32f8c3f0131d511bdf5dcb8bcf501b8d` immediately tightens the joins: each row must name its exact occurrence, references cannot be reused for distinct single-occurrence rows, and equal opaque strings cannot establish source-to-capture identity. This is substantive protection for repeated DAG nodes and projected XML/Markdown locations; generic types here have a concrete ambiguity to prevent.

Final `crates/vibe-core/src/machine_view/identity.rs` separates these axes. `crates/vibe-orchestrator/src/machine_view/page_session.rs:169–249` validates explicit `SourceCaptureBinding`, rejects duplicate/conflicting bindings, reused entity references and occurrence mismatch. `paging.rs` binds an in-memory cursor by Arc instance plus projection/filter/scope/stamps; it never rereads owners. Conversely `page_wire.rs` explicitly reports opaque wire cursors as **Unverified** even after local page and adjacency validation. A well-shaped page is not proof of source authenticity or a complete sequence. Location conversion and actual UI/editor consumption were not inspected.

`d536041d5192a8441a63721429579ba96ac29830` adds eight-MiB four-byte length framing, finite version/schema/position negotiation and host-assigned context IDs. It explicitly keeps legacy MCP newline JSON-RPC and one-shot calls independent. Final `crates/vibe-mcp/src/machine_session/framing.rs` checks length before allocation and rejects invalid bytes/shape/epoch; `state/negotiation.rs` checks offers, initialization and assigned context/target before yielding an **UnvalidatedRequest** to a domain owner. Main retains fixed MCP protocol `2024-11-05` in `crates/vibe-mcp/src/lib.rs` and has no machine-session module at this path.

**Transfer:** preserve occurrence and position/source provenance in any selected navigation result. Do not equate opaque identity wrappers with authenticated origin. New framing is implemented, but its necessity is consumer-specific: the historical contract itself says a library/one-shot call needs no session. There is no evidence in this batch that every useful read requires the additional protocol or all four snapshot axes. Nor does this audit prove no client needs it.

## F4 — Recovery drove the extra records; useful fences do not generalize a fixture

`48f3f79fcb93c8ee21300f64736887595e71d179` repairs PROP-080 reservation/journal atomicity assumptions: two separate atomic files are allowed, but a reservation without a journal may initialize only its reserved run; present/uncertain evidence cannot redispatch. `578c535dd3849fb192d6d718012d11e5d5eae965` adds the critical distinction that a lifecycle freshness header is not a terminal outcome. Final `crates/vibe-lifecycle/src/state/submission.rs` has Created/Existing/Retired reservation decisions separately from Pending/Ready journal admission. Package `journal/execution.rs` rechecks reserved intent and Ready, verifies actual output and artifact record, and durably publishes/readbacks a separate completion. Lifecycle adapter code uses retained outcome inspection, not merely run-ID equality. I inspected these boundaries, not every reservation transition or crash window.

`b6004684c7d1c83707c764a6539a416dc14ec670` adds short-lived owner/observer separation. ContinueCurrentDispatch survives observer loss only while the host process lives; detach is not provider cancellation; panic cannot stay Running. Final `machine_submission/lifecycle_adapter/live_owner.rs` checks same owner handle and trusted coordinates on attach, revalidates retained evidence after running, and marks a panicked owner stopped. This is real implementation, but the full observation/control/evidence submodules were not audited; arbitrary durable background execution is not established.

`ccde5f3e9479dcfed46b04bb6c46e280fcd166f7` selects a **fixed** first non-Validate package operation: `source.bin` → `target/vibe-package/launcher/launcher.bin`, target `launcher`. It explicitly defers general target/provider/destination, Cargo toolchain, Deploy correlation and production Finalize. `e4c5a1753d8b1034901d2c7f0dffa20e724d99de` adds three exact action formats (submit/inspect key only), deriving Completed/Uncertain/RecoveryRequired from that owner. `0bc3e7034862d3352fb44ce770b0b05e38d92343` adds a separate package frame mode with no streaming/replay/control claim.

Final `machine_operation/fixed_package/dispatch.rs` delegates to host submit/inspect, keeps original owner evidence on publication failure and distinguishes possible effects from preflight. `machine_session/package.rs` uses the existing envelope and mirrors nested owner truth into frame completion. The domain implementation in `vibe-lifecycle/src/mechanism/package/journal/execution.rs` still validates the fixed single-copy route. Main already has general `execute_package_targets` and A2 output in `crates/vibe-lifecycle/src/mechanism/package.rs`; that is not the new pre-effect retry guarantee.

**Causal finding:** a broadly useful requirement (same-key retry must not repeat an effect) first landed around a deliberately fixed demonstrator; later commits supplied that demonstrator with wire formats and its own session mode. The resulting protected surface remains much narrower than general package functionality. This is concrete partial delivery and architecture growth, not proof that idempotency journals are unnecessary. Transfer should target a selected real package journey through main's incumbent owner, preserving Ready/outcome/drift fences; it should not ship the fixed filename demo as a general protected package API or copy its whole transport stack merely to obtain idempotency.

## F5 — Ephemeral sessions caused durable grants; domain separation became duplicated mechanics

`810b7687aac1416c14af5f5978e1b91688a7d096` deliberately reuses existing SessionFrame and OperationEnvelope for fixed lifecycle values, rejecting another frame-arm outcome grammar. This is counterevidence to a blanket “adapters on adapters” verdict: a specific duplication was recognized and avoided.

`a9ecc70f91ae5e2ca6a286578067090b48b5da9b` then adds a host-owned reattach pointer because a new namespace per CLI process would allow the same key to execute again. Connection context IDs remain ephemeral; durable host scope is separate; approvals and results are not serialized in the pointer. `9907b46625ab3da29b431450a10260e930970758` states the actual security limit: cooperative same-project root access and mutation lease, project-local principal, explicit startup permissions, **no hostile cross-user isolation**. `c63fdf1caa8151cad64dddfcf69f5b839618b000` gives package its own domain-separated pointer and policy, preventing a Validate host from authorizing a copy; it explicitly leaves open a private shared pointer/IO kernel that preserves distinct authority.

This chain is visible in final code. `machine_submission/cli_grant.rs` and `package_grant.rs` independently define scope/pointer/Issuing→Issued storage and nearly parallel `issue`/`reattach` sequences: lease, reject existing pointer/C1 scope, publish Issuing, initialize policy, issue namespace, publish Issued, reconstruct/recheck. Their paths/hash domains and host constructors differ. `commands/machine_session.rs` requires explicit issue/reattach modes and finite TTL for issue, denies mismatched options, and constructs a `vibe-cli-project-local/e1` principal. These observations identify repeated mechanism, not a verified safe refactor. A shared kernel must retain distinct policy sources, namespace scope and error behavior; merging grants would be wrong.

`bde72bd216c510a4d8f5a73291c2d560ee621381` binds force to exact typed approval and admitted request/plan, not key novelty. `8f07e186da945136a1d34829ac4f3bbb81a08385` does the same for trace and requires owner TracePreparation/finalization after Ready, preserving measured effects if observation fails. Final `machine_submission/lifecycle_adapter.rs:853–862` compares approved force/trace, passes them into run identity, and `1838–2034` executes/finalizes the incumbent trace funnel and retains post-effect uncertainty. Main already has `crates/vibe-orchestrator/src/trace.rs::TracePreparation`, so the added capability is exact protected-request propagation and replay identity, not tracing itself. Exact approval issuance, all concurrent-policy races and general phases were not audited.

**Transfer:** the proof needed for consolidation is narrow: preserve same-key across process loss while sharing only private pointer publication/readback mechanics. Do not copy per-domain scaffolding blindly, and do not remove the durable/ephemeral distinction or exact option identity. No deletion or rewrite is proposed by this read-only audit. The reports establish where repetition arose and why some separation must survive.

## F6 — Environment bindings and recovery-only Deploy are useful separate authorities

`0ef17ab5563424c9020632164bab52b6375d9434`, PROP-076, adds opt-in target/environment identity carried through request/plan/grant/journal/receipt and preserves legacy local behavior. It explicitly says logical binding alone does not fence physical aliases/concurrent writers. Final `crates/vibe-lifecycle/src/mechanism/deploy.rs:94–103` validates a shaped wire binding and refuses `BoundRootAdmissionUnavailable`; a separate host-admitted path follows at line 112. This is an honest public boundary, not proof of arbitrary cross-target deployment. Receipt/intent/sidecar identity checks are present in the following function, but this audit did not follow every provider or fence.

`817c5ab27af08336fac0acdd806bfdc8e456ea4e` adds PROP-080 Deploy reattachment after manifest/profile/policy/generation drift: preserve old-key inspection through a read-only host without restoring effect authority. Final `machine_submission/deploy_grant.rs:125–137` has distinct Active and RecoveryOnly carriers. `reattach` at 299–329 validates the pointer/namespace, checks current facts and constructs RecoveryOnly on drift, then rereads pointer under lease; `current_matches` at 385–406 compares manifest/profile/generation/policy. That is stronger than a prose promise, but cold native execution was not rerun and the complete Deploy CLI/provider chain was not inspected.

**Main and transfer:** main has ordinary deployment/lifecycle owners; the exact environment and machine-submission modules inspected here are absent. Do not conflate legacy deployment with admitted environment-aware deployment, or proof of a wire schema with root authority. Preserve the asymmetric recovery rule: revoking/changing authority must block new effects without erasing access to known old effects. It is reusable independently of a universal session architecture.
