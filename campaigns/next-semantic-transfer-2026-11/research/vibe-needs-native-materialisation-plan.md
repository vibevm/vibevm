# N2: safe local materialisation and complete warm capture

Design/evidence only, 2026-11-07. N1 accepted `46b6297a3` per root (the handoff still says pending). No production edits, Cargo, public network or real HOME/config changes. HTTP/N1 guards remain unchanged until a specific admitted operation replaces them. SSH/N3 and recursive-submodule/redirect N4 are not claimed.

## Actual boundary and gaps

* `native_admission/context.rs` owns `env_clear`, private HOME/config/hooks, HTTPS-only transport and no lazy fetch/replacement objects. `NativeState::with_owned` checks retained config/alternates; object reads remain bound to the selected commit. Reuse these owners.
* `native_admission/metadata.rs::origin` deliberately refuses every external warm context: local config alone cannot establish selected Git's ambient/system/global/include meaning. Its local HEAD allowlist is not complete source capture.
* `PreparedInPlace::materialise` calls preflight before its own effects, checks existence/HEAD/origin, then refreshes in place or verifies a sibling candidate and remove/renames the destination. `bring` likewise preflights before deleting debris. N1 therefore preserves the immediate slot boundary.
* **Whole-install refusal occurs too late today:** `vibe-install/src/apply.rs:405` can publish the manifest before `materialise_deferred_in_place` at `:442`. `FileGuard` protects manifest/lock/provenance only. A typed native/transform refusal must be decided before that publish.
* **Deferred-slot undo gap:** workspace `InstallRollback` is created later in `install/hook_output.rs:126`/`:255`. `install.rs` skips `before_replace` when `content_dir == slot` (already_placed). Earlier deferred in-place edits are not retroactively saved. Existing directory undo uses path-based remove/restore; it does not establish an owned-after conflict check. Do not claim FileGuard or later outcome rollback restores these bytes.

## Contract: capture → stage → publish under the existing slot undo owner

Add a retained `PreparedNativeMaterialisation` result inside the existing prepared-source ownership, not a transaction framework. It carries selected revision, complete captured warm/source metadata, supported checkout semantics, verified staged result, expected old slot identity/HEAD/origin and publication recipe. Construction may write **operation-owned scratch**; it must not write caller manifest/lock/slot/refs/origin/.gitignore. All semantic/unsupported-transform refusals happen during construction, before caller publication. Drift/failure at publication still reports an honest refusal/recovery result.

### A. Complete warm capture, no guessed config locations

Introduce a narrowly scoped metadata-capture entry on the trusted Git installation. The caller supplies an immutable snapshot of its relevant **configuration-selection inputs**: actual HOME/XDG location, explicit system/global config selectors, command/environment config entries, invocation cwd/worktree and named source. Do not read an arbitrary fresh ambient environment during apply, and do not infer the installation's system path as `/etc/gitconfig`.

Run only fixed non-network Git metadata commands against that original context: selected Git `config --null --includes --show-origin --show-scope --list`, raw origin lookup and effective `remote get-url origin`, plus HEAD/ref facts. Use a command-specific environment: retain config-selection meaning, but suppress pager/trace-output/loader/exec overrides and execution routes. No arbitrary argv/aliases; no status/checkout/filter execution. Caller config is **data**, not subprocess authority. A dedicated proof must establish this fixed reader set does not execute hooks/helpers/fsmonitor or perform lazy reads; N1's generic command guard does not become open.

Capture ordered multivalued effective config with scopes/origins, effective and recorded origin separately, branch/object-format/worktree layout, and every applicable attributes source. Includes/includeIf are evaluated by the selected Git in the original directory/branch context, not by a homegrown partial parser. Preserve binary/environment command-scope inputs and duplicate-key order. Capture referenced file bytes and resolved path provenance, repeat observation to detect drift; re-evaluate effective metadata and applicable file witnesses before publication. An empty or absent config source need not be guessed from a conventional path: rediscovery of the effective view detects a newly consequential source. If complete origin or supported path semantics cannot be captured, refuse explicitly.

Never substitute recorded A for effective B. If Git's captured include/insteadOf rules produce B, admit B with the existing host binding and explicit auth route. Excluded B refuses before acquisition. Allowed B is passed as the explicit endpoint to N1's owned acquisition context; the child's isolated config must not replay the ambient rewrite a second time. SSH/helper/proxy/opaque effective routes remain unsupported pending their own capability, not silently ignored.

Fresh installs also need captured caller checkout semantics, not N1's deliberately empty acquisition attributes. Warm effective config capture is complete as an **observation**; execution admits only supported meanings. Do not flatten unknown keys into a config file and execute them.

### B. Payload transformations: preserve bytes, refuse unsupported execution

Build the candidate attribute view from the **selected commit's full .gitattributes tree**, captured `$GIT_DIR/info/attributes`, captured global/system attributes and the selected platform/config. Evaluate all candidate files, not just vibe.toml. Keep N1's stricter authoritative-manifest rule: filter/working-tree-encoding/ident on vibe.toml still refuses.

Initial supported payload conversion set: Git's built-in text/EOL rules (`text`, `-text`, `text=auto`, `eol`; captured `core.autocrlf`, `core.eol`, `core.safecrlf`) and explicitly captured file-mode/symlink/platform semantics. Replay resolved external attribute bytes in owned locations with original precedence. Git's default/global attributes search must be captured independently of config-list output: `core.attributesFile` may be absent while the default attributes file exists. Do not guess an installation's system-attributes path. Native profile must provide a complete, verified capture or refuse that unresolved source; supporting ordinary defaults is a required proof, not a reason to force all callers to specify a path.

External filter drivers/processes, fsmonitor executables, hooks, promisor/lazy-object access and uncontrolled helpers must never run during staging or publication. If an **effective active** payload filter needs them, refuse before caller effects; deleting its config and writing raw pointer/untransformed bytes is incorrect. Built-in `ident` and `working-tree-encoding` are not external executables, but their byte-equivalence/platform rules need separate parity tests; initially report them as specifically unsupported on payload rather than pretending they are arbitrary scripts. An unused filter config key alone need not reject a package whose effective attributes never select it, but it must not enter execution config.

Stage with the retained object database and explicit operation-owned worktree/index, using the same trusted Git and allowlisted captured built-in semantics. All input objects must exist locally; no source-store alternates or lazy fetch. Detect gitlinks and leave N4 unsupported before caller publication. Capture/verify staged manifest, selected HEAD, file set, payload bytes/modes/symlink semantics; conversion failures happen entirely in scratch.

For warm slots preserve existing Git identity/refs/origin semantics: snapshot their supported `.git` metadata into owned staging, execute using **only generated admitted config** (no includes, scripts, ambient lookup), and apply only the existing intended index/HEAD/ref changes. Restore captured user config/attributes as inert bytes after the final native command; do not execute Git against that restored authority. Do not replace a warm checkout with a fresh clone that silently drops unrelated refs/remotes/config. Linked worktrees, reftable/alternates or opaque layouts require their own capture proof; unsupported is typed. The exact portable directory/symlink admission must reuse current filesystem ownership rules.

### C. Publication and recovery: extend the current owner, fix timing

1. At `vibe-install` admission, prepare **every** native materialisation and validate configuration/source/transform capability before the first `files.manifest.publish`. Update Fetched/ResolvedDep metadata only in memory from the already retained candidate; no re-resolution.
2. Move deferred **native** slot publication into the existing workspace materialisation pass, through a narrow prepared-source placement callback/input. The workspace creates its existing `InstallRollback` before calling it; it records the old slot and `.gitignore` before any placement. Remove the native path's current before-workspace side effect and already_placed undo bypass. Keep legacy/unbound paths unchanged unless a deliberate shared fix is separately reviewed.
3. Publication rechecks expected slot identity, old HEAD, **effective and recorded origin**, captured config/attributes and retained selected-object ownership. Use existing `before_replace`/move-aside storage for a fully staged replacement, retaining the old directory rather than remove-then-rename. Transfer the same undo log into `InstallOutcome` until lock/provenance publication succeeds. Pre-install/boot/lock failures restore deferred slots too. No second registry-owned transaction journal.
4. Extend the existing rollback step for these deferred native slots with a receipt identifying the published staged tree/name. Undo must not remove a replacement written by another actor; report conflict and retain old stash for recovery. Current path-only `remove_any` is not sufficient for that claim. Cooperative publication windows must be documented; do not call them hostile-race CAS or crash-atomic replacement. Preserve primary error plus rollback error.
5. `PreparedInPlace::materialise` and direct `bring` callers must not bypass this safety: the new admitted materialisation either uses the same narrow placement/receipt owner or refuses **before** deleting/mutating a caller path. Do not relax generic run/raw/reported/preflight_materialisation wholesale. Fresh and warm registry-cache placements need the same specific admitted operation; this must be explicit in the implementation packet, not an implicit legacy bootstrap fallback.

## Smallest useful implementation perimeter

**N2a — capture+staging with actual reader, no publication capability yet:** `git_backend/shell/native_admission/{metadata.rs,context.rs,preparation.rs}` plus bounded `capture.rs`/`materialisation.rs`; retained record in `native_admission.rs`; exact dispatch in `shell.rs`/`git_backend/mod.rs`; `git_package_registry/fetch/prepared.rs` retains staged materialisation and performs early refusal. This yields useful read/stage results while original N1 guards remain.

**N2b — complete native local placement vertical:** the same staged record consumed by `vibe-install/src/apply/{metadata.rs,deferred.rs}` and `apply.rs` before metadata publish; `vibe-workspace/src/install.rs`, `install/{hook_output.rs,model.rs,rollback.rs}` admit the narrow deferred placement/receipt input and retain undo through final lock commit. `fetch/bring.rs` only gains materialisation when it uses this exact safe path. Existing `FileGuard` remains metadata-only. No new general transaction system, persistent wire schema or public source policy flag.

N2 is accepted only after N2b proves publication/rollback; N2a alone is not “safe install complete”. Exact callback signature must keep the dependency direction (workspace owns filesystem publication, registry owns source bytes) and must not introduce workspace→registry coupling. A source-specific placement interface/closure is enough; do not create a generic command executor API.

## Experiments and discriminating gates

Local script `/tmp/vibe-n2-materialisation-probe.py` ran on Git2.53.0. Corrected recipe produced byte-for-byte parity against actual legacy checkout for explicit LF, explicit CRLF, global-attributes CRLF default and binary files. The same source with a real smudge filter executed that filter and changed bytes under legacy; blindly stripping config produced different bytes. `check-attr --source=<selected commit>` detected the active filter without executing it or changing target bytes. Selected Git reported included-config origin and effective B separately from recorded A. These prove **selected fixtures**, not complete capture/publication.

The first recipe failed with Git128 because I omitted an explicit worktree from bare checkout-index. Corrected command supplies an operation-owned worktree. Failed script/receipt and corrected full command stdout/stderr/exits are retained. No public or loopback network was needed in this N2 experiment.

Implementation RED/gates:

* Real `apply` request with known unsupported payload filter: manifest/lock/provenance/slot/ref/origin/.gitignore hashes and all external marker/contact counters unchanged. This catches today's manifest-before-native-refusal timing; testing only direct materialise is insufficient.
* Effective warm B from global/local/conditional include and caller `GIT_CONFIG_*` is captured; excluded B zero contact, allowed B exact selected objects. New config/include/branch/default-attributes drift before publish refuses. No raw-A substitution or guessed config path.
* LF/CRLF/auto/binary and hierarchy/global/info attributes parity against real legacy checkout, both fresh and warm; external process filter marker is zero under typed refusal; LFS-like pointer is never silently accepted as payload. Supported symlink/mode and no-op refresh semantics remain accurate.
* Owned candidate mutation/config/alternates, old slot/HEAD/origin replacement, unsupported worktree layout and promisor stores refuse before caller effects. No uncontrolled hook/fsmonitor/filter/lazy fetch during staged checkout or cleanup.
* Failure after first of two native placements, pre-install callback failure, boot failure and lock/provenance failure restore **both** old slots and relevant refs/config/untracked bytes. Rename failure after stash restores old name. Concurrent replacement before undo is preserved and returns rollback conflict with retained backup.
* Successful fresh and warm full native materialisation from N1 verified TLS acquisition; no additional network during stage/apply; exact selected commit and expected checkout bytes; unrelated warm refs/config retained; old debris only removed after admitted publication. N1 HTTP-only/native generic guards and unbound controls remain green.

## Remaining proof boundaries

No complete production ambient/default-attributes capture or nonexecuting metadata-reader proof has been established yet. No rollback experiment against the product was run. Whole-tree checked undo is an extension of an existing owner, not something already guaranteed. Minimum Git/platform support remains N1-qualified Linux2.53.0 until tests broaden it. SSH, submodules and redirects remain N3/N4; external transforms are explicit typed limits until safely supported, never silently stripped.
