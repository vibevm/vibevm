Root design boundary,2026-11-05. Implementation required; not a delivered portable milestone. Builds on accepted c5662ee42 runtime and the three reviewed portable/auto/presence investigations. The existing finite import and ordinary operation/dependency owners remain authoritative; no second solver, generic serializer, routing database or environment framework.

## Transport and historical meaning

Add vibe-apps/2 at schemas/application/e2/apps.jtd.json with closed typed legacy-effective and configured rows. Retain apps/1 reader/writer compatibility. Full export is explicitly selectable with app export --configuration; it is also selected when the chosen manual roots plus their recorded required-Auto closure contain state apps/1 cannot preserve. Legacy-only ordinary exports retain successful apps/1 behavior. --all and --installations-only retain their existing selection/arrangement purposes. Both current default TOML and --json must support the full form.

Complete source input retains profile/policy, enabled/disabled/default feature intent, every selection object (including dormant and present-but-omitted members), exact/additive intent and public typed parameters. Preserve typed historical definition/fingerprint, retained automatic reliance, parameter type/origin/lexical source and value-free secret provision. Optional source realization is historical context, not target execution authority. Recompute target controls/questions/effective values/readiness; never manufacture resolved fields just to fit a ready local record. A narrow historical view shared by existing local records and the new portable projection is approved.

New portable None fields use omission. Preserve present empty arrays, false/zero/empty strings and parent map entries; do not prune them. JSON null may be a None alias only where the new schema declares it nullable and the actual reader agrees; export canonically omits None. Current canonical required-nullable JSON input/record rules remain unchanged. Use typed adapters, canonical signed-i64 strings and existing validators. No arbitrary JSON-in-string/Value payload representation. If a concrete generator shape cannot express the selected representation, report that exact boundary before inventing a general framework or weakening readers.

## Target decisions and secrets

Add app import --target-input FILE for a strict JSON vibe-app-import-input/1 document, with finite per-exact-package-key target inputs. They can select a target installer, bind public Path parameter IDs to explicit absolute target-native paths, acknowledge the exact current definition, and provide an explicit complete target configuration submission when the operator really chooses reconfiguration. Such a submission reuses the existing common input shape and must bind the current definition. Its presence is an intentional target replacement; the portable source file itself is never a fresh-defaults approval.

A path rebind changes physical realization without falsely turning profile/default origin into an authored Explicit override. Imported A paths must not be resolved against B's cwd or required to exist on B. Apply B validation (including must_exist) to the bound B realization. Subsequent B maintenance must reuse that realization. Bindings for absent/non-Path/secret values or mismatched identities refuse. Existing typed source/realization owners should be extended narrowly, not replaced.

Add app import --secret-input FILE for strict JSON vibe-app-import-secrets/1, keyed by exact application key and parameter ID. Support stdin '-' for this ephemeral input, read once; do not allow ambiguous competing stdin consumers. Values go only to the actual matching application operation. Ordinary console secret prompting remains supported. No unscoped --set broadcast. Unknown/private classification errors are value-free. No secret answer, digest, raw input document/path or replay argv enters index, cohort, work, public output or logs. Known previously Explicit provision (including optional secrets) creates resupply obligations; default/absent/legacy uncertainty retains honest distinctions. Authored public definition defaults remain public under the existing contract.

Source or target public input that maps a value to a target secret must refuse before that value is persisted. Exact private input structures are decoded at the boundary and converted immediately to an ephemeral redacted/non-serializable owner; a generated transport Debug value must not become diagnostic output. Value-free provided-ID obligations may persist and can strengthen, never silently fall back to defaults after a park.

## Export, existing installations and dependency closure

Full export requires a coherent ready snapshot under the existing home mutation boundary. Refuse unfinished relevant operations/cohorts, including an unindexed replacement over an older ready record, before opening/truncating output. No claim of source authentication or all-payload-byte reproducibility follows from a configuration snapshot.

Capture required Auto closure of selected Manual roots through recorded exact requirement edges, including legacy intermediates with configured grandchildren. Keep Auto meaning; unused Auto data must not be promoted or gratuitously installed as Manual. --all may include additional data without pretending it is an independently requested root.

An imported exact configuration binding must be considered BEFORE the incumbent installed-first shortcut. Compatible range spellings leading to one exact key share one real installation; incompatible same-key configured bindings refuse before effects. A newer satisfying installed version must not silently discard the imported exact configured binding. Existing Manual installations are never demoted by dependency consumption. Reuse only compatible public configuration/binding state; changed configuration uses ordinary explicit reconfiguration/review or refuses. --skip-installed remains an explicit reported skip, never a declaration that differing imported intent was applied, and cannot license a dependency consumer to use an incompatible bound configuration. Preserve holder/visibility/arrangement policy through existing owners, once per actual selected key, independent of dependency visitation order.

Target-only dependencies not represented by source history use ordinary resolution and truthful input requirements. Do not fabricate history or silently apply a different imported binding to them. A refusal or explicit reconfiguration requirement is preferable to invented old defaults; the user must receive an actionable ordinary route.

## Finite preparation, continuation and compatibility

Keep public target inputs fixed before their binding is consumed; prefer complete public preparation before beginning the finite cohort rather than introducing late mutable per-child configuration. Missing public choices/path/review produce typed preparation questions or refusal before package effects. Cohort resume must not replay mutable public files or alter already-started inputs.

Secret resupply remains ephemeral and application-scoped on initial import and resume. Preserve source/public preparation so the original portable/target files may disappear after the operation begins. A configuration or secret question must not be mislabeled Installed/Skipped or silently converted into terminal refusal if the documented workflow promises a resumable question. Conversely, never restart an absent child work record after uncertain effects merely to make resume green. Use the existing backward parent/row identity and exact attempt owner. Show the concrete before/after transition table before modifying private continuation schemas.

The private import-work owner may advance to an explicit protocol2/schema application/e2/import_work if its state shape needs that change; keep strict old1 readability, truthful archived metadata and no migration on read. Do not renumber steps2/index4 merely for convenience. Derive dependency binding scope through the existing verified cohort/parent ownership where possible; demonstrate a genuine gap before duplicating it in every child. Direct child resume must reconstruct binding scope for not-yet-run grandchildren. Completed cleanup/finalization must not start unused source/executor/secret preparation.

## Required complete outcome

Actual A export (JSON and TOML) → B import → B modify/update/repair must preserve original/dormant/empty/additive/profile/default-basis meaning. A path must be absent during the B test, B bindings must survive changed cwd, optional previously Explicit secrets must resupply without canaries in durable artifacts, and changed target basis/privacy must refuse or require explicit review. Include real parked parent/child/cohort continuation after source-file disappearance, scoped same-ID secrets, compatible required-Auto reuse, installed-newer adversary, Manual-mark preservation, conflicting binding refusal and legacy format compatibility.

The export/codec stage alone is not completion. Do not advertise a new CLI success that cannot import or resume. Stage independent internal foundations as useful, but continue through the actual operation owner and public journeys before claiming this portable feature accepted. Native Windows/Mac qualification remains separate from Linux execution and cross-host lexical fixtures.
