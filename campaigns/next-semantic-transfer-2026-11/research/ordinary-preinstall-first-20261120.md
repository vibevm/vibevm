# Source-bound ordinary configuration preview — implementation candidate

Contract: NST-ORDINARY-PREINSTALL-FIRST-01.md. This is a bounded candidate, not NST closure or all-kind describe/evaluate parity. Independent acceptance and final exact source/binary receipt are pending.

## Owners and public contract

`vibe-package-source::configuration_preview::configuration_preview` is the shared read-only operation. CLI `vibe show configuration-preview PACKAGE --path PROJECT [--input FILE] --json` supplies a trusted project root and optional bounded JSON answers. Registered MCP `configuration_preview` accepts `{package,input?}` inline and takes its root from ServerContext. Neither request carries a package source path or URL. The ordinary request/result are canonical JTD registrations generated into vibe-wire, not app-envelope aliases. Installed `show configuration-data`, `query_package` and selected app configuration retain their owners.

An unanswered request returns typed choice/parameter description and questions, without synthetic consumer answers or resolved features. Explicit selected choice and public bool return original maps separately from derived features/parameters. False remains an actual answer. The common decoder refuses explicit `input:null` before source access; this guarantee belongs to `vibe-wire::behaviour::ordinary_configuration_preview::parse_request`, not the raw generated `Option<Input>` serde implementation. A CLI file containing null is refused by the generated Input reader. Unknown fields/types/app envelopes refuse.

## Admitted source and definition

First support is a cold standalone project with an exact compulsory unanswered ordinary flow requirement, one explicitly declared unauthenticated local registry physically nested under the trusted project root, one concrete version directory, one visible unguarded exactly-one choice without defaults/profiles/extra features, and one required public bool without default. Forwarding/subskill/conditional source effects remain unsupported. Answered evaluation uses the existing ordinary normalization/evaluation owner, not a second resolver or persisted plan.

The positive host mode requires `VIBE_NO_DEFAULT_REGISTRY=1`; CI alone is insufficient. The already installed immutable startup Locator must have Allow policy and only RawFile-only rows proven inapplicable to ordinary package sources, with no invocation remap source. No second remap discovery or resolver is introduced. User settings.toml and project .vibe/settings.local.toml must be proven absent no-follow without reading their contents; declared root remaps refuse. The operation never sets it and requests cannot supply it. Existing ambient registry/site/cache, local registry overrides, retained lock, competing project-local registry and unknown/inaccessible layers refuse. Absence is proven no-follow through Project::pin_absent_path, not a best-effort list silently collapsing errors. No user/auth configuration is read by the preview operation to select a source. External file URLs do not grant directory authority.

`vibe-registry::local_preview::observe_local_preview` is the narrow source owner extension. All reads descend from the held Project/Pinned root, with bounded directory enumeration, regular single-link bounded file snapshots and complete before/after source observations including directory identities. Manifest parsing uses bytes from the same observation that supplies the content hash. The existing legacy hash recipe/order/excludes are reused unchanged. Limits: 1024 entries, depth16, 1MiB/file, 8MiB total; outside these forms the operation refuses rather than truncates. Sibling version/template routes refuse instead of invoking ordinary template acquisition. No cache/store publication, install, hooks, network or extra solver is used.

This is observed operator source evidence, not supplier authentication, a new unambiguous member hash format, or an atomic guarantee against unrestricted hostile same-user mutation. Ordinary install semantics remain unchanged.
