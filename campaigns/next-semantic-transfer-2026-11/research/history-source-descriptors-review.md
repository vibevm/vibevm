## S1 — One pure declaration selector, with an unresolved package empty-list boundary

`2928123034787ead067f508a8fa6597e61539ed0` introduces package descriptor grammar/selection in `vibe-core/src/manifest/source_descriptor/mod.rs`, package wire/meta fields and eight focused tests. `11eefad1ff16420c20de1874bfdc26ef3dcc640b` adds project.sources and extracts the same `select_source_rows`; it is reuse of one precedence law, not a second project classifier.

At final pin the row grammar remains strict: exactly one normalized relative `file` or `directory`; all four fields `media`, `interpretation`, `role`, `loading` required. There is no inferred media/loading default. `directory` matches descendants across a component boundary, not the directory itself or textual siblings. Exact file beats all directories; otherwise longest directory wins. Equally specific identical rows coalesce, conflicting rows return path-specific NeedsInput with authored indices. No match is Unclassified. Unknown fields (including authored `trust`) refuse. Generated current INDEX/STATIC paths refuse even through directory selection.

Media/role pairs: vibe-spec + spec permits text/markdown or application/xml; vibe-doc + documentation requires application/xml; commonmark + documentation/resource requires text/markdown; xml-data + resource accepts application/xml, text/xml or normalized +xml; opaque + resource/documentation accepts any valid normalized media token. Names and paths do not grant trust. Materialization separately limits VibeDoc to Doc packages and Vibe semantic inputs to supported specs-root/README layouts. Package format Simple/Normal remains independent of descriptor interpretation and boot linkage.

`package/source_export.rs` at pin defines package-only source_exports: ASCII `[A-Za-z][A-Za-z0-9._-]*` name, normalized exact relative file, nonempty ordered headings with normalized whitespace/no controls. Package wire serialize/deserialize rejects duplicate exact names. Parsing does not prove the file exists, selects CommonMark or has a unique heading. `vibe-facts/.../declared/export.rs::resolve_declared_export` supplies that later join: exact declared export, CommonMark/text-markdown descriptor, matching observation/resource/declaration/witness, then heading resolution over the same parsed snapshot. This produces an ordinary resource selection, not a Vibe fact. The public spec query below does not expose this named-export route; do not count a constructor/library helper as complete export delivery.

**Package and project compatibility contracts must be read separately.** Final PROP-072 SOURCE-HOST-OPT-IN explicitly defines project absent/empty as legacy; SOURCE-DESCRIPTOR-GRAMMAR/PRECEDENCE and SOURCE-REPRESENTATION-COLLISION do not explicitly decide an empty package list, and referenced PROP-045 SOURCE-CLASSIFICATION-LAW does not settle it either. A different package policy could therefore be intentional; applying the project rule to packages would be an unsupported inference. Project sources defaults to an empty Vec, omits it on serialization, and `SOURCE-HOST-OPT-IN` expressly preserves absent/empty legacy semantics. Package materializer `derived/selection.rs::read_descriptor_package` and installed `descriptor_map.rs:152–155` instead inspect raw TOML **key presence** of sources or source_exports; `sources=[]` opts into raw/unclassified preservation and an empty Vibe address map. In contrast facts CLI `authored_for_selected:287–289` selects legacy scanning on `meta.sources.is_empty()`. Checkout citation also uses empty rows as legacy. Consequently an explicit empty package list can be raw to install/map but suffix-semantic to facts; source_exports-only metadata has the same boundary risk. This is a concrete disagreement between package consumers under an unresolved package empty-list contract, not proof that the materializer alone is wrong or that all legacy compatibility is a bypass. If explicit empty means package opt-in/no sources, facts must not fall back; if it means package legacy, materialization/map must agree. The project contract already says empty is legacy.

## S2 — Installed maps bind local record consistency, not original source proof

`00ce69ab54c033cfe9bd736b5f20345fb7f6c7ad` adds `ValidatedDescriptorMap` and workspace `read_validated_descriptor_map`, injects maps into FileResolver point lookup, and adds actual materialization/resolver tests. Output-path collisions and raw-resource attempts to claim document_address refuse. Known descriptor root with missing map refuses; unmarked roots use the legacy resolver route.

Final map reader (`vibe-workspace/src/vibedeps/descriptor_map.rs:130–353`) captures a held slot manifest, checks selected coordinate, reads/validates slot record and independent expected source hash/target format, checks recorded manifest hash, derives source→output rows from original paths and transformed dispositions, observes selected output bytes and rechecks manifest/record/output states. Later code preserves materialized media separately, including conversion target media. Map shape validation now uses shared SafeFS path_identity_key rather than its initial lowercase-only alias key. Original source path, materialized output path, semantic document address, package hash and local output hash remain distinct, usefully.

The final legacy early returns were read, not inferred from Option: no-descriptor/no-record with allowed legacy posture rereads its manifest before None; no-descriptor with record validates manifest/record/selected expectations and rereads them before None. Citation callers can require a record for copied slots, while in-place legacy sources explicitly use a weaker live-manifest contract. Removing descriptor rows from a copied manifest cannot silently pass when the existing recorded manifest hash disagrees.

**Guarantee limit:** the record contains output digests and package-wide source_hash, but matching that claimed package hash to the lock is not recomputation of original content or proof of transformed derivation. A coordinated record+payload substitution is not excluded by this map alone. The original code and the historical task amendment explicitly say so. `ValidatedDescriptorMap::from_witnessed_rows` is also a public caller-trust composition seam; supplied digest strings pass logical validation without performing physical reads. No source-proven label should be inferred from the type name.

**Cost and observation choices:** construction reads/rechecks the entire selected map (up to 4,096 outputs, 64 MiB per output and 256 MiB total; manifest 1 MiB/record 8 MiB) before returning paths. Simple boot subsequently reconstructs a map per entry and reopens its selected output; classified point reading also observes bytes after map creation. Rechecking is meaningful, but redoing the complete map for each selected consumer is a concrete consolidation opportunity. `selected_specs_root` still uses pathname metadata; materialization `collect_files` and source-query preparation still enumerate ambient directories, with later bounded/held validation. These are finite cooperative observations, not a sealed whole-tree snapshot. Main's accepted held readers permit shared regular inodes and do not impose a fixed arbitrary source-byte cap: importing the prototype's state-style bounded reader requirements wholesale would regress that contract.

## S5 — Planning/acceptance evidence and target decision

`960bc3e20dfb9ac1d4209648fc34238b101be1dc` adds descriptor map/boot/replay/resolver-test paths to M-06-A.3's packet and explicitly says the first reader is a retained-record/output consistency map, not transformed-original proof; lifecycle-agent/citation routing remains due at A.4. Five seed contract hashes and one manifest task-file hash update accordingly. This records discovered integration scope rather than runtime delivery. It does not excuse leaving required consumers unreviewed during transfer.

`d40d02cb62fdbbbae153565d9540d8712c9d1103` adds an 11-line bounded source-consumer review claiming focused historical checks and selected descriptor behavior, with explicit no-descriptor/standalone/in-place/unsupported/native limits. This audit did not execute or validate its historical test counts. It is useful evidence of intended narrowed compatibility, not grounds to override the final prompt/pattern/citation bodies described above.

**Causal conclusion:** filename-derived meaning caused conversion collisions and premature parsing; explicit interpretation plus one selector solves a real problem. Map/output/byte/original identities protect different invariants and should not be flattened into one trust flag. Avoidable complexity appears where each consumer rebuilds and reparses the same selection facts, drops captured bytes and reopens a path, or adopts a different empty-list rule. Another universal source-world framework is not demonstrated necessary to fix those seams. Main already has better held source reads and point/pattern/anchor selection; preserve them.

**Concrete next design decision:** freeze the package opt-in rule, including explicit empty lists and export-only declarations, separately from the documented project absent/empty compatibility, then define the end-to-end promise “declared ordinary resources remain literal while declared Vibe sources alone gain semantic addresses/facts/transformations.” Recommendation for root review: preserve the documented project empty/absent legacy rule; require one consistent package decision before integration. A nonempty descriptor list owns its source classification, with unmatched files raw; a named export must select CommonMark before use. Keeping the materializer's explicit-empty package meaning is possible, but requires preserving empty-vs-absent in typed/serialized manifests and facts consumers. Treating package empty as legacy is a deliberate alternative requiring materializer/map changes, not something the project clause already authorizes. Do not leave the distinction dependent on raw-TOML versus Vec inspection.

The smallest **complete consumer set for that promise** is the existing materializer/slot-record owner; selected point/pattern/embed/prompt reads; node/static/dynamic boot lowering; facts/requirements/adoption and host sync; doc citations; show/tree/check/progress readers that parse or write semantic state; and their actual public command adapters. Each must consume the same classification and selected byte identity or report a precise unsupported operation before mutation. Directory defaults require the same validated descendant inventory where completeness is claimed. Unsupported cells must remain visible obligations until the selected migration is completed, not silently removed from its scope. Reuse main's held byte owner and one selected-map result instead of carrying independent loosely related paths/hashes through every adapter.

An independently useful explicit CommonMark/XML-data inspector can land before this full opt-in migration because it selects its parser explicitly and does not change existing global semantics. That separation does not finish or shrink the broader descriptor feature; authored named exports likewise require an actual public read/navigation consumer, not just grammar.

**First discriminating runtime test after design approval:** use a real local registry package with a raw `guide.md`/`guide.xml` same-stem pair, an explicit Vibe XML document stored under `.md`, directory default plus exact override, and a CommonMark named heading export. Install in Mixed and XML target modes. Verify raw bytes and whole slot stay intact; selected point/pattern/prompt/facts/doc/boot consumers agree on interpretation and media; raw markers never become facts; missing/ambiguous selected data refuses without writes; a post-map/pre-read replacement cannot enter the parser; absence/empty/no-descriptor controls preserve the chosen legacy contract. Also drive the new explicit export consumer to a unique heading span with unchanged raw bytes. These are proposed tests, not executed results. Root owns the feature scope and acceptance decision.
