# Common application configuration: first complete consumer

Root decisions, 2026-11-04. Design, not delivered behavior. Read with PROP-069, the existing app contracts and common-app-vertical-design.md. This work must finish an ordinary selected-installer journey; it does not close package solver/loading or the all-kind campaign.

## Scope and ownership

Global app install/plan/modify/update configure the selected installer. Source acquisition is not another implicit package configuration instance. Retain package kind, package configuration and requires data for truthful separate descriptions; do not execute package effects while acquiring installer source. Package and installer IDs never merge. Remove each temporary unsupported guard only when its actual consumer is connected. Keep ordinary workspace guards until that separate consumer works.

The shared ChoiceModel/FeatureModel and ConfigurationDecl normalization remain the only group/feature algebra. Add missing complete evaluation/typed projection capability to core where it is genuinely kind-neutral; keep host path checks, prompts, installation ownership and mutation in app. No fake legacy InstallerOptionDecl, duplicate validator/evaluator, new global service, parallel choice database or generic execution runtime.

## Submitted input, reuse and deltas

AppConfigurationInput retains existing ConfigurationIntentDecl plus explicit disabled_features. Public typed parameters only; raw secret assignments stay ephemeral. One ConfigurationSubmission contains a complete input and optional expected_definition fingerprint. Supplied complete input replaces recorded original input. Absent submission on modify/update/repair uses recorded original input; an old effective-only record is never called original intent. For a fresh operation with no complete input, begin require-selection, with ordinary feature defaults allowed as the established normalization specifies; missing choice answers become actual questions. Assume-yes never answers them or selects a default profile.

Existing --profile/--feature/--no-feature/--set remain explicit deltas. Apply the delta to the working original input, then materialize it before evaluation/recording. Profile replacement preserves explicit group/parameter overrides; complete replacement is the reset operation. A new positive feature clears its own old negative. A new negative clears its own old positive and older direct descendants whose parent chain includes it; newly contradictory flags in the same request refuse. New direct additions can replace older direct selections in an at-most-one closure group using the existing kernel's rules; do not erase consumer-choice answers just because their guards become inactive. A newly selected implication conflicting with a retained independent negative stays a named conflict, not guessed consent. Validate public visibility for direct negative and positive feature requests. Full choice-group replacements preserve exact/additive and omitted/[] distinctions.

The actual app installation/option supplies consumer identity. Switching installer does not reinterpret same-spelled previous answers automatically: request fresh input or explicitly accept a displayed transfer through the same validation. Legacy effective values can be labeled suggestions; never fabricate profile/default/exact provenance. install --force with the same rich option preserves its original input unless explicitly replaced.

## Defaults and semantic identity

A fresh complete submission with explicit use-declared-defaults policy authorizes evaluating the actual current definition in that operation. It does not claim that a dialog was shown. A split client may supply expected_definition and the host must compare it with the selected actual definition before effects. A mismatch refuses even if the submitted answers otherwise happen to work. No host bootstrap or mandatory second ceremony for ordinary local operation.

Record original input, effective result and a host-computed review basis when evaluation relies on implicit/default/profile meaning. Retain the historical typed definition snapshot needed to explain before/after review even when a local source was edited in place; it is historical evidence, never a second current definition authority. Retained policy is not permission to renew a changed basis. Basis uses a versioned deterministic typed semantic projection of the configuration, with canonical set ordering and exact typed values. Include relations, visibility, guards, cardinality, defaults, parameter rules, profile contents and effects/config-value data. Exclude labels, descriptions, presentation order and the UI-only default-profile marker. This is a stale-meaning check, not authentication of the entire source tree. No arbitrary TOML-to-JSON lossy hashing and no answer-secret hashes.

A whole semantic definition is an explicitly conservative review basis for automatic inputs: it may require review after an unrelated semantic change. Record why the basis is relied on (profile, feature defaults, omitted choice defaults, closure fallback, parameter default/absence). Keep dormant automatic choice reliance, including an omitted group whose default is currently absent, so a later default cannot be silently adopted. Retain previous reliance until the corresponding original input is explicitly replaced. Newly introduced reliance on maintenance also requires review; absence of an old receipt is not acceptance. Fully explicit input without automatic reliance validates under the new definition and survives unrelated default changes. Removed explicit/dormant IDs produce named reconfiguration, never filtering. Automatic closure fallback is observable through the existing implication reason; do not invent a second closure walk to infer it.

Review is an explicit attended decision after showing the changed meaning, or a complete current submission with expected_definition from the new view. Unattended reuse returns structured rediscovery before dependencies, uninstall, steps or publication. A raw expected_definition string on an otherwise absent/reused input does not silently replace original intent. Keep old basis until explicit acceptance, not merely describe/read. Any more precise partial basis is a later improvement and must retain these guarantees.

## Parameters and effect data

Reuse ParameterDecl canonical validation, including redaction, for legacy and common effective declaration slices. The existing type default is fallback for an absent parameter; ChoicePolicy controls choice-group omission, not a new kind-specific scalar rule. Apply explicit public parameter inputs above profile presets above declared defaults. Keep origin separately from canonical value. A required absent parameter becomes a typed question. Boolean false must remain false in existing step conditions. Config-value effects select typed inspectable/persisted DATA; they are not promises to write configuration files. In this single-definition app scope each ConfigValue effect refers to the one config_values map: repeated selected references deduplicate the named value and retain contributing feature IDs. Different values for the same key cannot be authored here, so no synthetic conflict mechanism/test is added. The broader actual multi-source consumer conflict requirement remains in PROP-069.

Retain raw original public path input, origin and its canonical absolute realization separately. Profile/default realizations never become synthetic explicit input. On stored reuse without a fresh setter/full replacement, keep that realization when origin/profile ID/lexical path source is unchanged and the type remains Path. Current validation rules are checked separately: changing must_exist/bounds/allowed-values must revalidate the old realization, never re-anchor it to the new CWD. A new common realization must be absolute and losslessly representable in its text transport; a failing host resolver must not save a relative path. Changed origin/source requires current host resolution after the corresponding review. Do not resolve the old relative answer against a new CWD and silently change its meaning. Keep an absent optional value explicit in the result/origin, so an added default is a meaning change.

Secret input is classified by the selected declaration before any serialization. Persist only value-free provided/resupply metadata; no reusable digest. A formerly supplied optional secret cannot silently become absent/default on continuation. It must be resupplied through the ephemeral channel or explicitly cleared through a supported fresh reconfiguration, not a fake exact replay. Existing authorized recipe/shell environment remains the transport; agent/native secret transport is not added.

## Completion, including continuation

Deliver together: ordinary local-registry describe → answers/evaluate → plan → real install → new-process modify/update → rollback/repair. Keep old wizard and successful legacy wire routes green. Include pending rich work/secret resupply and hosted resume safety before claiming the app journey complete. The new canonical application continuation is `vibe app resume GROUP/NAME@VERSION --operation ID` with explicit `-g` or `--path PROJECT` in generated commands and ephemeral secret --set/hidden prompts. Both exact package key and generation are required; there is no latest-operation lookup. A stored request is reused, never a new complete submission or replay of profile/public --set/config-file/stdin arguments. Public deltas refuse on resume; reconfiguration starts fresh. Root/child bindings and source routes are typed metadata in existing steps2, not credentials or shell argv. The formatter receives only a value-free pending target; no unsafe old-argv fallback.

Application resume dispatches the saved closed operation kind through existing install/update/modify owners. Whole-import continuation has its own exact cohort target and `vibe app import --resume OPERATION_ID` route, as refined below. Persist source route, exact predecessor and narrow phases around dependency descent/removal/publication. A crash during arbitrary external removal is an explicit uncertain outcome; do not certify or automatically repeat it. Linked child pending work is checked before indexed/same-choice shortcuts, including finish-parked children. The dedicated home-aware route can resume a project child before index publication without editing workspace requires or installing into the user home. Whole-import continuation retains its finite row cursor/completed rows/held+skip policy and pending arrangement, stops at the first delegated row, then resumes the same loop. Row-only continuation is not whole-import completion. The earlier raw-argv formatter proposal is superseded for the new path; compatibility paths must not leak values or claim stronger provenance than protocol1 contains.

Mandatory discriminators: exact-one/multi, omitted versus [], dormant switch-away/back, changed default/profile before mutation, fully explicit stable input across default changes, removed dormant ID, bool false actual step, typed integer bounds, canonical path across CWD restart, selected config-value data and contributor projection, legacy3 read and success-only rich4 write, rollback preserving original old rich record, force repair preserving input, cancellation, stale split fingerprint without publication, secret canaries absent from framework artifacts, optional secret resupply, recipe/shell identity rejection, selected legacy option beside rich option, separate package/installer IDs, callbacks and generated external answers producing the same outcome. Root acceptance requires real public CLI behavior, not only parser/evaluator tests.


## Continuation and portability compatibility refinements (2026-11-04)

Canonical generated continuation and app resume require an exact operation generation. Existing explicit manual install/update --resume retains its weaker current-unfinished-work selector for the selected key/home; with new state it reuses stored operation/input/source/basis, treating compatible repeated public flags as consistency checks rather than new deltas. Conflicting intent refuses; secret resupply stays ephemeral. It must not replay raw argv or silently renew defaults. Reopening completed retained work through a deliberate manual retry/from-step is a new execution generation, not reuse of an old delegation result. A successful optional runtime failure can leave Failed step evidence without an unfinished operation; preserve actual legacy retry eligibility and suffix/placement constraints. Skipped is settled in first-unfinished selection, matching the existing settled predicate, rather than rewinding completed work. Baseline body/test evidence: app-continuation-compatibility.md.

Index4 may also retain a value-free secretOrigins map when new legacy operations know explicit/default/absent secret provision; lossless-v3 eligibility includes this data. Secret Profile origin is invalid. An old3 record without provenance stays historically unknown on read/list. Its existing legacy fallback/default/required-prompt maintenance behavior remains a compatibility boundary, not proof of past secret absence. A newly completed operation records only what that operation actually bound. New known explicit provision requires resupply and cannot silently downgrade/default. There is no read-time rewrite or invented historical receipt.

Pending dependencies retain the actual finite PlannedDependency binding before descent, with child generation filled when started. Completed child work may be retained until its owning parent finishes to survive the child-completed/parent-checkpoint crash window; release follows original keep_work policy. A new unrelated parent must not resume another parent's/import's actions through a shared child. No refcount table, generic scheduler or full-slot before-image store is introduced.

Public work inspection must expose the actual generation needed by canonical resume after a crash even if no hosted fence was printed. Small optional application operation target/phase and retainedFor metadata are derived from pending work, never a second stored owner. The optional imports collection represents real independent cohort targets. Completed-only retainedFor explains why finished work is kept; cleanup protection also covers unfinished owned children. Existing step-failure evidence is not erased by overall completion. Root/import unfinished phases do not get fictitious steps; an unknown legacy step-state plus explicit operation phase is honest. Individual child cleanup refuses when its exact unfinished parent would remain; explicit same-home cleanup of the whole selected parent/child cohort remains available after preflighting the deletion set. Existing physical work directories are already home-local; the proposed home-hash expansion was retracted after reading the actual method and is not part of this design.

The first selected-installer candidate completes valid legacy import continuation but must refuse lossy legacy portable export of rich configuration and legacy-file import into a selected common installer before effects. This is a temporary boundary, not completed common portability. A REQUIRED next atom will design and deliver a typed portable rich format and real import/export roundtrip preserving original/dormant/exact/default meaning and value-free secret requirements. It must finish before the overall common-configuration feature can close; it is not removed from the campaign. Existing legacy portable effective/public-data projection retains its explicitly weaker secret provenance. No new portable epoch is silently introduced inside this candidate without its concrete format design.


Secret-default clarification: the established contract treats authored defaults/choices/labels as public definition data. A typed historical definition and semantic fingerprint may contain those literals, including a declared default on a secret-marked parameter. Runtime evaluated values and Debug remain redacted; supplied/resolved operation answers must never be injected into the definition or its hash. Origin=Default reports use of declared public data, not confidentiality of a literal stored in the manifest. This does not change legacy describe or make real credentials placed in public defaults confidential. Tests must distinguish an authored default from a different supplied override canary.


## Independent import-cohort owner — correction after actual collision (2026-11-04)

The first implementation put whole-import state in the first executing application's sole steps2 path. Root chose that reuse, and an actual public test disproved it: the first row created its checkpoint then failed before index publication; a later row required that same package and could not retry it because its work slot was also the still-live import. Relaxing foreign-work checks or overwriting that generation would lose the cohort. That ownership choice is revoked; it was never accepted into main.

Keep one finite cohort record under the existing app-work subsystem at `imports/<operation>/import.json`, protocol `vibe-app-import-work/1`, authored at `schemas/application/e1/import_work.jtd.json`. It owns exact home/id, public executor/lookup context, the preclassified public input, row cursor/outcomes/current child and arrangement progress. It is neither a package execution nor an installed record. Package steps2 removes its draft Import kind/cohort copy; package index.pending remains application-only. No generic operation database, scheduler, duplicated cohort state or fake package coordinate is introduced.

ApplicationImportTarget has home/operation. ApplicationContinuationTarget is one tagged mixed-owner reference: application with the existing ApplicationPendingTarget, or import with its real target and finite owning row index. Use that union only where either owner is possible (parent linkage, verified continuation traversal, retention). Private steps2 parent is required-nullable; null means no parent. Public optional retainedFor uses `{owner: <canonical union>}` through the supported named output projection, preserving ordinary e1 omission. There is no second semantic enum or JSON-string payload. Import results use required-nullable rowIndex; actual execution-row results retain their index/child attempt, while non-executing preflight/arrangement notes are distinguished. Recovery matches row, current cursor, selected source/public context and exact child generation, not only package key.

`vibe app import FILE` and `vibe app import --resume ID` are mutually exclusive modes of the existing user-home importer. The latter loads the original retained cohort; no file replay or unscoped --set is accepted. A child's envelope/context/generation stays child-owned, while its generated continuation command can name the exact verified owning application/cohort chain. Explicit child secret resupply remains `app resume KEY --operation ID`; completing that child then continuing the cohort must not repeat its prefix. Work inspection gains an optional imports collection and --import ID selector, not an invented application entry. Keep actual old-e1 reader compatibility checks.

Record an ordinary terminal row refusal durably before releasing that execution slot, so later rows/dependencies can retry the package under a new generation without replaying the refused row or overwriting the cohort. Never follow an old refused target into a newer generation during cleanup. Successful/active children retain their exact acknowledgement and retention safeguards. Cohort completion means all row outcomes and arrangement are settled; it never manufactures a successful installation for a refused row. Preserve the incumbent report and exit1 when any row was refused.

Explicit cohort cleanup preflights the whole selected set, preserves unrelated work and real step/failure evidence, and clears only matching selected pending references as needed for truthful fresh repair. It must not leave a dead index.pending reference blocking a later fresh operation, or delete a newer generation through stale metadata. Existing application work layout and older protocol1 compatibility remain; this new cohort namespace is a deliberate addition, unrelated to the retracted false cross-home collision claim.

## Scoped secret resupply is runtime provision, not immutable public intent

A declared secret may be explicitly resupplied to its exact application operation even when earlier provision was Default/Absent. Runtime supplied-ID membership is excluded from the immutable public execution digest; public source/plan/step/mode binding remains. Before any suffix effect, persist only the value-free strengthened resupply requirement, so a second park cannot silently fall back to a default/absence. Initially Explicit still requires resupply. Preserve initial/prefix provenance; a final record may describe its current Explicit binding but cannot claim the prefix used that new answer. Never store answer values or equality digests, and never broadcast a parent's same-named secret into a child.

Portable apps/1 carries public parameters. A parameter secret in the selected installer is refused before retaining portable input, rather than copied into cohort metadata. Use the ordinary ephemeral installer prompt/exact application route; this is a selection-aware admission correction, not permission to persist credentials. Rich portability remains a separately required next atom.


## Post-publication cleanup and hidden selections — reviewed follow-through

Update steps2 owns required `retirements` entries with `key`, `expectedRecord`, and state `queued|removing|removed`; `retiring` is an operation phase, not another database. Bind the victim set once before publication, retaining original record identities; do not extend it from a later inventory. Setup must succeed under the established required/optional rule before deleting previous versions. A terminal required finish failure keeps old versions and returns that failure. Parked setup resumes before retirement. A failed external removal may already have effects: persist Removing at the existing removal owner's effect boundary, preserve uncertainty and refuse automatic replay or success. Ordinary Fresh/from-step replacement cannot erase this evidence; deliberate scoped work abandonment is a separate explicit action.

Pure cleanup/finalization dispatch derives from the exact retained operation before looking up setup source or executor. A crash after index marker clearance and Published but before Complete must finish from the exact markerless result plus all-Removed obligations, not execute the installer or ask again for obsolete secrets. Argument/home/generation/current-record/victim checks remain; only unused setup dependencies are omitted. This does not authorize cleanup of a newer same-key record or certify arbitrary removal from absence alone.

Console editing of an active group's eligible members must preserve original members that are currently ineligible/dormant and not shown. Accepting unchanged prefill must not erase hidden choices; preserve the group's merge meaning unless a deliberate complete replacement changes it. Retained/profile/evaluated selection is the visible prefill, not today's declared default. Existing changed-default review and fully explicit controls remain.

Fresh agent consent is checked through the existing owner before package pending checkpoints, dependency effects or removal. Avoid double prompting when apply consumes that admission. A refused package does not get work created merely by the new continuation feature. Finite import can retain its own truthful per-row outcomes; package-level consent and cohort reservation are distinct and must not manufacture installed success.
