## Five already-centralized owner checks

- Network: CLI `composition/network.rs::route_for` consumes `vibe_core::net::route`; `vibe-net` handles session/transport. Do not move adapters into credential routing.
- Lifecycle: `vibe-orchestrator/src/prelude.rs` obtains `vibe_lifecycle::RunIdentity` and `LifecycleLease`; execution coordination is distinct from identity/lease ownership.
- Requirements: CLI `commands/requirements.rs` constructs `RequirementsQuery` and calls `vibe_requirements::query`, using `vibe_requirements::text::render` rather than reimplementing the report.
- UI preferences: CLI `commands/prefs/set.rs` uses `vibe_settings::cli::{run_prefs,PrefsOp,PrefsOutcome}`; layer selection and validation do not belong in the CLI renderer.
- Addressable actions: CLI `commands/prefs/tui/search/` consumes `vibe_actions`; address/keymap/search types remain with `vibe-actions`, not a new settings-specific action registry.

## Exit rule

No rewrite is authorized by a name or file count. Append the adapter trace, exact before/after consumers, deleted duplicates (or justified no-change), test receipts and independent acceptance. The dispositions above apply to the named paths: they are not a global absence-of-duplication claim. Next mandatory global pass keeps its original seven children and order, including initial and final synchronization with dirty work accounted for safely. NST-5 is a separate integrated verdict. Manual-only checks, including the blind adoption trial requiring runner provisioning, are SKIPPED by direct owner instruction / not executed (never PASS); automated failures are not waived. Freeze REMAINDER/IDE. No opportunistic feature qualification or new type cross-product on this route.
