## First material uncovered user route — actual public discriminator

User outcome: an ordinary flow author selects a valid ConfigValue effect and expects inspectable/replayable effective data under its existing package owner, not arbitrary config-file writes. The declaration parses and retains config_values.verbose=true. The actual `PackageConfiguration::evaluate_parts` still returns Unsupported for selected config-value inspection/replay.

One focused test in existing cli_common_package_optional/default_review.rs constructs exactly that authored effect on the selected disabled member and runs real offline install in a fresh isolated local registry. `nine-kind-gap-test-r1.log` records1 PASS establishing the refusal diagnostic, byte-identical authored input, no lock, no driver slot and no hook effects. Strict scoped lint, formatting and diff checks pass. This is an executed **R**, not successful feature delivery; source and binary hashes are in the private candidate manifest. No provider, remote download or publication occurred.

Next implementation boundary must be architect-owned: define the existing effective-data inspection/replay result and its consumer/persistence projection before replacing the guard. Do not turn ConfigValue into arbitrary filesystem writes or import a prototype solver. Forwarding/subskill/profile/parameter/transitive/source and per-kind public surface coverage remain separate gaps; one config-value repair would not close the matrix.
