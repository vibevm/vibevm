## 4. Three mandatory discriminators still not closed

### Ordinary install: preview is not apply

F12 proves shared source-bound read-only CLI/JSON/registered MCP answers. F13 proves real attended collection only on `show configuration-preview --interactive`, including source drift and terminal restoration. The same final ordinary94 suite retains the actual no-answer PTY test: `vibe install --offline --path PROJECT` exits before any configuration question under AUTHORED-SCOPES. Its serialized control calls preview, not install. Authored `[requires].configuration` install is E F1, but is not an external submit-to-install operation proving the same console request. No app `--configuration-input` or MCP tool is silently attributed to ordinary install. Consequently COMPLETE-JOURNEY/DESCRIBE-EVALUATE-PLAN/SURFACE-PARITY/ACCEPTANCE remain open even for this simplest Flow.

### Path: choose and bind host base before claiming must_exist

F10 delivers literal Path/must_exist=false only. Present and absent synthetic paths at must_exist=true both refuse explicitly. Core has no host base; process cwd is not authority. CLI/install planning has selected project-root context, but no accepted rule says whether consumer-node, workspace, source, or explicit native absolute target is the right semantics. A future planning-host contract must choose that base, containment and observation/replay policy and shared CLI/MCP behavior before admitting host validation. No ambient exists/canonicalize in pure evaluation and no blanket target-read grant. App target-path realization A4 cannot be copied as proof of ordinary semantics.

### Secret redaction: rejection and app proof are not ordinary delivery
