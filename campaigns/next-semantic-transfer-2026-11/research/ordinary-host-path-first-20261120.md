## Existing SafeFS seam

`Project::open` retains a no-follow root; `Pinned::open_child_checked` walks each relative parent without following links. `Project::source_file_present_in` uses capability-relative `symlink_metadata`, not a content read, for regular files; a terminal directory is opened no-follow without listing. Absolute/traversal/unsafe components, links/reparse and special entries refuse. Errors are mapped to static host-path diagnostics rather than resolved external paths.

The opaque proof retains root and parent handles/identities, lexical target and observed file/directory kind. Pre-effect recheck reopens from the same root, walks the current parent chain, rejects rebound ancestors and rechecks final presence/type. It does not promise same-inode identity for regular→regular replacement or atomic immunity after the observation. No general arbitrary-file host IO port, target content read/hash or directory enumeration is introduced.

Ready captures proof before confirmation and rechecks before staging/hooks. Fresh source-free admission and final boot owner repeat host checks even when the lock is Fresh. No-answer cold install after target disappearance refuses; ordinary history show remains readable. Metadata-only host readiness is not a source authenticity or materialization permission grant.
