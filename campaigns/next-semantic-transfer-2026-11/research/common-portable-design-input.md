# Complete configuration portability — design input, not acceptance

Read-only review of `/fast/git/wt/common-app-vertical`, against committed main `a0bc99b81a3eab2591bf13a348e7eeb13a3139ee`. No builds, tests, Git mutations or source edits. Reports and captured inputs are under `/tmp`. The companion JSON records every captured input SHA-256, read scope, final hash and drift. Three source files changed during review; their diffs are formatting only. FORMAT-CHANGES.md also gained an explicit all-work abandonment compatibility paragraph; the exact diff was read and retained, and it does not change the portability/default/path proposals. This report proposes the next atom; root retains protocol epochs, architecture and acceptance.

**Recommendation:** extend the existing portable-set and independent import-cohort owners with a typed, version-dispatched rich row. Transfer original intent and its historical semantic basis, then obtain a target-side reviewed configuration and target path realizations through the common evaluator. Never import the source machine's ready evaluation as executable authority. Complete portability means retaining intent through subsequent modification/update/repair, not identical effective results on different hosts.

## Observed owners and current limitations

- `crates/vibe-app/src/portable.rs:79–149` selects non-superseded installations, manual/non-hidden by default, and rejects the entire export if any selected installation has `configuration`. Otherwise `row_of` exports installer, effective features, public string parameters, license bit and lifecycle presentation. It does **not** export original/default/profile/dormant intent, secret origins, pending or completion. Main's counterpart already exported the same flat information without the candidate's rich-configuration refusal. The apps-manifest schema is byte-identical to main.
- There is **no pending/completion gate** in `portable_set`. Thus an indexed legacy finish-park is eligible for apps/1, with pending omitted. A rich indexed finish-park is refused because it has configuration, not because completion was checked. This is source-derived reachability, not a runtime reproduction in this task. New complete-configuration export should refuse unfinished source operations, as root directed. Do not retroactively claim apps/1 always had this contract.
- `portable.rs:167–186` decodes JSON or TOML using the generated apps manifest and then checks exact `vibe-apps/1`. `import_choice:393` reuses a source installer only if offered for current platform/arch; otherwise it uses ordinary host selection. `answers` filters unknown effective legacy answers and disables omitted default features. Rich original intent must not pass through this filtering.
- `portable/continuation.rs` preclassifies all selected rows before effects, rejects common configuration and public parameters classified secret by the target declaration, captures exact acquired source/option/host and a legacy definition digest. That digest hashes `(resolved.application, option)` with `vibevm.app.legacy-import-definition/v1` framing; it is operation admission evidence, not the shared configuration semantic fingerprint. `import_row` reconstructs a flat apps/1 row and would lose rich semantics.
- `operations/import.rs`, `import/store.rs` and `import/rows.rs` already provide a finite, independent cohort: exact local generation, cursor, exact current child, per-row results, re-admitted source/definition, backward parent binding and arrangement after rows. Resume restores saved context instead of reopening the import file. Installed outcomes carry exact target plus row index; refused child ownership is released only after recording the refusal. Arrangement is marked done, complete work settles and is removed. Keep these owners.
- CLI `commands/app/portable.rs` resolves and classifies all manual rows before installation; ordinary resolution/selection refusals become report rows, whereas unsafe portable classification stops the invocation before mutation. Export serializes before writing its destination, so refusal does not truncate an existing file. Current resume is `vibe app import --resume OPERATION_ID`. Do not replace these properties with one row-at-a-time ad hoc importer.
- `configuration/input.rs` distinguishes fresh complete submission from edits of saved original. `parameters.rs:126–220` records public lexical source separately from realized value and origin. It reuses a path only when type, origin and source match and the input is neither replacement nor fresh. `canonical:233` validates the target realization and `must_exist`. Secret metadata records origin/provided/resupply, with values only in ephemeral executable inputs.
- `configuration/record.rs:6–96` admits historical records structurally, verifies definition fingerprint and resolved consistency, and never tests historical path existence. However it requires realized paths to be absolute according to **the reader's current OS**. A Windows path in a portable artifact read on Unix cannot simply be admitted as a local ready record. A portable historical basis therefore needs its own transport admission, not `Index`/ready-record admission.
- `index/upgrade.rs` makes legacy effective state explicit by using `configuration=None`; it does not manufacture original intent. Candidate index wire protocol is 4 when configuration/pending/secret origins require it; flat compatible records may remain protocol 3. New portable protocol, index epoch and import-work epoch are distinct decisions.
- `portable/arrangement.rs` merges collections/pins/overrides after rows and reports unknown launcher keys. It copies icon strings without a target portability assessment. Host path icons need the same explicit binding/unavailable decision as other host resources; a portable arrangement is not a payload archive.

## Proposed transport contract

Use a generated typed envelope dispatched by protocol before decoding its specific payload, with a tagged row configuration: **legacy effective** or **common original**. Do not put richer data under `vibe-apps/1`, hide it in a JSON string or serialize the complete live index. An old reader must refuse the new protocol without installation; a new reader must retain the existing apps/1 path and its effective-only limitations. Keep collection/pin/name/hidden semantics in the existing arrangement owner. Package keys remain exact identities to resolve on the target, not source machine directory authority.

A common-original row needs these minimum semantic groups:

| Group | Transfer | Target meaning/owner |
|---|---|---|
| Identity | Exact package key; source option/platform/arch; source semantic definition/basis | Resolver and chooser find the target package/option. Source option is evidence, not a forced unsupported installer. |
| Original request | Policy, profile identity, features/default-feature policy, exact/additive selections including dormant ones, omitted versus explicit empty, public authored parameter overrides, disabled deltas where part of canonical original | Shared input/definition owner normalizes without discarding unavailable or dormant identities. |
| Reviewed automatic basis | Historical typed semantic definition plus fingerprint and source reliance/basis needed to explain accepted defaults/profile | Common evaluator compares against target definition. A source receipt is not target approval. Keep one authoritative historical basis, not contradictory copied current evaluations. |
| Public parameters | Parameter id/type/origin and original lexical source; optional historical realization explicitly diagnostic and host-qualified | Target parameter owner builds a fresh local realization while retaining source/origin. It must not execute a diagnostic old absolute path. |
| Secrets | Declared id, classification and value-free origin/previously provided obligation | Known Explicit requires resupply on target even if optional. Default/Absent follows reviewed target semantics; do not invent prior explicit supply for legacy unknown state. |
| Presentation | Manual/automatic mark, held/hidden and launcher arrangement | Existing lifecycle and arrangement owners, after target installation succeeds. |

Do not transfer secret values, hashes of secrets, copied environment, process inputs, step output, agent transcripts, work generations, source-home pending pointers, acquired-store absolute directories, project registry locators, payload/cache paths or local license authority. Authored public default literals are part of public package semantics, including public secret-default declarations already treated as public by the current model; do not erase or label those runtime secrets. A portable file is untrusted input, not a signature or a grant to run source-machine steps.

The current shared selection vocabulary uses nullable members to distinguish omission from explicit empty, and TOML cannot encode null. Preserve both JSON and TOML without a lossy serde accident: use a small generated portable presence tag (`omitted` versus `explicit` with members) mapped to the common semantic input, with equivalent typed JSON representation. This is transport representation, not a second configuration model. Do not copy nullable `ConfigurationRecord` wholesale into the default TOML export. Root may instead deliberately choose a JSON-only rich format, but that is a user-visible restriction; the tagged transport is the recommended complete route.

## Read, review and import rules

1. **Export only settled source intent for the new format.** Under the home's existing mutation lock, inspect selected installations and their matching current operation ownership, not just presence in the index. Refuse unfinished operations before output publication and identify the exact package/work target and applicable existing resume/work inspection route. Checking `pending` alone is the first concrete gate, but final implementation must also cover an existing ready record with a newer unindexed pending replacement. Conversely, a retained completed historical run is not unfinished. No new snapshot mode is required. Preserve old apps/1 behavior unless root explicitly chooses an independent compatibility change.
2. **Read safely without the source host.** Validate generated transport shape, identifiers, types, historical semantic fingerprint and internal consistency. Do not require source absolute paths, package cache or source registry to exist. A source realization, if retained for review, is a tagged historical string, not host-native `Path::is_absolute` admission. Reading/dry-run must not write a local ready record.
3. **Resolve and classify every selected row before effects.** Resolve exact package through the chosen target resolver; use the current chooser to select a viable target installer. Preserve source identity alongside target selection. An option/platform substitution needs explicit target acceptance and recomputation even if similarly named controls happen to exist. No implicit dropping of unknown original/dormant selections. If target definition cannot express them, return a specific question/refusal with the identities and required edit; a user may intentionally submit changed original intent.
4. **Compare historical automatic basis.** Evaluate original input against the target definition, retaining the source basis as comparison evidence. Same supported semantics can carry through; changed defaults/profile, removed controls, changed constraints or newly relevant dormant selections need the common review/questions mechanism. Feeding the exported original into ordinary fresh `ConfigurationSubmission` is insufficient: replacement semantics can release prior automatic reliance and silently accept current defaults. An import is transfer/reassessment until the user explicitly chooses a fresh replacement. Structural basis validation is necessary, but a file's claimed prior approval is not target confirmation.
5. **Bind paths on the target explicitly.** For each public path parameter with a value, show id, origin and lexical source, with historical A realization only as context. Accept either a target absolute binding for that exact row/id or an explicitly selected target base applied to stated relative sources. Never silently use importer cwd. Validate only the B realization with the existing type/host/`must_exist` checks. If no binding is supplied and the target cannot establish an explicitly reviewed binding, attended import asks; unattended import returns a structured path-binding question and does not run that row. A literal absolute source path can be explicitly reused on B if valid and approved; it is never assumed portable because it parses.
6. **Keep rebind separate from authoring.** Mapping `Profile:workspace='data'` from A to B must not synthesize an Explicit parameter override. Add a bounded target-realization input at the parameter evaluator boundary keyed by exact row and parameter, preserving original source/origin. Its accepted B value goes into the existing local ConfigurationRecord; no extra configuration database. `resolve_path(&str)` alone cannot distinguish two ids with the same lexical source, so do not make a per-id binding policy depend on that callback alone. If the user instead edits the lexical value or origin, that is an explicit original-request edit recorded as such. Bindings/acceptance attach to the target semantic fingerprint and are invalidated by relevant target definition/input drift.
7. **Secrets are row-scoped requirements.** Import the Explicit resupply obligation, not the secret. Current Default/Absent semantics and an explicit fresh target supply are legitimate distinct choices. A required missing secret produces a common question; a previously explicit optional secret cannot disappear by omission. Use only an ephemeral per-child supply channel tied to exact row/operation, never a cohort-wide map broadcast across packages. Privacy classification must precede persistence: a source-public value whose target declaration is now secret must not be copied to public cohort work or new local record. Refuse that transfer with a specific removal/resupply path, or obtain a sanitized explicit request plus ephemeral supply. A source-secret-to-public change has no transferable value; ask instead of inventing empty text.
8. **Use the existing durable cohort.** Store the accepted typed public original, historical/target basis and target bindings in its row branch, not flat `import_row`. Keep original document row identity distinct from package identity and from compacted accepted-row cursor; two rows may name one key. Re-admit target source/definition before an effect and exact child resume. Definition drift requires renewed review, not replacement of the saved request. Persist no ephemeral secret. Questions may park an already created cohort; dry-run only reports them. Later rows and arrangement cannot overtake a parked row. Existing refusal/continue behavior remains explicit in reports, while semantic questions are not silently turned into completed skips.
9. **Installed comparisons require full semantics.** Matching effective feature names/parameters is insufficient for a rich row with different dormant intent, profile/default reliance or secret obligation. Compare normalized original plus accepted target basis/realizations and existing pending state through the common owner. `--skip-installed` may deliberately retain the old installation but must report that transported intent was not applied. A pending generation cannot be ignored merely because the index has a matching key.
10. **Maintenance is part of the success condition.** Successful B installation stores a normal B ConfigurationRecord with preserved original/dormant input, target-reviewed basis, B realizations and value-free secret origins. Subsequent update/modify/repair in a new process uses that record. Matching B path source/origin reuses the B realization across cwd changes; feature edits do not flatten dormant selections or turn defaults explicit. A later target default/profile change is reviewed again. Re-export describes B's accepted basis and preserved original, not a forever-authoritative A realization.

Automatic installations need an explicit boundary too. Current import prepares manual rows and retains automatic rows only as keys for explanatory notes; it does not apply their saved configuration. The default export also selects manual records only. A full-configuration set cannot silently promise recovery of configured automatic dependencies through that route. Preserve the default manual selection contract as such, and when a rich automatic row is included (for example with `--all`), carry its configuration as an exact-key requirement configuration constraint for the existing dependency installation planner. Apply it only if that dependency is actually required; otherwise report it unused, without changing its mark to Manual or installing it gratuitously. If the dependency is already installed, its rich configuration agreement/skip decision must be explicit. The dependency planner's injection seam was not in this bounded read scope; confirming that seam is a required next-atom design check, not evidence that it already supports these constraints. Root must decide whether the new full export also closes over configured automatic requirements by default or describes its manual-only selection precisely. Do not label an ignored rich auto row a successful full transfer.

Arrangement should keep existing merge/order and missing-launcher reporting. If a host-local icon cannot be rebound, the user must see the unavailable override; do not claim full arrangement restoration. Names/pins remain useful without copying a host icon file.

## Concrete user path and unattended outcome

Export from A resolves completion first and writes the new generated envelope atomically only on success. On B, `app import FILE --dry-run` resolves all rows and reports target-option changes, stale defaults/profile, unknown/dormant identities, path bindings and secret-resupply requirements without mutation. Attended import routes the same questions through the current chooser/common configuration adapter; display current evaluated selection rather than declared defaults.

A noninteractive caller supplies a typed **row-scoped public review/binding input** through the existing read-once file/stdin configuration boundary, extended narrowly for import row identity, target option/basis and path realization mapping. Exact CLI flag spelling/API types belong to root's atom design. `--yes` is not an implicit path base, a secret value, or acceptance of changed original semantics. Unanswered questions return structured non-success with actionable row/id and no execution of that row. If work already exists, return the exact cohort/child target and existing resume command, preserving prior completed rows. On resume the original file may have disappeared; saved public row and exact source/definition are sufficient. Secret resupply remains exact child input. When rows settle, arrangement runs once under the current owner and the report identifies installed, refused and intentionally skipped intent.

License handling retains current target licensing decisions: a carried source license bit is not blanket target acceptance. `vibe install -g` and direct CLI/API configuration consumers continue through the same evaluator and parameter realization owner; they must not gain an ambient portable-import bypass. The new import adapter supplies typed original/basis/bindings to those owners. Package manifests need no parallel configuration dialect.

## Format/API change accounting and remaining root choices

`formats/REGISTRY.toml` currently declares apps-manifest epoch 1, recoverable, foreign parsers many; application-index epoch 3, nonrecoverable, unknown fields deny; import-work epoch 1, recoverable, unknown fields deny. Enriching portable rows and saved cohort rows is a real format change even if the index already has the necessary local ConfigurationRecord. Root must assess protocol/epoch registration, generated types/readers, upgrade/read dispatch and corpus under PROP-044; this report assigns no numbers. Preserve old work replay or refuse it explicitly with the established recovery path, never reinterpret it as rich original.

Recommended root choices: typed JSON/TOML transport presence tags; a new protocol with explicit version-dispatched legacy reader; new full export as the truthful default once implemented, with any requested legacy export restricted to truly representable legacy data rather than silent flattening; target realization input separate from authored parameters; row-scoped review/binding API shared by CLI and library. Remaining choices are concrete public shape/flag names, the minimum historical basis projection the shared evaluator can consume, exact compatibility of old pending-work rows, and host-native test coverage. No new generic journal, shadow database or intent-snapshot mode is needed.

Changelog must state: rich portable transfer and target reassessment; current apps/1 limitations retained; unfinished-source export refusal in the new format; explicit target path rebinding; ephemeral secret resupply; distinct import-work format changes; preservation through ordinary post-import maintenance. Do not advertise the current candidate as already delivering this.
