# Existing proxy copies must survive the index4 transition

Root decision, 2026-11-04. Required amendment to the selected-installer runtime activation, following the source audit archived as nst-proxy-upgrade-audit.md. Implementation/runtime proof pending. L2 reader preparation is accepted in 5d44c5104; it does not by itself refresh previously copied executables.

## Observed source gap

The old standalone executable accepts index3 only. Existing session copies under cache/app-proxies are refreshed only by a new exposure request; an open shell retains its old path. Global copies are refreshed after Index::save, including after catalog revision/event operations which can fail after index publication. The current mixed-index test uses the new binary at both installs and cannot prove old-copy upgrade. First4 publication can come from common configuration, secret origins or pending work. Finish failure does still pass through commit; do not claim it independently skips synchronization.

## Required behavior and approved boundary

Before publishing index4, refresh the valid already-existing managed global and per-installation session copies that the old/current inventory owns, including hidden retained installations. A newly installed app with no public commands must not bypass the prerequisite. Use declared package directories and public command names; do not scan and overwrite arbitrary cache descendants, unrelated names, tool shims or foreign/special paths. An absent session exposure need not be created. Prepublication refresh upgrades readers only; normal removal/addition reconciliation stays with its existing owner after publication. A partially completed reader upgrade followed by refusal leaves index3 readable because new readers support both versions.

The exact image used for these replacements must advertise index4 support. Add a narrow query under the original executable name: `vibe-app-proxy --supports-index vibe-user-applications/4` returns exit0 and exactly that protocol plus newline when supported; unsupported protocol/old executable returns nonzero. Support the corresponding protocol3 query too. Keep existing --probe output vibe-app-proxy/2 and --version unchanged. This is capability reporting by a trusted tool component, not authentication or a signed provenance guarantee.

Probe the same captured image that will be copied, not one path observation followed by another unchecked read. An ephemeral private snapshot named vibe-app-proxy (with the platform executable suffix) may be used so its normal original-name dispatch works; clean that snapshot after use. Do not persist a second proxy inventory, binary-state journal or capability marker. Keep execution bounded and report probe failure without interpreting arbitrary output as support.

Use the existing application mutation lock for the publication barrier and cooperating current session-exposure creation. A current exposure under index4 must not install an incompatible supplied image. Public/raw Index::save cannot silently bypass the incompatible-publication prerequisite. The existing public sync_proxies helper is also a mutation entrypoint: it must not reintroduce an incompatible global image after index4 is present. Self-locking public entrypoints and checked already-locked counterparts reuse MutationLock, bound to the actual home; they do not serialize or persist a token. Preserve a documented public locked-save path so an external caller can still perform an atomic read-modify-write without dropping and reacquiring its lock. Internal operation/dependency exposure paths reuse the outer lock rather than taking a nested lock. Keep truthful ordinary3 use and same-schema metadata maintenance where safe. The implementation must explain all save call-site changes and avoid temporary fake field values.

Do not redesign general index/catalog atomicity: if revision update fails after index4 publication, the operation may still fail, but previously existing valid managed commands must remain usable with upgraded copies. This does not guarantee replacing code already loaded into a running old process or coordinating an old tool process which ignores the new exposure lock. The stored-copy guarantee must be proved without inventing a routing database merely to cover that broader concurrency contract.

## Required evidence

Use a genuine old standalone proxy built from pinned865b41269 source, with source/dependency provenance and binary SHA retained outside the repository; no shipped binary fixture. Demonstrate old3 launch success before transition and tag4 refusal on the same old reader. Then test actual runtime install into a home containing that executable in a global and retained hidden/session path, preserving the original session selection without re-exposing it. Include a rich app with no public command, ordinary success, and deterministic post-publication catalog failure (revision path replaced by a directory). Existing commands must continue working; the failing operation must still report failure.

A prepublication image/copy failure must retain old index bytes and usable incumbent commands, leaving unrelated files untouched. Cover old/missing image, unsafe destination, a legacy pending-only transition, and current exposure under index4 refusing an old image. Durable source tests may use a controlled executable witness/failure injection to discriminate ordering, paired with the real old-binary integration evidence; they must not substitute a fake success for the actual user journey. Preserve the existing strict malformed-index and copied-proxy signal tests.

This amendment is part of the real evaluator/planner/state/lifecycle/CLI activation, whose exact frozen perimeter is119remaining paths. Preserve accepted lower layers and recovery metadata; regenerate the public work addition normally. Full portable configuration roundtrip and all-kind configured package solving remain separate required work.
