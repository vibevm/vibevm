## Optional failure: full public-route qualification

Inspected route: `commands/app/global.rs:285` resolves package and flags → `operations/mod.rs:180` locks → `install_entered:204` loads index/storage, chooses option, admits replacement, passes `prior` and Start through `apply:66` → `Run::new` checks state → owned `place_owned:259` or external `run_external:369` executes → commit.

An existing **same-key** installation is not an already-installed refusal: `admit` receives that key as replacing, `alternatives.rs:52` excludes replacing keys (and same-slot records) from reservation conflicts, and `ensure_available:532` checks unavailable owned library rather than requiring force. In `place_owned:266–287`, prior library is the default selected library; `owned_by_record` compares prior `(library,directory)` with intended target. Existing target requires force only when it is **not** owned by that record. With unchanged choice/library and valid available root, recorded destination does not block manual resume.

That establishes route admission, not every recipe's ability to complete:

- Optional **finish** failure, no earlier Skipped entry stealing the first-open position, and all Prepare Done/Skipped: Resume gets finish shortcut; same-record existing directory satisfies `placed_before`; prepare is kept, `take_out` bypassed, finish retried, commit allowed without force.
- Optional **prepare** failure: resume retries its suffix. The previous successful install moved `out` into the installed payload; open merely creates an empty out. The suffix must reproduce a nonempty out, or `take_out` refuses EmptyResult **before** moving existing target aside. If it reproduces out, same-record replacement is permitted without force. An optional failure after the only output producer can therefore be eligible yet unable to finish by ordinary resume alone.
- External result has no owned `take_out`; it retries the selected suffix and requires the resolved external app_root to remain a real directory. Other existing planning, dependency, agent-admission and external-script requirements still apply. Manual install replans from current public flags, so changed defaults/parameters are not automatically restored by legacy state.

Coverage layers inspected: `owned_payloads_are_replaced_and_removed_without_checks_and_force_is_narrow` (`cli_app_install.rs:332`) explicitly installs a foreign target with force, then replaces the recorded target without force; `keep_work_keeps_the_work_directory_for_a_later_from_step_and_app_work_cleans_it` (`cli_app_steps.rs:611`) exercises actual retained same-key suffix replay without force and keeps settled resume refusal; `a_parked_finish_step_resumes_against_the_placed_payload` (`cli_app_agents.rs:352`) exercises actual **install --resume** with existing index/payload, no force, and no prepare rerun. None of these tests asserts the full optional-runtime-failure + successful keep-work + resume combination. That exact public combination remains a proposed discriminator, not proven runtime evidence here.

**Canonical exact-generation continuation versus explicit manual retry:** a new `app resume <key>` tied to an already completed generation may honestly refuse “completed” even when legacy kept work contains optional Failed entries. This does not require keeping a successful operation pending. Compatibility lies in retaining deliberate manual retry/reopen routes (legacy install --resume where eligible; from-step explicitly restarts settled work), potentially under a new generation. Do not reuse a completed generation's delegation receipt as authority for a new replay. Root retains this contract decision.

## Index and scope limitations relevant to continuation

`commit` first inserts/saves installation, seeds catalog, then deletes retired directories and syncs proxies (`operations/mod.rs:368–445`). Therefore “index was written” is not itself proof even that all later commit-side effects succeeded. No new transactional guarantee is implied by this review.

Existing project `install_pending` filters solely on absence from index (`commands/app/project.rs:245–255`). An indexed parked-finish child is consequently omitted by that baseline path. Requirement execution similarly skips `dependency.installed`; fresh missing-child requests use `InstallRequest::default()` start (`operations/deps.rs:149–179`). These are existing limitations to fix with truthful continuation, not constraints to preserve by equating indexed with complete.

`modify` has no public resume/from-step flags; its internal install request defaults Fresh (`cli/app.rs:280–296`; `operations/modify.rs:102–109`). Do not generate a fictitious `modify --resume` command from this baseline. This review does not design an additional continuation framework or claim legacy replay preserves original public inputs.

## Explicit cleanup-all semantics

CLI `app work --clean` requires either package or `--all`; `--all` requires clean, and package/all share an exclusive Clap group (`cli/app.rs:257–267`). Dispatch ignores the boolean after parsing and passes package-or-None to `clean_work` (`commands/app.rs:126`). `-g` selects user home; otherwise selected project chooses its own home (`commands/app/home.rs:55–73`).

`clean_work` holds the home's mutation lock, obtains the listing, and removes **every listed selected directory without a Done-only filter** (`steps/work.rs:124–138`). No-package means all home work, including Failed, Interrupted, Delegated and Unknown/unreadable-state entries. Package selection can match multiple versions by requirement, not just one exact pending generation (`steps/work.rs:142–167`). This command explicitly abandons those continuation artifacts; it does not uninstall indexed applications, undo placed payloads, delete `app-sources`, delete `app-runs`, or invoke a cancellation workflow. Missing named selection refuses WorkMissing; empty all-home cleanup succeeds. Counts/sizes are listing observations, not a transaction across all directories: deletion can stop on an error after earlier deletions.

## Discriminating acceptance cases for the new continuation

1. Optional ordinary shell failure followed by successful required step: overall success, Failed retained in index/run history; no automatic unfinished-operation classification. Test both no-keep-work (nothing resumable) and keep-work (legacy manual retry admitted, then verify actual suffix completion). Contrast optional planned skip and optional parked/interrupted special cases.
2. Successful retained Done/Skipped run: manual resume refuses, from-step build actually reruns the suffix without refetch. New operation receipt must not permanently prohibit this explicitly requested replay; use a new operation identity if needed.
3. Prepare park versus finish park: first has no new first-install index; second has installed payload plus Delegated index entry. Repeated unanswered finish resume must stay pending and must not rerun prepare. Project child/parent routing must not skip the second merely because index exists.
4. Required authored finish failure versus legacy post hook failure: former commits failed finish state; latter restores previous index/payload. Preserve default work-retention differences; do not infer pending from Failed alone.
5. Explicit scoped `work --clean --all` with done, failed, delegated and unknown work: removes all selected-home work, including pending continuation metadata, while preserving installations/payloads/run/source caches and other home. Later pending resume must honestly report missing work; cleanup must not silently preserve pending directories against the explicit all request.
6. Existing legacy edge to expose, not blindly canonize: earlier Skipped + later Failed/Delegated. Settled check accepts Skipped, but first-open scan does not, so resume can rewind earlier than the actual failure and can disable finish shortcut. Test this deliberately before claiming strict first-unfinished behavior. Likewise owned `--from-step finish` on settled work lacks automatic out payload and need not succeed: preserve the replay entry point, do not promise every suffix reconstructs a valid payload.

No new wire fields or framework proposed. Root should decide any intentional correction to these baseline quirks explicitly and record it separately from continuation compatibility.
