# Checked retirement for one guarded leaf

The existing `InstallRollback::remove` and `Step::MovedAside` inverse are not suitable for the new operation: the inverse removes whatever now occupies the original path. `verify_recorded_files` intentionally permits additional files. Neither proves ownership of an entire directory for removal. Keep the ordinary update guard closed until the following lower-owner gate passes.

Implement a separate checked-removal step in the workspace rollback owner, scoped to the newly authorized guarded-leaf operation. Require the prior lock, selected package identity, and authenticated expected materialization (including generated slot metadata). A snapshot made from the to-be-removed directory by itself is not an expectation. Compare a complete bounded no-follow census including unknown files and empty directories; verify held slot and parent identities and reject missing, modified or unprovable ownership. Use existing safefs and move-aside facilities. Bind the moved object to the proved object and revalidate the stash before discard or restore. Never call `remove_any` on the original path as this step's inverse. Restore only to the original verified parent and an absent name, with a no-replace claim (not an existence check followed by an overwriting rename). On conflict preserve the foreign occupant and the stash, report recoverable residue through the existing error path. Where these guarantees cannot be supplied, refuse the operation rather than widening the trust model. Keep unrelated update/rollback operations unchanged.

First prove the lower step on disposable local fixtures: exact owned leaf, a foreign extra file or directory, same bytes at a replacement identity during the operation, clean rollback, a foreign occupant appearing after move, and a changed stash. Check retained bytes and recovery location on conflict. Only then wire into the already scoped whole-workspace update. Derive lock membership and the staged provisional world from the same solved graph; do not reinsert a retired row via a legacy overlay. Require a public positive update, an independent root retaining the leaf and the earlier guarded-update contract's regression and failure/rollback controls. No deletion of real user data or source/cache trees. Lower-level evidence alone is not acceptance of `update --all`.

### Linux admission and census

The current non-Windows `rename_noreplace` returns `Unsupported`. Add an opt-in Linux directory operation anchored to held parent directory descriptors without silently enabling legacy callers. Destination no-replacement must be atomic; source-identity pre/post checks are cooperative observations, not an atomic source-inode comparison. Unsupported filesystems or cross-device moves must refuse without an overwriting fallback. Preserve uncertain residue. For the first plain-copy leaf, derive the complete expected file set, canonical slot record and directory ancestors from the pinned source/materializer; a matching source hash in the slot record alone is insufficient. No wildcard boot metadata, extra empty directories or unproved file modes. Do not broaden this to converted, overlaid, or in-place packages.

### Source ownership and rollback custody

The concrete source owner checks the exact old locked coordinate, registry binding and content pin. The existing plain-copy materializer builds a private reference slot from those verified bytes, without hooks or project publication. Workspace compares that complete reference against the held live slot; it does not depend on the registry crate or trust an arbitrary caller assertion that a slot belongs to Vibe. Only the checked result may enter the opt-in rollback operation. If a move possibly succeeded before a rollback step was registered, preserve the temporary stash instead of letting its destructor erase it. Return the recovery path without replacing a newly occupied original name.

For the first Linux slice, retain the backup rather than recursively deleting the temporary container. This is deliberate: checking the `slot` child cannot authorize deleting an unrelated sibling. After lock publication, report that the update was applied and give the retained backup path; do not report rollback or rerun hooks. A no-op repeat must not create a second backup. On rollback, move the verified slot back only to an absent name and preserve any remaining container and foreign entries. Test a synthetic foreign sibling on both paths. Automatic backup cleanup is not part of this slice.
