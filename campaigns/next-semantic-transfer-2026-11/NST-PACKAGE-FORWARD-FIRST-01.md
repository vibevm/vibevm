# First candidate-bound forwarded feature

Implement one hop between ordinary local-registry packages. A selected feature on P requests one declared feature on its existing dependency T; T's selection must change an actual observable dependency or data result. Reuse the real candidate-owned dependency edge, existing resolver and original workspace input. The forwarding consumer is the selected candidate/edge, not a fabricated workspace path. Validate the target kind, version, declared feature and admission before effects. Preserve the source's original choice; never flatten forwarded input into user consent. Dormant and unselected alternative candidates must contribute no input. No new solver, unbounded fixpoint, profile/parameter forwarding, network or agents.

Begin with a bounded acyclic, unambiguous candidate/edge. Keep evaluation keyed by actual candidate and its effective incoming inputs; do not reuse an evaluation across differing inputs. Show target selection affects the installed result, the direct explicit target control agrees on the graph but has different provenance, and an independent incompatible consumer refuses before lock, slots, boot or hooks change. Preserve version/source movement and unsupported routes; unknown or cyclic cases may explicitly refuse. A cold process must reproduce source and target records without inventing a new forwarding consumer. Do not enable the writer until stored provenance can be validated independently and actual older clients cannot silently discard it. If the graph requires candidate-conditioned solver admission that cannot be expressed by the existing owner, stop and identify that precise seam before redesigning it. Return exact files, binary, full relevant gates and receipt. This atom does not prove general transitive forwarding.
