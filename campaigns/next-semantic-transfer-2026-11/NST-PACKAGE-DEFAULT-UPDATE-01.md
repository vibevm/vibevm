# Governed whole-workspace update of ordinary configured packages

The schema-12 candidate's public install and cold replay passed for both default states. The public update did not test a changed default: it reached the general configured-input refusal first. Preserve that exact failed observation in `automatic-cli-tests-r1.log`; do not weaken the diagnostic assertion or substitute a second install for an update.

Only the ordinary, whole-workspace `update --all` route over supported local-registry package inputs is in scope. Use the existing update command owner (`commands/update/scoped.rs` and its apply/stage owners), installer planner, resolver snapshot and validated prior lock. Check where current code refuses configuration in both planning and apply. Do not globally remove those guards. Do not implicitly admit partial/named updates, mixed in-place sources, transitive input forwarding or unsupported feature classes. If the full-update path cannot preserve update selection and its existing commit/rollback semantics through the common planner, report the exact missing owner contract before product changes there; do not add another solver or a second publication path.

Run the public command in separate synthetic fixtures with the same reachable 1.0-to-1.1 source update. An explicit disabled selection must actually advance to 1.1 without taking its new enabled default. An omitted previously relied-on default must refuse on the semantic comparison, leaving lock, slots, boot, and hook effects unchanged. An unchanged relied-on default is a separate control: it should not be blocked simply because the source version changes. Reject corrupt historical basis before effects; `--assume-yes` does not acknowledge changed meaning. Keep unchanged old feature and format gates. Report exact before/after version, selected dependency graph and refusal stage. Stop before interactive acknowledgment or enlarging the update matrix.

### Independent pre-repair comparison

The architect exercised CLI SHA-256 `41df60bc80cda660edb9fee6f468fa3b0ddcc4647057928e4cb4fbdd2967ce96` in isolated local registries. An omitted default installed/replayed at epoch 12; an explicit equal selection installed/replayed at epoch 8. In each case the fresh process retained byte-identical lock contents. After publishing fixture version 1.1 with the opposite declared default, both public `update --all` commands exited 1 with the same broad unsupported-configuration diagnostic. The before/after sets and digests of eight selected project files per fixture (lock, manifests, slot and boot files) matched. The fixture has no hook, so it is not hook rollback evidence. This confirms an early refusal without those file changes and rules out treating that refusal as a test of default drift. Do not bypass scoped apply's prepublication and rollback checks or repeat B-234 by replaying the old version as an update.

### Configuration must survive the whole update

The scoped resolver currently selects the graph without a configuration snapshot. Staging constructs `ResolvedDep` with `configuration: None` both for the selected world and updated rows; replacing package rows alone does not replace the corresponding lock configuration. For the supported whole-workspace route, carry one validated selected record per coordinate from resolution through fetch verification, staging, prepublication checks and apply. Recheck the original consumer set before publication. Keep unaffected rows, preserve the existing rollback/cancellation boundary, and never drop stored configuration merely to pass a guard. This is a bounded extension of update, not a call to plain install: the latter's locked-version replay would reintroduce B-234.
