# UP-ARTIFACT-CAPTURE-BACKING-01 — owned backing adapter

Date: 2026-11-16. Narrow architectural amendment to committed
UP-ARTIFACT-CAPTURE-01 (`2e67c525c85912fd29a610f766e3bbe3d6699ed9`).
Decision: choose the operation-owned backing adapter, not mandatory new forwarding
traits through every materializer. Builder implements under the separately relayed
owner direct USER-PROJECT mandate. No worker launch or broader authority follows.

## Required operation sequence

1. Before prepare_manifest and any target publication/hook, capture ALL cached
   originals through existing retained-root no-follow source observations. Enumerate
   full original shippable inventory, prune exclusions before traversal, validate
   names/types and recensus directory identities. Captures retain bytes/modes.
   Registry utility verifies the same captured rows against the expected recipe,
   coordinate and manifest meaning. No portable hash comparison for native in-place.
2. Only after every cached capture verifies, allocate private operation backing.
   Use existing runtime scratch-root authority (ordinary temp-dir selection, not
   a baked machine path, implicit settings initialization or original-cache parent).
   Admit its parent/root through existing safefs. Fresh allocation is finite
   admission, NOT proof of a syscall-returned created-directory capability. Reject
   unsafe/unusable roots; do not create missing settings or change shared modes.
   Ensure backing is not inside any captured input or target slot and cannot become
   part of its own inventory. Private permissions must exist before sensitive writes.
3. Retain backing immediately without automatic recursive TempDir Drop cleanup.
   Publish descendants exclusively from captured bytes through retained parents,
   preserving permissions without chmod of any original/shared source. Never make
   capture backing by hardlinking mutable cache. Recheck admitted identities and
   full prepared content before exposing backing to consumers. On uncertainty retain
   evidence, do not delete or repair whatever occupies a name.
4. Keep administrative recovery metadata OUTSIDE the payload root: e.g. private
   operation root contains a payload child and sibling recovery record. Otherwise
   materializer traversal could install/hash the recovery ledger as package content.
   Publish private recovery metadata exclusively, mode 0600, with original coordinate,
   expected identity and backing binding/identity. No credentials; private paths stay
   in private recovery evidence, never public reports. Record partially prepared
   backing before possible failure; retain it on success/failure for this atom.
   Explicit disk debt is acceptable here; future cleanup needs its own exact
   identity/authority/lifetime decision. No general deletion grant.
5. After ALL backing payloads are ready and verified, update only the cached read
   locations (`fetched.cached.cache_dir` and corresponding `resolution.content_dir`)
   as one local batch transition. Require exact unambiguous coordinate/version/hash/
   manifest correspondence; missing/duplicate/mismatched rows refuse. Preserve
   source_uri, source refs/commits, hashes, lock provenance, embedded pins and native
   prepared objects. Do not misrepresent backing path as original source identity.
6. The bundle owns captures and admitted backing for the complete apply call, through
   slot materialization, conversions, hooks, boot and metadata finalization. Preserve
   owner lifetime explicitly; don't create then drop an unused precheck bundle.
   Existing consumers may reopen the operation-owned payload path under their
   existing finite-observation contract, NEVER the original cache. This is an
   explicit refinement of predecessor's mandatory borrowed-input trait requirement.
   Backing admission and rechecks do not promise hostile same-UID exclusion or CAS.
7. Validate the reported consumer census in the integrated candidate: lock recording
   uses original source provenance; slot verifier uses expected hashes; configuration
   uses captured-equivalent manifest; embedded-source data is already retained;
   boot reads installed slots. Returned reports/native carriage and parked/resume
   state must not contain a dropped ephemeral backing dependency. If a consumer
   still needs backing, retain its reference and recovery owner rather than serialize
   a naked path or silently return to original cache. Stop for exact scope change
   if this census proves wrong; no further generic exploration gate is required.

## Modes and limits

Copy consumes owned captured backing; Hardlink makes a genuine link attempt from
that backing with existing copy fallback. PROP-022 permits initial sharing, not
mandatory sharing of original-cache inode. No forever-immutable-slot promise or
always-copy mode suppression. Transformation consumes these same originals, with
independent derived identity. Native commit-derived identity and legacy opaque-hash
workspace entrypoints retain existing behavior. No backing helper is a substitute
for retained destination C0-C4 authority or strong Windows namespace APIs.

The precheck-only intermediate is NOT a repair even if the old RED becomes GREEN.
All predecessor gates remain, particularly deterministic original-cache mutation
AFTER capture/before consumption, both recipes, full-batch late mismatch, Copy/
Hardlink/fallback/permissions, declared/transformed originals, cancellation and
honest partial failure. Verify administrative metadata never enters slot/hash/boot.
Also test backing identity/path substitution within the finite-observation boundary;
report excluded final-gap races rather than claim unconditional content CAS.

Return exact integrated frozen manifest/diff, consumer and ownership mapping,
backing disk-debt/recovery facts, nonzero selected tests and unrun gates. This
amendment approves the bounded architecture/perimeter, not source correctness,
whole USER-PROJECT acceptance, public activation, installation or publication.
