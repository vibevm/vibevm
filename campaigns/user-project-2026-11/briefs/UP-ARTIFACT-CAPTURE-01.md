## Capture and consume contract

1. Registry owns canonical original-tree recipe/exclusions/order, not workspace.
   A focused CapturedPackageTree may capture(root, expected identity) and expose
   read-only original rows/bytes/modes and established identity. Expected strings
   must be parsed/validated, including recipe selection; opaque native commit
   hashes must not be treated as portable tree hashes. Capture inventory errors,
   unsafe entries and unstable reads refuse; do not silently omit failed entries.
   Preserve existing valid source types/modes; report an unsupported case rather
   than broadening traversal. Reuse existing held source reads and safe path rules.
2. Hash the complete ORIGINAL shippable inventory using the expected recipe,
   including originals later filtered or converted out of the slot. Recipe parity
   is mandatory. Prepared output/derived aggregate is not the original identity.
   Capture bytes and permissions from the same observation, not a hash/reopen pair.
   No new arbitrary global byte quota; allocation/I/O failure is honest refusal.
3. Batch capture happens at ordinary apply entry before prepare_manifest or any
   slot/hook/native deferred publication. Every cached row is checked against its
   planned identity, coordinate and manifest meaning. A late batch mismatch must
   not occur after earlier batch items have already published. Native in-place is
   typed and explicitly outside portable capture, not silently treated as cached.
   Capture itself has no target effects. Operation-owned backing, if needed, must
   have an explicit owner, location, identity and failure/retention behavior.
4. Workspace defines a narrow read-only prepared-original input seam; install adapts
   registry captures to it. Workspace gains no registry dependency. This is not an
   arbitrary filesystem framework or a forged PreparedSlotPlacement: that existing
   interface is in-place-only. Batch ownership stays alive through all consumers.
   Missing required cached input refuses; no fallback to ambient paths on this route.
5. Mixed/declared/transformed publication reads captured originals. Converters and
   policy checks see those originals, not a second cache observation. Derived hash
   remains independent. Existing legacy wrappers without verified input preserve
   their opaque-hash contract; do not globally reinterpret dummy-hash fixtures as
   source authentication. Ordinary install's cached route must not choose legacy
   wrappers to evade verification. Enumerate all forwarded consumers, including
   native composition containing ordinary cached dependencies.
6. Verified Copy consumes owned captured bytes. Hardlink remains supported with a
   genuine link attempt and incumbent copy fallback. PROP-022 HARDLINK-MODE and
   ACC-MODE-BEHAVIORS say initial files MAY be shared, not that original-cache inode
   sharing is mandatory. Operation-owned captured backing may be the source if its
   publication consumes the verified bytes and original cache changes cannot alter
   it. Do not hardlink mutable cache into the capture, silently always-copy the mode,
   chmod shared source, or claim permanent slot immutability. Name exact backing
   lifecycle; no broad deletion grant or false hostile same-UID exclusion from mode
   bits/random naming. If existing mechanisms cannot enforce the required finite
   handoff, stop with a precise blocker rather than inventing 'sealed' authority.
7. Reconcile/record/hook/boot/lock finalization keeps existing effect ordering and
   explicit rollback laws. Later failure must preserve typed actual effects and
   failed undo; no whole-world atomicity or restored claim from slot-local success.
   Source mismatch caught in early capture is distinct from a later publication
   error. No new cleanup/Drop rollback, native plugin undo or root-authority claims.
