### Что уже стоит, и на чём это держится

Шесть схем каталога описаны (`schemas/index/e1/` — пять, `schemas/journal/e1/`
— одна), у каждой **оракул провода** в `crates/vibe-index/tests/wire_parity_*.rs`.
Оракул строит полностью заполненный рукописный тип, гоняет его через JSON в
сгенерированный и обратно и сравнивает значения. **Это твоя страховочная сеть
на весь остаток Ф4.2**: преобразования генератора меняют форму типов в Rust —
и обязаны НЕ трогать байты. Оракул именно это и меряет; он переживёт все
преобразования по построению.

Словник `formats/vocabularies.json` несёт **18 фрагментов** (включая составной
`version_entry` со всем замыканием); подстановка транзитивна, отказы
именованы, `x-vocabularies` снимается с внедрённого фрагмента.

**Аннотации политики уже написаны и СЕГОДНЯ НИКЕМ НЕ ЧИТАЮТСЯ** —
`x-vocabulary`, `x-empty`, `x-default`, `x-rust-type`. Их потребитель — ровно
та работа, которой ты начинаешь. Не прими их за работающий механизм и не
переизобретай: они данные, ждущие своего читателя.

### Ф4.2 — восемь преобразований, одно готово

Список полный и решённый (план Р5 + `f4-jtd-tagged-union-probe.md` §5):

1. закрытый enum → открытый `Unknown(String)` — **по `x-vocabulary`, а не по
   факту закрытости**: генератор выдаёт открытый и закрытый словари
   синтаксически НЕРАЗЛИЧИМЫМИ, измерено;
2. camelCase → snake_case — снимает `#![allow(non_snake_case)]` в ОБОИХ
   потребителях;
3. политика пустого по `x-empty`;
4. `deny_unknown_fields` по реестру (`foreign_parsers = "none"`);
5. `Option<Box<скаляр>>` → скаляр + `default` + именованный предикат по
   `x-default` — иначе булева ось получает третье состояние, запрещённое
   ратифицированным контрактом;
6. `DateTime<FixedOffset>` → `DateTime<Utc>`;
7. **боксирование плеч объединения — ПОСТРОЕНО** (`06875323`,
   `xtask/src/codegen/postproc.rs`);
8. доменные типы по `x-rust-type` (`Group`, `semver::Version`,
   `DateTime<Utc>`) — иначе реэкспорт понижает типы до строк по всему индексу.

**Первое дело следующего шага — РАСКОЛ.** `xtask/src/codegen/mod.rs` — **586
из 600**. Каждое преобразование требует проводки в `generate_into`. Начинать
надо с раскола по шву ответственности, а не с ужатия: прецедент раскола в
этом же каталоге уже есть дважды (`format_id.rs`, `postproc.rs` + `postproc/tests.rs`).

**Форма постпроцессора задана и проверена:** `postproc.rs` — построчный
сканер с ГРОМКИМ отказом на незнакомой строке внутри распознанной
конструкции, с сохранением окончаний строк и с распознаванием по НАЧАЛУ
строки (в дереве есть док-комментарий, цитирующий тег-атрибут в обратных
кавычках, — единственная реалистичная ложная сработка). Новые преобразования
садятся тем же приёмом; тесты — отдельным файлом через `#[path]`.

## Делегирование — по умолчанию

`SUBAGENT-MODE.toml` = `claudez`. Пакеты режет босс; воркеры не запускают git;
диффы читает, правит и коммитит босс; ревью не делегируется никогда. За
прошлую сессию: **тринадцать пакетов, тринадцать приняты, ноль циклов
доработки**. Что доказано работающим (полностью — в §8):

- периметр записи как ЗАКРЫТЫЙ СПИСОК файлов — **и он обязан называть файл,
  который предписанный им же раскол создаст**, иначе два пункта пакета
  сталкиваются;
- заголовки результата и шаблон отчёта вшиты в пакет дословно;
- на каждое утверждение базовой линии — confirm-or-refute с цитатой;
- не отдавать воркеру число, которое он может пересчитать сам;
- **красное доказательство требуется как пункт приёмки**, и на объединение их
  ДВА: поле у плеча и целое плечо (плечо, которого не упражняли, ничего не
  доказывает);
- **self-verify пишется от того, что правка ТРОГАЕТ, а не от того, что
  добавляет** — правка общих ДАННЫХ обязана назвать крейты, чьи тесты на них
  стоят;
- **отчёт пишется РАНЬШЕ финальных гейтов, но каждая строка приёмки начинается
  словом PENDING** — иначе срез сохранит отчёт и вместе с ним неизмеренное
  утверждение (случилось, поймано перемером);
- два последовательных шага делят один worktree через `-c` с боссовым
  wip-коммитом между ними: сборка тёплая, диффы раздельные.

**Убитая задача не убивает воркера** — два случая за прошлую сессию, оба
дописали работу (логи росли на 62 и 5 КБ ПОСЛЕ «убийства»). Процедура: фоновый
сторож до стабилизации лога, **никогда не прибираться вокруг живого
процесса**, читать worktree, добирать хвост. «Killed» — не вердикт.

## Порядок посадки — оплачен красной панелью

Применить дифф → `cargo fmt --all` → **`cargo xtask specmap`** → панель → суд
→ коммит. Карта, пересобранная ДО того как лёг код, — карта дерева, которого
уже нет.

**Слайс, трогающий `crates/vibe-wire/src/generated/**`, садится в порядке
СТЕЙДЖ → панель → коммит.** `check-codegen` — это `git diff --exit-code`,
рабочее дерево против ИНДЕКСА, и untracked он НЕ ВИДИТ. За прошлую сессию это
правило применялось трижды и трижды было нужно.

**Панель обрывается на первом красном шаге** — «упала на X» ничего не говорит
о шагах после X, зелёный хвост единственное доказательство. Если посадка
трогает саму панель, её гоняют дважды. **`cargo test` останавливается на
первом упавшем ТАРГЕТЕ** — красное доказательство, растянутое на два таргета,
показывает одно падение без `--no-fail-fast`.

**`cargo fmt` без `--check` выходит с нулём и когда результат не чист** —
проверять надо той формой, которую гоняет панель.

## Shell — оплачено ошибками, не повторяй

Никогда голый `cd` — только `( cd … && … )` / `git -C` / абсолютный путь;
`cmd | tail; echo $?` печатает код ПАЙПА — редирект в файл и `$?` сразу;
**правки только editor-инструментами** (`sed -i` — нарушение); python — с
`PYTHONIOENCODING=utf-8`; файл, вырезанный текстом, начинается с шапки `//!`,
а не с пустой строки.
